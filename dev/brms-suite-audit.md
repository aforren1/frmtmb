# brms 2.23.0's own test suite, sized for Phase 2.6

Item 2.6a. This document SIZES the port. It ports nothing, and it
changes no package code. Every count in it is generated by a script
named beside it; nothing here is typed from memory.

## 1. Where the suite is

CRAN's Windows binary drops `tests/`, so the suite needs the source.
brms 2.23.0 is the CURRENT CRAN version, so it is not in the archive:
the archive URL returns an HTML "Object not found" page of 992 bytes,
which is what the first fetch here collected.

    curl -sSL -o brms_2.23.0.tar.gz \
      https://cran.r-project.org/src/contrib/brms_2.23.0.tar.gz

- tarball: `dev/brms-suite/brms_2.23.0.tar.gz`, 5,189,786 bytes

  `dev/brms-suite/brms/tests/testthat/`
- `DESCRIPTION` reads `Version: 2.23.0`, which is the installed version

`dev/brms-suite/` is added to `.gitignore`. It is 434 files and 5 MB of
another project's source, and the two lines above re-fetch it exactly.
`dev/brmslp/` sets the precedent.

**The suite is named `tests.<topic>.R`, not `test-<topic>.R`.** A glob
written for this repository's own convention finds nothing at all.
23 files, 8,616 lines.

## 2. How the counts were produced

- `dev/brmssuite-count.R` writes `dev/brmssuite-counts.tsv` and
  `dev/brmssuite-blocks.tsv`. It PARSES each file and walks the AST
  with `all.names()`, so an assertion split over four lines counts
  once and a `expect_equal` inside a comment or a string counts not at
  all. A first draft that matched `^expect` counted `expected_ar_mat`
  and three siblings, 11 data objects, as assertions.
- `dev/brmssuite-classify.R` assigns a bin to every block and writes
  `dev/brmssuite-classified.tsv` and the generated table in section 3.
  It STOPS if any block matches no rule, so a block cannot fall out of
  a total silently.
- `dev/brmssuite-verbs.R` prints the assertion verb per file.

Two totals, and why they differ by 14. Counting per FILE gives 2,025
assertions; counting inside `test_that()` blocks gives 2,011. The gap
is assertions that are not in a block: 8 in
`tests.read_csv_as_stanfit.R`, which live in its `compare_functions()`
helper, 4 in the two helper definitions at the top of
`tests.brmsfit-methods.R`, and 2 in the
`expect_match2 <- brms:::expect_match2` alias line in
`tests.stancode.R`. The tables below use the block count.

## 3. The counts

Bins are Phase 2.6a's, with the reason recorded because it changes the
cost:

| bin | meaning |
|---|---|
| 1 | transfers as-is: grammar, priors, family and data validation, argument names, return shapes |
| 2T | the assertion reads a POSTERIOR that ML replaces with an estimate and a standard error, so it is restated |
| 2P | the assertion reaches a brms INTERNAL object that frmtmb builds differently, so it is rewired; the tolerance is unchanged and is usually an identity |
| 3S | Stan code or Stan data |
| 3M | MCMC diagnostics, or a quantity defined only over draws |
| 3I | a brms-internal utility with no frmtmb counterpart |

A block takes ONE bin, by its subject. Where a block mixes, the note in
section 4 says so; `tests.brmsfit-methods.R`'s `fitted` block is the
clearest case, 23 assertions that are bin 1 on argument names and bin
2T on the four summary columns.

## 5. The fixtures are the hidden cost

Five files run on `brms:::brmsfit_example1` to `6`, fits stored in
brms's `sysdata.rda` and not reconstructible from the tarball:
`tests.brmsfit-methods.R` (317 assertions), `tests.posterior_epred.R`,
`tests.emmeans.R`, `tests.data-helpers.R`, `tests.priorsense.R`.
Their formulas, read off the installed package by
`dev/brmssuite-fixtures.R`:

| fit | formula |
|---|---|
| 1 | `count ~ Trt * Age + mo(Exp) + s(Age) + volume + offset(Age) + (1 + Trt \| visit) + arma(visit, patient)`, `sigma ~ Trt`, student |
| 2 | `count \| weights(AgeSD) ~ 1/(1 + exp(-a)) * exp(b * Trt)`, nonlinear, `a` and `b` each `~ Age + (1 \| ID1 \| patient)` |
| 3 | `count ~ Trt * me(Age, AgeSD) + (1 + mmc(Age, volume) \| mm(patient, visit))` |
| 4 | `rating ~ x1 + cs(x2) + (cs(x2) \|\| subject)`, `disc ~ 1`, ordinal |
| 5 | `count ~ Age + (1 \| gr(patient, by = gender))`, `mu2 ~ Age`, a 2-component mixture |
| 6 | multivariate: `volume ~ Trt + gp(Age, by = Trt, gr = TRUE)` and `count ~ Trt + Age` |

`dev/brmssuite-featureprobe.R` puts each term through
`frm(..., dry_run = "frame")`. 20 of 24 are accepted: `mo()`, `s()`,
`t2()`, `mm()`, `mmc()`, `cs()`, `gp()`, `weights()`, `se()`,
`trunc()`, `cens()`, `nl = TRUE`, `mvbf()`, `categorical()`,
`mixture()`, `offset()`, `(1 + x | g)`, `(1 | ID | g)`,
`arma(cov = TRUE)`, and a plain `(1 | g)`. Four are refused:

- `me(Age, AgeSD)`, `could not find function "me"`. Fixture 3 cannot be
  built at all.
- `gr(patient, by = gender)`, `gr()` takes `cov` and `prec` only.
  Fixture 5's grouping is not available; a plain `(1 | patient)` would
  change what the block tests.
- `arma(visit, patient)` without `cov = TRUE`, a documented refusal
  with a stated reason. Fixture 1 needs the argument added.
- `thres()`, not among the supported addition terms. This is what
  `tests.standata.R`'s grouped-threshold block, 11 assertions, needs.

So the port needs its own fixture set. Three of brms's six designs are
reachable with a one-argument edit, one is not reachable, and two need
a term frmtmb does not have.

## 7. brms contracts this project has not written down

Whether or not frmtmb meets them, these are contracts brms's own suite
asserts and no document here states.

1. **Every brms error is a classed condition.** `stop2()` raises with
   `.subclass = c(..., "brms_error")`, so `tryCatch(brms_error = )`
   catches any of them, and `conditionCall()` is preserved. Measured:
   `brms::brm(y ~ x, d, family = "ordinal")` raises
   `c("brms_error", "rlang_error", "error", "condition")`; the same
   refusal from `frm()` raises `c("simpleError", "error", "condition")`.
   No frmtmb error is classed anywhere in `R/`.
2. **`bf()` is idempotent.** `expect_identical(form, bf(form))` for
   both a dpar formula and a nonlinear one.
3. **A family constructor takes an UNQUOTED link.** `student(identity)`,
   `negbinomial(sqrt)`, `exponential(log)`. This is stats' `family()`
   convention, carried forward.
4. **A family object's `$link` is a single string**, with
   `link_<dpar>` beside it for every secondary parameter:
   `beta_binomial()$link_phi`, `zero_inflated_binomial()$link_zi`.
5. **`default_prior()` is the canonical spelling.** `get_prior()`
   became its alias in brms 2.20.14. `validate_prior()`,
   `empty_prior()` and `as.brmsprior()` are the rest of that surface.
6. **`set_prior()` arguments may be VECTORS**:
   `set_prior("normal(0, 2)", class = c("b", "sd"))` yields two rows.
7. **`print(brmsprior)` prints `class_coef ~ prior`**, for example
   `sd_x ~ cauchy(0,1)`.
8. **A link is refused per family AND per dpar.** `bernoulli("sqrt")`,
   `exponential("cloglog")`, `Beta("1/mu^2")`,
   `zero_inflated_negbinomial("logit")` are all errors in brms.
9. **`mixture()` refuses incompatible components**: ordinal with
   non-ordinal, and real support with integer support.
10. **`family = c("weibull", "sqrt")` is a supported spelling**, family
    and link in one character vector.
11. **An ordinal or categorical response must be an ordered factor or
    positive integers.** An unordered factor is an ERROR, not a
    warning, because its level order is arbitrary.
12. **brms MESSAGES when a model would be better specified**: binomial
    with `trials(1)`, or an ordinal or categorical response with two
    categories, suggests `bernoulli`.
13. **`re_formula` term order must match the original formula**
    (issue #844): `check_re_formula()` refuses
    `~ (0 + x2 + x1 | x3)` against `(0 + x1 + x2 | x3)`.
14. **Deprecated argument spellings keep working and WARN.**
    `as.data.frame(fit, pars =)` and `as.data.frame(fit, subset =)`
    both warn and still return the right thing; `nsamples()`,
    `posterior_samples()` and `parnames()` are live.
15. **`update()` refuses `data =` and demands `newdata =`**, and
    refuses a formula update naming a variable the data lacks.

## 8. Findings from the spot check, filed and NOT fixed

No package code was changed in this lane. Each item below has its
construction. `dev/brmssuite-defects.R` runs items 1 to 7;
`dev/brmssuite-shapes.R` runs items 8 to 10.

### Already recorded elsewhere, reproduced here

- **`fitted()` swallows its dots.** Item 2.5e. Reproduced, and the
  swallow is wider than the row states. On the epilepsy fit,
  `fitted(fit)[1]`, `fitted(fit, re_formula = NA)[1]`,
  `fitted(fit, scale = "linear")[1]`, `fitted(fit, dpar = "inv")[1]`
  and `fitted(fit, this_argument_does_not_exist = 42)[1]` are all
  3.499480 and `identical()` to each other. `scale` and `dpar` are two
  more brms arguments 2.5e's acceptance criteria should name.
- **`hypothesis()` returns a different object.** Already finding 7 in
  `dev/brms-methods-tests.md`. Measured again here: `names()` is
  `hypothesis, estimate, se, lwr, upr, z, p` where brms has a
  `brmshypothesis` list whose `$hypothesis` is an 8-column frame.

### New

1. **`family$link` silently returns a LIST, by partial matching.**
   frmtmb's family object has no `link` element at all; it has
   `links`, a per-dpar list of link objects. `$` partial-matches, so
   `student()$link` returns that list rather than `NULL` or an error,
   and brms-shaped code reading `fit$family$link` gets a list of
   functions where it expects `"identity"`. `link_shape`, `link_phi`
   and `link_zi` are `NULL`. This is the `$`-on-a-hazard-container
   failure the house rules already name, on a PUBLIC object.
   Construction: `names(student())` has `links` and not `link`;
   `str(student()$link)` prints three per-dpar entries.
2. **No family accepts an unquoted link.** `student(identity)`,
   `negbinomial(sqrt)`, `exponential(log)`, `geometric(identity)`,
   `zero_inflated_poisson(log)` all error with "A link must be named by
   a single string". 5 assertions in `tests.families.R`.
3. **The link is NOT validated against the family for `mu`, and an
   invalid link FITS.** `bernoulli("sqrt")` builds a family whose `mu`
   link is `sqrt`, with `linkinv = eta^2`, and
   `frm(y ~ x, d, family = bernoulli("sqrt"))` RETURNS a fit,
   `(Intercept) = 0.64759734`, `x = -0.02160626`, with only an
   `nlminb` "NA/NaN function evaluation" warning. The same design under
   `bernoulli()` gives `-0.3224290` and `-0.1236686`. A probability
   under a `sqrt` link is unbounded above 1, which is why brms refuses
   it. The check EXISTS for secondary dpars:
   `weibull(link_shape = "logit")` is refused by name with the allowed
   set. It is missing for `mu`. Also accepted: `exponential("cloglog")`,
   `Beta("1/mu^2")`, `zero_inflated_negbinomial("logit")`,
   `beta_binomial("log")`.
4. **`bf()` is not idempotent.** `bf(bf(y ~ x, sigma ~ 1))` errors with
   "`formula` must be a formula". Any brms idiom that normalizes a
   formula by calling `bf()` on it breaks.
5. **`mixture()` accepts components with incompatible support.**
   `mixture(poisson(), categorical())` and
   `mixture(lognormal, exgaussian, poisson())` both return a
   `frmtmb_family`. brms refuses both, the second because a mixture of
   a real-support and an integer-support density is not a density.
   The ordinal check exists: `mixture(poisson, "cumulative")` IS
   refused.
6. **`set_prior()` refuses a vector `class`.**
   `set_prior("normal(0, 2)", class = c("b", "sd"))` errors with
   "`class` must be a single non-empty string". brms documents and
   tests the vector form.
7. **`default_prior()` and `validate_prior()` do not exist.** frmtmb
   exports `get_prior()`, which brms demoted to an alias in 2.20.14. A
   brms script written in the last two years calls `default_prior()`.
   `empty_prior()` and `as.brmsprior()` are also absent.
   `get_prior()` itself is in good shape: it returns a data frame with
   brms's nine columns. On brms's own test call it reports classes
   `b, cor, Intercept, sd` plus a `theta` row brms does not produce;
   the `theta` row is worth a look on its own.
8. **`posterior_summary(fit)` fails with an internal message.** It
   dispatches to `posterior_summary.default`, which calls `as.matrix()`
   on the fit and dies with "is.atomic(x) is not TRUE" after a
   `mean.default` warning. `loo()` and `waic()` on the same fit refuse
   cleanly and say to sample first; this one does not.
9. **`VarCorr(fit)` names its element `"1 | patient"`.** brms names it
   `"patient"`, and so does lme4. The name matches neither ancestor.
10. **`variables(fit)` drops brms's `b_` prefix but keeps
    `sd_<group>__<coef>`.** On the epilepsy fit it returns
    `Intercept, zBase, Trt1, zBase:Trt1, sd_patient__Intercept`, where
    brms returns `b_Intercept, b_zBase, ...`. Half of one convention
    and half of the other. `variables()` is one of the 13 rows
    `dev/brms-api-diff.md` records as matching brms EXACTLY, which is
    true of its formals and not of its answer.
11. **An unordered factor response reaches an ordinal family with a
    WARNING**, where brms errors: "Ordinal response 'y' is an unordered
    factor; its level order (high < low < mid) is taken as the category
    order". The warning is good and the divergence is loud, but brms is
    the tiebreaker and brms refuses.
12. **`(1 | g) + (x | g)` is accepted.** brms refuses duplicated
    group-level effects on one factor. lme4 and glmmTMB accept it and
    mean two independent blocks, so this is a divergence to adjudicate
    rather than an obvious defect, but it is undocumented either way.
13. **`y ~ x * cs(g)` is accepted.** brms refuses `x:cs(g)` by name.
14. **`bf(y ~ ~ x)` is accepted.** brms refuses `~~` by name, its issue
    #749.
15. **No bernoulli suggestion.** `binomial` with `trials(1)`, and an
    `acat` response with two categories, produce no message.
16. **`brmsfamily()` does not exist.** brms's generic constructor,
    `brmsfamily("zi_poisson")` or `brmsfamily("gaussian", inverse)`,
    is how a ported script builds a family from a name. frmtmb spells
    it `frm_family()`, and `frm_family()` refuses the
    `c(family, link)` form as well, item 10 in section 7.

## 10. Which bin-1 files pay first

In order, with the reason.

1. **`tests.families.R`**, 84 assertions, no fixture. It already found
   items 1, 2, 3 and 5 of section 8, including an invalid link that
   FITS. 30 of its 84 assertions are refusals of a bad link, and
   frmtmb's per-family `mu` link check does not exist.
2. **`tests.brm.R`**'s error block, 23 assertions, no fixture. 15 of 23
   are the same refusal in other words, which means the boundary is in
   the right place and the messages need a regexp; 2 are refusals
   frmtmb does not make.
3. **`tests.standata.R`**'s 19 validation blocks, 87 assertions. 12 of
   the 16 run here were the same refusal in other words and 3 were
   refusals frmtmb does not make. This is the file that reads the
   response against the family, which is where a silent wrong answer
   is worst.
4. **`tests.priors.R`**, 36 assertions. Found two naming gaps and one
   grammar gap in a group that took minutes, and the prior surface is
   the one thing a ported brms script carries verbatim.
5. **`tests.brmsformula.R`**, 16 assertions. Found `bf()`'s idempotence
   break, which is a one-line fix with a wide blast radius.
6. **`tests.brmsfit-methods.R`**, 223 assertions, after the fixtures.
   The measured shape divergences are there, but most of what the
   second spot check reported is the deliberate lme4 heritage of
   `predict()` and `fitted()`, so this file needs its divergence list
   written BEFORE it is ported or it will report 25 failures that are
   policy.

The user's instinct is confirmed with a qualification. Argument
spellings and return shapes ARE where the drift is, but the sharpest
findings came from the family and validation layer rather than from the
method layer, because the method layer's divergences are mostly already
known and deliberate while the family layer's are not.
