## How the release tree was built

The lanes were combined in `../frmtmb-wt-release` (branch `wt-release`
at `4854e425`), in the brief's order: loodraws, cdfs, nb2dm, fuzzfix.
Every lane is on `4854e425`, so the base of every merge is the HEAD
blob. Nothing was committed and no git write was made: blobs are read
with `git show`, and `git merge-file` works on files, not on the index.

- `dev/rel073-merge.sh` (from `dev/rel072-merge.sh`) merges in one
  rerunnable pass: it restores each of the files any lane changed to
  its HEAD blob, removes the untracked lane files an earlier run copied
  (`dev/rel073-log/copied-<lane>.lst`), merges the lanes in order with
  `git merge-file` (line endings normalized to LF), copies the lanes'
  untracked files again (stored as LF), regenerates `R/links-brms.R`
  with lane nb2dm's generator (`dev/famlink-gen-links.R`), then runs
  the consolidation's edits (`dev/rel073-resolve.R`) and the NEWS
  merge (`dev/rel073-news-merge.R`), and stops if a conflict marker is
  left. `man/*.Rd`, `NAMESPACE`, frmtmb.sample's generated
  `helper-brms-suite.R` and `R/links-brms.R` are left out of the
  textual merge; roxygen and the generators write them.
- Files changed (`dev/rel073-log/merge-work/<lane>.status`): loodraws
  22, cdfs 30, nb2dm 27, fuzzfix 13; 52 without the generated ones.
  Untracked lane files copied, 0 clashes (`dev/rel073-log/merge-2.txt`):
  loodraws 36 (and 4 generated Rd files skipped), cdfs 141, nb2dm 50,
  fuzzfix 61. Among them every `dev/<lane>-*` script and findings file,
  the reviewers' `dev/<lane>-rev-*` scripts, `dev/fuzzfix-nested-quad.patch`,
  `dev/reviews/2026-10-20-<lane>.md`, core `R/loo-generics.R`,
  `R/families-cdf.R`, `R/weights-unbounded.R` and the lanes' new test
  files. Logs, check trees, OpenBLAS copies, Stan caches and reviewer
  output directories are gitignored and were not copied.
- The generator's `R/links-brms.R` equals lane nb2dm's file
  byte for byte (line endings aside).
- `dev/rel073-revorder.sh` merges every file two or more lanes changed
  (11, NEWS and generated files left out) in the reverse lane order and
  compares (`dev/rel073-log/revorder.txt`): 8 are identical; the other
  3 differ by exactly the consolidation's edits (`R/compat.R`, item 1),
  or by the conflicts the resolve settles (`dev/upstream-bugs.md`,
  `tests/testthat/helper-fuzz.R`). So no hunk of one lane depends on
  where another lane's landed.
- Interim builds go to `C:/Users/adf44/source/r/wt-release-lib`
  (`dev/rel073-install.sh <lib>`: roxygen of core, install, roxygen of
  each extension against it, install in dependency order, drmTMB 0.7.0
  copied from rellib-r10; `dev/rel073-log/install-1.txt`). Every
  generated Rd and NAMESPACE file that one lane changed equals that
  lane's; core `NAMESPACE` is the union of three lanes' exports.
