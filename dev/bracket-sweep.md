# The bracket sweep: `$` to `[[` on the hazard containers

Inventory taken at v0.49.0 (ec6dbfa), before any edit. It lists every
`$` access in `R/` of core and of the four extensions whose container
is one of the hazard containers below.

## Why these containers

`$` on a list falls back to PARTIAL matching when no name matches
exactly. The containers here are keyed by an open or prefix-colliding
vocabulary, so a missing slot does not give `NULL`, it gives a
neighbor. The package has been bitten three times this way: `pars$b`
read `beta`, `ctx$mix` read `mix_g`, and at v0.49
`par_template$theta` read `thetaac` on a model with residual
autocorrelation and no random effects, so `get_prior()` offered rows
for parameters that did not exist.

A container is CONFIRMED when two names it is accessed with in this
tree stand in a prefix relation, so the partial match is reachable
today. It is CLASS when the container type is prone but no colliding
pair exists yet. Both are swept; only the confirmed ones were live.

Environments are deliberately NOT swept. `$` on an environment is
already an exact-name lookup with no partial fallback, so
`frmtmb_aterm_registry`, `frmtmb_frame_checks` and `hyp_shadow_state`
carry no hazard. `covstruct_registry` is a plain list and does.

Structs with a closed slot vocabulary are also not swept: `resp`,
`rspec` and `spec` have fixed field sets and no colliding pair, and
the user-facing S3 objects (`fit`, `x`, `object`) have stable exact
names that `$` is the documented spelling for.

## How the sweep was done

The rewrite was position-driven from `utils::getParseData()`, never
from a regexp: only the parser can tell a `$` in code from one inside
a string or a comment, and the container is the SYMBOL token
immediately to the left of the `$`, which is what makes a chain like
`frame$par_template$theta` count as an access on `par_template`.
Slots holding functions (`fam$sim(...)`, parsed as
`SYMBOL_FUNCTION_CALL`) were rewritten too; `sim` against `sim_ctx` is
one of the live pairs.

Comments and roxygen were left alone. Documentation that shows a user
reaching into a fit still says `fit$frame$par_template`, because `$`
is the documented spelling for the user-facing objects, so `man/` did
not change and roxygen did not need to run.

Behavior preservation was proved rather than assumed. Both the
pre-sweep and post-sweep trees were parsed, every `x$name` in each was
normalized to `x[["name"]]`, and the resulting ASTs were compared file
by file. Identical normal forms mean the edit changed nothing but the
spelling of some `$` accesses. The same proof was re-run after the
line rewrapping below.

Converting `$name` to `[["name"]]` adds five columns, which pushed
some lines past the tree's 80-column limit. Those were rewrapped, at a
comma or a binary operator, aligned under the innermost open bracket
where that fits. Lines that were already over the limit at v0.49.0
were left as they were, so the diff carries no unrelated churn, and
the swept files end with the same count of over-long lines they
started with.

## The lint

`tests/testthat/test-bracket-access.R` keeps this clean. Its rule is
keyed on the container's NAME, not on `$`: a `$` is a hit when the
token immediately to its left is a SYMBOL listed in
`hazard_containers`. So `fit$obj`, `x$fit` and `object$draws` are
untouched, and the names in the list are reserved - binding one of
them to something that is not the container it names is itself a hit,
and the fix is to rename the local.

The extensions are policed from core rather than from a copy of the
test in each of them, so the container list has one home; the boundary
test already reaches across the monorepo the same way. The price is
that the guard runs in core's suite and not in each extension's own
`R CMD check`. A cloned copy would trade one container list for five
that drift, which is the worse bargain.

Both assertions are empty after the sweep, so the scanner needs a hit
of its own to prove it can still see one. The boundary test points its
control at a corner of the monorepo that still has a token; the sweep
left no such corner, so this control writes a small source file and
scans that, which also pins down the four things that must NOT match:
a legal container, a closed struct, a `$` inside a string, and a `$`
in a comment.

## What the sweep found

One partial match actually fired at run time in the pre-sweep tree,
and only one. It is in `VarCorr.frmtmb_fit()`:

    th <- x$estimates$theta

On a model with a residual autocorrelation structure and no random
effects the estimates hold `beta`, `betad` and `thetaac`, and no
`theta` at all, so that read returned the autocorrelation parameters
where the random-effect covariance parameters belong. This is the
v0.49 shape again, in a call site that release did not reach.

It was wrong and unused. The only consumer of `th` is a loop over
`frame$re_blocks`, and that list is empty in exactly the case where
the partial match is possible, so nothing downstream ever saw the
value. `VarCorr()` returns an empty list either way and the printed
`summary()` is byte-identical before and after. So the sweep records
this as a latent hazard removed, not as a behavior change: nothing
observable moved anywhere in core or in the four extensions.

The regression test is in `test-autocor.R`
("VarCorr() on an autocorrelation-only model reads no theta"). It
pins the shape (`thetaac` present, `theta` absent, `re_blocks` empty,
`VarCorr()` empty) and then asserts the absence of the partial match
itself with `warnPartialMatchDollar`, so it fails on the pre-sweep
spelling and passes on `[[`.

### How that was found, and what the first attempt was worth

The suites alone cannot see this one: converting a `$` whose value is
discarded changes no assertion. It was found by turning
`warnPartialMatchDollar` on and running the package with a calling
handler that records every fallback.

The first version of that detector ran the whole core suite and
reported nothing, which was worthless: testthat installs its own
calling handler and muffles warnings before an outer handler can see
them. A deliberate partial match injected into package code went
unreported, which is how the blindness was caught. The working
detector therefore drives the package directly, with no testthat in
the stack, and carries a positive control that must fire
(`frame$linpred` against the frame's `linpreds`). It covers eleven
model shapes - mixed, autocorrelation with and without random
effects, distributional, poisson, bernoulli, ordinal, `se()`,
`cens()`, `trunc()` and a mixture - across summary, coef, confint,
get_prior, fitted, predict (in-sample and newdata), residuals,
simulate, vcov, logLik, model.frame and conditional_effects. On the
swept tree it reports nothing, with the control still firing.

That is coverage, not proof: a partial match on a path none of those
eleven shapes reaches would not be seen.
