# Lane equiv: a measured equivalence rate against brms 2.23.0

Round opened 2026-10-28, base ac4906bd (frmtmb 0.77.0), measured on
`rellib-r15`. This lane changes no package code and no test. Every
file it adds is under `dev/equiv-*`. Nothing is committed.

Revised after the review `dev/reviews/2026-10-28-equiv.md` (FIX). What
the revision changed is section 9.

## 1. The question

The ported brms suite (633 of 823) measures what brms finds easy to
test, and 125 of its 236 bin-2 passes check a shape only. This survey
measures something else: of the feature pairs that `frm_compat()`
lists, weighted toward the ones users reach, what share behaves as
brms 2.23.0 does, when both packages run on the same data.

Every rate and count in sections 2.4, 3, 4 and 5 is a generated block
that a recorded rerun refreshes. The defects are eight classes
(section 4), two of them silent wrong answers.

## 2. Design

### 2.1 The population

`dev/equiv-dump-compat.R` writes `frm_compat()` on rellib-r15 to
`dev/equiv-frame-out/compat.tsv` (3 MB, machine output, gitignored),
once with core alone loaded and once with all eight extensions. The
population is the core pairs (column `in_core_only`), the table the
brief names; the generated frame block in 2.4 gives the counts.
Extension pairs are out of scope (section 8). The review checked that
no core pair changes status when the extensions load.

### 2.2 Strata

One stratum per compat status:

- (a) untested: no rule decides the pair, or the rule says untested.
- (b) conditional: the rule says the pair works under a condition its
  note states. The spec meets the condition.
- (c) works: a control. It checks whether a "works" claim holds.
- (d) refused: a small control. It checks that brms also refuses, or
  that the refusal is a recorded decision (2.6).

### 2.3 Weighting toward what users reach

"Common" is read off the code users copy (`dev/equiv-weights.R`). The
corpus (`dev/equiv-data/corpus.tsv`) is the code of the brms 2.23.0
vignettes, the `\examples` of the brms Rd files that have examples
(dontrun code included, because that is where brms keeps its model
calls), and the code of frmtmb's vignettes. A feature's count `d` is
the number of documents that use it, found by one regular expression
per feature (the `pattern` column of `dev/equiv-data/weights.tsv`).
Comments are stripped. A model call that names no family counts for
gaussian, brms's default. The feature weight is `1 + d`, so no pair has
probability zero. A pair's weight is the product of its two features'
weights, which assumes a user reaches the two features independently.

Limits: the weight counts documents, not users; a pattern can miss a
spelling; methods are counted by their call (`fitted(`, `predict(`)
and modes by their argument. `frm_curve` is credited with every
`conditional_effects()` call, its brms analog, but its L2 reference is
`posterior_linpred(re_formula = NA)`, not `conditional_effects()`.

The `bar_crossing` pattern first matched nested grouping inside a bar,
`(1 | g1/g2)` and `(1 | recipe:replicate)`, which is not the feature;
the feature is the refused crossing of a whole bar term, `x * (1 | g)`.
The pattern is corrected in `weights.tsv`. The sample was drawn from
the earlier weights, frozen as `weights-drawn.tsv`; the summary gives
the rate under the corrected weights as a sensitivity line, and a redraw
waits for the next frame change.

### 2.4 The sample

`dev/equiv-sample.R`, seed 20261028, weights `weights-drawn.tsv`.
Within each stratum, `n_h` draws WITH replacement, each pair with
probability proportional to its weight. Each draw is then an
independent Bernoulli trial whose mean is the reach-weighted rate of
the stratum, so the share over draws estimates it without bias and a
Wilson interval on `n_h` is valid. A pair drawn twice is measured once
and counted twice. The sample is frozen in `dev/equiv-data/sample.tsv`
(rerunning the sample script reproduces it bit for bit, checked with
`cmp`), so a later build reruns the same pairs.

### 2.5 Levels and tolerances

Each pair is run, not recalled (`dev/equiv-measure.R`, one R process
per pair). Both packages read ONE spelling: the spec's formula, family
and prior are text, evaluated once by frmtmb's `bf()`/`set_prior()`
and once by brms's (`dev/equiv-specs.R`). The minimal model is n = 200
rows, 10 groups of 20 in time order, a random intercept and slope in
the truth, and a fixed seed per pair.

- **L1, model identity.** brms's Stan program under flat priors (or
  the spec's prior on both sides) is compiled through the suite's
  content-addressed cache, and `log_prob(adjust_transform = FALSE)` is
  compared with frmtmb's objective at the frmtmb estimate and at two
  more points, through the suite's translator `stan_pars_from_fit()`
  (tests/testthat/helper-brms.R, reused, not rewritten). A fit with
  random effects compares the joint density at the conditional modes
  plus the map's log-Jacobian, as the suite's check C does. The two
  extra points come from an `frm()` run whose optimizer converges and
  then steps every outer coordinate by +0.05 and -0.05
  (`eq_step_optimizer()`). The rows are in group and time order: brms
  re-sorts a frame for an autocorrelation term, which reorders its
  latent vectors against the data, and on unsorted rows me() x arma()
  read -2360 nats where sorted rows read 1e-13 (an instrument artifact,
  fixed in `eq_base()` before the reported run). Pass: `log_prob -
  ours` equals the stated constant (0, or `lgamma(J)` for brms's
  Dirichlet(1) on a mo() simplex) to `1e-6 * max(1, |ours|)` at all
  three points, and the gradient at the estimate (the inner block, for
  a joint) is below `1e-3`, the suite's tolerances. Under a prior,
  frm()'s MAP carries the log-Jacobian of the map from each
  prior-carrying parameter to its internal one (NEWS 0.52.0 and 0.53.0
  for the dpar classes, 0.68.0 for sdgp and lscale, the ordered map for
  thresholds). Stan's chart is the same for those blocks (log, or
  ordered), so Stan's Jacobian is added for the prior blocks alone, and
  the constant is free (brms normalizes a truncated density, frm()'s
  penalty need not) but must be the same at all three points.
- **L2, methods at the same parameter values.** The suite's
  Fixed_param brmsfit (`brms_fixed_fit()`, helper-brms-methods.R) holds
  frmtmb's estimate as every draw. fitted, residuals, emmeans, the
  hypothesis Estimate and frm_curve (against
  `posterior_linpred(re_formula = NA)`) are compared with the suite's
  rule, `max |a - b| / max(1, |a|, |b|) < 1e-8`. simulate and predict
  (with `propagate_error = FALSE`) draw 4000 a side at the same values,
  and each row's mean and variance is a z-score against its Monte
  Carlo error (the variance's from the row's measured fourth moment);
  the bound is the two-sided Bonferroni point at 0.001 over the rows.
  A method both packages refuse counts as agreement. `confint_profile`
  has no brms counterpart at fixed values: L2 only checks that its
  interval is finite and does not count as a level; the comparison is
  L4. A method pair whose method half reaches no level is cannot
  measure, whatever its model half says (p029 was scored on its model
  alone before this rule).
- **L3, frmtmb.sample draws against brms draws.** Not used.
- **L4, the ML route.** Two forms. (i) For a model without random
  effects that the translator cannot map: brms's program is maximized
  under flat priors from 6 starts (`rstan::optimizing`, no Jacobian,
  so its mode is the maximum likelihood point), and its best value must
  equal frmtmb's maximized log likelihood to `1e-4 * max(1, |ours|)`.
  A different model has a different maximum, and no map is needed.
  The review measured these maxima agreeing to 1e-9 to 1.6e-6 nats.
  (ii) Otherwise brms is sampled under flat priors (2 chains of 2000),
  with Rhat at most 1.05: a profile interval end within 0.25 posterior
  sd of the posterior quantile, or every fitted mean within 0.5
  posterior sd of the posterior mean of `posterior_epred()`. Form (ii)
  also reads an estimation mode with its own objective (`importance =`),
  whose model identity L1 reads on the same spec without the mode, with
  the Laplace fit's own reading as the control.

  Form (ii)'s fitted-mean reading has low power on a penalized model,
  measured twice: the univariate `y1 ~ t2(x, z)` of pair p048's data is
  an L1 identity (constant 1.7e-13) and still reads max |z| 0.851, and
  the review's mutant of p042 cut to `s(z, k = 4)` reads 0.974. The 0.5
  bound sits between, so the route can fail an identity and pass a
  modest misfit. Its agreements are flagged `weak_evidence` in
  results.tsv, with the REML pair (no brms quantity checks REML beyond
  the model), and the summary gives the rate without them as a named
  sensitivity row. The headline keeps them.

### 2.6 Verdicts and the decision standard

One per pair: equivalent; defect (frmtmb is wrong, or refuses where
brms builds AND compiles the model, and no decision covers it);
divergence by decision; refusal correct; compat row wrong (the table's
status does not match the measurement); cannot measure (with the
reason). `dev/equiv-flow.R` assigns the verdict from the measurement. A
brms "works" is confirmed by one cached compile: `make_stancode()`
writes an nl body that calls an unknown function into the program and
fails only at the compile (pair p014). Where a measurement cannot
settle a verdict alone, the verdict is set in
`dev/equiv-data/adjudication.tsv` with its reason; the summary counts
those.

The decision standard, one for every pair: a frmtmb refusal or
divergence is "by decision" only when NEWS, SPEC.md,
`dev/core-boundary.md` or the brms-suite ledger gives a REASON for it.
A compat note that states the refusal does not count, and neither does
a NEWS line that states a limit without its reason. Under it, one
divergence stands (p002) and every other frmtmb refusal of a model
brms compiles is a defect; section 9 lists what the standard changed.

"agree" is equivalent, refusal correct, or a compat row whose behavior
agrees with brms (both refuse, or frmtmb fits a refused row and
matches brms). A pair with no brms spelling (frmtmb's own covariance
structures, `ps()`, `nbinom1`) is "cannot measure" and stays in the
denominator.

Defect candidate, not ranked (no sampled pair; found by the nl x
family sweep): **frm()'s default starts for a nonlinear coefficient
fail under Gamma's and inverse.gaussian's default links.** A nonlinear
coefficient starts at 0, where the inverse link (Gamma) and 1/mu^2
(inverse.gaussian) are undefined, so `frm(bf(y ~ b0 + b1 * x, b0 + b1 ~
1, nl = TRUE), family = Gamma())` stops with "The nonlinear fit failed
from its default starting values (NA/NaN gradient evaluation)" while
the linear fit succeeds. From starts that keep mu positive (eta =
1/mean(y), or 1/mean(y)^2) the body is honored: the nl maximum equals
the linear one (the default-link columns of
`dev/equiv-data/nl-sweep.tsv` and the reasons of the two compat rows).
Choosing a start the link can evaluate is frmtmb's job, and frm() has
the data to start the body at the mean. Both rows are proposed
"conditional (default link needs starting values that keep mu
positive)".

## 7. Rerun

One command from the worktree root, measuring a build installed in a
library (default rellib-r15):

    FRMTMB_EQUIV_LIB=<library> bash dev/equiv-run.sh 8 [outdir]

It measures every pair of sample.tsv that has no result in the outdir
(default `dev/equiv-out/`; resumable, `FORCE=1` remeasures all), one
pair per R process, 8 at once, with `FRMTMB_STAN_CACHE=dev/stan-cache`
and the Makevars line set, and writes results.tsv, compat-proposals.tsv
and summary.md into the outdir. The tracked record (dev/equiv-data/ and
the generated blocks here) changes only with `RECORD=1`, which also
reruns the nl x family sweep into the record. Do not edit the run
script, or any script it runs, while it runs: bash reads a script as it
goes, and the two first runs ended with "unexpected EOF" in their logs
because the script was edited under them (those logs are deleted; no
reported row came from them). Cost, from the seconds each pair records
(the cache held 238 programs when the lane began):

How the specs got their present budget: in the second run p023 and
p109 (exact gp(), brms sampled over a 200-position kernel) hit the
2400 s per-pair timeout, and p022 and p094 sampled for 369 s and
1547 s to an unconverged posterior, so those four specs record L1
alone (`eq_gp(sample = FALSE)`). In the first run p136 (an exact gp()
inside a nonlinear parameter, 200 positions) hit the timeout; its
spec now uses about 40 positions. A cold rerun adds a compile of about
a minute per new program.

No gated test tier: the identity pairs repeat rows test-brms-likelihood
and test-brms-methods already hold, a tier would have to copy the specs
out of dev/ (which the built package excludes), and the run's value is
the rate, not a regression gate.
