## 1. BLOCKER. The draws method plots `mu`, not the expected response

`extensions/frmtmb.sample/R/conditional-effects-draws.R:87-88, 136, 144`

The draws method resolves `dpar` to `"mu"` and passes THAT to
`ce_boot_one()` on every call. Core's fit method does not: at
`R/conditional-effects.R:1701-1703` it computes

```r
mean_display <- !categorical && !cats_mean && !dpar_given &&
  (!mean_is_mu(rspec$family) || has_trunc(rspec))
pred_dpar <- if (mean_display) NULL else dpar
```

and passes `pred_dpar`, which is `NULL` for a family whose mean is not
the inverse link of `mu`. `ce_boot_one()` (`R/conditional-effects.R:556-566`)
branches on exactly that: `dpar = NULL` predicts the EXPECTED RESPONSE,
`dpar = "mu"` predicts the mu dpar. The draws method has no
`mean_display`, no `dpar_given`, and never passes `NULL`.

The column NAMES match, so every one of the lane's seven cases passes
while the plotted curve is a different quantity.

Core's own comment at `R/conditional-effects.R:1695-1700` names this as
the defect it fixed on the fit side: "Taking the estimate from the mu
predictor alone plotted `(1 - zi)` times too little on a zero-inflated
fit and a sign-changing error on a hurdle one." The draws method has
just reintroduced it.

## 2. MAJOR. `abs()` passes the affine probe and halves the denominator

`extensions/frmtmb.sample/R/evidence-ratio.R:173-192`

`er_affine()` measures the intercept at `rep(0, m)` and each slope at a
unit vector, then validates with ONE probe point,
`chk <- seq_len(m) * 0.7 - 0.3` (for `m = 1` that is 0.4). All three
evaluation points are non-negative, so `abs()` is indistinguishable from
the identity and the guard passes.

Measured on the lane's own model with `normal(0, 1)` on class `b`:

```
hypothesis(pr, "abs(x) = 0")
#   hypothesis  estimate evid_ratio post_prob
# 1 abs(x) = 0 0.1303422   4.011212 0.8004475
# no warning
```

The denominator used is `dnorm(0, 0, 1)` = 0.39894. The prior of `|X|`
for `X ~ N(0, 1)` is a half-normal, whose density at 0 is
`2 * dnorm(0)` = 0.79788. So the reported Bayes factor is **2x too
large**, with no warning, on a hypothesis a brms user would plausibly
write. (It is also a boundary null, which the file already refuses for
class `sd` at `:126-131` on exactly this reasoning.)

Reproduction: `scratchpad/rvsc-sd2.R`, section "abs() slips the affine
probe?", which prints the implied denominator (0.3989423) beside the
correct one.

### Fix

One extra evaluation closes it. After the existing check add a
NEGATIVE probe:

```r
chk2 <- -chk
if (!isTRUE(all.equal(at(chk2), a + sum(b * chk2), tolerance = 1e-8))) {
  return(NULL)
}
```

`abs()` gives `at(-0.4) = 0.4` against `a + b * (-0.4) = -0.4` and is
refused. Cost is one more `hyp_eval()` per hypothesis.

## 3. MAJOR. The MCSE is 1-degree-of-freedom at 2 chains

`extensions/frmtmb.sample/R/evidence-ratio.R:281-287`

`er_blocks()` takes `nchains(x)` whenever it is 2 or more, and falls
back to four blocks only when `nchains < 2`. At 2 chains the reported
MCSE is `sd()` of TWO numbers over `sqrt(2)`: one degree of freedom.
That is not an error bar, and the attribute is documented in NEWS and
in `sampling.Rmd` as the thing a reader should consult "before believing
one".

Measured, two independent 2-chain runs of the same model, same priors,
seeds 7 and 99 (`scratchpad/rvsc-sd2.R`):

| run | `evid_ratio` for `x = 0` | reported MCSE |
| --- | --- | --- |
| seed 7 | 4.09712 | 0.1783 |
| seed 99 | 4.55679 | 0.2024 |

Gap 0.4597, which is 2.58 reported MCSE (1.71 combined). The estimator
understates because it has no degrees of freedom, not because the lane's
between-block reasoning is wrong.

The lane's OWN 4-chain numbers are fine by contrast: `dev/sample-ce-findings.md:226-229`
has S1 at 0.4114 (brms draws) vs 0.4686 (frmtmb draws), gap 0.0572
against MCSEs 0.0376 and 0.0550, combined 0.0666, so 0.86 sigma. The
construction is sound; the block count is not.

### Fix

Floor the block count, e.g. `nc <- max(nc, 4L)` when `n` allows it, and
say in the docs that fewer than four chains gives a MCSE with too few
degrees of freedom to read.

| `else if (to < point) to <- point + sd(x)/4` | same | yes |

## The prior density is on the right scale

The brief's check: a class `b` prior sits on the natural coefficient
scale, so `normal(0, 1)` should contribute `dnorm(0, 0, 1)`.

Dumping the resolved entries (`scratchpad/rvsc-sd2.R`) for
`y ~ x + w + (1|g)` with `set_prior("normal(0, 1)", class = "b")`:

| entry | comp | idx | kind | `scale` | `offset` |
| --- | --- | --- | --- | --- | --- |
| 1 (Intercept) | beta | 1 | t | internal | `list(comp="beta", idx=2:3, w=c(5.3e-4, 3.6e-4))` |
| 2 (sigma) | betad | 1 | t | **sd** | NULL |
| 3 (sd_g) | theta | 1 | t | **sd** | NULL |
| 4 (x) | beta | 2 | **normal** | internal | NULL |
| 5 (w) | beta | 3 | **normal** | internal | NULL |

`scale == "internal"` with `offset == NULL` is an identity map onto the
coefficient, so `er_prior_density()` evaluating `dnorm(v, 0, 1)` at
`v = 0` is right. Confirmed numerically:
`evid_ratio` for `x = 0` is 4.097122 and
`er_kde_at(dr) / dnorm(0, 0, 1)` = 1.634515 / 0.3989423 = 4.097122.

The guard at `evidence-ratio.R:224-226` (`!identical(e$scale, "internal")
|| !is.null(e$offset)`) is therefore doing exactly what it should:
entries 2 and 3 carry `scale = "sd"` (a log change of variables) and are
refused; entry 1 carries the centering `offset` and is refused.

## Lower-bounded parameters refuse, and say why

Both spellings, measured:

- `sd_g__Intercept = 0`: `evid_ratio` NA. "it names sd_g__Intercept,

- `sigma_Intercept = 0`: `evid_ratio` NA, and this one DOES take the

the density at the raw intercept differs.

Confirmed by the entry dump: entry 1's `offset` is

centering over the other coefficients, and `prior_logdens()`
(`R/priors.R:1795-1798`) documents that the shift enters the density.
The refusal text ("an Intercept prior is about the intercept at the
predictor means") is accurate about the mechanism it fired on. Verified.
