## What I verified and found correct

- **The math.** Let `Z` be n x K iid N(0, 1), `R = L'L` with `L =
  chol(R)`, and `D_i = diag(sigma_i)`. Row i of `Z L` is `z_i' L`, so
  its covariance is `L' I L = R`. Scaling by `D_i` gives covariance
  `D_i R D_i`, rows independent. So the result is MVN(mu_i, D_i R D_i)
  for any per-row sigma, and `chol(D R D) = L D` makes brms's per-row
  factor the same draw. Divide row i by `sqrt(W_i / nu)`, with one
  `W_i ~ chi^2(nu)` per row. The row becomes `mu_i + D_i (L' z_i) /
  sqrt(W_i / nu)`, which is brms's `rmulti_student_t()` (brms
  `R/distributions.R` lines 185 to 193 divide the whole normal row by
  one `sqrt(rchisq / df)`). Numerical check (`review-rescorpp-math.R`,
  seed 101/7, 20000 replicates of 150 rows, `sigma_y1 ~ x` spanning
  0.032 to 19, `sigma_y2` 99.4, `sigma_y3` 0.000896):
  - Gaussian, whitened by `chol(D_i R D_i)` on 10 rows: KS p min
    0.0443 of 40 tests, variance z in -1.8 to 2.02, off-diagonal
    `cor * sqrt(M)` in -1.95 to 2.15. The independent-draw control
    gives a Mahalanobis KS p of 0.
  - Student (nu 6.73): margins against `pt(nu)` give KS p min 0.0183
    of 30. Mahalanobis/3 against F(3, nu) gives KS p min 0.0573 of 10.
    Against `brms::rmulti_student_t()` at the same Sigma, the
    two-sample KS p is 0.883 (Mahalanobis) and 0.896 (y1 margin). The
    separate-W control gives p 2.35e-65.
  - Subset `(y3, y1)`: Kendall tau -0.4284 against
    `2/pi asin(r)` -0.4298.

## Findings

### 1. major: `predict()` of a multivariate model with a category-valued response summarizes category codes as numbers

Evidence: `review-rescorpp-api.R` uses the `ord` model, `cumulative`
`o1` with gaussian `y2` and no rescor. `predict(ds)` returns 150 x 4 x
2. Its `o1` layer is `Estimate 1.945, Est.Error 0.771, Q2.5 1, Q97.5 3`,
the mean and quantiles of the category CODES. `predict(ds, resp = "o1")`
on the same draws returns `P(Y = 1) 0.325, P(Y = 2) 0.405, P(Y = 3)
0.270`. `predict(ds, resp = c("o1", "y2"))` does the same as without
`resp`. brms 2.23.0 stops on both calls ("arg 'y2' has dims=150, 4, 1;
but need dims=150, 3, X", `review-rescorpp-layout-ord.log`). frmtmb's own
`fitted()` refuses the same model ("stacks one matrix per response, and
a response here predicts more than one value per row"). The cause is the
new early return in `predict.frmtmb_draws()`: `if
(draws_resp_stacks(fit, resp)) return(draws_summarize_or_not(out, ...))`
runs before the `fam_is_category_valued()` branch. So the layer
`predict(ds)[, , "o1"]` silently differs from `predict(ds, resp =
"o1")`.

Fix: in the stacked branch of `predict.frmtmb_draws()`, refuse when any
response in `want` is category valued (`fam_is_category_valued()`),
with the `draws_resp_stack()` sentence or one that names `resp =`.
`summary = FALSE` can keep returning the codes, as brms does
(30x150x2, SAME). Add a test on an ordinal + gaussian `mvbf`.

### 2. minor: the Student-t test cannot tell a multivariate t from a multivariate normal

Evidence: the mutation "nonu" sets `nu <- NULL` in
`predict_rescor_draw()`, so student rescor draws are gaussian. It gives
"RESULT nonu test-rescor-draws.R pass 51 fail 0"
(`review-rescorpp-mut-nonu.log`). The test "a Student-t rescor draw is
the multivariate t, one nu per row" compares rank correlations, which
are almost the same under MVN and MVT. Its |e| Spearman line does not
separate them at 120 rows either. No core test checks the tails of a
student rescor draw (`test-brms-shapes-punch2.R` checks only the
gaussian correlation).

Fix: add a margin check to that test. One way is a KS or tail-quantile
z of `(pp - mu) / sigma` against `pt(., nu)` pooled over draws. Another
is the Mahalanobis/K statistic against `pf(K, nu)`. Show that "nonu"
then fails.

### 3. minor: the order checks in the new tests cannot detect a misordered correlation matrix

Evidence: the mutation "sortC" replaces `C[k, k]` with `C[sort(k),
sort(k)]` in `rescor_row_loglik()`, which is the order bug the test
comment says the permuted call checks. It gives "RESULT sortC
test-mv-gaps.R pass 62 fail 0" and "RESULT sortC test-rescor-draws.R
pass 51 fail 0". Both tests permute a 2-response subset, and a 2 x 2
correlation matrix is unchanged by a permutation. The code is correct:
the 3-response permutation `c("y3", "y2", "y1")` matches `dmvnorm` to
8.2e-16 (`review-rescorpp-loglik.log`). The test comment in
`test-mv-gaps.R` ("the column order of the correlation must follow
`resp`, which a permuted call checks") claims a check that cannot fail.

Fix: permute 3 responses (for example `c("y3", "y1", "y2")`) against a
hand density in the reordered order, and confirm that "sortC" fails.

### 4. minor: `log_lik(resp =)` takes neither brms's spelling nor guards bad sets, unlike the other methods

Evidence: `review-rescorpp-misc.R` (responses `y_a`, `y_b`) and
`review-rescorpp-loglik.R`:

- `log_lik(ds, resp = "ya")` and `loo(ds, resp = "ya")` stop with
  "names no response of this model", but `posterior_predict(ds, resp =
  "ya")` and the other stacked methods accept it (`draws_resp_set()`).
  brms's `log_lik(resp =)` takes `ya`.
- `log_lik(ds, resp = c("y_a", "y_a"))` returns `Inf` in every cell.
  The correlation matrix is singular and `RTMB::dmvnorm` gives `+Inf`.
  On the student model, the same call stops with "Lapack routine dgesv:
  system is exactly singular". brms stops on a duplicate, because
  `rescor__y1__y1` is missing.
- `log_lik(ds, resp = character(0))` returns a 2 x 98 matrix (K = 0).
  brms's `validate_resp()` reads an empty `resp` as every response.

The lane changed exactly this check, from `resp %in%` to `all(resp
%in% ...)`.

Fix: read `resp` in `log_lik.frmtmb_draws()` through
`draws_resp_set()`. That gives both spellings, `unique()`, and the
shared refusal, and maps `character(0)` to every response as brms does.
Add a test of `"ya"` and of a duplicate.

### 5. minor: the exported `predict_rescor_draw()` pairs `dps` with `rspecs` by position

Evidence: `review-rescorpp-api.R` calls `predict_rescor_draw(fit,
fit$spec$responses[c("y3", "y1")], eval_dpars(fit), ok)`. It returns a
draw named `y3` with mean 1.081, where `mu_y3` has mean 0.055 and `mu_y1`
has mean 1.047, and residual sd 0.902 against `sigma_y3` 0.489. The
draw used y1's `mu` and `sigma` and labeled them y3. Both internal
callers pass `dps` in the order of `rspecs`, so frmtmb is not wrong
today. But this is now a documented export ("`dps` holds each
response's dpar values"). A third party who subsets `rspecs` and passes
the full `eval_dpars()` gets a silent wrong draw. The core-boundary
rule wants a seam that is "useful on its own".

Fix: index `dps[[names(rspecs)[k]]]` when `dps` is named, or stop
unless `identical(names(dps), names(rspecs))`. State the pairing in
`frmtmb-sampling-api`.

### 6. minor: `loo_predict()`, `loo_epred()` and `loo_predictive_interval()` refuse several responses

Evidence: `review-rescorpp-layout-{g2f,g3,mix,re}.log`. For
`resp = c("y1", "y2")`, brms returns a 200 x 1 x 2 array (`dn mean |
y1,y2`). frmtmb stops with "`resp` must name one response of this
model". Under rescor, brms weights these by the joint `log_lik()` of
the named subset, which `log_lik(resp = c(...))` now gives. The
refusal is pre-existing (`loo_resp_name()`). But frmtmb.sample's NEWS
now says "`resp` takes several responses, in the order you name them",
and the `loo_*()` readers do not.

Fix: let `loo_draws_expect()` take a set through `draws_resp_set()`.
Stack the layers and weight by `log_lik(resp = <the set>)`. Or say in
NEWS and in the Rd that the `loo_*()` functions take one response.
