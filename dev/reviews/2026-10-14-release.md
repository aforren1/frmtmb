## 1. ci701 x illse in `R/se-check.R`

**By reading.** `fit_outer_hessian()` computes `at` as
`se_pull_back(<fit point>, pull)` before the lookup, and the key is
`list(at = <pulled point>, u = par_units)`. A pulled call and an
unpulled call at the same fit have different `at` whenever the pull
moves anything, so they cannot share an entry; when the pull moves
nothing the two Hessians are the same computation. The scaled branch
differences at `at / u`, so the stored `at` is the point the Hessian
was taken at. `fit_outer_hessian_at(fit, p, kept_only = TRUE)` builds
the unpulled key and returns NULL against a pulled entry. One entry is
kept, so alternating calls recompute, never misserve. `obj_he_cached()`
keys on `p` alone; nothing in `R/` or the extensions' `R/` mutates
`obj$env$data`, `map` or `parameters` (grep), so "a function of `p`
alone" holds. `autoscale_sdreport()` compares `fit$cache$hessian_fixed$at`
with the fit point, and `hessian_fixed` is only ever set from an
unpulled call.

**By measurement** (`dev/relrev071-cache.R`, `cache.txt`):
test-review-v29.R's fit from `theta = (0, 0, 500)` (units 0.5 to 1,
edge correlation `theta_3`), and the same data rescaled (units 0.0039
to 1020). Pulled and unpulled Hessians differ (max |dH| 0.442 and
4420). Four call sequences (u p u p, p u p u, p p u u, u at p
at_kept), each call against a fresh computation with the kept result
cleared: 16 of 16 `identical()` on each fit. After a pulled call the
key equals the pulled point. The unscaled branch has the same logic;
I could not make a v29-like fit with all units 1.

**`edge` gates the route.** `cov_from_hessian()` runs
`se_reparam_cov()` first only when `!any(held) && !any(edge)`, with
`edge <- se_edge_sd(fit, H) | ec`; with an edge correlation tier 3
removes it and hands `free` to the route. That is what both reviews
asked (ci701 review R7) plus the coordinator's extension. My
reconstruction (section 6e) shows the resolution is exactly ci701's
and illse's lines.

### 6a. `test-se-conv.R`: the premise is lost (fix 1)

The lane's test asserts that a stop with an empty sd row, 92 below the
maximum, is called short, which needs illse's R2-1 change
(`headroom_drop_rows()` asks `se_sd_gain_up()`). The rewrite starts
every parameter, `beta = c(0, 0), betad = 0, theta = -15`. I ran the

headroom without R2-1 (`dev/relrev071-seconv.R`,

| build, start | as installed | gain stubbed to 0 |
|---|---|---|
| rellib-r9, new start | "would still gain 58.6 ... short of the maximum" | "would still gain 2.13 ... short of the maximum" |
| illse lane, new start | 58.6, short | 2.13, short |
| illse lane, the lane's start | 54.2, short | "gains 0.000164 ... so the estimates are at the maximum" |
| rellib-r8, new start | no clause (0.70.0) | no clause |

From `beta = (0, 0)` the intercept's gradient is 26.2, so the stop is
short whatever the sd row says, and the test passes with R2-1 removed.
It fails on rellib-r8 only because 0.70.0's warning has no clause at
all. The record's "so it still pins the change" is wrong for R2-1.

A replacement that does not depend on `frm()`'s start and does pin
R2-1 (same file's data): start at lm()'s maximum given sd = 0,
`beta = coef(lm(y ~ x))`, `betad = log` of the ML residual sd,
`theta = -15`, with `iter.max = 0` (`seconv2-*.txt`):

| build | as installed | gain stubbed to 0 |
|---|---|---|
| rellib-r9 | code 1, "would still gain 54.3 ... short" | "gains 1.18e-21 ... at the maximum" |
| rellib-r8 | no clause | no clause |

`iter.max = 1` gives the same (54.3; 4.22e-16). So that test fails on
0.70.0, fails with R2-1 removed, and passes on the merged build.
The handoff's lesson, "a test that pins a stop short of the maximum
should give every parameter its start", should add: and the start must
leave only the direction under test short; check by removing the fix.
