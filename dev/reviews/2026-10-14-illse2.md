## Findings

### 1. BLOCKING: the REML log-likelihood is off by log|det T| on every whitened fit

`beta_whiten_nll()` tapes the joint likelihood in `gamma` with
`beta = T gamma` and leaves the density on the `beta` scale. Laplace
then integrates `exp(-nll(T gamma)) d gamma`, which is the integral over
`beta` divided by `|det T|`. So `logLik()` (and AIC, BIC) of every REML
fit that gets a whitener is the right value minus `log|det T|`.

Evidence (`dev/illse2-rev-remlll.R`, `dev/illse2-rev-remlll2.R`, logs
`remlll-*.txt` and the console run of `remlll2`):

    case                          lane logLik    lme4 (= base)  lane - lme4  log|det T|
    sleepstudy subset, Days+1e5   -586.74207925  -587.80813803  +1.066059    -1.066059
    reml_data(1, 4), (1 | g)      -88.49607134   -75.00165953   -13.494412   +13.494412
    reml_data(1, 5)               -91.24344085   -70.95690936   -20.286531   +20.286532
    reml_data(1, 6)               -93.17685435   -64.72807066   -28.448784   +28.448646

`reml_data()` is test-se-reparam-reml.R's generator. 0.71.0 agrees
with lme4 on every row (to 4e-6 at degree 5; at degree 6 lme4 stops
1.3e-3 below 0.71.0). The REML criterion does not depend on a shift of
a covariate: the lane gives -587.80813825 for `Days` and -586.74207925
for `Days + 1e5`, the same model. `profile = TRUE` is not affected (it
maximizes `beta`, it does not integrate it): -591.77142224 on both
arms at every shift. Estimates and SEs are not affected (the objective
moves by a constant). The lane's REML tests check only the covariance,
and its p3reml "short" column evaluates its own criterion, so neither
saw it. NEWS calls the REML change exact.

Which fits: the whitener takes a design whose column-scaled condition
number is above 1e4. A raw polynomial of degree 4 on [1, 2] is enough
(row 2), as are `year + year^2` (5.3e5) and a covariate shifted by
1e5; `age + age^2` on [20, 80] (60) is not.

Fix: put the Jacobian into the tape for REML only:

    beta_whiten_nll <- function(nll, bw, jacobian) {
      force(nll)
      blocks <- bw[["blocks"]]
      # Laplace over gamma integrates exp(-nll(T gamma)) d gamma, the
      # integral over beta divided by |det T|; a profiled beta is
      # maximized, not integrated, and takes no Jacobian
      ldt <- if (jacobian) {
        sum(vapply(blocks, function(blk) {
          determinant(blk[["T"]], logarithm = TRUE)$modulus[[1]]
        }, 0))
      } else 0
      function(pars) {
        ... as now ...
        nll(pars) - ldt
      }
    }

called as `beta_whiten_nll(nll, bw, jacobian = REML)` in
`fit_assembled()`. Add a test that the REML `logLik()` of a degree-5
raw polynomial with `(1 | g)` equals lme4's within a ratio, and that
`Days` and `Days + 1e5` give the same REML `logLik()`; seen to fail on
install 17. Rerun the lane's REML numbers after the fix.

### 2. MAJOR: asking for more optimizer work turns the sd escape off

`sd_up_escape()` is off whenever `optCtrl` holds any value that differs
from frmtmb_control()'s default. That catches a caller who raises the
caps or tightens a tolerance, and that caller then gets a worse fit than
the default. Degree 7 seed 4 (`dev/illse2-rev-esc2.R`, `esc2-*.txt`;
"short" against the exact profile maximum -61.7559980476):

    control                                lane: short   escape  SE finite  warning
    default                                3.686e-08     0.00118  8 of 8    none
    optCtrl iter.max = eval.max = 1000     3.686e-08     0.00118  8 of 8    none
    optCtrl iter.max = eval.max = 5000     1.222e-03     no       0 of 8    gradient
    optCtrl rel.tol = 1e-12                2.110e-01     no       0 of 8    conv, short
    restarts = 3                           3.686e-08     0.00118  8 of 8    none
    grad_tol = 1e-4                        3.686e-08     0.00118  8 of 8    none

The same under OpenBLAS 0.3.26 LAPACK (`esc2-lane-ob26.txt`). The
`rel.tol = 1e-12` row is 0.211 short on the base too: newton_polish()
is off whenever a tolerance is named. NEWS says "A caller's own
iteration cap or tolerance keeps the stop it asks for", which is not
what the code does.

Fix: turn the escape off only when a setting asks for an earlier stop
than the default: `iter.max` or `eval.max` below frmtmb_control()'s
1000, or `rel.tol`, `x.tol`, `abs.tol`, `xf.tol` above nlminb's
defaults (1e-10, 1.5e-8, 0, 2.2e-14), or another optimizer. Keep the
`iter.max = 0` stop of test-se-conv.R. Add a test that `iter.max =
5000` on degree 7 seed 4 reaches the maximum (seen to fail on install
17). Correct the NEWS sentence. File newton_polish()'s rule (off for
any named tolerance, so a tighter `rel.tol` leaves a fit 0.211 short)
as a defect.

### 5. MINOR: the REML coefficient covariance is glmmTMB's, not lme4's, and the docs do not say so

This is not a change of this lane. frmtmb's REML `vcov()` is the
`beta` block of the inverse joint precision: the conditional part
`sigma^2 (X'V^-1 X)^-1` (lme4's `vcov()`) plus `J V_theta J'`. On three
ordinary REML fits (`dev/illse2-rev-reml.R`, `reml-*.txt`) the lane's
SEs are bitwise those of 0.71.0, no whitener is formed, and:

    model                                frm SE / lme4 SE - 1      explained by J V_theta J'
    sleepstudy (Days | Subject), balanced -5.9e-6, 3.1e-7           J = 0 (balanced)
    sleepstudy subset, (1 | Subject)      4.76e-5, 2.34e-5          to 3.7e-13
    simulated, unbalanced, (1 | g)        1.04e-3, 8.3e-4, 3.1e-4   to 7.0e-12

glmmTMB (REML = TRUE, user library) gives the same SEs as frmtmb on the simulated fit
(0.1566099622 against 0.1566099622, `misc-lane.txt`). So the
"breaking change to every REML user" the brief asks about does not
exist: the lane leaves well-conditioned REML fits alone. But
`?vcov.frmtmb_fit` does not say that under REML the covariance carries
the variance parameters' uncertainty and differs from lme4's on an
unbalanced design, and NEWS compares lme4's `vcov()` to the exact
conditional covariance without saying that frmtmb reports another
quantity. Fix: one paragraph in `vcov.frmtmb_fit`'s REML section and
one clause in the NEWS bullet. Also noted, not of this lane: frmtmb's
REML AIC counts only the outer parameters (1179.6 against lme4's
1183.6 on the same fit).

### Item 6: "promise already under evaluation" from TMB's finalizer

**Reproduced.** `dev/illse2-p4wide.R 150 2000 1:2` on the lane
(`rc-wide-lane-b.txt`) prints three lines "Error in (function (ptr) :
promise already under evaluation". They appear during the second fit;
stdout is buffered, so they print above seed 1's line. With seed 1
alone they do not appear (`rc-wide-lane.txt`). The numbers are
unaffected.

**Mechanism.** `TMB:::registerFinalizer()` gives every ADFun a
finalizer, `function(ptr) if (!isNullPointer(ptr)) .Call(...)`. Also,
`TMB:::isNullPointer` is a lazy-load promise until it is first used
(`dev/illse2-rev-tmbfin.R`, TMB 1.9.25, RTMB 2.0). When the first
finalizer of a session forces that promise while other ADFun finalizers
are pending, they meet the promise under evaluation. R prints their
errors to stderr, and those ADFun objects are not freed. This happens
at most once per session: after the promise is forced it cannot recur.

**Not reproduced on rellib-r9 (0.71.0) under the restored library:**

- the same 159-parameter fit at the cap of 100 (`rc-wide-base.txt`);
- the same fit at a cap of 400 (`rc-wide-base400-b.txt`, seeds 1:2),
  where 0.71.0 still declines the route;
- 20 gaussian and 20 bernoulli GLMM fits of n = 2000
  (`dev/illse2-rev-fin.R`, `rc-fin-*-base.txt`);
- 300 RTMB tapes left to the collector, without frmtmb
  (`rc-fin-rtmb-base.txt`).

The same 40 ordinary fits on the lane print nothing either
(`rc-fin-ordinary-lane.txt`, `rc-fin-wide-lane.txt`). So the defect is
TMB's. The lane's route makes it reachable on wide fits, because it
builds many large Hessian tapes that become garbage together. I cannot
check whether the library restore also played a part (the lane saw
nothing on install 20, before the restore), because the pre-restore
library no longer exists.

**Where it can show:**

- **testthat:** the lines are not a condition, so they cannot fail a
  test or count as an escaped warning. They would appear in the test
  process's stderr, and so in a CI log or `testthat.Rout`. No test file
  of the four printed them (`rc-t-*.txt`: 0 lines), and the lane's full
  scan passed.
- **A user's console:** an ordinary fit did not trigger it in 80 fits.
  A user who fits wide models (100 to 400 parameters, the new route)
  can see three alarming "Error in" lines once per session, together
  with a small leak.

**The fix.** Forcing the promise removes the lines: with
`f4/force-tmb.Rprofile`, `rc-wide-lane-forced.txt` shows 0 lines over
seeds 1:2, with the same numbers. Doing it in frmtmb's `.onLoad()` is
safe:

    # TMB's ADFun finalizer calls isNullPointer(); forced while lazy,
    # by the first finalizer of a session, it fails every finalizer
    # pending with it ("promise already under evaluation") and leaks
    # their tapes
    tryCatch(invisible(get("isNullPointer", envir = asNamespace("TMB"),
                           inherits = FALSE)),
             error = function(e) NULL)

TMB is already loaded, as RTMB's import, so this costs one lazy-load
fetch. It changes no result, and the `tryCatch()` covers a TMB that
renames the function. Every ADFun is created after frmtmb loads, so the
promise is always forced before the first finalizer can run. It is
optional for this merge: it does not change results and cannot fail a
test. Report the finalizer to TMB upstream as well: it should call
`.Call("isNullPointer", ...)` directly.
