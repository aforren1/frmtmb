## BLOCKER 1. From the default start, `b1 * exp(b2 * x)` under `cumulative()` is still the thresholds-only fit

`dev/review-nlfix-ridge.R`, seed 9202, data with latent `1.5 exp(0.6 x)`, n = 300:

| arm | logLik | b1, b2 |
|---|---|---|
| `frm()`, default start, conv = 0, "both X-convergence and relative convergence" | -413.5626 | 0, 0 |
| `frm(y ~ 1)`, thresholds only | -413.5626 | |
| `frm()`, `start` b1 = 1, or `start` b2 = 0.1 | -371.7584 | 0.9015, 0.8576 |
| brms `optimizing`, flat priors, 5 of 6 starts | -371.7584 | |
| brms posterior, default inits (`sampling`, 2 chains, 500 iter, short: Rhat 1.09) | | b2 mean 0.74, sd 0.38 |

The gap is 41.8 nats. Cause: at b1 = b2 = 0 the body is constant, the thresholds
start at their exact maximum, so the gradient of b1 is exactly 0 (the ridge) and the
gradient of b2 carries the factor b1. `max|grad|` reads 3e-11. It is a saddle, and the
optimizer starts on it.

The same on the same data: `b1 * (1 - exp(-b2 * x))` and `b1 / (1 + exp(b2 * x))` at
-413.5626, `cumulative("probit")` at -413.5626, `hurdle_cumulative()` -481.63 against
-447.03 from a start. `acat()` stops at -378.10 against -372.23 from a start, with a
false-convergence warning. `sratio()` and `cratio()` escape because their threshold
starts are not at the exact maximum. `dev/review-nlfix-a5.R` (seed 7502) shows it on a
second data set: gap 28.5.

What the user sees is conv = 0, the coefficients 0 and 0, and "the likelihood is flat
along them ... so the data do not determine them there". That is false: the data
determine them well. This is D1's symptom, the logLik the survey called silent, with a
warning that points away from the cause, under a compat row that says `works` and a
NEWS item that says the body is fitted.

Why the lane did not see it: every `ord_*_nonlin` and `ord_*_exp` spec in
`dev/nlfix-l1-specs.R` carries a `start`, and `test-nl-family.R` fits `b1 * x`. L1
cannot see it either: my spec `r_ord_default` reads `equivalent`, const -5.7e-13, grad
1.6e-12, because the objectives agree at the saddle.

Fix: do not return this fit under this message. Either restart once from a small
nudge of the body's coefficients when the body is constant across rows at a stationary
point on a `drop_intercept` family, and keep the better maximum, or stop with a
sentence that names the thresholds-only model and asks for `start`. Test: this data
set from the default start reaches -371.7584 or refuses, for `cumulative()` and
`hurdle_cumulative()`, and the compat note states what happens.

## BLOCKER 2. `simulate(newdata =)` on a body with `cov = FALSE` counts the AR part twice

`dev/review-nlfix-a4c.R`, seed 4401. One model, two spellings, logLik equal, 4000
replicates, rows with an observed past:

| | slope of (row mean - body) on the observed shift | max row-mean difference |
|---|---|---|
| linear spelling | 0.0032 | |
| body | 1.0032 | 0.3924 against the linear spelling (Monte Carlo se 0.008) |

Documented behavior (`?autocor-terms`, R/autocor.R lines 193 to 196): a replicate on
`newdata` "starts each group from an empty past and needs no response". On a body it
reads the response of `newdata` and then runs the recursion on top. Cause:
`sim_newdata_dpars()` (R/simulate-newdata.R, line 335) takes its body branch through

`cov = FALSE`, and `sim_autocor_cond()` adds its own. No warning. In-sample
`simulate()` is right (slope 0.0026 on both spellings).

Fix: read `nl_body_value()` in that branch. Test: row means of `simulate(newdata =)`
on a body against the linear spelling, as a ratio to the Monte Carlo error.

## MAJOR 1. The guard refuses correct models, in a sentence that is false

`dev/review-nlfix-a2.R` (seed 6201), `dev/review-nlfix-a9.R` (seed 9901). The rule

|---|---|---|

dpar, so refuse only when the body's VALUE moved by a meaningful amount against the
response scale and the objective did not move. If the body did not move, say nothing, or
at most warn about the start. Use an irrational step per coefficient. Tests for each row
above.

`mu * 0` and `mean(mu)` families refuse, and `categorical(refcat = NA)`, where softmax
of identical locations is constant, refuses correctly.
