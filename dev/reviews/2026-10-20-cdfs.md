## Findings

### 1. HIGH: `log_igamma_two()` is `NaN` below the mode once the shape passes about 12,600

`igamma_gl_tails()` integrates the upper window from `x` over
`wup = s * 100 / (sqrt(100 + k^2) - k)`. When `x` lies more than about
37 sd below the mode, that window crosses the mode. The integrand
`exp(lf(t) - lfx)` then overflows to `Inf`, and the arm that the blend
weights zero is `0 * Inf = NaN`. The caller clamps `x` up to
`0.7 (a + 1)` first. At that point the integrand's rise to the mode
is `a (-log 0.7 - 0.3) = 0.057 a`, which passes 709 at `a` of about
12,500. So from there the whole lower region is `NaN`: both tails and
the gradient.

`dev/cdfs-rev-igamma.R` (ARM=lane), `igamma-lane.txt`:

```
a 12000   NaN at x/a =
a 13000   NaN at x/a = 0.01 0.3 0.5 0.6 0.7
a 100000  NaN at x/a = 0.01 0.3 0.5 0.6 0.7 0.75 0.8 0.85
a 1e+06   NaN at x/a = 0.01 0.3 0.5 0.6 0.7 0.75 0.8 0.85 0.9 0.95
```

This defect reaches these callers:

- **Gamma and hurdle_gamma**, with `a` the shape. A shape of 12,600 is
  a CV of 0.9%. `dev/cdfs-rev-gamma2.R`, `gamma2.txt`, compares a
  right-censored fit, 200 rows, 20% censored, with an independent
  `stats::pgamma()` ML fit:

  ```
  shape 30000: frmtmb ... ll 438.77489770 conv 0 | indep ... ll 438.77489729
  shape 100000: frmtmb par 1.0000965 0.099810173 10.736578 ll 519.67140734 conv 1 | indep par 1.00004 0.099740683 11.533074 ll 539.69911450
  ```

  The shape-1e5 fit stops at "false convergence (8)", 20.03 below the
  maximum.
- **The poisson pair**, with `a = q + 1`. This pair is `lccdf` of
  poisson, and the zero-inflated and hurdle poisson CDFs read it. A
  count at or above about 12,600 with `mu` below about 0.7 q gives
  `NaN` (`igamma-lane.txt`):

  ```
  q 100000 mu 70000: slot NaN  ref -5673.322609
  q 20000 mu 15000: slot NaN  ref -758.4143219
  ```

  A detector that saturates at 75,000 (`y ~ Poisson(exp(11 + 0.3 x))`,
  63 of 300 rows right-censored) stops with "NA/NaN gradient
  evaluation". The base build fails on the same fit with `-Inf`
  (`igamma-base.txt`).

Fix, measured in this session only (`dev/cdfs-rev-igamma-fix.R`,
`igamma-fix.txt`): cap the exponent at 600 in both window sums,
`exp(ad_min(lf(.) - lfx, 600))`. The arm is weighted zero wherever the
cap is active. A cap of 700 is not enough: 40 terms of `exp(700)`
times `wup` still overflow.

```
a 13000: NaN 0, worst rel log err 1.18e-14
a 100000: NaN 0, worst rel log err 7.31e-15
a 1e+06: NaN 0, worst rel log err 1.19e-14
gradient at a = 1e5, x = 0.7 a: -35670.33 30002.33
Gamma shape 1e5: par 1.0000402 0.099740495 11.532927 logLik 539.69911608 conv 0
poisson large counts: par 10.99988855 0.300099082 logLik -1644.667837 conv 0
```

Both fits now reach the independent maximum. The poisson fit is
exactly the independent -1644.667837, so the lane's poisson survivor
then also fixes a fit that fails on 0.72.0. Add tests at shape 1e5 and
at `q = 1e5`, `mu = 7e4`. Both fail now. Extend `test-cdfs.R`'s gamma
grid, which stops at 1e4.

### 2. HIGH: zero-inflated CDFs drop the point mass on every row but the first when a `trunc()` bound is a constant

`zi_cdf_log()` sizes its rows by `n <- length(q)`. A bound written as
a constant, `trunc(ub = 30)`, reaches the slot as a single value. The
base pair has one value per row, but
`i0 <- which(q >= 0 & !base_zero)` is `1`. So only row 1 gets
`zi + (1 - zi) F_b`, and every other row's normalizer is
`(1 - zi) F_b`. The defect is in all six zi families. Five are
measured below. `zero_inflated_asym_laplace` has the same code path.

`dev/cdfs-rev-zitrunc4.R`, `zitrunc4.txt`, shows the objective at the
same parameters with a constant bound and with the same bound as a
data column:

```
zero_inflated_poisson trunc(ub = 30)           -fn: constant bound -124.85586509 | column bound -127.88216946 | diff 3.03
zero_inflated_negbinomial trunc(ub = 30)       -fn: constant bound -134.84816713 | column bound -137.87544592 | diff 3.03
zero_inflated_binomial trunc(ub = 9)           -fn: constant bound -111.04692611 | column bound -114.07365959 | diff 3.03
zero_inflated_beta_binomial trunc(ub = 9)      -fn: constant bound -125.79406877 | column bound -128.88956275 | diff 3.1
zero_inflated_poisson trunc(lb = 1)            -fn: constant bound -123.13362860 | column bound -119.97539844 | diff -3.16
zero_inflated_beta trunc(ub = 0.95)            -fn: constant bound -1.80529655 | column bound -21.47648529 | diff 19.7
hurdle_poisson trunc(ub = 10)                  -fn: constant bound -127.71752123 | column bound -127.71752123 | diff 0
poisson trunc(ub = 10)                         -fn: constant bound -129.46141839 | column bound -129.46141839 | diff 0
hand -127.83716240  column -127.83716240
yp | trunc(ub = 10) ~ x : ERROR The optimizer failed on this model (zero_inflated_poisson, ML, nlminb)
yp | trunc(ub = ub10) ~ x : logLik -114.225740  zi 0.0000
```

The hand-rolled likelihood equals the column form. The constant form
rewards `zi` by `-log(1 - zi)` per row, and the optimizer runs off to
`zi = 1` and a NaN (`zitrunc2.txt`: logit zi 1802.9, fn -Inf). brms's
survey cases and the lane's four truncated identity tests use other
families, so no test reaches this. The fuzz grid can draw ZIP with
`trunc(lb = 1)` as a constant (`fuzz_families`), and none of its
invariants compares the likelihood with a hand-rolled one.

`hurdle_cdf_log()` has a smaller form of the same defect. Its
`cdf_edges(., q < 0)` marks only row 1 when a constant bound is
negative, so a no-op `trunc(lb = -1)` on hurdle_gamma would have
`F(-1) = hu` on rows 2 to n.

Fix: in `zi_cdf_log()` and `hurdle_cdf_log()`, take
`n <- max(length(q), length(lb$lF), length(lb$lS))` and recycle `q`
and `base_zero` to `n` before any `which()`, as the base pairs do with
`rep_len()`. Add a test: for each zi family, a constant bound and the
same bound as a column give the same objective, and the objective
equals the hand-rolled likelihood. That test fails now.

### 3. MEDIUM: interval censoring cancels in an upper tail and at a point mass

Core scores an interval as `log(F2 - F1)` on the probability scale
(`row_lpdf()`). With this lane, that rule reaches 23 more families. It
fails in two places:

- Where both ends lie above the median, `F1` and `F2` round toward one.
- For the zero-inflated and hurdle families, where `F1` is the point
  mass. An interval `(0, y2]` is `(hu + tiny) - hu`.

`dev/cdfs-rev-grad5.R`, `grad5.txt`, uses the data of
`cdfs-rev-grad.R` and switches off one code at a time:

```
skew_normal    codes kept -1   (n  21): max rel |AD - FD| 3.02e-11
skew_normal    codes kept 2    (n  19): max rel |AD - FD| 2.06e-01
  interval rows: worst |log(F2 - F1) - log(S1 - S2)| 0.211 at y 3.278 y2 3.978 (F1 0.99999999999999989, ...)
hurdle_gamma   codes kept 2    (n  33): max rel |AD - FD| 8.10e+00
  interval rows: worst |log(F2 - F1) - log(S1 - S2)| 0.0111 at y 0 y2 0.5 (F1 0.21333333333333335, ...)
von_mises      codes kept 2    (n  42): max rel |AD - FD| 4.47e-01
  interval rows: worst |log(F2 - F1) - log(S1 - S2)| 0.0217 at y 1.154 y2 1.554 (F1 0.99999999999999856, ...)
```

The finite differences in `grad2.txt` disagree across step sizes for
hurdle_gamma `hu` (`1.40` at 1e-3, `-21217` at 1e-5, `2000545.9` at
1e-7). So the objective itself is rounding noise there, and an
optimizer that steps into such a region gets a wrong gradient. These
are points away from the optimum, where a row's mass is about
`exp(-35)`. brms has the same cancellation (`log_diff_exp` of two
lcdfs near 0), so this is not a parity regression. But the lane now
has both tails exactly on the log scale.

Fix: for an interval, take `lS(y1) + log1m_exp(lS(y2) - lS(y1))` where
`lS(y1) > log(1/2)`, and the `lF` form elsewhere. Switch on the tape
with `sign_pos()`, as the pairs already do. That form also makes the
hurdle `(0, y2]` exact, because `l1m` cancels exactly. Apply the same
rule to the two-bound truncation normalizer `log(Fub - Flb)`.

### 4. HIGH (pre-existing in core, now reached by 23 more families): the `trunc(lb = )` normalizer is still `log(1 - F(lb))`, and it is the weibull fuzz failure

When there is no upper bound, `row_lpdf()` divides by `1 - F(lb)` on
the probability scale. That loses every digit once `F(lb)` rounds to
one, the case the lane fixed for right censoring. Then the objective
is not merely inaccurate: it is `-Inf`, an infinite likelihood that
the optimizer can step into (`dev/cdfs-rev-trlb.R`, `trlb.txt`; 50
rows in `[10, 12.5]`, `trunc(lb = 10)`, the mean put far below the
bound):

```
gaussian mean far below lb: fn -Inf  gradient Inf Inf
student  mean far below lb: fn 63.72416  gradient  -3.2816408   0.4739358 -26.7694548
Gamma    mean far below lb: fn -Inf  gradient NaN NaN
```

Every CDF family now has `lccdf`, and brms uses `lccdf(lb)` here
(`trunc(lb = 1)` becomes `poisson_lccdf(lb[n] - 1 | mu[n])`,
`brmscode.txt`).

The gated fuzz spec `family=weibull aterm=trunc re=diagbar ... (seed
20446531)` is this defect. It fails on rellib-r10 and on the lane with
"NA/NaN gradient evaluation". With `row_lpdf()` patched in session to
`ll - fam_lccdf(fam, lb, ...)` when `trunc_ub` is NULL, it fits
(`dev/cdfs-rev-fuzzweib.R`, `fuzzweib.txt`):

```
   ERROR: The optimizer failed on this model (weibull, ML, nlminb): NA/NaN gradient evaluation. The
   call: frm(bf(y | trunc(lb = 0.5) ~ 1 + x + diag(1 + x | g)) + weibull(), ...
   trunc_lb 0.5  min y 0.5016092
   fits: logLik -145.969682 conv 0
```

Fix it in this lane, with a test that the objective above is finite
and equals `-sum(lpdf - lccdf(lb))`. The test fails now with `-Inf`.
The `lb` in scope is already shifted for discrete families, so one
line serves both kinds.

### 5. MEDIUM: ex-gaussian derivatives are wrong once `sigma / beta` passes about 1e3, and its density is wrong from 20 (pre-existing)

The CDF values are exact. The AD derivatives are not, because
`lx = u^2 / 2 - u z + log Phi(z - u)` cancels to `O(1 / u)` from
terms of size `u^2` (`dev/cdfs-rev-grad4.R`, `grad4.txt`, against
central differences of the 400-bit closed form):

```
mu -2 log sigma 0 log beta -7 (u = 1.1e+03): worst rel err 5.80e-02
mu -2 log sigma 0 log beta -10 (u = 2.2e+04): worst rel err 1.97e+04
   AD lS: 2.37322 4.74662 -0.000193093   ref: 2.37322 4.74643 9.78379e-09
mu -2 log sigma 10 log beta 0 (u = 2.2e+04): worst rel err 6.04e+09
mu 2 log sigma 0 log beta -5 (u = 148): worst rel err 1.62e-07
```

While checking this, I found a larger, pre-existing defect. The
density `exgaussian()` uses, `RTMBdist::dexgauss()`, switches to a
gaussian approximation at `lambda sigma` of about 20. From there it is
wrong (`dev/cdfs-rev-exgdens2.R`, ARM=base, `exgdens2.txt`, against
`brms::dexgaussian()`):

```
sigma / beta 15     max |lpdf - brms| 2.842e-14  at y = -1.5
sigma / beta 20     max |lpdf - brms| 1.620e-01  at y = 3
sigma / beta 100    max |lpdf - brms| 3.046e-02  at y = 3
RTMBdist::dexgauss directly, mu 0 sigma 1 lambda 20, y = 0: -0.9189385  closed form: -0.9214231
```

So a near-gaussian exgaussian fit, where `beta` runs toward 0, is
scored with a wrong density on the uncensored rows. With this lane, it
also gets an exact CDF on the censored rows, and the two are not
consistent with each other. The density is not this lane's code. File
it as RTMBdist-4 and give it its own fix: the closed form in logs,
which `exgaussian_cdf_log()` nearly has. For the CDF in this lane,
blend to the gaussian limit `Phi((q - mu + beta) / sigma)` above
`u = 1e3`, or take `lx` from an asymptotic Mills ratio. Add a
derivative test at `u = 1e3` and `1e4`.

### 6. MEDIUM (decision for the user): the discrete censoring convention is not brms's

The brief says: "match brms's convention for each (`lcdf(y)` vs
`lcdf(y - 1)`)". The lane keeps frmtmb's inclusive convention for 11
new discrete families (13 with negbinomial2 and poisson). A
right-censored `k` is `P(Y >= k)`, where brms reads `P(Y > k)`, and an
interval is `[k, k2]`, where brms reads `(k, k2]`. The lane's reasons
are: the convention is core's, it is deliberate, and it is
documented. That is a precedent argument, and the user has ruled that
backward compatibility is never a reason. brms is not "clearly wrong"
here: `(y, y2]` is the continuous convention carried over, and its
right and left codes are complements.

The lane's argument for keeping the convention is that one number
means one thing under `trunc(lb = )` and under `cens()`. It is
documented in NEWS, in `frm_compat()`, in a once-per-session notice
and in `vignette("brms-migration")`. A brms user who ports
`y | cens(cc, y2)` still gets a different model silently. The same
data given to brms unshifted (`brmsfit.txt`) moves negbinomial's

The NEWS advice "Subtract one from right and interval lower bounds to
reproduce a brms fit" fails at a bound of 0. brms refuses the shifted
response ("Family 'beta_binomial' requires response greater than or
equal to 0", `brmsfit.txt`). An interval `[0, k2]` has to be handed to
brms as a left-censored `k2`. A right-censored 0 has to be left out,
because it carries `P(Y >= 0) = 1`. Say so in NEWS and in the
vignette.

Ask the user to decide at consolidation, for all discrete families at
once, poisson and discrete_weibull included. Whatever the decision,
this lane is consistent with core.

### 7. LOW: compois's survivor is floored at -690.8

The survivor is `log1m_exp_ad(lF)` of a summed CDF. That form loses
digits once `S` is below about 1e-13, and its floor then returns
`log(1e-300)` (`acc.txt`):

```
compois mu=0.1 nu=0.3 lS                     n    4 worst 2.11e+01 at q=10 (ref -31.2895 got -690.776)
compois mu=3 nu=1 lS                         n    5 worst 6.37e+00 at q=48 (ref -93.6719 got -690.776)
```

brms's `com_poisson_lccdf` is also `log1m_exp(lcdf)`, which is `-Inf`
there. The floor turns a right-censored row in the far tail into a
finite, wrong value with a zero gradient. An upper sum over a fixed
window past `q` gives the tail directly. For example, take 200 terms,
or terms until the mass ratio `lambda / j^nu` has fallen far enough.
The window's length is data plus a cap, not a parameter. At minimum,
say so in the `frmtmb_family()` documentation, which now says only
"complement".

### 8. LOW: hurdle `F(0)` loses relative accuracy as `hu` gets small

`hurdle_cdf_log()` forms `lF = log1m_exp(lS)`. At `q = 0`, `F` is
`hu`, so its relative error is `eps / hu` (`acc.txt`):

```
hurdle_poisson hu=1e-12 lF                   n    5 worst 7.83e-06 at q=0 (ref -27.631 got -27.6312)
hurdle_negbinomial hu=1e-12 lF               n    5 worst 3.22e-06 at q=0 (ref -27.631 got -27.6309)
```

A left-censored row at 0, `P(Y <= 0) = hu`, is scored from that
value. Form `lF` directly as
`logspace_add(log hu, log1m hu + log((F_b(q) - f_b(0)) / (1 - f_b(0))))`,
or document the limit.

### 9. LOW: the probability-scale `lcdf` contract still ends at 1e-308

`lcdf` returns `exp(lF)`, and core takes `log(F - Flb)`. So a
left-censored row whose `F` underflows is `log(0) = -Inf`, although
the lane computes `lF` exactly. The lane decided to keep core's
contract (findings section 9). For gaussian and lognormal this is
pre-existing. Note it in the `frmtmb_family()` documentation, or let
core accept a log-scale slot. Related: `beta_binomial`'s summed `lF`
comes out at +3.0e-10 at shapes (1e5, 1e5) and 1000 trials
(`acc.txt`). That is harmless after `exp()`, but `F > 1`.

### 10. LOW: von Mises arcs next to +-pi, and the student tail at `nu = 1e12`

`vm_lmass()` forms a short arc `(-pi, -pi + 1e-9]` as a difference of
two tails. It is good to about 4e-8 relative (worst
`von_mises kappa=0.001 mu=3.1 lF ... 4.32e-08`, 64 lines of
`acc.txt`; everything else in the von Mises grid is 1.2e-12 or
better). The comment says "No branch subtracts two numbers near one
half". That is true, but the branch subtracts two numbers near each
other. Student at `nu = 1e12` is good to 3.6e-9 at `z = 50`. These
are inputs that do not occur in practice. Correct the comment.

### 11. LOW: what the BREAKING check does not cover (pre-existing, and brms accepts all of it)

`trunc-{lane,base}.txt` shows the same output on both builds:

```
gaussian lb = -Inf, ub = Inf                 frmtmb: ERROR: The optimizer failed on this model (gaussian, ML, nlminb): NA/NaN gradient evaluation.
poisson trunc(lb = 0) (y has 0)              frmtmb: ERROR: Discrete truncation needs lb >= 1 (lb = 0 is no truncation)
poisson lb = -Inf, ub = 30                   frmtmb: ERROR: Discrete truncation needs lb >= 1 (lb = 0 is no truncation)
```

### New findings

**N1. HIGH: a CDF summed from its masses has `log F` only to absolute
accuracy, and `log_window_two()` reads it where it needs relative
accuracy.**

Where `S(lo) < 1/2`, `log_window_two()` takes the window as
`lF(hi) + log1m_exp(lF(lo) - lF(hi))`. That form keeps the window's
digits only if `lF` near 0 has relative accuracy, as `pnorm(log.p =
TRUE)` and `log_igamma_two()` give. Two kinds of pair do not:

- `poisson_cdf_log()` for `1 <= q <= 30` forms `lF` as a running log
  sum. `lF(30)` at `mu = 3` is `+2.26e-16`; the true value is
  `-4.1e-21` (`sumtail.txt`).
- `compois_cdf_log()`, which also sums.

The zero-inflated and hurdle poisson read the poisson pair. A window
whose ends both use the same summed form cancels its own rounding and
comes out right, so poisson `(20, 25]` and `(25, 30]` are exact. A
window that crosses 30 does not (`sumtail.txt`, against mass sums):

```
poisson mu 3 interval (30, 31]                           got -690.775528    ref -47.0352426    rel 1.4e+01  <--
zero_inflated_poisson mu 3 interval (30, 31]             got -691.132203    ref -47.3919175    rel 1.4e+01  <--
hurdle_poisson mu 3 interval (30, 31]                    got -691.081134    ref -47.3408484    rel 1.4e+01  <--
compois mu 3 nu 1.5 interval (20, 25]                    got -690.775528    ref -35.430419     rel 1.8e+01  <--
compois mu 3 nu 1.5 interval (31, 33]                    got -690.775528    ref -70.6518908    rel 8.8e+00  <--
```

The truncation normalizer uses the same window. A poisson fit
truncated to `[31, 60]` (`dev/cdfs-rev-sumfit.R`, `sumfit.txt`;
1489 rows; the window is `(30, 60]`) gives:

```
independent: 3.2865436 0.40089486 logLik -4137.953281
frmtmb:      3.2865436 0.40089478 logLik -4137.953281 conv 0
intercept 2.0: frmtmb -fn -16285.0502  exact -16284.7749
intercept 1.5: frmtmb -fn 4589.3811  exact -22582.3035
intercept 1.0: frmtmb -fn 244363.5673  exact -28999.5407
intercept 0.5: frmtmb -fn 410624.0882  exact -35476.2464
```

The fit reaches the right maximum only because the least-squares
start lies near it. Off the start, the objective is unbounded below,
with a spurious "likelihood" that grows as `mu` falls: +410624 where
the exact value is -35476. An optimizer step there runs away. The
compois case also makes its censored objective rough: with interval
rows at `nu = e^3`, the central differences are 312031 and -3.1e7
where AD gives 1300, while every other code is smooth (`compois.txt`).
The ZIP gradient row in `win.txt` (FD -25230470) is the same defect.

Fix: in `poisson_cdf_log()`'s summed form and in
`discrete_sum_cdf_log()`, take `lF` from the exact upper sum where it
is the small tail. That is `lF = log1m_exp_ad(lS)` blended in where
`lS < log(1/2)`, the mirror of what the survivor already does. For
compois the upper sum has to be formed wherever `S < 1/2`, not only
below 1e-3. beta_binomial sums both tails directly and is right here
(1.2e-11 at `(45, 50]` of 50 trials).

Add tests that fail now:

- poisson `(30, 31]` at `mu = 3`;
- the `[31, 60]` objective at an intercept of 1, against the mass-sum
  likelihood;
- a compois interval in its upper tail.

**N2. MEDIUM: `cens()` composed with a two-sided `trunc()` is
frmtmb's (correct) likelihood, not brms's, and the documentation says
"term for term".**

brms 2.23.0 scores a right-censored row under `trunc(lb, ub)` as
`lccdf(Y) - log_diff_exp(lcdf(ub), lcdf(lb - 1))`, and a left-censored
row as `lcdf(Y) - (...)` (`dev/cdfs-rev-ctcode.R`, `ctcode.txt`; the
same for gaussian). Its numerators include mass outside the window,
so a censored row's "probability" can exceed one. frmtmb uses
`(y, ub]` and `(lb', y]`, the probability of the event inside the
window. 0.72.0's comment called brms's composition "a different,
wrong likelihood". brms is clearly wrong here, so frmtmb is right to
differ.

But NEWS ("as brms 2.23.0 does it, term for term" and "for truncated
fits including ... a censored count inside a window"), `?frmtmb_family`,
`row_lpdf()`'s documentation and the compat rows all say it matches.
The lane's evidence for that is a `trunc(lb = 2)`-only case, where the
two compositions coincide. With both bounds, `conv.txt` shows:

```
poisson trunc(lb = 2, ub = 9) + cens     ERROR: ... Actual comparison: 6.1647 >= 0.0002
negbinomial trunc(lb = 2, ub = 9) + cens ERROR: ... Actual comparison: 14.8475 >= 0.0002
```

These are differences of 6.16 and 14.85 nats. The interval rows agree:
the poisson bins inside `trunc(lb = 1, ub = 20)` fit within 0.05 SD,
because an interval lies inside the window in both packages.

Fix:

- State the divergence in NEWS, in `?frmtmb_family`'s table, in the
  `row_lpdf()` documentation and in the compat rows.
- File it in `dev/upstream-bugs.md`, under the next free brms number.
- Pin frmtmb's composition with a hand-rolled test: right- and
  left-censored rows under `trunc(lb, ub)` on a count and on a
  continuous family.
- Rename `test-cens-trunc.R`'s "discrete cens() composes with trunc()
  as brms composes them", which is true only with no upper bound.
