## 1a. The RDM derivation, done independently

Derived from scratch rather than read off the lane's code, then
compared.

**The single-accumulator law.** One accumulator is a unit-diffusion
Wiener process with drift `v` that must travel a distance `c` drawn
uniformly on `(k, k + A)`. For a FIXED distance the first passage is
inverse Gaussian with mean `c / v` and shape `c^2`, which in the form
that matters here is

    f(t; c) = c t^(-3/2) phi(x),    x = (c - v t) / sqrt(t)

Averaging over the distance integrates in closed form because

    G(c) = v Phi(x) - phi(x) / sqrt(t)

is an antiderivative in `c`. I differentiated it rather than taking
the claim: `dx/dc = 1/sqrt(t)`, so

    dG/dc = v phi(x)/sqrt(t) + x phi(x)/t
          = v phi/sqrt(t) + (c/t^(3/2) - v/sqrt(t)) phi
          = c phi(x) / t^(3/2)

which is exactly `f(t; c)`. The two `v phi / sqrt(t)` terms cancel.
So the density is `(G(k+A) - G(k))/A`, which is what `rdm_law$ldens`
computes at `R/rdm.R:264-273`. **Confirmed.**

**The "LBA shape with s = 1/sqrt(t)" identity, on paper.** The LBA
single-accumulator density with threshold `b`, start-point range `A`
and drift SD `s` is

    f_LBA = (1/A) [ v (Phi(z2) - Phi(z1)) - s (phi(z2) - phi(z1)) ]
    z1 = (b - A - v t)/(t s),  z2 = (b - v t)/(t s)

and with `b = k + A` the RDM is

    f_RDM = (1/A) [ v (Phi(x2) - Phi(x1)) - (1/sqrt(t))(phi(x2) - phi(x1)) ]
    x1 = (k - v t)/sqrt(t),    x2 = (k + A - v t)/sqrt(t)

`z_i = x_i` requires `t s = sqrt(t)`, that is `s = 1/sqrt(t)`; and the
same substitution turns the LBA's `s` prefactor on the `phi`
difference into the RDM's `1/sqrt(t)`. It is ONE substitution doing
both jobs, not a coincidence of two. **The identity is real, and it
is exact.** Checked at the code level too: `lba_law$ldens` writes
`dphi <- phi(h) - phi(g)` where the RDM writes `phi(x2) - phi(x1)`, so
the sign flips with the argument order and the two expressions agree
term for term.

**Measured, 360-point grid** (`rrg-deriv-rdm.R`), `t` in
{0.05 .. 10}, `v` in {0.3 .. 6}, `A` in {0.1, 0.5, 1.2}, `k` in
{0.2, 0.7, 1.5}. Reference is a 120-node Gauss-Legendre average over
the distance of the POINTWISE law, with the survival written
`Phi(x) * -expm1(logE - logPhi(x))` so that nothing subtracts.

**The density identity against `lba_law`, over every row with no
threshold at all: max 1.00e-11, and only 3 of 360 rows differ by more
than 1e-12.** Those 3 are the deepest tail rows (`t=10, v=6, A=0.1`,
density 9.8e-81), and the difference is in the LBA's favor being
WORSE: `lba_law` forms `phi(h) - phi(g)` directly while `rdm_law` uses
`ddm_expdiff(ddm_lphi(x2), ddm_lphi(x1))`, the log-space form that does
not cancel. So the two agree to the precision the LBA's own
subtractive spelling can carry, which is the correct outcome.

**Where the identity stops, and the lane says so.** The LBA identity
is a DENSITY identity only. Checked: `lba_law$lsurv` at
`s = 1/sqrt(t)` disagrees with `rdm_law$lsurv` on 357 of 360 rows, up
to 99 percent. That is not a defect. The LBA survival carries a
`Phi(-v/s)` never-arriving mass, which exists because an LBA drift is
drawn once per trial and can be negative; a diffusion with positive
drift reaches any positive level almost surely, so the RDM has no such
mass, and its survival instead needs the reflected image term
`exp(2 v c) Phi(-(v t + c)/sqrt(t))` that the LBA has no analogue for.
The lane states this ("the survival needs a second antiderivative ...
and that one carries a `1/(2 v)`"), and the code accordingly writes
its own `lsurv` rather than borrowing. **The lane's claim is
correctly scoped: `lba_race_lpdf()` is reused, `lba_law` is not.**

**The survival's second antiderivative, checked.** Integrating
`exp(2 v c) Phi(-(v t + c)/sqrt(t))` by parts, the leftover integral
collapses because
`exp(2 v c) phi((v t + c)/sqrt(t)) = phi((c - v t)/sqrt(t))` exactly
(complete the square), giving

    H(c) = [ exp(2 v c) Phi(-(v t + c)/sqrt(t)) + Phi(x) ] / (2 v)

so the survival is `(i1 - [(E2 - E1) + (Phi(x2) - Phi(x1))]/(2v))/A`,
which is `R/rdm.R:288-298` term for term. The `i1` regrouping at
`:281` is also exact, not an approximation: the code writes
`sqrt(t)(x2 dPhi + dphi) + A Phi(x1)` where the textbook form is a
difference of two `x Phi(x) + phi(x)` values, and the two agree
because `x2 - x1 = A/sqrt(t)`, so the discarded `sqrt(t) Phi(x1)(x2 -
x1)` is exactly `A Phi(x1)`. **The removable singularity claim is
also right**: at `v = 0` the bracket is
`(E2 + Phi(x2)) - (E1 + Phi(x1))`, and `E_i + Phi(x_i) = Phi(-c_i/sqrt t)
+ Phi(c_i/sqrt t) = 1` identically, so the bracket is `1 - 1 = 0`.

**The v -> 0 degradation, reproduced.** The lane reports this rather
than fixing it. My numbers, at `A = 0.5, k = 1`, against the same

## 1b. The go/no-go no-go term, derived and checked at 200 bits

**Derived independently.** Starting from the Cox and Miller
eigenfunction solution, the defective density at the LOWER boundary is
`f_low(t) = (pi/a^2) exp(-v a w - v^2 t/2) sum_k k sin(k pi w)
exp(-k^2 pi^2 t/(2 a^2))`. Integrating term by term,

    F_low(t) = 2 pi exp(-v a w) sum_k k sin(k pi w)
                                (1 - exp(-lambda_k t))/(v^2 a^2 + k^2 pi^2)

The UPPER boundary is `v -> -v`, `w -> 1-w`, and
`sin(k pi (1-w)) = (-1)^(k+1) sin(k pi w)`. Absorption is certain, so
`1 - F_up(infinity) = P_lower`, and

    nogo(t) = 1 - F_up(t)
            = P_lower + 2 pi exp(v a (1-w)) sum_k (-1)^(k+1) k sin(k pi w)
                                 exp(-lambda_k t)/(v^2 a^2 + k^2 pi^2)

which is `ddm_nogo_large()` at `R/wiener-cdf.R:175-190` **term for
term**. I reached it without reading the lane's code.

The split is not cosmetic. I first wrote the reference in the UNSPLIT
form and it was useless: `sum_k k sin(k pi w)(1 - exp(-lambda_k t))/den`
converges like `sum sin(k pi w)/k`, conditionally, and 2000 terms gave
four digits. The split form's series carries `exp(-k^2 pi^2 u/2)` and
is converged by `k = 40`. **The lane's reason for writing it this way
is correct, and stronger than the lane states.**

**The small-time image sum, also derived independently.** Completing
the square in the Navarro-Fuss small-time density gives
`f_low(t) = sum_j exp(-2 v a (w+j)) g(t; c_j)` with `c_j = a(w+2j)` and
`g` the inverse-Gaussian density at a signed distance. Each `g`
integrates to `A(t,c) = Phi((vt-c)/sqrt t) + exp(2vc) Phi(-(vt+c)/sqrt t)`,
whose limit at `t -> 0+` is `0` for `c > 0` and `1 + exp(2vc)` for
`c < 0`. Subtracting that constant and expanding reproduces
`ddm_lower_cdf_small()` at `R/wiener-cdf.R:114-138` exactly, including
that for `j < 0` both normal arguments are REFLECTED as well as the two
terms negated. I got that reflection wrong on my first attempt and the
reference diverged to 1e+73; the lane's version is right. **The claim
that the branch is on the loop index and not on a parameter is also
right**: `w` is in `(0,1)`, so the sign of `c_j` is decided by `j`.

**Measured against two independent references at 200 and 260 bits.**
The two share no algebra. They agree with each other to:

### The parameter maps, against EMC2's own model definitions

Checked against the `RDM` and `DDMGNG` model objects, which are EMC2's
own statement of what its parameters mean, rather than against
`rRDM` alone, which is where the lane read them.

**RDM. `EMC2:::RDM()$Ttransform` is literally**

```r
pars <- cbind(pars, b = pars[, "B"] + pars[, "A"])
```

**so EMC2 itself defines the threshold as `b = B + A`, and its `B` is
the gap above the start-point box, not the threshold.** The lane's map
is right, and this is the strongest evidence available for it: EMC2
saying so, rather than an inference from a simulator. `p_types` is
`v, B, A, t0, s`, and `dRDM`, `pRDM` and `rRDM` all divide `A`, `B`
and `v` by `s`, so `s` is a reparameterization exactly as the lane
says and nothing is lost by fixing it at 1.

Map confirmed: `v1..vn -> v`, `A -> A`, `k -> B`, `ndt -> t0`,
diffusion 1.

**Go/no-go. `EMC2:::DDMGNG()$Ttransform` is**

```r
pars <- cbind(pars, z = pars[, "Z"] * pars[, "a"], sz = ...,
              TIMEOUT = dadm$TIMEOUT, Rnogo = as.numeric(dadm$Rnogo))
```

**so `Z` is a PROPORTION and the absolute start point is `z = Z * a`.**
Corroborated twice more: `Z` declares the transform `"pnorm"` with
bounds [0.001, 0.999], which only makes sense for a proportion; and
`pDDM` passes `w = pars[, "Z"]` straight to `WienR::pWDM`, whose `w`
is the relative start point. The lane's map `bias -> Z` is right, and
`bias` is `wiener()`'s relative `w`, so the two families of this
package agree with each other as well as with EMC2.

Map confirmed: `mu -> v`, `bs -> a`, `ndt -> t0`, `bias -> Z`.

`log_likelihood_ddmgng` is transcribed correctly in the lane's notes.
One detail the lane does not mention, which supports its case: EMC2
floors the per-row log-likelihood at `min_ll = log(1e-10)`, so **EMC2
cannot represent a no-go probability below 1e-10 at all**. That is a
sharper version of the same tail limitation than the WienR
measurement, and it comes from EMC2's own likelihood rather than from
a comparison.

|---|---|---|---|
| first dpar `rate`, no `mean_fn` (rdm's shape) | REFUSED | **7.1884** | **length 0** |

### The mechanism is three sites, not one

The lane's one-line summary, "core falls back to the first primary
dpar", is right about `predict()` and loose about `fitted()`.
Precisely:

1. **`R/predict.R:639-642`, `mean_is_mu()`** - the root.
   ```r
   mean_is_mu <- function(fam) {
     is.null(fam[["post"]]$mean_fn) ||
       identical(body(fam[["post"]]$mean_fn), quote(dpars[["mu"]]))
   }
   ```
   A family that declares NO mean is treated as one that declares
   "the mean is mu". Missing is read as agreement.
2. **`R/predict.R:1168-1169`** - the consequence for `predict()`.
   Because `mean_is_mu()` is TRUE, `type = "response"` never routes to
   `predict_mean_response()`; it falls through to
   ```r
   dpar <- dpar %||% if ("mu" %in% names(rspec$dpars)) "mu" else
     rspec$primary_dpars[1]
   ```
   which is where `rdm()`'s `v1`, the lane's 3.51, came from.
3. **`R/families.R:437-441`, `response_mean()`** - the `else` branch
   is `dpars[["mu"]]`, which is the drift for `wiener_gng()` and NULL,
   hence the length-0 residuals, for `rdm()`.

`fitted()` at **`R/predict.R:1704`** refuses only when BOTH hold:

```r
if (!"mu" %in% names(dp) && is.null(rspec$family[["post"]]$mean_fn))
```

so a family is protected by NOT having a dpar called `mu`, which is
backwards. `rdm()` was saved from `fitted()` by an accident of naming;
`wiener_gng()`, whose drift is called `mu`, was not.

### The one-line core fix, and the evidence that it is safe

**`R/predict.R:639-642`: make a missing `mean_fn` mean "no mean"
rather than "the mean is mu".**

```r
mean_is_mu <- function(fam) {
  !is.null(fam[["post"]]$mean_fn) &&
    identical(body(fam[["post"]]$mean_fn), quote(dpars[["mu"]]))
}
```

That one flip routes every `type = "response"` request for such a
family into `predict_mean_response()` and so into `response_mean()`,
making `families.R:437-441` the single place that has to refuse with a
reason. Strictly the consolidation needs one line at each of two
sites: the flip above, and turning `response_mean()`'s `else` branch
from `dpars[["mu"]]` into a `stop()` naming the family and telling the
author to declare `post$mean_fn`. `fitted()`'s guard at
`predict.R:1704` should then drop its `!"mu" %in% names(dp) &&` for
the same reason, which is a third line but is implied by the first.

**Measured that this cannot break core.** I enumerated all 40
families in `frmtmb:::family_registry`:

* **all 40 have a dpar called `mu`**, so no core family ever reaches
  the `primary_dpars[1]` branch at all;
* exactly **5 have no `post$mean_fn`** - `cumulative`, `sratio`,
  `cratio`, `acat` and `categorical` - and every one of the five is
  ordinal or categorical, which `predict()` returns on at
  `predict.R:1071` and `:1086` and `fitted()` at `:1693` and `:1699`,
  all **before** any of the three sites above.

So the refusal cannot fire for a built-in family, and the only callers
it can reach are contributed families that genuinely have no mean.
The lane's decision to declare a refusing `mean_fn` is the right local
workaround, and the core fix would make it unnecessary rather than
wrong.

## 4. `dec()`: `lba()` does silently drop it

**Confirmed, and worse than "ignored": the fit is bit-identical.**

`rdm(3)` refuses, with a message that names the reason and the
alternative:

```
rdm: dec() carries a two-level boundary indicator and this family needs
to know which of 3 accumulators reached the threshold, so the term has
no meaning here and is refused rather than ignored. The winner travels
through vint() as a whole number from 1 to 3.
```

`lba(3)` on the same data and the same formula **fits**. Measured, on
300 rows, `rt | dec(two) + vint(choice) ~ 1` against
`rt | vint(choice) ~ 1`:

| | with `dec()` | without `dec()` |
|---|---|---|
| fixef (6 values) | 2.48526682 1.99264734 1.56425069 -0.48133201 -1.38916200 1.00186495 | identical |
| max absolute difference | **exactly 0** | |
| logLik | 70.3793487679 | 70.3793487679 |
| warnings at fit time | **none at all** | |

The term is parsed and stored - `aterm_values` on the fitted object
carries both `dec` and `vint1` - and then never read by the
likelihood. So the user's `dec(two)` column travels all the way into
the fit object and changes nothing, silently.

**Should `lba()` refuse too? Yes.** The divergence is currently a
booby trap in exactly the direction the lane identifies: a user
porting a model from `wiener()`, where `dec()` IS the spelling, writes
`dec()` out of habit. Under `rdm()` they get a sentence; under
`lba()`, the sibling family with the identical dpar set, they get a
fit that quietly ignored half of what they wrote. Two families with
the same parameters and the same formula interface should not disagree
about whether a term is meaningful.

**The fix is one hunk plus a test**, as the brief anticipates:
`lba_check_response()` in `R/lba.R` gains the `dec()` refusal that
`rdm_check_response()` already has at `R/rdm.R:326-334`, with the
count spelled `n` instead of 3, and one `expect_error()` beside the
`rdm()` one at `tests/testthat/test-rdm-gng.R:350-353`. **Listed as a
punch item, not done here**: it changes a shipped family's behavior,
which is a decision for the consolidation rather than for a reviewer,
and the lane's own reasoning for leaving it alone (a sibling lane may
be editing `R/lba.R`) is sound.

### The pattern is wider than `lba()`, which the consolidation should know

I checked the mirror case. `wiener()` accepts a `vint()` term it
cannot use just as silently:

```
frm(bf(rt | dec(resp) + vint(extra) ~ 1), family = wiener(), data = dw)
-> FITTED (vint silently accepted)
```

So this is not an `lba()` defect so much as one instance of a general
one: **frmtmb has no seam for "this family does not accept that
addition term."** `frmtmb_family(required_aterms =)` is a
CONJUNCTION of what the density needs (`R/families.R:55-61`,
`R/objective.R:43-56`); there is no complementary allow-list, so an
extra term is never refused by declaration and every family that wants
to refuse one must hand-write the check in its own `valid_y`.

That makes the `lba()` hunk the right SHORT-term fix - it belongs to
this package and is small - while the durable fix is a core
`permitted_aterms` (or a rule that any aterm neither required nor
core-generic is refused by name). Worth one line in the consolidation
plan; too big for this lane.

## 5. The simulators and the density tier

### The tier itself

`tests/testthat/test-simulate-density.R` grew from 63 to 69 passing
tests, **reproduced exactly** (69 measured, see item 7). The six new
ones are two `test_that()` blocks per family plus the two new entries
in the "every family declares a simulator" block.

The shape of the check is right and worth saying so. It does not
compare the simulator to a formula; it discretizes the family's OWN
`lpdf` into 8 equiprobable cells over a bracket, draws 4000 times from
the family's `sim` SLOT, and runs a chi-square at alpha 1e-6. That is
the seam `frm_simulate()` and `simulate()` actually use, and nothing
tied it to the density before. It also asserts the two boundaries'
masses sum to one, so a simulator cannot pass by losing probability.

### The mutations: does it catch a wrong simulator?

I patched each simulator in the loaded namespace with
`assignInNamespace()` and re-ran the tier's own machinery. Critical
value at df=7 is 40.52.

| simulator | chi-square | verdict |
|---|---|---|
| **rdm as shipped**, winner 1 / 2 | 6.59 / 1.70 | pass |
| **rdm MUTATED**: distance `U(k-A, k)`, `k` read as the THRESHOLD | **19717.36 / 20730.40** | **caught** |
| **rdm MUTATED**: distance `U(0,A) + k/2`, box shifted | **4275.43 / 4529.42** | **caught** |
| **gng as shipped** | 0.79 | pass |
| **gng MUTATED**: deadline test dropped from the rejection loop | **32.10** | **passes the chi-square** |

**The RDM mutation is caught overwhelmingly.** The first mutation is
precisely the `B`-versus-threshold confusion the lane warns about in
its EMC2 notes, and the tier lands on it at 19717 against a critical
value of 40.5 - a factor of 486. The second, a subtler shift that
keeps the box the right WIDTH and only moves it, is still caught at
4275. The tier has ample power on this family.

**The go/no-go mutation is caught, but NOT by the chi-square.** At
32.10 against 40.52 the statistic passes - a 20 percent margin, which
is far too close for comfort. What catches it is the tier's separate
range assertion on the line above:

```r
expect_true(all(draws > dp[["ndt"]] & draws <= td))
```

and that assertion fails hard: the mutated simulator put **147 of 4000
draws past the deadline, the largest at 3.87 against a deadline of
1.5**. So `test-simulate-density.R` does catch the mutation and the
tier is sound as written.

But the reason is worth recording, because it is a property of the
harness and not of this family. `ddm_cells()` builds its cells on the
bracket `[ndt, td]` and `findInterval()` puts every draw above the top
cut into the LAST cell, so mass that escapes the support is folded
back into the bracket instead of being counted against it. The
chi-square is nearly blind to an out-of-support draw by construction.

**Punch item, small:** give `ddm_cells()`/`expect_ddm_gof()` an
overflow cell above the bracket so that the statistic itself sees
escaped mass, rather than leaving all the power on a separate
`expect_true(all(...))` that a future edit could drop. Not a defect
today - the assertion is there and it works - but the tier currently
looks stronger than it is on any family with a bounded support, and
`wiener_gng()` is the first such family in this package.

## 8. Names, ahead of the rename to `frmtmb.eam`

### The dpar vocabularies already answer most of this

Measured on the built families:

| constructor | `family` string | dpars | required aterms |
|---|---|---|---|
| `wiener()` | wiener | `mu, bs, ndt, bias` | (none declared) |
| `gddm()` | gddm | `mu, bs, bias, ndt` | (none declared) |
| **`wiener_gng()`** | wiener_gng | **`mu, bs, ndt, bias`** | `dec` |
| `lba(3)` | lba | `v1, v2, v3, A, k, ndt` | `vint1` |
| **`rdm(3)`** | rdm | **`v1, v2, v3, A, k, ndt`** | `vint1` |

Each new family has EXACTLY the dpar set of the family it extends.
`rdm()` is dpar-identical to `lba()`; `wiener_gng()` is dpar-identical
to `wiener()` and `gddm()`. The names should track that kinship, and
they do.

### `rdm()` is the right name

It is the literature's own name - Tillman, Van Zandt and Logan (2020)
call it the racing diffusion model - it matches `lba()`'s acronym
style exactly, it is what EMC2 calls its model, and it is unambiguous
in this package: nothing else here races. Under `frmtmb.eam` it reads
better still, since "racing diffusion model" is squarely an evidence
accumulation model. **Keep.**

### `wiener_gng()` is the right name, and the prefix is load-bearing

It is the odd one out on style: the only constructor with an
underscore, and the only one named after a PARADIGM (go/no-go) rather
than a model. I still think it is correct, for three reasons.

1. **The prefix carries information that a bare `gng()` would
   destroy.** Go/no-go is an observation scheme, not a model. EMC2
   itself distinguishes `DDMGNG` from its other models precisely
   because you could race LBAs under a go/no-go protocol just as
   easily. `wiener_gng()` says which accumulator model is underneath,
   and the dpar table above shows that is not decoration: the
   parameters ARE `wiener()`'s, and the go branch is literally
   `wiener()`'s density.
2. **It tells a user what transfers.** Someone with a `wiener()` model
   who gains no-go trials changes one word and keeps every formula,
   every prior and every dpar name. The name advertises that.
3. **brms parity.** `wiener()` is brms's spelling, and this package's
   stated convention is to follow it; a `gng()` that did not visibly
   descend from it would break the thread.

The alternative worth naming is `ddm_gng()`, which would generalize
better if a `gddm()`-based go/no-go ever appeared. I would not rename
now: `wiener_gng()` is accurate today, and `ddm_gng()` would be a
promise the package does not yet keep.

**Under `frmtmb.eam` both names survive unchanged.** The rename makes
`wiener()` itself the slightly awkward one - it names a stochastic
process rather than a model - but that is brms's word and parity
outweighs tidiness. Nothing here needs to change for the rename.

### The vignette does read as one family class

`vignettes/ddm.Rmd` runs `wiener()` (to line 390), then
`## More than two alternatives` (LBA, 391), `## Racing diffusions`
(RDM, 519), `## Go/no-go: one boundary you can see` (653),
`## References` (801).

The order is by increasing departure from the base model, and every
new section opens by naming what it inherits, which is what makes it
read as one class rather than a catalogue:

* RDM opens "`lba()` races accumulators that are noiseless once they
  start. `rdm()` races accumulators that are not ... The geometry is
  identical, so the two families share a spelling and a model moves
  between them by changing one word." That is exactly right, and it
  is the prose statement of the dpar table above.
* Go/no-go opens "`wiener()` cannot fit that, because it needs to know
  which boundary each trial ended at and half the trials do not say.
  `wiener_gng()` is the model Gomez, Ratcliff and Perea (2007) wrote
  for it, and the one EMC2 calls `DDMGNG`."

**The two race families are adjacent, which is right**, and the
go/no-go section sits last even though its kin is `wiener()` at the
top. That is the one arguable placement: a reader could expect
go/no-go beside `wiener()`, since it is a `wiener()` variant, rather
than after two race families it has nothing to do with. It works
anyway because the section's first paragraph sends the reader back to
`wiener()` explicitly, so nobody is left wondering what it descends
from.

I would leave it. Moving go/no-go up would split `lba()` from
`rdm()`, and that pairing is the stronger one: `rdm()` is
unintelligible without `lba()` immediately before it, whereas
`wiener_gng()` only needs a pointer. **No change recommended.**

## Verdict

**GO WITH FIXES.**

The mathematics is right, and I checked it by deriving it rather than
by reading it. Both closed forms - the RDM's inverse-Gaussian average
over a uniform start point, and the go/no-go's two series for the
probability of no upper crossing - I rederived from first principles
and they match the lane's code term for term, including the two
regroupings (`i1` in the RDM survival, the split of the large-time
no-go series) that exist purely to avoid cancellation and that I
confirmed are algebraically exact rather than approximations. The
"LBA shape with `s = 1/sqrt(t)`" identity is real, is exact, and is
correctly scoped: it is a DENSITY identity, the survival is genuinely
different, and the lane says so and writes its own.

Every reproducible headline number reproduced, most of them to the
digit: the EMC2 residuals (6.11e-16, 1.33e-15, 1.71e-13; 6.41e-13,

stronger evidence than the lane itself used. The merge against the
gddm-ref lane is clean on every file, and so is the merge against
main as it now stands, since that lane landed on main mid-review. The
core trap is real, and I reproduced it from scratch on core with no
extension loaded.

editorial. Neither is a defect in the model, the derivation or the
architecture; both are claims that are stronger than what the code
delivers.

1. **The blended no-go probability is 7.7e-05 at worst, not 1e-12**

## Should EMC2 leave Suggests?

**Yes, at the consolidation, not in this lane.** `^dev$` is in
`.Rbuildignore`, so `dev/rdm-gng-emc2-reference.R` never ships, and
EMC2 appears in no executable line of the built package - only in
vignette prose, roxygen comments and test comments. Listing it makes
`install.packages(dependencies = TRUE)` pull EMC2 plus GPArotation,
magic, matrixcalc, corrplot, psych and lpSolve to run a script the
tarball does not contain. Dropping it costs nothing and is one line;
the reason to do it at the consolidation rather than here is that
`DESCRIPTION` is the file every lane touches, and this is not worth a
conflict.
