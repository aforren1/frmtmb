## Findings

### 1. major: frmtmb.sample's NEWS calls a reweighted reference "brms's"

`extensions/frmtmb.sample/NEWS.md` lines 17 and 37: "0.946 against
brms's 0.921 ... now it is 0.923 (1.4)" and "0.946 against brms's
0.922". Both brms numbers are brms's draws reweighted to frmtmb's
marginal-sd prior. brms's own posterior under its own defaults is
0.9156. Against it, frm_sample after is 0.9226, z 9.37
(`dev/review-acprior-unweighted.R`, `unweighted.txt`, seed 3,
4 x 4000). The gap left is the sigma default: brms puts
`student_t(3, 0, 2.5)` on the innovation sd, frmtmb.sample on the
marginal sd, so the joint default is still not brms's for a
cov = TRUE ar or ma. The documented parameterization divergence
explains it, but the NEWS reads as parity.

Fix: say in NEWS that the comparison is with brms's draws reweighted to
frmtmb's marginal-sd parameterization, and that against brms's own
posterior the gap is now 9.4 MC SE. In findings
and the backlog, add the sigma default as a parity item: under a
first-order cov = TRUE ar or ma, put the default on
`sigma * sqrt(1 - ar^2)` (`sigma / sqrt(1 + ma^2)`) with its Jacobian,
which is the edit `dev/review-acprior-direct.R` makes to brms in
reverse.

### 2. major: the cosy bound brings divergences brms does not have

`dev/review-acprior-cosydiv.R` (`cosydiv.txt`), the lane's cosy data
(ML cosy -0.0089), 4 x 2000: frm_sample after has 9, 5, 6 divergent
transitions with mode starts (seeds 3, 4, 5) and 5, 6, 6 with random
starts. brms on the same data and seeds: 0, 0, 0. With the bound lifted
(`set_prior("", class = "cosy", lb = -1/3)`, flat over the window;
`dev/review-acprior-cosydiv3.R`, `cosydiv3.txt`): 0, 0, 0. So the
divergences come from the bound at 0 on frmtmb's sampled coordinate
(window logistic, then tmbstan's `lb + exp(u)`), not from the start.
The lane's own run shows it too (`agree-after.txt`: 27 divergent in
4 x 4000) and the findings do not mention it. The means agree with
brms (z -0.35), so this is diagnostics noise on every cosy-near-0
fit, not yet a measured bias. The divergent draws are spread over cosy
0.0004 to 0.149 (`cosydiv2.txt`), so the location is not obvious.

Fix: find the cause before release. A candidate: when a bound narrows a
mapped parameter, sample a logistic onto `(lb, ub)` of the natural
parameter instead of a log bound stacked on the window's logistic. If
not fixable in this round, record it in findings and NEWS and file it.

### 3. major (pre-existing): bounded defaults lose their bound

`keep_flat_defaults()` copies the default's lb/ub only for
`flat_interval` defaults. brms keeps every declared bound under a user
prior: `real<lower=1> nu`, `real<lower=0> sigma` (identity link),

`normal(2, 2)` on nu, 4 x 2000, seed 3): 3.55 percent of nu draws below
1, where brms has none by declaration. For sigma and ndt the likelihood
rejects the outside region, so the effect is rejections, not a
different posterior.

Size: the same function. Extend the filter in `keep_flat_defaults()` to
every default with a non-NA lb or ub (brms_natural_bounds()'s), copy
the bound on each unset side, and keep the density inheritance for
`flat_interval` only. About 5 to 10 lines and one test per class.
Recommendation: fold into this fix round, since the lane wrote the
function and its doc says "since brms keeps both". If the user keeps
the round narrow, it is the first backlog item.

Jacobian. The gap is 1.6e-15 for ar, -2.7e-15 for ma and 2.2e-16 for
arma. On rellib-r13 the gaps are 0.199, 0.098 and 0.178.

**Unchanged elsewhere.** `dev/review-acprior-r2-objs.R`
(`r2-objs-*.txt`) fits eight MAP models with b, Intercept, sigma, sd,
cor, rescor and dpar priors and no cov = TRUE term: gaussian, random
effects, `sigma ~ z`, poisson, bernoulli, multivariate with rescor,
cov = FALSE ar with a sigma lb, and cosy. The objective at the optimum
and every estimate printed to 12 digits are IDENTICAL to rellib-r13
(`diff` minus the library line).

**The test reruns** are in item 4. The entry-wise `expect_identical()`
compares the same scalar density, computed by the same R code on the
same inputs in one process. No BLAS call is on that path, so OpenBLAS
cannot change it. The lane's OpenBLAS 0.3.26 run gave pass=89.

**Not covered: `sigma ~ x` under `ar(cov = TRUE)`.** It is a silent
divergence from brms, and the two routes agree with each other.
`class = "sigma"` is refused there, with brms's own reason. A prior on
`class = "Intercept", dpar = "sigma"` reads frmtmb's log MARGINAL sd
(entry `innov no`). brms's `Intercept_sigma` is the log INNOVATION sd:
`sigma = exp(Intercept_sigma + ...)` goes into `normal_time_het_lpdf()`
with `cholesky_cor_ar1()` divided by `1 - ar^2`
(`dev/review-acprior-r2-brmssigx.R`, `r2-brmssigx.txt`). So the
densities differ by a shift of log c. The default and a user prior read
the same scale, so the sampling table still round-trips. The fix would
be small: read the density at `x + lc`, with no Jacobian term, since a
shift has unit Jacobian. The lane filed only the DEFAULT of this case.

### 2. lb/ub on sigma: correct

- **Refused.** `lb = 0.2` on `resp = "y1"` and `ub = 3` univariate are
  refused: "class = "sigma" takes no lb here: under ar(t, g, cov = TRUE)
  brms's sigma, which a prior on class "sigma" is about, is the
  innovation sd, frmtmb's marginal sd times a factor of the correlation
  parameters, so a bound on it is not a bound on the parameter frmtmb
  holds. Write the density alone".
- **Taken:**
  - `lb = 0` on a log link (lower -Inf);
  - `lb = 0` on an identity link (lower 0);
  - `lb = 0.2` on resp y2 of the same multivariate model;
  - `lb = 0.2` on cov = FALSE ar, on order-2 cov = TRUE ar, on cosy, and
    on a model without autocorrelation (lower log 0.2 = -1.609 each).

The refusal does not fire on another response or on a model without
the term.
