### F2. The corrected factorization sentence is false for `frmtmb.learn` (MEDIUM)

`R/structure.R:929`.

```
paste0(lead, "its likelihood factorizes no finer than ",
       structure_unit(st),
       ", so the quantity this needs per row is not defined")
```

This reads the `unit` slot and states it as a factorization claim. The
slot's own roxygen, which this lane did not change, says the two are
different questions and names the counterexample:

> `R/structure.R:274-282` ... It declares what may honestly be LEFT OUT,
> which is a different question from how finely the likelihood
> factorizes: `rw_delta` has a per-trial conditional density and a
> leave-one-out unit of one subject's whole sequence.

`dev/structured-family-protocol.md:200-206` says the same thing: "`rw_delta`'s
finest factorization is the TRIAL, and its `unit` is one subject's whole
sequence."

Measured on `frmtmb.learn` installed read-only into `rvat-lib`.
`bandit2arm_delta()` declares `loglik` and `unit = "one subject's trial
sequence"`, passes no `supports`, and writes its own sentence for only 4
of the 13 capability flags. The other 9 (`reml`, `quadrature`, `profile`,
`se_fit_response`, `re_form`, `multivariate`, `cens_trunc`, `mi`,
`cluster_robust`) reach `structure_generic()` and print:

```
REML = TRUE is not available for a 'bandit2arm_delta' family: its
likelihood factorizes no finer than one subject's trial sequence, so the
quantity this needs per row is not defined
```

Both halves are false. The same package's own `deviance` refusal, three
slots away in `ln_refusals()`, says "the per-trial factors exist, but the
structured protocol's `loglik` slot returns one total".

This is not a regression: main's sentence ("its likelihood does not
factorize over the rows of the data") was false for the same family. But
Defect 3's stated purpose was to remove a false sentence about
factorization, and the replacement is still false for one shipped family
while citing, as its authority, a slot documented to answer a different
question. The honest refusal reports what the family declared and what
the core can therefore not obtain, which is what the capability-only
branch two lines up already does well.

**This got sharper while the review ran.** A sibling lane has now
declared `loglik_row` and `loglik_group` on all eight `frmtmb.learn`
families, establishing both statements by measurement. The finer
factorization this sentence denies is therefore no longer asserted only
by the protocol document: it is carried in the families' own
declarations, in the slots the protocol defines for exactly this
question. At the head I measured, `bandit2arm_delta()` declared `loglik`
alone and neither factorization slot, which is why the sentence merely
contradicted `dev/structured-family-protocol.md:200-206`. Once that lane
lands, core would ship a sentence telling a user that a family's
likelihood "factorizes no finer than one subject's trial sequence" while
that same family declares that it factorizes per row and per group. A
core refusal contradicting a shipped extension's own declaration is not a
wording nit, and it is why this item is on the punch list rather than in
the notes.

No test anywhere asserts this sentence. Grepping core and every
extension's `tests/` for the old wording, the new wording and the "is not
available for a" stem returns nothing, which is how the falsehood
survived a rewrite whose stated purpose was to remove one.

The lane's own claim for `lca()` and `hmm()` checks out. Core's
equivalents were measured directly: `mixture_mvn(2, 2)` declares no
`loglik`, and main's sentence was flatly false for it; the new branch
returns "the family declares it unsupported and gives no reason of its
own", which is true. `mixture(gaussian(), gaussian(), groups = ~g)`
declares `loglik` and a unit and gets the unit quoted, which is correct.
`lca()` in `frmtmb.latent` declares no `loglik` (`lca.R:519`) and `hmm()`
declares `loglik`, `loglik_group` and `unit = "a hidden-Markov sequence"`
(`hmm.R:496`), so both land on the right branch.

### F3. `mixture()` composes exclusive sets by set equality, not intersection (LOW-MEDIUM)

`R/families.R:5127-5136`, the `setequal()` at `:5134`.

`mixture_exclusive_aterms()` keeps a set from the first component only if
every other component declares a set equal to it. The documented rule is
weaker:

> `dev/structured-family-protocol.md`: two spellings are interchangeable
> only if EVERY component treats them so.

Measured with two toy families, A declaring `list(c("dec", "vint1"))` and
E declaring `list(c("dec", "vint1", "vint2"))`:

| components | composed exclusive set |
|---|---|
| same set | `dec/vint1` |
| same set, order flipped | `dec/vint1` |
| one declares none | none |
| disjoint sets | none |
| `{dec,vint1}` vs `{dec,vint1,vint2}` | **none** |

Every component in the last row treats `dec` and `vint1` as one datum, so
the documented rule keeps that pair. The implementation drops the rule
and the mixture then accepts both spellings together, which is exactly the
defect this lane exists to close. The failure direction is open, not
closed.

Not reachable from a shipped family: `wiener()` is the only family in the
tree that declares a set, so no two components can currently disagree.
It becomes reachable the moment a second family declares one, and nothing
would catch it, because no test covers mixture composition of
`exclusive_aterms` at all.

### F4. `exclusive_aterms` coerces before it validates (LOW)

`R/families.R:5060` and `:5080`.

`exclusive_aterm_groups()` runs `lapply(x, as.character)`, and
`check_exclusive_aterms()` then tests `is.character(z)` on the already
coerced result, so the test cannot fail for any coercible type. Measured:

| declaration | `required_aterms` | `exclusive_aterms` |
|---|---|---|
| `list(c(1, 2))` | refused, "Got a list of length 1" | **accepted**, becomes `c("1","2")` |
| `list(c(TRUE, FALSE))` | (same class of refusal) | **accepted**, becomes `c("TRUE","FALSE")` |

The resulting set matches no addition-term value, so the rule silently
never fires. The sibling argument this one is modeled on catches the same
shape. The lane's test covers `bad(42)`, which is not a list and so takes
the earlier branch.

Related nit: the refusal text for a malformed set says only "Got a list of
length 1" and does not say which set or why, so `list("dec")`,
`list(c("dec","dec"))` and `list(c("dec", NA))` all produce the same
message.

### F8. The recorded gap is wider than recorded, and is still a follow-up (INFO)

The lane records that `mixture()` passes no `required_aterms`, so
`mixture(wiener(), lognormal())` does not inherit the boundary
requirement. It also drops the EXCLUSIVITY, because `lognormal()`
declares no set and the intersection is therefore empty. Measured on 120
rows, with `max_ndt` set because a bare `wiener()` inside a mixture
refuses before frame assembly:

| library | `mixture(wiener(max_ndt=.25), lognormal())`, `rt \| dec(u) + vint(1-u)` |
|---|---|
| merge base | fits, logLik 37.7792922437219 |
| worktree | fits, logLik 37.7792922437219, identical |

and `dec(u)` alone gives the same 37.7792922437219 in both, so the
contradictory column is still silently unread through a mixture.

**Follow-up, not a merge blocker**, for three measured reasons. It is not
a regression: the numbers are bit-identical before and after. The lane
strictly improves the neighbouring case, `mixture(wiener(), wiener())`,
which the merge base fits silently at -32.5351928252200 and the worktree
refuses by name. And the fix is a `mixture()` semantics decision, namely
which of its components' requirements a mixture inherits when only one
component has them, which is a larger question than this lane's argument.

The same measurement exposes a pre-existing rough edge worth its own
note: `mixture(wiener(max_ndt=.25), lognormal())` with no boundary term
at all fails with `Not compatible with requested type: [type=NULL;
target=double]` rather than a refusal, on both the merge base and the
worktree.

### (b) The exclusivity mechanism

The before state reproduces on the merge base. On 120 simulated rows, all
four formulas give one identical log-likelihood, including the
contradictory one:

| formula | merge-base logLik |
|---|---|
| `rt \| dec(u)` | -35.3347749936344 |
| `rt \| vint(u)` | -35.3347749936344 |
| `rt \| dec(u) + vint(u)` | -35.3347749936344 |
| `rt \| dec(u) + vint(1-u)` | -35.3347749936344 |

The absolute value differs from the lane's -76.0486443897369 only because
the simulated data differ. The structure of the defect is exactly as
reported: contradictory columns, one number, no complaint.

The refusal fires on the worktree, names both terms, and says which to
keep:

```
wiener: `dec` and `vint1` are spellings of the same datum for this
family, and this response supplies both. The density reads `dec` and
would ignore `vint1`, so they could disagree with nothing to say so.
Keep dec(<column>) and drop vint(<column>).
```

Composition attacks:

- **Any-of group equal to the exclusive set reads as exactly one.**
  Verified behaviorally in both directions on a purpose-built family:
  neither term gives "the density needs one of `dec` or `vint1`", both
  give the exclusivity refusal. No single message uses the phrase
  "exactly one", which is fine, because a user only ever reaches one of
  the two.
- **A conjunction declared exclusive is refused at construction.**
  `required_aterms = c("dec","vint1")` with the same set exclusive stops
  with "no model could satisfy the family. Make them alternatives
  instead: required_aterms = list(c("dec", "vint1"))." Also fires when
  the conjunction has a third member the exclusive set does not name.
- **Mixture composition** is F3 above.
- **`gddm()` still accepts both and fits.** `rt | dec(u) + vint(cond)`
  fits, and `gddm()[["exclusive_aterms"]]` is empty, which is the reason
  the argument is opt-in.
- **`lba()`, `rdm()`, `wiener_gng()` unaffected.** None declares a set,
  and each accepts only one of the two spellings, so the allow-list
  already refuses the other. Confirmed against the table: `lba x dec()`,
  `rdm x dec()` and `wiener_gng x vint()` are refused, each keeping its
  own hand-written note.

One residual, already scoped out by the protocol and not this lane's:
`rt | vint(u, junk)` fits `wiener()` with `vint2` unread, at the same
-35.3347749936344. Exclusivity is spelled in values, so it cannot see a
second value of the same term.
