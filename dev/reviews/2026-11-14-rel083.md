## Findings

### F1 (FIX, tooling). The session summary counts hygiene's tag as untagged

`dev/rel083-sessions-sum.sh` counts a LEAK line as tagged only when it
holds `[with load of`. Hygiene's `dev/release/run-session.R` (item 3164)
now prints extension session state as `LEAK <file> <pkg>::<env>: <names>
[extension session state]`, a tag by design ("The tag keeps the
checklist's rule (a LEAK line has a tag)", `dev/hygiene-findings.md`).
So the summary prints 24 plain and 27 gated lines as `UNTAGGED LEAK`
(`dev/rel083-log/sessions-rel0.83.0-sum.txt`, `-g-sum.txt`), where
0.82.0 printed 0. `dev/lane-rules.md:432-433` tells every lane the same
false thing: "one without `[with load of ...]` is your test's".

Each of the 51 lines is session state of an extension cache, not a
leak. Gated, from `dev/release/rel0.83.0g-sessions/*.txt`: 12
`frmtmb.ode::ode_failure_log: when groups penalty n_groups`, 9
`ode_failure_log: when n_groups`, 3 `frmtmb.ode::ode_warned: states8`, 3
`frmtmb.eam::gd_cache: tri`; the plain 24 are the same kinds. The other
194 gated lines carry `[with load of ...]` (142 the Stan model load).
The record's "No other LEAK line" means "no other untagged line"; say
that.

Fix: in `dev/rel083-sessions-sum.sh`, count and list as untagged only
lines with neither tag (`grep -v -e '\[with load of' -e '\[extension
session state\]'`), print the extension-state count on its own, and
rerun the two summaries. Reword `dev/lane-rules.md:432-433` ("a line
with neither `[with load of ...]` nor `[extension session state]` is
your test's"). The next round copies this script.

### F2 (FIX, docs and NEWS). `nl_starts = FALSE` still restarts from a saddle

`?frmtmb_control` (`R/fit.R:3096` to `:3107`) and the NEWS bullet say
"`FALSE` runs neither, so the fit is the one the optimizer reaches from
the start, with no message about a restart", then "The restart from a
saddle point is outside this switch". Under `FALSE` the saddle restart
still moves the fit and still says so, so the first sentence is false.

Reproducer: `dev/reviews/rel083-review-saddle.R` (the case of
`test-se-limit.R`, "a family limit on a nonlinear fit still triggers the
restart": `y ~ a * w^b, a ~ gp(x)`, student()), output
`rel083-review-out/saddle.txt`:

| nl_starts | logLik | conditions |
|---|---|---|
| TRUE | 55.66528709 | `M:frmtmb_nl_restart` |
| FALSE | 55.66528709 | `M:frmtmb_nl_restart` |

Expected by the text: under `FALSE`, the optimizer's own stop and no
restart message. Actual: the restarted fit and its restart message. The
coordinator kept the saddle restart outside the switch; that is the
user's to confirm, but the text must not say both. Fix (text only):
"`FALSE` runs neither. A fit from the default start can still restart
from a saddle point (message class `frmtmb_nl_restart`); this switch
does not change that." The same in NEWS. Or, if the user wants `FALSE`
to mean "the fit from the start", put `nl_fit_off_saddle()` under the
switch too and add this case to `test-nl-starts-control.R`.
