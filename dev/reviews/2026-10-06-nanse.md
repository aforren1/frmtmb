## Verdict: NOT MERGEABLE

The diagnosis of defect 8 is right. The warning, the allfit work and
the merge mechanics hold up. But the repair can report finite,
confident standard errors for parameters that are not identified, and
predictions that move along a lost direction get finite, too-narrow
intervals where base gave NaN. Those are the failure modes the repair
exists to avoid. Two blocking findings, B1 and B2, both in
`cov_from_hessian()`.

## Blocking

### B1. A widely shared flat direction leaves finite, wrong SEs

`cov_from_hessian()` tier 3 names a parameter only when its component
in the unit eigenvector of a flat direction is above `se_load_tol =
0.1`. A flat direction shared by more than about 50 parameters loads
below 0.1 on each, and those parameters keep a finite SE from the
pseudo-inverse. That SE is not the marginal SE (infinite) and not the
conditional one either.

`dev/nanse-rev-cases.R` and `dev/nanse-rev-pred.R`: `y ~ a + b`,
`a ~ 0 + f` (k levels, 5 rows each, residual sd 0.5), `b ~ 1`, nl.
Only `a_k + b` is identified. In unit-diagonal coordinates the null
vector loads sqrt(1/(2k)) on each `a_k` and 0.707 on `b`.

    k     base                 lane / trial merge
    10    all 12 SEs NaN       11 of 12 named flat, all NaN (correct)
    60    all 62 SEs NaN       only b named; 60 a_k SE 0.1969 finite
    120   all 122 SEs NaN      only b named; 120 a_k SE 0.2136 finite

At k = 60, `summary()` prints `a_f3 -1.14 0.2 z -5.79 p 7.2e-09`,
`a_f4 1.41 0.2 z 7.14 p 9.2e-13`, and `confint()` has 61 of 62 finite
rows, for coefficients whose value is arbitrary. The conditional SE of
`a_k` given `b` is 0.5 / sqrt(5) = 0.2236; the reported 0.1969 is below
even that, because the projection also removes part of the `a_k`
variance. The warning says "The other standard errors are reported
without these directions", which a reader takes as "the others are
fine".

`dev/nanse-rev-spread2.R`, two crossed factors, `a ~ 0 + f`,
`b ~ 0 + g`, k levels each, 6k rows: every coefficient is unidentified.

    k = 20: base 0 of 40 finite; lane 2 of 40 finite (SE 0.504), 38 named
    k = 60: base 0 of 120 finite; lane 97 of 120 finite (median SE
            0.191), 23 named, the 23 whose loading the unequal cell
            counts pushed past 0.1

On the trial merge, lane fixes' `nl_flat_message()` fires instead (same
0.1 threshold, same 23 names) and the SE warning is silent, so the
merged release shows 97 finite SEs where the release build shows NaN.

The same rule also removes a valid SE. `dev/nanse-rev-grby.R`,
frmtmb.sample's `gr(g, by = f)` fixture: `x` loads 0.10 on a direction
of eigenvalue -1.18 driven by a by-group SD at exp(-6.6). Base reported
SE(x) = 0.1023; lme4 on the same model (dummy-coded per by-level, ML,
singular) gives 0.1009 at a logLik 1.4e-4 higher; the lane reports NaN
for `x`. So the lane's statement that base's finite values on the 15
"more NaN than base" firings were meaningless is false for this one.

Required: a flat (near-null) direction must take the SE of every
parameter it reaches with a non-negligible variance contribution, not
those above a fixed loading. For example, name parameter i when
`v_ik^2 / max(lambda_k, eps * lambda_max)` exceeds a large multiple of
the variance the kept directions give it, or when `|v_ik|` exceeds
something of the order of `sqrt(se_flat_tol)`; keep a loading rule only
for clearly negative directions. Add a test with the k = 60 spread and
the crossed design, seen to fail on the current lane, and keep the
gr-by fixture's `x` finite.

### B2. Predictions along a lost direction get too-narrow variances

`get_joint_cov()` reads `cov_fixed_prop`, the pseudo-inverse with the
lost directions removed, for every prediction on a model without
random effects. That variance is right for a prediction orthogonal to
the lost directions, and finite and too small for any other. Nothing
checks which case applies, and nothing warns at prediction time.

`dev/nanse-rev-pred.R`, k = 10 above, where the lane names all 11
coefficients as lost:

    fitted(dpar = "a") Est.Error   base NaN NaN   lane 0.1818 0.1818
    fitted(dpar = "b") Est.Error   base NaN NaN   lane 0.02989 0.02989
    warnings at prediction time    0 on every arm

Both are non-estimable (true variance infinite). The same holds on the
trial merge. NEWS says "Predictions leave out only the undetermined
directions"; that is the defect, not a property. frmtmb already has the
right pattern: `predict.R` tests each new design row against the frozen
null space `alias_null` of a rank-deficient X and returns NA where the
row is not estimable. Required: keep the basis of the dropped
directions, and give a prediction a NaN standard error (with one
warning) when its gradient has a component along them above a relative
tolerance. On `mo()` the gradient along a saturated coordinate is
exactly 0, so the lane's `conditional_effects()` result on seed 71
survives that rule.

### Blocking

**RB1. The fit-time check is not deterministic, and its deferred
warning can be lost (m2).**

What the projection reads. `fit_assembled()` takes
`t_start <- proc.time()[["elapsed"]]` and passes the elapsed fit time
to `se_check()`. `fd_hessian()` projects its own elapsed time after
each column and gives up when `el * n / i` exceeds
`max(0.3 * t_fit, 0.05)` s. That is wall-clock time on both sides,
plus an absolute 0.05 s floor and a 0.02 s minimum before it projects.

Reproduced with `dev/nanse-rev2-determinism.R` (the same frm() call
repeated; W = SE warning at fit time, D = deferred):

    idle       ridge_re_s1   20 of 20 W
               ridge_re_s11  19 W, 1 D   WWWWDWWWWWWWWWWWWWWW
    30 busy R  ridge_re_s1   18 W, 2 D   WWWWWWWWWWWDWDWWWWWW
    processes  ridge_re_s11  17 W, 3 D   WWDWWWDWWWDWWWWWWWWW

In the test suites:
- The lane's own `test-diagnostics-ux.R`, on the lane build, failed in
  2 of 8 concurrent runs (`dev/nanse-rev2-log/v-dux-lane-*.txt`: one
  run with fail 5 and 2 escaped warnings, one with fail 1 and 1
  escaped warning). On the merge it failed in 1 of 3 reruns and in run
  2 of the full suite (fail 4, warn 1).
- In run 1 of the merged suite, frmtmb.spline `test-difference.R` let
  a deferred SE warning escape from `frm_curve()`. The test allows the
  warning only around `frm()`.
- The lane's own record shows the same instability: 41 against 43
  suite firings, and `test-case-studies.R` was edited "because a
  loaded machine can defer the check".

A deferred warning is lost when the first SE use is fixef().
`fixef.frmtmb_fit()` reads `tryCatch(suppressWarnings(vcov(object)))`.
`se_deferred_report()` fires inside that call, is muffled, and clears
`se_deferred`; it also sets `warned_nonfinite_cov`. So nothing warns
afterwards. `dev/nanse-rev2-deferred.R` forces deferral by making
`fd_hessian()` report "over budget" in that process. On fixes'
`c0 + exp(a)^k` model, which loses 4 of 6 SEs:

    first use summary()   1 SE warning there, then vcov() 0
    first use fixef()     0, then vcov() 0, then summary() 0
    first use vcov(), confint(), VarCorr()   1 each

`dev/nanse-rev2-c0k.R` (lane, 6 repetitions, no instrument): on
repetition 4 the check deferred, and frm() plus fixef() gave no
warning while three coefficient SEs were NaN.

Required:
- Replace the wall-clock budget with a deterministic criterion. One
  option is counted work: build the finite-difference Hessian at fit
  time when its 2 * np gradient evaluations are at most a fixed share
  of the fit's own counted evaluations (nlminb's
  `opt$evaluations`, the other optimizers' counts). Another is a fixed
  parameter count, for example np <= 50, above which the check always
  defers. Either way the same call gives the same warnings on any
  machine.
- Make the deferred report survive internal `suppressWarnings()`:
  call `se_deferred_report()` explicitly before those wrappers, or
  clear `se_deferred` only once the warning has reached the caller.
- Remove the vcov() workaround from `test-case-studies.R` once the
  criterion is deterministic.
