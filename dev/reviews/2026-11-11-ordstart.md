## Findings

### 1. MAJOR: The fit depends on the session's RNG kind

`mixture_starts_draws()` calls `set.seed(20261111L)` without `kind =`,
so the draws come from whatever RNG kind the session has set. A session
with `RNGkind("L'Ecuyer-CMRG")`, which parallel work sets, gets other
jitter and another answer. The help text and NEWS say that "the same
call gives the same fit".

Reproducer: `dev/reviews/ordstart-review-rngkind.R`, log `rngkind.log`.
It fits all 40 seeds of the lane's table under each kind.

```text
draws, default kind: 0.9977 -0.108 0.325 | L'Ecuyer-CMRG: 3.2313 0.4109 0.9587
RNGKIND cum_cum 14 default -389.6804 lecuyer -379.3097 diff 10.3707
RNGKIND cum_cum 10 default -391.5022 lecuyer -394.2865 diff -2.7843
RNGKIND cum_sratio 12 default -371.0583 lecuyer -375.0992 diff -4.0409
RNGKIND cum_sratio 10 default -394.4668 lecuyer -391.4011 diff 3.0656
fits whose logLik differs by RNG kind: 11 of 40
```

The values under L'Ecuyer-CMRG match 0.81.0's own values:
- cum_cum 14 lands at -379.3097, next to 0.81.0's step function
  (-379.3087).
- cum_cum 10 lands at 0.81.0's run-off point (-394.2865).

The lane's two headline moves therefore depend on the RNG kind. Under
another stream, 10 starts give a different answer on 11 of 40 fits. A
fixed seed hides this variance; it does not remove it.

Fix: draw under a fixed kind, for example `set.seed(20261111L, kind =
"Mersenne-Twister", normal.kind = "Inversion")`, and restore the old
kind as well as `.Random.seed`. Add a test that fits under
`RNGkind("L'Ecuyer-CMRG")` and compares with the default kind. Say in
the findings how unstable the pick is across draw sets: 11 of 40 fits
differ by up to 10.4.

### 2. MAJOR: Under autoscale, the starts run twice and the step-start warning is lost

`cold_start <- is.null(start) && is.null(template)` is computed at the
top of `fit_assembled()`. In the autoscale path, the pre-fit is a cold
call to `fit_assembled()` with its warnings muffled, so the starts run
there and their warning is dropped. The main fit receives
`template <- pre$template` only after `cold_start` was set, so it runs
the starts again around the pre-fit's choice.

Reproducer: `dev/reviews/ordstart-review-paths.R autoscale`, log
`autoscale.log`. It uses the 40-fit data with `xs = x * 1e-4`, an sd
below `autoscale_small_sd = 1e-3`:

```text
AUTOSCALE cum_cum  4 | plain ll -388.0955 picks 1 ms set stepw TRUE ... | scaled ll -388.0955 picks 2 ms set stepw FALSE ... | autoscaled TRUE
AUTOSCALE cum_sratio 14 | plain ll -389.4253 picks 1 ms set stepw TRUE ... | scaled ll -389.4253 picks 2 ms set stepw FALSE ... | autoscaled TRUE
```

(The `degen` column in this log also matches the step-start warning's
text, so read only `stepw` there.)

- 15 of 15 autoscaled fits ran the starts twice (`picks 2`). The
  elapsed time was 1.06 to 2.86 s, against 0.44 to 2.31 s unscaled.
- 11 of 11 fits that give `frmtmb_mixture_step_start` unscaled give no
  such warning when autoscaled.
- On cum_cum seed 10 (`ordstart-review-misc.R`, logs `misc-base.log`
  and `misc-lane.log`), the degenerate warning goes away:

  ```text
  base: SEED10 y ~ x + z  ll -394.2865 degen TRUE | y ~ xs + z ll -394.2865 autoscaled TRUE degen TRUE
  lane: SEED10 y ~ x + z  ll -391.5022 degen TRUE | y ~ xs + z ll -391.5022 autoscaled TRUE degen FALSE
  ```

  This is a fit that 0.81.0 warned on in both arms; the lane returns it
  in silence. It is the path dependence of the "collapsed" test that the
  lane filed, made reachable by the flat-tier move.

Fix: run the starts once. One way is `ctl$starts <- 0L` in
`autoscale_prefit()`. Another is to keep them in the pre-fit, pass
`starts = 0` to the main fit, and raise the pre-fit's step-start finding
on the user's call. Add an autoscaled case to `test-mixture-starts.R`.

### 3. MAJOR: Candidates are ranked as maxima without being measured or converged

- `mixture_ord_start_class()` uses `(dg$sharpen > -0.1) %in% TRUE`.
  When doubling a component's latent distances gives a non-finite
  log-likelihood, `mixture_ord_degeneracy()` drops it, and `sharpen` is
  `NA`. The component then counts as "not a step function".
- `mixture_starts()` accepts any run with a finite objective, whatever
  its convergence code.

In three-component fits, every point the lane calls a "flat boundary"
has an unmeasured sharpen and coefficients of 1e3 to 2e4. The lane
prefers these points to measured step functions, even when they are
lower.

Reproducer: `ordstart-review-sweep.R lane sweep` (log `lane-sweep.log`:
every tier-1 candidate of `cum3_K5` is `.../1/-Inf/<max|par|>`, with
max|par| from 740 to 9.5e4) and `dev/reviews/ordstart-review-cum3.R`
(log `cum3.log`):

```text
SEED 1 lane ll -460.5832 code 1 (function evaluation limit reached without convergence (9)) max|par| 1177 | starts=0 ll -455.1767 code 0
  component      reach collapsed sharpen       near     cover weight
1         1 1.798e+308      TRUE      NA 1.798e+308 0.000e+00 0.2923
2         2  5.887e+03     FALSE      NA  2.480e+01 1.000e+00 0.1699
3         3  4.254e+00     FALSE      NA  7.079e-01 1.306e-12 0.5377
SEED 4 lane ll -456.0897 code 0 max|par| 1.054e+04 | starts=0 ll -451.6403 code 1
SEED 6 lane ll -454.2496 code 0 max|par| 2.008e+04 | starts=0 ll -451.4528 code 0
SEED 7 lane ll -448.8986 code 1 (singular convergence (7)) max|par| 2229 | starts=0 ll -453.6446 code 0
```

- On `cum3_K5` seeds 1, 4 and 6, the lane replaced a step function with
  such a point, 5.41, 4.45 and 2.80 lower. The fit still warns as
  degenerate.
- On seed 1, the winning run had stopped at nlminb's evaluation limit.
  The fit gained "Optimizer did not report convergence ... (9)", and
  convergence went from code 0 to code 1 on seeds 1 and 7.
- The step-start warning on these fits says "the fit reports the best
  maximum without one". The point it reports has a slope of -1177, a
  threshold at 1.8e308, and is not a measured maximum.
- 0.81.0 warned on all of these fits, so the brief's rule is not broken.
  The lane's own justification for tier 1 is broken: "flat kinds buy
  almost no likelihood", "the likelihood barely moves". That was
  measured on two-component data only.
- A smaller form of the same gap: a component with weight near zero
  gets `sharpen` near 0 (2.3e-11 at max|par| 22.7 on
  `single_n3000_s8_seed1`, `lane-steep.log`). It is ranked and named as
  a step function. I did not see it change a pick.

Fix:
- Treat an `NA` sharpen as a step function, or as unknown and ranked
  with the steps. Consider `reach` or |par| as a second sign of run-off.
- Rank only runs that converged, or that `check_convergence()` would
  accept at the maximum.
- Rerun the three-component cases, and add one to the tests with every
  valid ending accepted.

### 5. MINOR: The text of `frmtmb_mixture_step_start`

The warning is correct about `logLik()` and the information criteria:
they are those of the point returned, and the "log-likelihood plus log
prior" switch under a prior is right. The problems:

- Grammar: "components 1 and 3 is a step function" (`cum3_K5_seed4`,
  `lane-sweep.tsv`).
- "at most -455.1767 against -460.5832" calls the HIGHEST step-function
  value "at most". It should be "up to" or "the highest at".
- The remedy, "Priors on the components, as brms has them", does not
  name the classes. brms's defaults leave b flat, and the lane found
  that its sampler does not mix there. The degenerate warning names
  `class = "Intercept"` and `"b"` with `dpar = "mu<k>"`; use the same
  words.
- Warning or message: it fired on 10 of the 116 fits that 0.81.0 passed
  in silence (6 of 82 in the sweep, 4 of 34 in the steep set). The
  point returned is a proper maximum. Whether the warning fires depends
  on where the jitter is centered (0 of 11 under autoscale, finding 2)
  and on the RNG kind (finding 1). A classed message is consistent with
  `frmtmb_converged_at_max` and with nlstop's `frmtmb_prior_multistart`.
  The lane already put this question to the user; I recommend a
  message.

### 6. MINOR: The cost where it hurts

optimizers, and the lane shows that all optimizers agree. The vignette

`frm_bootstrap()` and `refit()` warm-start without the starts. The
replicates therefore come from another estimator than the original fit,
which avoids step functions, and they can end at one. Document this

### S3. M3 and Q4: fixed as specified; the "proper" tier has a blind spot (MINOR)

I reran the sweep (`lane-sweep.log`, `cmp-sweep.txt`, 104 cases; the
base arm is unchanged):
- 18 fits moved, 10 up and 8 down;
- of the 82 fits that 0.81.0 passed, 0 lost likelihood and 0 gained the
  degenerate warning;
- convergence went from code 0 to nonzero on 0 fits and from nonzero to
  0 on 5;
- no chosen point had coefficients of 740 or more.

This matches the lane's numbers for these cases.

I profiled the five Q4 replacements (`ordstart-short-profile.R`,
`profile.log`). The profile holds the largest coordinate at t times its
value and re-optimizes the rest. I also looked at the warnings and
thresholds and refitted from each point (`ordstart-short-q4pts.R`,
`q4pts.log`).

**cs_sr_acat seed 4 is not a real interior maximum.**
- The 325.5 is `mu2_Intercept[2]`, the second sratio threshold of
  component 2, not a cs() coefficient. That threshold's cs() slopes are
  `mu2_x[2]` = 161.3 and `mu2_x[3]` = 204.3, all with SE NaN.
- This is a per-threshold near-step in x: the threshold crosses near
  x = 2, where only a few rows lie. Doubling the distances costs 0.305,
  so the -0.1 sharpen cut misses it.
- The smallest Hessian eigenvalues are -3.9e-31, -4.1e-15 and -2.0e-07.
- Component 2 gives one category a probability of at most 1.8e-85.
- With that coordinate held at its own value (t = 1), re-optimizing the
  others gains 0.4638. A refit from the point (`starts = 0`) also gains
  0.4638 and ends at code 1.
- nlminb's code 0 was relative convergence on a flat ridge.
- The fit does warn: "Standard errors are not available for 4 of 15
  parameters", plus the step-start warning.

**The other four:**
- **dpar_formula seed 4:** a threshold that runs off along a flat
  direction. `mu2_Intercept[2]` = -32.45 with SE 4443. The profile is
  flat from t = 0.8 to t = 30, within 7e-8. Cover is 3.2e-8, and at
  t = 0.5 the point is 0.30 higher. Apart from the step-start warning,
  the fit is silent.
- **cs_sr_acat seed 1:** flat. SE NaN on four parameters (SE 8310 on
  the profiled coordinate), and the profile is 1.09 higher at t = 2.
  The fit warns that standard errors are not available.
- **cs_sr_acat seed 3:** a local interior maximum. `mu2_x[2]` = -38.1
  with SE 43.6, and the profile falls on both sides of t = 1. It is
  0.13 higher at t = 2, so it is not the best point along that line.
- **dpar_formula seed 7:** a clean interior maximum. max|par| is 2.15,
  SE 1.13, and the profile falls on both sides.

I checked the same things at the other step-to-proper moves
(`ordstart-short-moves.R`, `moves.log`):
- **Silent apart from the step-start warning, with a finite SE above
  5e3 and a component that gives a category at most about 1e-8:**
  cum_sratio 14 (SE 5.05e3, cover 6.6e-7), cum_sratio 18 (SE 5.2e3,
  cover 9.1e-9) and acat_cumcll_K7 seed 6 (SE 8.19e3, cover 1.2e-8).
- **Clean:** cum_sratio 4 and 15, acat_cumcll_K7 seed 4 and
  theta_formula seed 4.
- **Collapsing category but small natural-scale SE:** cum_cum 14 and 15
  and cum_sratio 9. They have a near-zero eigenvalue (3e-8 to 5e-8) and
  cover of 1e-8 to 1e-7.

In sum, of 15 step-to-proper moves, 6 land on a point with a flat
direction that the step classifier and the fit-end check both call
proper. One of them (cs_sr_acat seed 4) is not a maximum. These fits
are of the same kind that 0.81.0 already passes in silence, the lane's
filed "10 percent of passed fits ... at most 1e-8" item. The brief's
rule is not broken. Each move carries the step-start warning, and two
carry the standard-error warning.

But the warning says "the fit reports the best maximum without one",
which is not true for cs_sr_acat seed 4. Part of the drop in the
degenerate warning (12 to 5 on the 40 fits; cum_sratio 14 and 18) is
the check's blind spot rather than a proper answer.

Recommendations:
- Reword the warning to "the best converged point without one".
- Extend the lane's filed backlog item with these six cases. The
  candidate fix to measure is to rank a candidate as proper only when
  its exact outer Hessian has no eigenvalue below a relative floor, or
  when its smallest category cover is above 1e-8. Otherwise rank it as
  a flat boundary. This changes only which points are called proper,
