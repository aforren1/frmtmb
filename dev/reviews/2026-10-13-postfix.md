### Verdict: MERGEABLE AFTER FIXES (3 remaining issues)

1. **The acceptance rule passes regular local maxima, and it does so
   with no warning.** `dev/postfix-rev2-nlnew.R` runs a stress block
   on `y ~ A * sin(2 pi x / P)`, gaussian, x = 0 to 15 (120 points),
   A = 2, sd 0.6. It uses P in {1.3, 3, 4, 7, 9} and seeds 1001 to
   1006, which gives 30 data sets. Each one fails at the default start.
   The best fit of each comes from the hand start plus 12 random
   starts.

   ```text
   rellib-r8:  error 30
   lane:       error 4   rescued 4   WRONG-PASSED 22
   ```

   "WRONG-PASSED" means the fit came back with convergence 0, every
   fixef SE finite and 0 warnings, but 93 to 118 log-likelihood units
   below the best fit. `dev/postfix-rev2-sinus.R` shows these fits:

   ```text
   P 3.0 seed 1001: A 0.204 (SE 0.196), P 19.78 (SE 4.61), logLik -220.19 vs -119.31
   P 7.0 seed 1002: A -0.394 (SE 0.190), P 10.82 (SE 0.687), logLik -219.90 vs -101.82
   P 1.3 seed 1001: A 0.143 (SE 0.213), P 1.010 (SE 0.016), logLik -230.15 vs -117.79
   ```

   Each fit is a slow or aliased sinusoid that explains almost
   nothing. The residual sd is 1.52 at the fit, against sd(y) 1.53 for
   P 3, seed 1001. In each of these cases the message says "The fit
   converged with every standard error", which reads as assurance.
   Messages are not warnings, so `warnings()`, tests and
   `allow_warnings()` do not see them. A local test (convergence code,
   Hessian rank) cannot tell a local maximum from the global one. So
   the rule does not do what its NEWS bullet implies.

   Fix, minimum: when a fit restarts from the scan, give a
   `frm_warning()`, not a message, naming the scan's point. Do not say
   "every standard error". Safer: never return a fit from the scan.
   Keep 0.70.0's error, and name the scan's point there. The six new
   models below, which are rescued correctly, would then need `start`,
   as they did on 0.70.0.

2. **The "candidate to try" is the point whose fit was just refused.**
   `dev/postfix-rev2-cand.R` takes the start named in the error and
   passes it back, with the same seeds as round 1:

   ```text
   M2 Michaelis-Menten  conv 1, warning, logLik -279.852688, gap -79.92
   M4 a exp(-x / tau)   conv 1, warning, logLik -1442.568574, gap -181.82
   M7 sinusoid          conv 0, SE warning, logLik -265.375135, gap -176.42
   M9 ridge             conv 0, not-identified warning, gap 3.3e-12 (the ridge itself)
   ```

   These are the round-1 wrong fits to every digit. The candidate
   reproduces exactly the fit the package refused, and now the fit
   comes back because the start is the user's. Fix: do not offer the
   point as a candidate. Say that it is where the refused fit started,
   and point to `par_template()` and a located prior. Also, the
   non-convergence warning on such a refit still says "unless `start`
   or a located prior placed them, the fit began at zero". That is
   true here only as a conditional.

3. **The pooled category probabilities of `fitted()` no longer sum to
   one.** `dev/postfix-rev2-rubin.R` uses a cumulative model with 3
   imputations at x = -3, 0, 3. The `Estimate` probabilities sum to
   0.99669 to 0.99983. On the response scale they summed to 1 exactly,
   as one fit's do and as brms's do. This is the price of pooling each
   category on its own logit scale. The lane says the pooled
   `conditional_effects()` does the same. Fix: renormalize the pooled
   estimates, or pool the category estimates on the response scale and
   keep the logit scale only for the interval ends.

## Round 1

Reviewer of `frmtmb-wt-postfix` (base d2ef6312, frmtmb 0.70.0). Lane
library `wt-postfix-lib` read, never written; base `rellib-r8`; brms
2.23.0 from the user library. Scripts `dev/postfix-rev-*.R`, logs
`dev/postfix-rev-log/` (local). Every number below is pasted from those
logs.

### Verdict (round 1): MERGEABLE AFTER FIXES

1. **`nl_intercept_scan()` turns a clear error into a wrong fit on half
   of the new cases.** `dev/postfix-rev-nlscan.R` (seeds 101 to 109,
   and `dev/postfix-rev-nlscan7.R`), six models outside the lane's six
   that fail at the default start on 0.70.0. Each one fails with "The
   nonlinear fit failed from its default starting values (NA/NaN
   gradient evaluation)" on rellib-r8. On the lane build, compared with
   the best of a hand start and a 10 to 20 point multistart:

   ```text
   model                                         scan start            result                 default - best
   M1 poisson(identity) a exp(b x), b = -0.5     a 10, b -0.2          conv 0                 -2.8e-13
   M2 Gamma(identity) Michaelis-Menten           Vm -5000, K -5        conv 1 (singular)      -79.92
   M4 Gamma(identity) a exp(-x/tau), a = 2e5     a 5000, tau -200      conv 1 (singular)      -181.82
   M7 gaussian A sin(2 pi x / P), P = 2.5        A -0.2, P 50          conv 0, SE warning     -176.42
   M8 Gamma(identity) a ~ 1 + (1 | g)            a 5, b 2              conv 0                 -3.6e-12
   M9 Gamma(identity), six intercepts (ridge)    (2,2,2,-0.2,1,1)      conv 0, flat warning   +3.3e-12
   ```

   M7 is the worst kind. It reports convergence (code 0) at A =
   -47803, P = 1.0e7, which is a straight line through the data. Only
   the standard-error warning flags it. The lane found the same failure
   on its own model 7 ("stopped 100.73 log-likelihood units below the
   maximum, converged, with only a standard-error warning") and then
   tuned the grid until that model passed. So the rule is fitted to its
   test set; the NEWS claim of a general restart is not supported. The
   coordinate passes also move intercepts to the wrong sign (M2, M4),
   where the body is finite but the region is wrong. Fix: accept a
   restart from the scan only when it converges (code 0) AND the SE
   check passes without a flat direction. In all other cases, keep
   0.70.0's error and add the scan's point to it as a candidate
   `start`. Pin M2 and M7 in `test-nl.R` as cases that must stay
   errors. Also, after a scan, the non-convergence warning (R/fit.R
   about line 4276) still says "unless `start` or a located prior
   placed them, the fit began at zero". That is false after a scan;
   change the text when `nl_scan` is set.

2. **The scan is computed before any earlier recovery start is tried,
   and it changes fits that the earlier starts rescue.**
   `fit_recovery_starts()` builds `nl_scan` eagerly, and each
   `obj$fn()` call moves the tape's `last.par.best`. TMB starts the
   inner problem from there. `dev/postfix-rev-flat.R` uses a Gamma
   nonlinear model with `(1 | g)` and a located prior. Its first
   attempt fails, and "the placed intercepts with the nonlinear slopes
   at zero" rescues it on both builds. Four fresh processes per build
   gave the same result:

   ```text
   rellib-r8  par 4.8800347713965602 0.3415737626993442 ... 2.2853221669448156 -1.3023835890559512   done [1.17s]
   lane       par 4.8800347713965584 0.34157376269934436 ... 2.2853221669448192 -1.3023835890559503  done [3.39s]
   ```

   The ulps move is harmless. The cost is not: 86 Laplace evaluations
   that are never used make the fit about 2.9 times slower. On M8 the
   scan takes 2.25 s of a 2.45 s fit, against 0.13 s from the hand
   start. Fix: compute the scan lazily, only after the earlier starts
   have failed. Its cost is 12 + 74K objective evaluations for K
   scanned intercepts (160 at K = 2, 456 at K = 6, counted by tracing
   `obj$fn`). That bound is acceptable once the scan is lazy.

3. **`frm_sample(frm_multiple)` prints R-hat and ESS across
   imputations with no warning, and uses an `r_eff` that brms does not
   use.** `dev/postfix-rev-sampleC.R` uses 3 imputations that differ on
   purpose, 2 chains each, seed 7. `summary()` gives Rhat 1.88, 1.80
   and 1.45 and Bulk_ESS 8.6 to 11.9, with 0 warnings. brms 2.23.0's
   `summary.brmsfit()` drops Rhat, Bulk_ESS and Tail_ESS for a
   `brmsfit_multiple` (`R/summary.R` line 109). Its
   `r_eff_log_lik.matrix()` returns 1 for such a fit (`R/loo.R` line
   770) "due to stacking of chains from multiple models". The lane
   computes `r_eff` from the stacked chains: range 0.0024 to 0.77,
   elpd_loo -130.66, against -129.53 with `r_eff = 1`. The Rd says what
   an R-hat across imputations means, but a printed 1.88 that comes
   with no warning reads as a failed sampler. Fix: when
   `out$nimp > 1`, drop the three columns from `summary()` and use
   `r_eff = 1` in `loo()`, as brms does. `out$nimp` is set but no code
   reads it.

4. **`fitted()` and `conditional_effects()` of one pooled fit give
   different bands for the same rows.** `fitted()` pools on the
   response scale, and `conditional_effects()` pools on the link scale
   and transforms back. `dev/postfix-rev-rubin.R` section 2 uses a
   bernoulli model, n 40, 10 x values missing, mice m = 5, seed 44. At
   x = -1.906:

   ```text
   fitted(fm, newdata)      Estimate 0.0929  Q2.5 -0.1668  Q97.5 0.3526
   conditional_effects(fm)  estimate 0.0833  lower 0.0040  upper 0.6741
   ```

   The poisson mixed model in section 1 gives a pooled `Q2.5 < 0` for a
   mean, and its lower bound differs from the curve's by 17 percent of
   the value. One fit's own `fitted()` has the same out-of-range Wald
   interval (Q2.5 -0.13 on imputation 1). That behavior is older than
   this lane, but the lane chose to pool on that scale. Each Rd states
   its own scale, so this is documented, not hidden. Fix, minimal: in
   both Rd entries, say that the two bands differ and why. Better:
   for `scale = "response"`, pool `fitted()` on the link scale as the
   curves do, so that the bounds stay inside the family's support.

### Attacks that found nothing wrong

- **Rubin's rules by hand** (`postfix-rev-rubin.R` section 1: poisson
  `(1 | g)`, n 200, 15 groups, mice m = 5, seed 42). These differences
  are 0: `vcov()` against the mean W plus (1 + 1/m) B; `fitted()`
  Estimate, Est.Error and Q2.5 (t on the Barnard-Rubin df) against the
  values by hand, row by row; `ranef()` mode and condSD; `VarCorr()` sd
  against exp(mean log sd) and its delta-method Est.Error. `coef()`
  differs by 2.0e-16. The pooled df (191.44, 26.02, 193.11) is the
  Barnard-Rubin formula by hand at dfcom 196. These are identities that
  check the code against its own documentation, not a check against
  another package. The lane's mice comparison is that check, and I did
  not repeat it. `coef()` and `ranef()` of a frmtmb fit are lme4-style
  data frames, so averaging every entry is Rubin's point estimate. It
  does not average any Est.Error column. Log-sd and Fisher-z pooling is
  the usual choice, and the Rd states it.
- **Small-sample df** (section 3, gaussian, n 15). The df is 10.02
  against `mice::pool(lm)`'s 11.01, because frmtmb's dfcom is
  `n - p - 1` = 12 (sigma counted) and mice's is 13. This comes from
  0.68.0, not from this lane. It is a defensible ML choice, but it is
  not mice's.
- **Refusals, guard-absent cases** (`postfix-rev-refuse.R`, both
  builds). `summary(waic = FALSE)` and `frm(threshold = NULL)` are
  accepted. `waic = NA` and `waic = "no"` get `check_flag`'s refusal.

  refused by `check_count`. A positional `ndraws` lands in the right
  slot.
- **"Coefficients differ" refusal.** A factor level that is empty in
  imputation 2 (the level kept, no rows) is refused with "(fc)",
  because `frm()` drops the empty column (fixef rows Intercept, x, fb).
  brms 2.23.0 also drops unused levels by default (`data-helpers.R`
  line 15), so its imputations would also differ in parameters.
  `brm_multiple()` was not run on this case. A group level empty in one
  imputation still pools `fixef()`, `vcov()`, `VarCorr()` and
  `fitted(newdata)`. `ranef()` refuses it by name. Both are correct.

  `newdata`, and `kfold()` is not implemented. So an answer is not

- **`conditional_effects(method = "predict")` on draws against brms
  2.23.0** (`postfix-rev-brms.R` and `postfix-rev-sample.R`, the same
