### 2. minor: the `-Inf` limit is acceptable; `waic()` should stop as `loo()` and `psis()` do

The question was whether a common fit reaches the cell under
`frm_sample()`. I sampled GEV fits where the sampler reads the fitted
objective and its barrier (`dev/review-rel081-gevxi.R`, `.sh`, `2.sh`; 4
chains x 1000, seeds 1 to 3):

| model | xi | n | runs | draws | `-Inf` cells |
|---|---|---|---|---|---|
| `bf(y ~ 1, xi ~ x)` | -0.3 + 0.2x, 0.2 + 0.2x | 100 | 6 | 12000 | 0 |
| `bf(y ~ 1, xi ~ x)` | -0.6 + 0.2x | 30 | 1 | 2000 | 0 |
| `bf(y ~ 1, xi ~ 1)` | -0.3, 0.2 | 100 | 6 | 12000 | 0 |
| `bf(y ~ 1, xi ~ 1)` | -0.6 | 30 | 3 | 6000 | 0 |
| `y \| cens(cc) ~ 1`, lowest fifth left-censored (blocked chart) | -0.3, -0.6 | 100, 30 | 6 | 12000 | 0 |
| scalar `xi` (`tmp_xi` chart), control | -0.3, 0.2 | 100 | 6 | 12000 | 0 |

`loo()`, `psis()` and `waic()` ran in all 28. Many of the predicted-xi runs
had divergent transitions (38 to 1367), which is the barrier acting as a
wall, but no kept draw lay outside. The barrier probe
(`dev/review-rel081-barrier.R`, output `-barrier.txt`) explains why: just
outside the support the objective is continuous with the inside (at
`xi = -0.9`: -3.84 at t = 0, -3.94 at t = -1e-9, -103.8 at t = -1e-6), so a
draw outside must land in a band of width about 1e-8 in t, which holds no
measurable posterior mass. brms's sampler rejects such a draw outright.
So the cell is reachable by a hand-built draws object only, and 0.80.0
gave a finite, wrong answer there (the barrier). Not a blocker.

`waic()`, though, returns `elpd_waic = NaN` with no error
(`dev/rel081-log/loo-inf.txt`: "loo::waic.matrix(log_lik): ok; elpd_waic
NaN; pointwise non-finite rows 28"). That is a silent non-answer next to
two functions that stop, and brms 2.23.0 stops in all three (its `NaN`
fails `validate_ll()`'s `anyNA()`). An elpd of `NaN` in a `loo_compare()`
table is easy to miss.

Recommendation: stop in `waic()` (and in `loo()` / `psis()` before the loo
package does), in one place in frmtmb.sample's criterion code, with a
classed error that names the rows and draws and the cause, for example
"log_lik() is -Inf at 62 cells (rows 21, ...; draws 1, 2, 3): those draws
put the rows outside the support of gen_extreme_value(), and a
leave-one-out or WAIC estimate does not exist there". It matches brms on
the outcome (all three stop) and gives a better message than loo's. Then
the NEWS limit bullet and the backlog item say "stop" for all three.

### 2. `loo_check_finite()`: right on every path but one

`dev/review-rel081-fix3-paths.R` (output `-fix3-paths.txt`) runs the test's draws (62
cells `-Inf`) through every criterion entry point:

- **class `frmtmb_loglik_not_finite`, with the counts:** `loo()`, `waic()`, `psis()`,
  `psis(r_eff = 1)`, `loo(mv, ds)`, `loo_compare(mv, ds)`, `loo_model_weights(mv, ds)`,
  `add_criterion(mv, "loo")` and `"waic"`, `loo_predict()`, `loo_linpred()`,
  `loo_epred()`, `loo_R2()`.
- **refused as not implemented (`frmtmb_sample_error`), before any matrix:**
  `loo_moment_match()`, `kfold()` (and `reloo()` and `loo_subsample()` by the same
  code).
- **a matrix the user passes to the loo package himself:** `loo::waic(log_lik(mv))`
  answers. That is the loo package's own behavior; frmtmb.sample is not in that path.
- **the bypass:** `pp_check(mv, type = "loo_pit_overlay")`, `"loo_intervals"` and
  `"loo_pit_qq"` stop with the loo package's unclassed "All input values must be finite
  or -Inf". `draws_ppc_psis()` (`R/methods-draws.R:1792`) calls `log_lik()` directly,
  not `loo_matrix()`. It still stops, so no answer is wrong. But the new NEWS bullet
  ("The `loo_*()` functions and the `loo_*` types of `pp_check()` stop in the same
  way") and the help section of `?sample-loo` both say otherwise, and so does the
  record's table.

Fix: in `draws_ppc_psis()`, after the `tryCatch()` that builds `ll`, add
`loo_check_finite(ll, paste0("pp_check(type = '", type, "')"))`. Then add one
`expect_error(pp_check(cs$moved, type = "loo_pit_overlay"), class =
"frmtmb_loglik_not_finite")` to the second new test. Short check:
`test-loo-newdata-fitted.R` and `test-ppcheck-loo.R`, plain and gated, and roxygen
(no Rd changes). The other route is to take `pp_check()` out of the NEWS bullet, the
help section and the record. I prefer the fix, because then all three stop the same
way.

Wrong firing: the guard fires only on a cell that is not finite. Before the change
such a cell already stopped `loo()` and `psis()` (`+Inf` in the ratios, or `NaN`),
so only `waic()` behavior changes. `waic()` used to give `NaN`, which is no answer, so
no finite case is newly refused. The cases the question names:
- A weight-0 row with a `-Inf` density: `0 * -Inf` is `NaN` and stops. brms gives
  `NaN` there too.
- A discrete observation of probability 0 in a draw, for example a binomial at `p` = 1
  in doubles: `-Inf`, and brms's `waic()` would give `NaN` where frmtmb now stops. The
  message's wording "outside the support" is still literally true there. Both are
  stops on a matrix that has no estimate, so they are acceptable.

The 87-file sample suites (4047 plain, 4414 gated) show that no existing test fed a
non-finite cell to a criterion.
