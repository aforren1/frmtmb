## 1. Findings, ranked

### MAJOR 1. D4's "it costs nothing" is false as soon as a fit is saved

`dev/adefects-rev-share.R`, `dev/adefects-rev-share2.R`,
`dev/adefects-rev-d4.R`.

R's serializer does not deduplicate a shared ordinary SEXP. The control,
which needs no address reading:

| object | raw bytes | `object.size` |
|---|---|---|
| `list(x = mf)` | 320,223 | 321,128 |
| `list(x = mf, y = mf)`, SHARED | 640,352 | 642,048 |
| `list(x = mf, y = <equal copy>)` | 640,352 | 642,048 |

`mf` is 20,000 x 2. The shared list and the copy cost exactly the same,
both +320,129 over one frame. After `readRDS` the two elements sit at
different addresses (`@0x...232f48` and `@0x...233048`) and mutating one
leaves the other at its old value.

On a real fit, `y ~ x + (1 | g)`, seed 20260917,
`dev/adefects-rev-d4.R`:

| n | base raw | lane raw | delta | base gz | lane gz | delta |
|---|---|---|---|---|---|---|
| 40 | 3,621,538 | 3,623,309 | +1,771 | 311,033 | 312,028 | +995 |
| 20,000 | 7,214,338 | 7,615,309 | +400,971 | 2,138,594 | 2,448,511 | +309,917 |

+5.6% raw and +14.5% compressed at n = 20,000, and 400,971 bytes is one
copy of that 20,000 x 3 model frame. Sharing survives `update()` and
`frm_multiple()` in memory; it does not survive `saveRDS`/`readRDS`,
`save()`/`load()`, or a fit inside a saved list. All three measured
FALSE on addresses and TRUE on `identical()`.

The assertion that is supposed to pin the claim,
`tests/testthat/test-adefects.R:133`, is
`expect_identical(fa$data, fa$frame[["data_frame"]])`, which is value
equality and passes on a copy. Nothing pins the sharing.

Ask: correct `dev/adefects-findings.md` D4, `NEWS.md` ("so it costs no
memory") and the `R/fit.R` roxygen, with the on-disk number. If zero
cost is actually wanted, store the frame once: drop
`frame[["data_frame"]]` and have `model.frame()` read `fit$data`.

### MINOR 1. `fit$data` is `model.frame()`, not brms's `data` element

`dev/adefects-rev-d4b.R`. brms's `brmsfit_example1$data` is the
validated raw data, `count, Trt, Age, volume, visit, Exp, patient`,

not what brms keeps. The chosen object is the defensible one, because it
is the one that is already stored; the doc claim needs qualifying rather
than the code changing. `brmsfit-methods:675`, which passes

### MINOR 2. D7 makes `log_lik`'s fallback table load-order dependent

`dev/adefects-rev-d7.sh`, `dev/adefects-rev-log/d7-lane.txt` and
`d7-base.txt`, 26 scenarios per arm.

`S3method(log_lik, frmtmb_draws)` in frmtmb.sample now resolves through
frmtmb's ACTIVE binding at registration time, so with rstantools loaded
the method lands in rstantools' table and frmtmb's fallback table never

14 probed generics (`loo`, `waic`, `bayes_R2`, `as_draws_df`,
`variables`, `ndraws`) ALREADY behave this way on the base build, so the
change makes `log_lik` consistent with the majority rather than opening
a new class. The failure is loud and needs an explicit
`unloadNamespace()`. In the 22 realistic scenarios the draws method
dispatches.
