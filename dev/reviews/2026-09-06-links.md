# Findings, ranked

## H1. `conditional_effects()` on the newly enabled `1/mu^2` link returns a NaN, inverted band

`R/links.R:227-232` (the new link). Root cause is in the band
construction, not in `links.R`.

`1/mu^2` is `stats::inverse.gaussian()`'s DEFAULT link and was not in the
registry before this diff: main's `frmtmb_links` has exactly eight
entries and no `1/mu^2`, so `frm(y ~ x, family = stats::inverse.gaussian())`
previously died in `get_link()` with "Unknown link". This lane makes that
call fit for the first time, and its `conditional_effects()` band comes
back broken.

Reproduction:

    library(frmtmb)
    set.seed(11); n <- 400; x <- rnorm(n)
    d <- data.frame(x = x)
    mig <- 1 / sqrt(pmax(0.5 + 0.2 * x, 0.05))
    d$yig <- rgamma(n, shape = 20, rate = 20 / mig)
    f <- frm(yig ~ x, data = d, family = inverse.gaussian(link = "1/mu^2"))
    z <- conditional_effects(f)[[1]]
    sum(z$lower__ > z$upper__)                       # 99 of 100 rows
    sum(!is.finite(z$lower__) | !is.finite(z$upper__))  # 1 row NaN
    head(data.frame(z$estimate__, z$lower__, z$upper__), 2)
    #   estimate__  lower__  upper__
    # 1   9.069503      NaN 5.658388
    # 2   6.612201 15.34118 4.909077

Two separate defects meet here:

1. **Inversion.** The band is built on the linear-predictor scale and
   pushed through `linkinv` without reordering the endpoints. `1/mu^2`'s
   `linkinv` is `1/sqrt(eta)`, which DECREASES in eta, so `lower__` and
   `upper__` come out swapped. This part is pre-existing and not the
   lane's: `Gamma(link = "inverse")` and
   `inverse.gaussian(link = "inverse")` invert on 100 of 100 rows with
   `R/families.R` and the band code byte-identical to main. Controls
   (`log`, and the lane's new `sqrt`) are clean at 0 of 100.
2. **NaN.** `1/sqrt(eta)` is undefined for eta < 0, so once the band's
   lower endpoint crosses zero the result is NaN, not merely misordered.
   The pre-existing `inverse` link (`1/eta`) only goes negative, so this
   failure mode is new with `1/mu^2`.

The lane's report to me says it checked "conditional_effects() with a
band" for each new link. Its test does check bands, but only for the
four (0, 1) links, where it asserts `all(ce$lower__ > 0 & ce$upper__ < 1)`.
There is no band assertion for `1/mu^2`, `sqrt`, `softplus` or
`squareplus`, and the one link that fails is the unchecked one.

The band fix belongs to whoever owns the prediction and plotting code,
not to a links lane. What this lane owes is to stop claiming the check,
add the row to its own tests, and record the defect so a user does not
find it first.

## M3. `probit_approx` is not an inverse pair, by design, and the start-value path pays for it

`R/links.R:88` sets `linkfun = RTMB::qnorm` while `R/links.R:89-91` sets
`linkinv` to the Phi_approx cubic. The round trip
`linkfun(linkinv(eta)) - eta` is 6.5e-02 relative, against <= 6e-12 for
every other link in the registry. `init_dpars` reaches the link through
`linkfun`, so a probit_approx fit starts from a point the inverse link
does not map back to.

This mirrors brms exactly (`brms:::link` is `qnorm` for probit_approx
too) and the lane documents it at `R/links.R:80-85` and in the vignette.
Not a defect, and the fits converge. Flagging it only because it is the
one place in the registry where the pair is deliberately inconsistent and
a future reader will trip on it.

## M4. Non-`mu` dpar links are unreachable, so part of the brief could not be tested

The brief asked for "a dpar other than mu (sigma with softplus, shape
with squareplus)". Core has no `link_shape` / `link_sigma` argument;
every family hard-codes `shape`, `phi` and `sigma` to `log` in its
`links` list, and `frmtmb_family()` takes link objects only for the dpars
the family chooses to expose. `Gamma(link = "log")` with
`bf(y ~ x, shape ~ x)` fits, but the shape's LINK is not settable. So the
new positive-mean links reach `mu` only. Pre-existing, out of this
lane's scope, and worth noting as the next seam after the ordinal one.

## One residual, low severity

**The direction test is global, so a non-monotone link can still invert.**
`ce_band_ends()` decides the swap with `all(dm[fin] < 0)` over the whole
vector. That is right for `inverse` and `1/mu^2`, which are monotone. It
is not right for `sqrt`, whose `mu_eta` is `2 * eta` and changes sign.
Called directly with a mixed-sign `dm`:

    lo    hi    dm   lower  upper  inverted
    -2.2  -1.8  -4   4.84   3.24   TRUE
    -1.2  -0.8  -2   1.44   0.64   TRUE
    -0.3   0.3   0     NA     NA   FALSE   (pole test catches this one)
     0.8   1.2   2   0.64   1.44   FALSE
     1.8   2.2   4   3.24   4.84   FALSE

The two rows whose band sits entirely left of zero come back inverted,
because rows to the right of zero make the global test false. Feed the
same two rows alone and the swap fires and they are correct.

I could not reach this through `frm()`. Twelve seeded `poisson(sqrt)`
fits on data generated with `mu = (0.1 + 0.9x)^2` over x in [-3, 3], a
setup designed to put the fitted linear predictor across zero, produced
**zero** CE grid rows at eta < 0: the sqrt likelihood depends only on
`eta^2` and the optimizer lands on the all-positive branch every time.
Rows that straddle zero are caught by the pole test and returned NA.

So this is a latent hazard in the helper rather than a live defect, and
it is strictly narrower than the bug that was fixed. Recording it rather
than blocking on it. A per-row `ifelse(dm < 0, ...)` swap instead of the
global `all()` would close it in one line, and the four helper-case test
already has the scaffolding to assert it.
