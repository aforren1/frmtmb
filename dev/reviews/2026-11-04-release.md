# Release review: frmtmb 0.79.0 and frmtmb.sample 0.26.0, 2026-11-04

Adversarial review of the consolidation in `frmtmb-wt-rel079` (branch
`wt-rel079` at `d5d0056d`, uncommitted) and of the release library
`rellib-r17`. The record is `dev/round-20261104.md`. Everything below was
measured on this machine during the review, on `rellib-r17` unless a line
says otherwise. Scripts and logs are in `dev/review-rel079-x-run/` (fits),
`dev/review-rel079-s-run/` (survey, performance), `dev/review-rel079-m-run/`
(merge, commit script) and `dev/review-rel079-v-run/` (numbers, logs, floors,
and my replication of the majors). All four are gitignored by `*-run/`. Seeds
are in the scripts.

## Verdict: FIX

Three majors give wrong numbers with no sign. All three are on new rows of a
latent residual, and all three are in code that the seven lanes could not see
together. I replicated each one on new seeds with a separate script
(`dev/review-rel079-v-run/repl.R`, seeds 9101 to 9103). Fixes for all three
exist and are built in `rev-rel079-x-lib`. With the fixes in, 8 core test files
pass and the same script reads the reference values (`repl2.R`, `repl2.txt`).

There is no blocker in the merge, the survey, the floors of the code, the
commit script or the performance. The headline 89.0 is real and it measures
the release build. No route is slower than the record states.

After the fixes: rerun the core suite and frmtmb.sample's, OpenBLAS on the
changed files, `R CMD check` on core and latent, and the dry run. A short check
of the fixes is enough. The survey does not need a rerun for the code fixes,
since it reads `frm()`, `logLik` and gradients, not these `fitted()` routes.
