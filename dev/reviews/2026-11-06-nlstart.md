## BLOCKER 1. A coefficient with a prior gets a unit read from the likelihood alone, and the fit is worse than 0.79.1

`dev/review-nlstart-prior.R`, both arms, seeds 6201 to 6203, summary
`dev/review-nlstart-priorsum.R` (`priorsum.txt`). Body `a * xs` with `xs = x * s`, a
`normal(0, sd)` prior on `a`, n = 200:

- 63 rows. On 15 the lane is lower than 0.79.1, by 5.7e-6 to 9.1e-4. Each is at
  convergence code 1 with a `frmtmb_warning`. 0.79.1 is at code 0 with no warning on
  all 15. None is higher by more than 1e-6.
- All 15 have s = 1e-8 or 1e-20: s = 1e-8 with sd 1e-3 and 1, and s = 1e-20 with sd
  1e-3, 1 and 1e3.
- Seed 6201 with `normal(0, 1e-3)` at s = 1e-20 is the case the brief asked for
  (`review-nlstart-units.R`, `units-*.log`). The lane stops after 1 iteration at code
  1: -298.07060590, sigma 0.10284669, `a` = 0, units 1.476e20. 0.79.1 and the linear
  spelling `y ~ 0 + xs` with the same prior both reach -298.07016213 at sigma 0.10135636.
  A start at the linear spelling's sigma reaches it too.

Cause: `nl_par_units()` sets the unit of `a` to sd(y) / rms(dbody/da), about 1.5e20.
This is right for the likelihood. But the prior's curvature 1/sd^2, multiplied by
unit^2, dominates the optimizer's coordinates by about 1e40. `a + b * x` at y about 1e6
with priors (the `apbx` rows) is never worse.

The prior is still read on the natural scale. The unit only rescales the steps. A
located `normal(5e19, 1e19)` reaches the exact MAP to 1.2e-7 relative. 0.79.1 reaches
it only to 6.6e-3, with an SE of NaN.

The rows are small and loud, but every one is worse than base. Fix: in
`nl_par_units()`, take the prior's precision into the scale. For example, take
`u = 1 / sqrt(r^2 / resp_u^2 + 1 / sd_prior^2)` for a coefficient with a normal or
student_t prior, or give no unit to a coefficient whose prior sd is below
`resp_u / r`. Test: this row reaches the linear spelling's logLik at code 0. Today
`test-nl-start.R` has no prior.
