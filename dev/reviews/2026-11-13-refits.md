## FIX items

### F1. 1687: `refit()` reads the number 1 two ways on a fit coded 1/2

`R/sugar.R:314-333` (`refit_bernoulli_codes()`) reads a vector as codes
when every value is 0 or 1, and as values otherwise. On a fit whose
response is {1, 2} (1 = failure), the number 1 is a success in one
vector and a failure in the next. frmtmb's own newdata readers
(`response_codes_newdata()`: `residuals(newdata =)`, `pp_check()`,
`bayes_R2()`, `log_lik()` in frmtmb.sample) read values only. brms
2.23.0 also reads a fitted model's new response values only, against
the stored `resp_levels` (`data-response.R:86-100`).

Reproducer (`refits-review-probe5.R`, seed 9, n = 40, `y = s + 1`):

```
residuals(f12, newdata y = 1) reads 1 as:         failure (value)
refit(f12, rep(1, n)) reads 1 as:                 success (code)
refit(f12, c(2, 1, 1, ...)) reads the 1s as:      failure (value)
```

Expected: one reading of 1 for a given fit. Actual: the reading
depends on the other entries of the vector. The ambiguous set is
every number in {0, 1} that is one of the fit's values with another
code: {1, 2} and {1, 5} (1), {-1, 0} (0). {0, 1}, logical, factor,
{-1, 1} and {0, 2} have no ambiguity (`refits-review-bern.R`: refit,
`update(newdata =)`, `influence()` and the bootstrap all agree there).

Recommended rule:

1. A newresp that holds only the fit's two values is read as values
   (as `residuals(newdata =)` and brms read it).
2. Otherwise, a newresp that holds only 0 and 1 is read as codes.
3. Otherwise, refuse (already done for a mix and for a third value).
4. Refuse the vector that 1 and 2 both accept with different readings
   (all entries in the ambiguous set): it is always constant, so it is
   rare, and the message names both readings.
5. `frm_bootstrap()` (`boot_refits()`, `R/bootstrap.R:110`) must not go
   through the guess: map each draw to the fit's values first
   (`lv[code + 1]`) or pass a marker that says "codes".

Does the bootstrap break under it? Under rules 1 to 4 alone, yes: an
all-1 draw of a {1, 2} fit (13 of 40 draws in `refits-review-bern.R`,
seed 5, 11 of 12 successes) would be read as values, or refused. With
rule 5 it does not: the draws never reach the user-facing reading. The
lane's current rule gives `identical()` bootstrap tables for 0/1 and
1/2 codings (`max|diff| = 0`); rule 5 keeps that. A user's own loop,
`refit(fit, simulate(fit)[[1]])`, would get the rule-4 refusal on a
constant draw; the alternative is that `simulate()` marks its codes.
This is the lane's question 2; recommend the rule above.

Tests: `test-refit-plumbing.R` and `test-bernoulli-coding.R` pin only
the {-2, -1} and factor codings, where no number is ambiguous. Add a
{1, 2} test of rules 1 to 5.

### F2. 3430: a workspace object of length n replaces the data's cluster

`R/sandwich.R:59` evaluates `~ cl` in the model frame with the
formula's environment as enclosure. When `cl` is not a model variable
but the workspace has a `cl` of length n, that object is used and the
data's `cl` is never read. Pre-existing (identical on rellib-r21), but
it is the path this item hardened and the brief requires "never silent
mismatch".

Reproducer (`refits-review-probe2.R`, V10, seed 1, 120 rows, data
`dd` with `cl`, plus a global `cl <- factor(rep(1:2, length.out = 120))`):

```
vcov_cluster(fit, ~ cl) SEs:   0.0162685 0.0645226 0.0215026
expected (dd$cl):              0.3053286 0.1815976 0.1108744
```

Expected: the data's column first, as `sandwich::vcovCL()` reads it
(`expand.model.frame()`: data, then the formula's environment). Fix:
take `v` from the frame only when `all.vars(ex)` are frame columns;
else go to the checked call data (`refit_data_matches()` path); fall
back to the formula environment only when the data lack the variable.

### F3. NEWS: BREAKING marks

The findings report "two BREAKING behavior changes of `update()`";
`NEWS.md` has one `BREAKING:` bullet in the new section. Mark also:

- `update(fit, ~ . - x)`: `getCall()` and the evaluated call change
  form (a plain formula or `frmtmb::bf()` call).
- `influence()` on `s()` / `t2()` fits: the deletion tables change
  (rellib-r21 vs lane, `refits-review-probe3-*.log`: `s(x).fx1` row 2
  2.219820 -> 2.390876; `t2` row 3 -0.277282 -> 0.282698).
- `formula(fit)` of `y ~ . - w` is `y ~ (x + z + o)`, where 0.82.0 and
  brms store `y ~ (x + z + w + o) - w`.
- `vcov_cluster(~ v)` now refuses call data whose rows differ from the
  fit's (it computed before, by position).
