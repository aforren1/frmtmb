## 1. BLOCKER: the fast path accepts newdata that differs in a variable the model reads

`draws_newdata_is_fitted()` has two paths. When every model-frame column
is in `newdata`, it compares ONLY the frame columns and returns. A
variable that the model reads but the frame does not hold is not
compared. `frame_raw_vars()` documents one such variable: the upper
bound of an interval `cens()`. The lane's claim ("every model-frame
column or every raw variable the model reads") does not hold on that
path.

Case (`review-hollow-probe2.R`, seed 2; `review-hollow-probe3.R`):
`frm(y | cens(cc, y2) ~ x)`, row 4 interval censored. `names(fit$data)`
is `y,x,cc`; `y2` is only in `frame$raw_vars`. Newdata = the data with
`y2[4] + 3`:

```
cens: upper bound of an interval row changed, accepted  TRUE
cens: logLik fitted vs with changed bound               -59.313127 vs -58.130862
cens changed bound: accepted; identical to log_lik(ds): TRUE
row 4 (interval [2.3384, 3.3384] then [2.3384, 6.3384]): log_lik -3.625350;
  density on the changed interval -3.558393, on the fitted -3.625350
```

So `log_lik(ds, newdata = d1)`, and through it `loo()`, `waic()`,
`psis()`, the `loo_*()` functions and `loo_model_weights()`, return
the fitted answer for data whose likelihood is different. That is a
silent wrong value; on base the call was refused. The same root cause:
`fit$data` plus a changed `x` column on `y ~ poly(x, 2)` is accepted
(`poly: fit$data plus a different x column  TRUE`).

Fix: on the fast path, also compare each `frame$raw_vars` column and
each `frame$data_vars` variable that `newdata` holds (a variable absent
from `newdata` can stay accepted there, since then `newdata` is the
frame itself). Add the `cens()` case to "rows other than the fitted ones
are still refused" in `test-loo-newdata-fitted.R` and see it fail on
the lane build first.

The other cases I constructed are refused correctly
(`review-hollow-probe1.log`, `probe2.log`, `probe5.log`): reordered rows,
an extra row, a subset, `ar()`/`cosy()` time swapped within a group,
`weights()`, `trials()`, `se()`, `me()` sdx, `gp()` inputs, `mo()`
level, `mm()` members, nl covariates, a `sigma ~ z` covariate,
`offset(log(age))`, `log(y)` response, multivariate `subset()`, a
filled-in `mi()` value, a dropped NA row with a changed value. The true
fitted data is accepted as a tibble, a data.table, with extra columns,
with `g` as character, with reordered factor levels, with integer in
place of double, as `na.omit(data)` when the fit dropped NA rows, and
with NA in an unused column.

## 2. MINOR: label comparison accepts a change of type

`same()` compares by `as.character()` when EITHER side is a factor or a
character. A numeric `k` fitted and a character or factor `k` in
newdata compare equal (`probe2.log`: "numeric fitted, character newdata
TRUE", "numeric fitted, factor newdata with same labels TRUE"). That
newdata is not "exactly the fitted rows": the model would build another
design from it. `as.character()` of a double also keeps only 15
significant digits, so the comparison is not exact there. Compare by
label only when both sides are factor or character.

## 3. MINOR: the stated reason for refusing a subset is false for a subset

NEWS (frmtmb.sample) says other newdata is refused "for the same reason
as before: a leave-one-out weight comes from the row's own column of
log_lik(), so it exists only for a row the model was fitted on", and the
error says "A row the model was not fitted on has no observation to
leave out". A subset of the fitted rows consists of fitted rows, so
neither sentence is true for it. brms gives those rows' pointwise elpd
(lane log `brms-probe.txt`: 20 rows, max difference 3.75e-4 against
`loo(fit6)` rows 1:20, the gp noise of item 6).

The findings give the real reason: a by-value match is ambiguous for
repeated rows and wrong for `ar()` rows. That reason is partly true.
Identical rows have identical `log_lik()` columns unless a per-row
latent value (`me()`, `mi()`) or a neighbor (autocorrelation) enters. A
key match on row names (`fit$data[1:10, ]` keeps them) followed by a
value check was possible for models with no autocorrelation term and no
per-row latent values. Refusing is an acceptable scope. But state the
true reason in NEWS and in the refusal for a subset, or record it as a
follow-up.

## 4. MINOR: Row 1's reason is broader than the evidence

The Savage-Dickey ratio is invariant under a smooth change of chart: the
Jacobian cancels between the posterior and prior densities. Only its
normal approximation depends on the chart. For a coefficient (identity
chart; the design basis p = Mq is linear) there is one normal
approximation, and the lane's own probe gives 0.00599 against the
draws' 0.00495 for `x = 0` (`hollow-out/row1-probe-base.txt`). NEWS and
`?hypothesis` say that at a tested point the approximation "changes with
the scale ... so it gives no single number". That holds for `sd`, not
for `b`. Also, frmtmb already chose a chart for this approximation: the
MAP fit's Wald interval for the sd is on the sd scale (0.588 +/- 1.96 x
0.158 = 0.279 to 0.897), so "0 on its logarithm, the scale frmtmb fits
on" is beside the point. The sound reason is the tail error: 2560 times
the draws' ratio for the sd.

`NA` is a defensible decision for the row (the fixture is ML with flat
priors, so the ratio does not exist, and that part of the reason is
right). Rewrite the reason in NEWS, `?hypothesis` and the ledger row so
that it is true for every parameter class, for example "a decision: a
fit does not report a Bayes factor from the normal approximation, whose
tail density can be wrong by orders of magnitude". Alternatively,
compute the ratio for identity-chart rows only. The user decides which.

## 5. MINOR: `make_conditions()` on draws now reads the model frame

Core `make_conditions()` reads `x[["data"]]` from any non-fit list, so
it now takes `draws$data`, the model frame. For a transformed term this
differs from the fit (`probe3.log`, `probe4.log`):

```
make_conditions(fit, 'x'):   -1.01354  0.09759  1.20872
make_conditions(draws, 'x'): `x` is not a column of the data. It has: y, poly(x, 2)
base make_conditions(draws, 'x'): `x` is not a column of the data. It has: ...1
```

This is not a regression (base failed on every model, now only on
transforms). But `$data` makes draws look like a supported input. Send
`frmtmb_draws` through its base fit (`fit_refit_data()`), as the fit
branch does.

(a) B1, attacked again. Script `dev/review-hollow-probe6.R`, log
`.log`, lane build. For each model: is the true data accepted, is
`fit$data` accepted, and is a change of 0.5 (or a flipped logical) in
row 4 of a variable accepted:

```
nl body only (t2)       frame=[y,t2]          | data TRUE, fit$data TRUE | t2=refused u=ACCEPTED
dpar sigma ~ z          frame=[y,x,z]         | data TRUE, fit$data TRUE | z=refused x=refused u=ACCEPTED
offset only (age)       frame=[y,x,offset(log(age)),age] | TRUE, TRUE     | age=refused u=ACCEPTED
weights(w)              frame=[y,x,w]         | data TRUE, fit$data TRUE | w=refused u=ACCEPTED
mvbf subset(s)          frame=[y,x,s,z]       | data TRUE, fit$data TRUE | s=refused x=refused u=ACCEPTED
me(x, sdx)              frame=[y,x,sdx]       | data TRUE, fit$data TRUE | sdx=refused x=refused u=ACCEPTED
cens(cc, y2) column     frame=[y,x,cc] raw=[y2] | TRUE, TRUE           | y2=refused cc=refused u=ACCEPTED
trunc(ub = hi) column   frame=[y,x,hi]        | data TRUE, fit$data TRUE | hi=refused u=ACCEPTED
trunc(ub = 10) number   frame=[y,x]           | data TRUE, fit$data TRUE | hi=ACCEPTED u=ACCEPTED
cens shortcut: frame object TRUE  frame + moved y2 FALSE  frame without terms attr FALSE
```

`u` and, under `trunc(ub = 10)`, `hi` are not read by the model, so
accepting them is right. A bound given as a number is not a per-row
variable, so there is nothing to compare: `trunc(ub = 10)` fits, and
`frm()` itself refuses `cens(cc, 5)` and a `cens()` bound taken from
the formula environment. The `identical(newdata, fit$data)` shortcut
is safe. An object identical to the frame holds no `y2`, so it cannot
ask for another bound. Any edit (a `y2` column added, the `terms`
attribute dropped) makes it non-identical, and then the full comparison
runs and refuses when `y2` is missing or moved. The cost is that a
plain copy of a `cens()` frame is refused. That fails closed, and
`test-loo-newdata-fitted.R` pins it. The lane's reruns of probes 1, 2,
3 and 5 (`dev/hollow-out/rev-probe*-fix.txt`) differ from mine only in
the intended lines; I checked probe 2 line by line.
