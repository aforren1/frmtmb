## Findings

### B1 (BLOCKER). NaN standard error at a real maximum when `par_units` comes from a smooth

`se_edge_limit()` takes `u <- fit$par_units %||% se_limit_units(fit, om)`.
The lane's units fix (`se_limit_units()`) runs only when `par_units` is
NULL. A smooth makes `par_units` non-NULL under `autoscale = FALSE`
(`smooth_fx_units()`), and every other coefficient is then probed in raw
units. A coefficient of a column at scale 1e-5 or 1e-6 reads "level"
at 2 raw units both ways and at 16, and zero reads a loss, so the rule
fires at the maximum. This is the false alarm the lane found in
test-predfix.R and fixed for the no-smooth case only.

Reproducer: `Rscript dev/reviews/boundfam-review-units.R <lane|base>`
(logs `boundfam-review-units-{lane,base}.txt`). Each fit is started at
the maximum that the autoscaled fit found, `autoscale = FALSE`,
`y ~ xs + s(z)`, n = 300, seed 9, `par_units` = 1, 1, 6.34, 1:

| case | objective | xs | base SE | lane |
|---|---|---|---|---|
| poisson, sc 1e-6 | 473.18771786 (= autoscaled) | 325886 | 43402.7 | NaN, W "maximum likelihood estimate does not exist" |
| bernoulli, sc 1e-5 | 188.60348237 (= autoscaled) | 12903.5 | 13007.9 | NaN, same W |
| bernoulli, sc 1e-6 | 188.60348237 | 129035 | 130078 | NaN, same W |
| poisson, sc 1e-5 | 473.18771786 | 32588.6 | 4340.27 | 4340.27 (no fire) |

The same fits without the smooth (`par_units` NULL) keep their SEs on
the lane. The same root cause also misreports a stop short of the
maximum: from the default start, poisson sc 1e-6 with `autoscale =
FALSE` stops at xs = 0.00123, objective 502.41121629, 29.2 above the
maximum (473.18771786). Base is silent there (SE 41370.7). The lane
warns "stopped on the way up ... rises by a further 0.0022": the
direction is right, but the gain is 4 orders too small, because the ray
is probed in raw units (`boundfam-review-fp-{lane,base}.txt`, case
"units").

The trigger is narrow (an explicit `autoscale = FALSE`, a smooth or
another source of `par_units`, a column with sd at or below about 1e-5),
but the brief's rule is that any NaN at a real maximum blocks. Fix: take
`se_limit_units()` for each candidate whose `par_units` entry is 1, or
always derive the probe's unit from the column spread and the predictor
unit, whatever `par_units` holds. Add the smooth case to test-se-limit.R.

### M1 (MAJOR). A separating zero-inflation slope gets the quiet "family limit" message

A slope of a family parameter that runs off is a separation of that
parameter's model, not the family's limiting case. The rule calls it
quiet (`se_limit_quiet()`: every limit parameter is of a non-primary
dpar), so the fit gets the `frmtmb_boundary_fit` message only. The
message says "a zero-inflation or mixing probability at its limit drops
that part of the model", which is false here: zi is 1 below x = 0 and 0
above. The other zi coefficient keeps a huge finite SE. Because
`se_boundary_stop()` accepts "limit", the optimizer's code-7 warning is
also removed. The fit gets no warning at all, at code 1.

Reproducer: `Rscript dev/reviews/boundfam-review-fn.R <arm> zisep`
(`boundfam-review-fn-{lane,base}.txt`): `bf(y ~ 1, zi ~ x)`,
`zero_inflated_poisson()`, n = 200, y = 0 for x < 0, else
`rpois(exp(2))`.

| seed | arm | conditions | zi_(Intercept) | zi_x |
|---|---|---|---|---|
| 1 | base | W code 7 ("estimates are at the maximum") | -13.36, SE 1913 | -1706.5, SE 137904 |
| 1 | lane | M frmtmb_boundary_fit only | -13.36, SE 1063 | NaN (limit) |
| 2 | base | W code 7 | -17.24, SE 19975 | -594.8, SE 372756 |
| 2 | lane | M only | -17.24, SE 1562 | NaN (limit) |

The bernoulli fit of the same zero pattern (`z ~ x`) gets the
complete-separation warning on both arms. The undefined test does not
catch zi_(Intercept): a 2-unit step on a slope of -1707 moves the
boundary by 0.1 percent, so no curvature halves.

The hurdle form behaves the same way (`boundfam-review-split.R`,
`boundfam-review-split-{lane,base}.txt`): `bf(y ~ 1, hu ~ x)`,
`hurdle_poisson()`, zeros only below x = 0.

| seed | arm | conditions | hu_(Intercept) | hu_x |
|---|---|---|---|---|
| 1 | base | W code 7 | SE 1618.7 | -1772, SE 180480 |
| 1 | lane | M only, code 1 | SE 1436.65 | NaN |
| 2 | base | W code 7 | SE 35562 | -625, SE 662970 |
| 2 | lane | M only, code 1 | SE 2172.91 | NaN |

By contrast, `bf(y ~ 1, shape ~ g)` with group b poisson (seed 2) runs
shape_gb to 16.6. That is a group at its family limit, and the message
fits it (base: SE 386 in silence).

Fix: tell the two apart. A probability dpar (zi, hu, zoi, coi, a mixing
theta) whose limit direction drives some rows to 0 and others to 1 is a
separation of that dpar's model. It must warn, as the bernoulli does,
and lose the dpar's other coefficients. Only a limit that moves rows
one way (an intercept, or a contrast whose rows all go to the same end)
is the family's limiting case.

### M2 (MAJOR, merge with ppdraw). How limit parameters reach predict()

On the lane alone, `fit_draw_space()` sets
`boundary_only = all(se_lost == "boundary")`, which is FALSE for
"limit". `predict_par_drawer()` then drops the covariance. Every fit at
a family limit (a negbinomial on poisson-like data, a student fit on
gaussian-like data) gets the plug-in fallback and the warning "the
covariance of the estimates could not be recovered from the Hessian".
A variance component at zero gets draws from the held covariance. So
the lane's own message ("the other standard errors are kept, as those
of the model at that limit") does not hold in predict().

Reproducer: `boundfam-review-fn.R <arm> pred`, negbinomial seed 2,
`predict(newdata = 3 rows, ndraws = 400)`:

- Lane: 1 W (plug-in), Est.Error 1.45, 1.78, 2.39.
- Base: 97 "NAs produced" warnings, then 112 of 400 draws not finite
  per row (NA cells), from the log-shape SE of 1218.
- `fitted()`: identical on both arms.

Base was not good either, so on its own this is not a regression in
kind, but the two reports disagree.

Lane ppdraw (`frmtmb-wt-ppdraw`, R/brms-shapes.R and R/predict-brms.R)
already accepts "limit" in `boundary_only` and restores the RAW rows
(`draw_limit_restore()`, `sdr$cov_fixed_raw`) for every "limit"
parameter. That includes the undetermined mean parameters of a warning
fit: pois0's x (raw SE 2.4e137), eam's bs1 (5575), and the cens fits'
SEs of 6e8. Those are the variances this lane says have no meaning.
For consolidation:

1. `boundary_only` must accept "limit" only where `se_limit_quiet()`
   holds (family limit).
2. The raw-row restore must apply only to the "end" family parameter
   (whose flat side draw_edge_law() holds), never to "undefined"
   parameters or to a mean coefficient at its end.

A warning-class limit fit keeps the plug-in fallback.

### m4 (MINOR). Quadrature: no limit verdict, and quadseam needs more than a gate change

`se_edge_limit()` is off under quadrature (hard-coded
`!isTRUE(fit$quadrature)`). A negbinomial with `(1 | g)` on poisson-like
data (`boundfam-review-fn.R nbquad`, seed 2, log shape 17.09):

- Laplace, lane: the boundary message, shape NaN.
- Laplace, base: "flat" W.
- Quadrature, both arms: SE 482.3 in silence.

There is no regression, but after quadseam merges, one-block quadrature
gives boundary verdicts for sds and still none for family limits. To
turn the rule on there, three things must change:

- `se_edge_limit()` must evaluate through quadseam's `se_probe_fn(fit)`,
  one tape per point, because the frozen tape reads garbage away from
  the estimate.
- `se_limit_curv()` uses `obj$gr` and `obj$he` on that same frozen tape.
  quadseam's re-anchoring has no gradient counterpart, so the undefined
  test cannot run there as written.
- The gate should then read `se_edge_probed(fit)`.

Textual merge of R/se-check.R with quadseam is clean (`git merge-file`,
0 conflicts). The hunks closest together are in `se_boundary_stop()`:
quadseam's first lines and boundfam's doc and `ok <-` lines, with 4
unchanged lines between them.

### m5 (MINOR). Cost when the rule fires is outside the fit-time budget

The undefined test takes 4 gradients per other outer parameter
(`cost2.txt`: 12 gradients, 3.6 to 4.1 s of a 23.6 to 25.3 s fit). With
random effects, each gradient is an inner solve, so the cost grows with
the number of parameters. `se_check_at_fit()` budgets `4 * np` gradients
for the FD Hessian alone, and `se_boundary_stop()` forces the analysis.
A firing fit with many coefficients can double the check's work beyond
what the budget counted. Not measured beyond the lane's one case.
