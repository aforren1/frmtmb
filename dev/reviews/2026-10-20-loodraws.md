## Findings

### 1. MEDIUM: refusals fire on calls brms accepts, with brms's own defaults

The lane's guard absent case tests only `NULL` values. brms's defaults
for the new-level arguments are not `NULL`, and `loo_model_weights()`
refuses by name whatever the value (`dev/loodraws-rev-guards.R`,
`guards.txt`; brms column is the same call on the brms fit):

```
loo_epred(allow_new_levels = FALSE)            brms: ok 80x1     frmtmb: ERROR: loo_epred() cannot honor `allow_new_levels`: ...
loo_epred(sample_new_levels = 'uncertainty')   brms: ok 80x1     frmtmb: ERROR: loo_epred() cannot honor `sample_new_levels`: ...
loo_R2(allow_new_levels = FALSE)               brms: ok 1x4      frmtmb: ERROR: loo_R2() cannot honor `allow_new_levels`: ...
loo_model_weights(newdata = NULL)              brms: ok 0.154755 0.845245   frmtmb: ERROR: loo_model_weights() cannot honor `newdata`: ...
loo_model_weights(allow_new_levels = FALSE)    brms: ok 0.154755 0.845245   frmtmb: ERROR: ... cannot honor `allow_new_levels`: ...
loo_model_weights(draw_ids = 1:1000)           brms: ok 0.165712 0.834288   frmtmb: ERROR: loo_model_weights() cannot honor `draw_ids`: the weights are computed from log_lik() of each model, which refuses it
loo_epred(draw_ids = 1:1000)                   brms: ok 80x1     frmtmb: ok 80x1
```

The `draw_ids` refusal's reason is false: `log_lik(ds, draw_ids =)`
works (the four other functions pass it). So the six do not keep one
`newdata`/draws policy (brief item 4): `loo_epred()` takes `draw_ids`
and `loo_model_weights()` refuses it; `loo_epred()` lets
`newdata = NULL` pass and `loo_model_weights()` does not. `loo()`
refuses `allow_new_levels = FALSE` and `draw_ids` too (pre-existing:
`loo(allow_new_levels = FALSE)` brms -123.85, frmtmb ERROR;
`reff.txt` for `draw_ids`).

Fix: in `loo_draws_opts()` and `draws_model_weights()`, treat a value
equal to brms's default as absent (`NULL`; `allow_new_levels` and
`allow.new.levels` `FALSE`; `sample_new_levels` `"uncertainty"`), and
let `loo_model_weights()` pass `draw_ids` to `log_lik()` as the other
five do. A test per refused name with its default value.

### 2. MEDIUM: on a subset of draws, `loo_*()` weights differ from brms's and from frmtmb's own `pp_check()`

brms 2.23.0 has one convention: on a subset (`ndraws` or `draw_ids`
smaller than the draw count), `get_chain_id()` returns one chain, and
`r_eff` is `relative_eff()` on that one chain, in `loo()`, in every
`loo_*()` (they call `loo()`) and in `pp_check()` (it calls `loo()`).
frmtmb's `pp_check()` already follows it. The lane's `loo_*()` use
`r_eff = 1`, as frmtmb's `loo(ndraws =)` does. On the same draws and
the same sorted random `draw_ids` (seed 13; `dev/loodraws-rev-reff.R`,
`reff.txt`):

```
1000 of 4000, gauss: brms loo() r_eff is one-chain relative_eff: TRUE (range 0.785 1.06)
  loo_epred(draw_ids =) frmtmb vs brms rel diff 0.000118
  pp_check(draw_ids =) lw: frmtmb vs brms max abs diff 0; frmtmb pp_check vs r_eff-1 weights 0.028
1000 of 4000, ri:    one-chain range 0.697 1.2; loo_epred rel diff 0.000298; pp_check vs r_eff-1 lw 0.0727
3000 of 4000, gauss: one-chain range 0.903 1.15; loo_epred rel diff 9.21e-06; pp_check vs r_eff-1 lw 0.0174
3000 of 4000, ri:    one-chain range 0.506 1.34; loo_epred rel diff 0.000217; pp_check vs r_eff-1 lw 0.0389
```

On all draws the two sides are identical (finding 0), so the whole
difference is the convention. It is small against the Monte Carlo
error (elpd differences 6.4e-4 and -4.7e-4 against an SE of 6.34 and
5.96), but it makes `loo_epred(ds, draw_ids =)` differ from brms on
identical draws, and makes `loo_epred()` and `pp_check(type =
"loo_pit")` weight the same draws two ways. Recommendation in (a).

### 3. LOW: `resp` takes frmtmb's spelling in three functions and brms's in `loo_R2()`

For a response column `y_a`, brms's name is `ya` (`mvbf()$responses`:
`ya y2`). `dev/loodraws-rev-guards2.R`, `guards2.txt`:

```
loo_epred(resp = 'ya'): ERROR: loo_epred(): `resp` must name one response of this model; it has y_a, y2
loo_epred(resp = 'y_a'): ok 80x1
loo_R2(resp = 'ya'): ok 1x4
loo_R2(resp = 'y_a'): ERROR: Invalid argument 'resp'. Valid response variables are: ya, y2
loo_epred() dimnames[[3]]: y_a y2
rownames(loo_R2()): R2ya R2y2
```

brms takes `ya` in all six and names the third dimension `ya`. The
split is inherited (`posterior_epred()`, `log_lik()` and `loo()` take
`y_a`; `bayes_R2()` takes `ya`), but the lane's six functions now
expose both spellings side by side. Accept both spellings in each, and
use brms's in the dimnames, or record the divergence in NEWS.

### 4. LOW: `add_criterion(x, c("loo", "loo_R2"), seed = 1)` fails

`guards2.txt`: brms `ok loo loo_R2`; frmtmb `ERROR: loo() has no
argument `seed``. brms hands `...` to every criterion and `loo()`
ignores `seed`. The lane made `"loo_R2"` storable, so the natural call
that stores both with a seed now fails. Route `seed` (and the other
`loo_R2()`-only arguments) to `loo_R2()` only.

### 5. LOW: `psis(ds, draw_ids =)` ignores `draw_ids` in silence (pre-existing)

`dev/loodraws-rev-psisdots.R`, both builds (`psisdots-<arm>.txt`):
`psis(ds, ndraws = 100)` is 100 x 40, `psis(ds, draw_ids = 1:100)` is
300 x 40, and `psis(ds, junk = 1)` passes. `loo::psis()` swallows the
names. The lane routes `psis()` through `draws_psis_of()` and its docs
tell users to build `psis_object` with `psis()`, so a user who
subsets with `draw_ids` gets weights for all draws (the dimension check
in `loo_draws_expect()` then refuses, which limits the damage). brms's
`psis(fit, draw_ids =)` honors it. Honor `draw_ids` and refuse unknown
names, as `loo_draws_opts()` does.

### 6. LOW: the parity evidence and the NEWS numbers can be exact

## The lane's open questions

### (a) r_eff on subsets: use brms's convention everywhere

brms 2.23.0 uses `relative_eff()` with one chain on any subset, in
`loo()`, `loo_predict()` and friends, and `pp_check(type = "loo_*")`
(`reff.txt`: TRUE on both models at 1000 and 3000 of 4000 draws).
frmtmb's `pp_check()` already matches it exactly (lw max abs diff 0).
Change `loo_r_eff()` to return the one-chain `relative_eff()` when the
`chain_id` attribute is absent (keeping 1 for `brm_multiple`-style
draws), so `loo()`, `psis()`, the six `loo_*()` and `pp_check()` share
one convention and equal brms on the same draws. The cost is a tiny
move in `loo(ndraws =)` numbers (elpd 1e-3 at most here: ndraws 1000
-127.285341 vs -127.286358; 3000 -127.246386 vs -127.246411). On
frmtmb's evenly spaced `ndraws` rows the one-chain estimate measures
the thinned sequence's autocorrelation (range 0.683 to 1.14 here),
which is at least as defensible as 1. Mark it BREAKING for `loo(ndraws
=)`.

### (b) generics: move the six generics and the fit refusals to core

What a user sees on an ML fit (`dispatch-rev-<order>.txt`):

| attached | `loo_R2(fit)` | `loo(fit)`, `bayes_R2(fit)` |
|---|---|---|
| frmtmb only | could not find function | refusal naming frm_sample() |
| rstantools, then frmtmb | no applicable method for 'loo_R2' ... "frmtmb_fit" | refusal |
| brms, then frmtmb | no applicable method | refusal |
| frmtmb.sample loaded (any order with loo, rstantools, brms) | refusal naming frm_sample() | refusal |

With frmtmb.sample loaded, every route works on draws and fits,
including `rstantools::`, `brms::` and `loo::` calls with frmtmb.sample
loaded but not attached. The gap is a session with core only, which
is exactly the user an ML refusal is for. Moving the six generics and
the `frmtmb_fit` refusals to core, as `bayes_R2()`, `log_lik()` and
`loo()` are, closes it; the draws methods stay in frmtmb.sample. Core's
owner table takes one owner per name, so `loo_epred` (defined by both
brms and rstantools) needs the two-owner rule frmtmb.sample already
has. `kfold()` and `reloo()` have the same gap. This is a core change,
so do it as its own lane or at consolidation, not as a fix to this
lane; it is not a merge blocker.

### (c) the BREAKING `posterior_average()` change: yes, it is brms's

brms's `posterior_average()` reaches `model_weights()`, then
`loo_model_weights.brmsfit()`, which computes `log_lik()` and its
`r_eff` per model and never reads a stored criterion. Run: 2
`log_lik()` calls with stored criteria present, weights identical with
and without them (`guards2.txt`). The lane's route now does the same
(`pa-rev.txt`), where rellib-r10 read the stored `loo` (`pa-base.txt`).
Keep it, and add the test of finding 7.

### New LOW: the gated test's tolerance rationale does not match the arithmetic

`near()` bounds each difference by `N * eps * scale`, where N = nrow(dd) = 80 and the scale is the measured largest value. The stacking and pseudobma weights are bounded by `sqrt(eps)`.

- The scale is measured in the run, and the bound is a multiple of eps, so it is "a ratio to the run's own rounding", not a free absolute constant.
- The factor is justified as "N terms of eps each", but the sums that `E_loo()` and `psis()` form run over S = 1000 draws, not over the 80 rows. The 80 is a chosen constant, not the term count.
- `sqrt(eps)` is cited as `optim()`'s `reltol`. That is a tolerance on the change in the objective, not on the argmin.
- Both bounds pass with margin. The lane's OpenBLAS measurements are at most 7.9 eps (mean), 5.2 (`draw_ids`), 2.1 (`log_lik`) and 49 eps for `loo_R2` against 320. The weights differ by 7958 eps, about 1.8e-12, against 1.5e-8.
- Both bounds still catch the defect class they guard. The old `r_eff = 1` convention moved `loo_epred(draw_ids =)` by 1e-4 relative, and moved weights by about 1e-2.
- The cleaner form is a true ratio to what the run measures: `d <- max(abs(ll_frmtmb - ll_brms)) / max(abs(ll_brms))`, then bound each downstream quantity by `C * max(d, eps) * scale`, with C stated once.

This does not block the merge. Fix the comments at least, so that the next reader does not read 80 as a derived quantity.
