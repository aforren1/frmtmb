## 1. The formula

Derivation. With `n` the shape,
`log p(y) = lgamma(y + n) - lgamma(n) - lgamma(y + 1) + n log(n / (n + mu)) + y log(mu / (n + mu))`.
Write `log(n + mu) = log n + log1p(mu / n)` and
`R = lgamma(y + n) - lgamma(n) - y log n = sum_{j=0}^{y-1} log1p(j / n)`.
The `j = 0` term is 0, so the sum runs over `0 < j < y`. The `y log n`
terms cancel, which gives
`R + y lmu - (n + y) log1p(mu / n) - lgamma(y + 1)`: the lane's
formula. At `y = 0` and `y = 1`, `R = 0`; `nb_rising()` gives 0 there
because it reads `part[short - 1]` only for `short > 1`.

Check (`nbrobust-review-formula.R`, log `nbrobust-review-formula.log`,
table `nbrobust-review-formula.tsv`). The grid has counts 0, 1, 2, 3, 7,
23, 24, 25, 26, 60, 500, 1e4 and 1e5, log means -30 to 11.5 (8 values)
and log shapes -10 to 50 (17 values): 1768 points per arm. The
reference is the textbook mass in Rmpfr at 400 bits, and its
derivatives are central differences of the mpfr value (step 2^-100), so
no analytic derivative is shared with the lane. Units are the error
over `eps (y + mu + 1)`. The arms are scalar (one shape), vec (a shape
per row), osa (`lgamma_shift_diff()` for every count) and robust
(0.83.0's `dnbinom_robust()`).

    scalar  lsh <=10   max units dsh  2.08  dmu 0.857  max abs val 5.39e-10
    scalar  lsh 18-24  max units dsh  4.21  dmu 0.857  max abs val 4.66e-10
    scalar  lsh 24-30  max units dsh  4.81  dmu 0.851  max abs val 9.31e-10
    scalar  lsh >30    max units dsh  2.58  dmu  15.7  max abs val 3.74e-10
    osa     lsh >30    max units dsh  4.45  dmu  15.7
    robust  lsh 18-24  max units dsh 2.5e+10
    robust  lsh 24-30  max units dsh 2.75e+13
    robust  lsh >30    max units dsh  4.5e+15

The vec arm is identical to the scalar arm in every band. The largest
absolute value error is at `y = 1e5`, where the log mass is formed from
terms of about 1e6; the retaped value at a second point agrees to the
same level. The lane's claims of correctness and of a derivative
error of at most 6.6 units hold on this independent grid.

The switch at 24. The count is data, so nothing is continuous across 24
in a parameter. What matters is that both forms give the same value and
derivative at the same count. The sum against `lgamma_shift_diff(n, y) -
y lsh` at y = 23, 24 and 25, log shapes -3 to 35: the derivative
difference is at most 1.03e-14 (unit 5.3e-15). The value difference is
at most 1.74e-13 at log shape 35, where both terms are `eps y lsh` in
size.

Non-integer y: `count_y()` refuses one for every family here. If one
reaches `nb_rising()`, it goes to `lgamma_shift_diff()` and gives the
gamma-function extension: -2.426015 at y = 2.5, the same as the mpfr
reference.

## 2. Each family and link

`nbrobust-review-fams.R <base|lib>` (logs `-base.log`, `-lib.log`, tables
`-base.tsv`, `-lib.tsv`, digest `nbrobust-review-fams-read.log`). The
families are negbinomial, negbinomial2, nbinom1, geometric, zinb and
hurdle nb; the links are log, identity, sqrt, softplus and squareplus;
negbinomial and geometric are run with and without `rate()`. There are
320 cases, half of them at a log shape of 15 to 40, with counts 0, 0, 1,
2, 3, 5, 9, 24, 25, 40 and 130. The reference is written from the
textbook masses in mpfr (zinb `log(zi + (1 - zi) p0)`, hurdle
`log(1 - hu) + l - log(1 - p0)`; nbinom1 shape `mu / phi`; geometric
shape 1, times `d` under `rate()`). The gradient in every linear
predictor is a central difference of the mpfr value.

- Lane: no case has a value error above 1.2e-12 on the tape or 1.9e-12
  off the tape (no `.eta_`, the post-fit route), or a gradient error
  above 3.7 units in any dpar. Bad rows: 0 of 320.
- 0.83.0: 120 of 320 bad. The derivative in the shape is off by up to
  4.4e15 units. On the tape, zinb with the identity link at log
  shape 31.18 is off by 0.0611 in value, from the non-log
  `lp0 = shape (log(shape) - log(shape + mu))`. Off the tape, the value
  is NaN at log shapes 35.7 to 39.9 (negbinomial softplus with `rate()`,
  nbinom1 sqrt, zinb log, sqrt, softplus and squareplus) and off by up
  to 0.899 (zinb softplus, log shape 38.7). `draws_row_loglik()` in
  frmtmb.sample calls `row_lpdf()` on doubles, so `log_lik()` and
  `loo()` read these values. NEWS does not say so (FIX 3).

Identity link at a nonpositive mean, on the tape (value, derivative in
the mean) and off it. Both builds give NaN for every family at
mu = -0.5 and at mu = -1e-8. At mu = 0 exactly, the lane gives -Inf and
+Inf for negbinomial, negbinomial2, geometric and zinb, where 0.83.0
gave NaN. nbinom1 and hurdle give NaN on both. 0.83.0's `dnbinom2()`
branch was not finite either, so the lane takes no silent log of a
nonpositive mean that 0.83.0 handled. Under either build, nlminb reads
a non-finite objective as a failed step.

## 7. Tests

Rerun with `dev/release/run-tests.R`, NOT_CRAN=true, one file per
process (logs `nbrobust-review-tests-{base,lib}-<file>.log`):

    rellib-r22  RESULT test-numerical-robustness.R pass=758 fail=20 err=0 skip=0 warn=0
    rellib-r22  RESULT test-family-fitend.R        pass=51  fail=3  err=0 skip=0 warn=0
    lane        RESULT test-numerical-robustness.R pass=778 fail=0  err=0 skip=0 warn=0
    lane        RESULT test-family-fitend.R        pass=54  fail=0  err=0 skip=0 warn=0

These are the lane's numbers. The failures on 0.83.0 are behavioral
(gradient error, a missing message, gradient warnings), not missing
symbols.

Tolerances:

- The gradient test bounds `|g - exact|` by `64 eps sum(y + mu + 1)`,
  a multiple of machine epsilon times a scale the data set. Its
  reference is derived without the cancellation; I rederived it as
  `-rise + y r / (1 + r) - n (log1p(r) - r / (1 + r))`, with the series
  `r^2/2 - 2r^3/3 + 3r^4/4 - 4r^5/5`. Correct.
- The shape sweep reuses `expect_robust_at()`, whose check is
  `|g - fd| / max(1, |fd|) < 1e-5`. That is an absolute tolerance when
  `|fd| < 1`, which is always so at a large shape. The helper predates
  the rule and pins the defect (0.00189 and 47 on 0.83.0). Low
  priority.
- "negbinomial and negbinomial2 both name the poisson limit" now
  requires the message and no warning on every rounding. It passes on
  0.83.0 as well, so it tightens the test but does not pin the defect;
  the lane says so.

## Further findings

### 8. A far start on overdispersed data (MEDIUM, file it; FIX 2)

`nbrobust-review-start.R <arm>` (logs `-start-{base,lib}.log`). Data:
seed 5, n = 200, `rnbinom(size = 2)`. The maximum is at log shape
0.7613, logLik -424.5690959863.

    lane, k = 0 (k = 5 and 10 the same)
    start 15  code 0 lsh 14.9996 logLik -470.9476069766  SE warning "(at 15,
              toward -Inf, where the log-likelihood rises by a further 17)"
    start 20  code 0 lsh 20.0000 logLik -470.9477411293  SE warning "flat ...
              so the data do not d[etermine it]"
    start 25  code 0 lsh 25.0000 logLik -470.9477420329  same SE warning
    start 30  code 0 lsh 30.0000 logLik -470.9477420390  same SE warning

On 0.83.0 the same starts stop at the same points. From 15 and 20 they
give the same SE warning. Of the 6 stops from 25 and 30 (k = 0, 5 and
10), 5 also give "Large maximum absolute gradient" (0.00173 to 0.347),
and two of those give "false convergence" too; k = 10 from 25 gives
none. That is the noise, by accident. The
true shape gradient there is 6e-9 (25) and 4e-11 (30), so no
gradient-based stop can see the maximum, which is 46 log-likelihood
units away. With the exact gradient, the only signal left is an SE
warning that says the data do not determine the shape, which is false
here. The limit message does NOT fire on these stops (no
`frmtmb_limit_fit` in the log): the limit rule makes no false claim.
The censored data of finding 4 show the same: from `betad = 30` the
lane ends at code 0, log shape 30.0000, logLik -330.601016988,
against -323.685028305 from the default start, with the "flat" SE
warning. 0.83.0 ends at code 1 with gradient warnings. The lane did
not create the plateau, but it removed the accidental alarm. The
lane's new fit-end test ("started far along its poisson limit stops
there") is right for its poisson data. Its case where the condition is
absent (overdispersed data) is this finding.

### 9. Low findings (optional)

4. NA response: `nb_lpmf(c(1, NA, 3), 0, 0)` stops with "missing value
   where TRUE/FALSE needed" in `nb_rising()` (`max(short, 1)` is NA),
   where `dnbinom_robust()` returned NA for that row. No package path
   hands it an NA (`nbrobust-review-na.R`, logs `-na-{base,lib}.log`):
   plain NA rows are dropped, `mi()` is refused, `subset()` in a
   multivariate model fits, hmm() fills a placeholder and masks it.
   All five families give the same logLik on both builds to 8
   decimals. A custom family that wraps a core lpdf could still meet
   one.
5. Value at a large count. At y = 1e4 and 1e5 and log shapes -10 to 0,
   `nb_lpmf()`'s absolute value error is 5 to 20 times
   `dnbinom_robust()`'s: 1.6e-11 against 1.9e-12 at y = 1e4, and up to
   5.4e-10 against 3.5e-11 at y = 1e5. `stats::dnbinom()` is exact
   there (`nbrobust-review-smallshape.log`). That is still about one
   ulp of `y log y`, so no fit can see it. The NEWS figure "agrees with
   it to 5e-12 relative" was measured to y = 1e4. At y = 1e5 the
   relative error is up to 5e-11 (log mean 11.5, log shape 10), but
   `dnbinom_robust()` is not right to 1e-13 there either, so the claim
   as worded holds.
