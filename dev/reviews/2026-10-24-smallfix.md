### 2. S1, major (pre-existing): fixef() answers with NA errors

This is the defect class of the lane's own `predict()` fix.

`fixef()` of a fit with any missing package answers, with `Est.Error`
NA, instead of refusing. It is the same pattern the lane fixed in
`fit_draw_space()`: `fixef.frmtmb_fit()` wraps `vcov()` in
`tryCatch(..., error = function(e) NULL)` (`R/methods-fit.R:1677`) and
reads the refusal as "no covariance".

```
s1b/new-coxcar--base_none.txt (rellib-r12): CALL fixef :: OK Est.Error: NA,NA
s1/new-coxcar--none.txt (lane):             CALL fixef :: OK Est.Error: NA,NA
s1/new-coxcar--all.txt (lane, both present): CALL fixef :: OK Est.Error: 0.342,0.142
```

It happens in all six stacks with a missing part, and for the 0.73.0
cox fit even with frmtmb.survival installed (`s1/old-cox--all.txt`).
Other handlers of the same shape: `R/methods-fit.R:675`
(`summary_mo_frame()`), `R/me.R:454`, `R/interop.R:194` and `:279`,
`R/families.R:3509`, `R/se-check.R:1973` and `:2408`,
`R/se-reparam.R:442` and `:959`, `R/sandwich.R:558`.

Fix: the general one is to let the refusal through every such handler,
for example `error = function(e) if (inherits(e,
"frmtmb_extension_missing")) stop(e) else NULL`; the narrow one is to
call the two checks at the head of `fixef.frmtmb_fit()`. Either way,
`fixef` joins the test's method list. If the lane leaves this for a
later round, the findings must say so: it is the defect the lane found
in `predict()`, in a method the lane did not test.

### 10. S4, major: the evd allow-list papers over an avoidable skip

evd is not out of DESCRIPTION by design. `dev/famuni-findings.md` line
626 records why: the first check gave a WARNING for the undeclared
`evd::dgev`, and the test was changed to read evd by name. extraDistr,

(`scripts/s4-gev.R`, log `s4-gev-ref.txt`):

```
evd 2.3.7.1 extraDistr 1.10.0.5
inside rows 40 of 48 ; max |evd - extraDistr| / max(1, |evd|) inside: 1.168756e-15
outside: evd -Inf extraDistr -Inf
```

The test's tolerance is `64 * eps * max(1, |ref|) / min(1, zx)`, about
1.4e-14 at least, so extraDistr serves as the reference. With

CMD check on all four platforms and in coverage. The `absent: 'evd'`
entries and `any::evd` then go, and the gate has no exception. As
written, the one GEV reference test runs on one Linux job only. Fix:
switch the reference to `extraDistr::dgev()` (argument names `mu`,
`sigma`, `xi`), drop the allow-list and the extra package, and update
the NEWS bullet. Rerun `test-families-extreme.R` and its OpenBLAS pass,
since the reference changes.

### 2. require_fit_packages(): no measurable cost
