## Findings

### MAJOR 1. A user's bounds-only prior is dropped from the fit, and `frm_sample(fit)` then samples brms's default in its place

`drop_unbounding_slots()` (called in `frm()`) drops every bounds-only
specification whose bound maps to an infinite internal bound. That is
right for the restated rows of a passed-back table, but it also drops a
specification the user wrote. `frm_sample(fit)` stacks `fit$prior`
over the defaults, and in brms `set_prior("", class = "sd", lb = 0)` is
the user's `""` on that slot, which is (flat) on the sd (brms's
`validate_prior()` shows the row as `source = user`, prior empty,
`dev/priortab-out/brms.txt` case 9h). So the drop changes the sampled
prior with no message.

Reproducer (`priortab-review-probe2.R`, sections D1 to D3):
`f <- frm(y ~ z + (1 | g), data = d, prior = set_prior("", class = "sd", lb = 0))`,
then `sample_resolve_priors(f, NULL, base = f$prior)`:

| | base | lane |
| --- | --- | --- |
| `is.null(f$prior)` | FALSE | TRUE |
| effective `sd` row via the fit | `""`, lb 0 (brms's flat) | `student_t(3, 0, 2.5)` |
| effective `sd` row via `frm_sample(ml_fit, prior = sp)` | `""`, lb 0 | `""`, lb 0 |
| same for `class = "sigma"` | `""`, lb 0 | `student_t(3, 0, 2.5)` |

The two routes to the same request now disagree on the lane build only.
The frm() objective is unchanged (35.0222221 both arms), so the lane's
round-trip check could not see it. NEWS says only "The fitted objective
does not change".

Fix: drop only rows that came from a table (the route mark, or
`source == "default"`), or keep the dropped specifications on the fit
(for example in an attribute that `frm_sample()` stacks) and drop them
only from the ML label and `vcov_cluster()`'s check.

### MAJOR 2. The support box is closed, so a density that is zero at its boundary gives a "converged" fit with objective Inf at the boundary

`support_box()` boxes a coefficient to the closed support `[0, Inf)` or
`[0, 1]` for beta, lognormal, gamma and inv_gamma. At the boundary these
densities are 0 (or infinite), so the penalized objective is `+Inf` (or
`-Inf`) exactly where nlminb can now step. With a slope that the data
want negative (`yneg = y - 0.8 z`, ML slope about -0.5):

| prior on `b z`, no bounds | base | lane |
| --- | --- | --- |
| `lognormal(0, 1)` | error, NA/NaN gradient | conv 0, objective Inf, z = 0, "X-convergence (3)" |
| `beta(2, 2)` | error | conv 0, objective Inf, z = 0 |
| `gamma(2, 2)` | error | conv 0, objective Inf, z = 0 |
| `gamma(0.5, 1)` | error | conv 0, objective -Inf, z = 0 |
| `beta(2, 2)` with `lb = 1e-8, ub = 1` | conv 0, 129.8616523, z = 0.006822082 | the same |

(`priortab-review-probe2-*.txt` B1 to B3, `priortab-review-probe3-*.txt`
M.) The true MAP under beta(2, 2) is interior (z = 0.00682, objective
129.86); the lane reports z = 0 with convergence code 0 and an infinite
objective. The only signal is the warning "The gradient at the reported
optimum is not finite". The explicit `lb = 0` spelling gives the same
wrong fit on base too (pre-existing), but the lane routes the brms
spelling with no bound, which used to fail loudly, into it, and the NEWS
and `?set_prior` text say it gives "the same fit that the bounds would
give" as if that fit were sound. `uniform()` is fine: its density is
positive at its ends, and every uniform case reproduces the lane's
numbers.

Fix: box only densities with a positive density at the closed end
(uniform), or box the others to an open interval (for example the next
representable number inside), or refuse a fit whose objective is not
finite. Narrowest: limit `prior_dist_support()`'s box to `uniform`, as
item 4925 asked.

### MAJOR 3. The 4266 heuristic accepts a coerced route = "fit" table once any one row equals a brms default, and its (flat) rows then replace brms's defaults with no message

`table_lists_defaults()` returns TRUE when ANY row of the coerced frame
carries a brms default density in its own slot, and the coerced-table
refusal is then skipped for the whole frame
(`priortab-review-probe3-*.txt`, H1, H4):

- H1: `tab <- as.data.frame(default_prior(y ~ z + (1 | g), data = d))`
  (route "fit"), then `tab$prior[tab$class == "sigma"] <- "student_t(3, 0, 2.5)"`.
  Base refuses ("would replace brms's default on Intercept, sd with
  (flat)"). Lane accepts, and the effective prior has `Intercept` flat
  and the `sd` class row flat with lb 0, in place of
  `student_t(3, 1, 2.5)` and `student_t(3, 0, 2.5)`.
- H4: a coerced `route = "sample"` table with `Intercept` edited to
  `"(flat)"`, frmtmb's printed spelling. Base refuses; the lane accepts.
  The lane's findings say such a frame "is still refused, by design";
  that holds only when no other row carries a default, which is the case
  the new test checks (`data.frame(prior = "(flat)", class = "sigma")`).

Fix: decide per row, not per frame. A row whose prior is the printed
`"(flat)"` on a slot where brms has a proper default stays refused
whatever the other rows hold; `""` and `set_prior("")` (brms's own
spellings, the reported cases) are accepted.

### MINOR 4. Tables listed by Stan name do not supersede the defaults in frmtmb.sample

`prior_spec_slot()` and `table_lists_defaults()` now key `resp` by its
Stan name, but `spec_target()`, which `drop_superseded()` and
`keep_default_bounds()` use, still keys by the raw name. A
`route = "sample"` table of `mvbind(Y_a, Y_b)` now prints `Ya`, `Yb`;
passed back to frm_sample(), its rows no longer supersede the defaults
(resp `Y_a`), and the effective prior lists both: 12 rows instead of 8,
`student_t(3, 0, 2.5) sigma Y_a` beside the user's
`normal(0, 1) sigma Ya` (`priortab-review-probe4-lane.txt`, T1 and T2;
base T1/T2: 8 rows, one per slot). The resolved entries are still one
per parameter (4 entries, the user's `normal` on `betad 1`), so the
sampled density is right; what is wrong is `prior_summary()` of the
draws and the default-prior announcement, which list a default that does
not apply. The same happens on base for `set_prior(resp = "Ya")` (T3);
the lane turns the plain table round trip into that case. A default's
bound is not carried to a `resp = "Ya"` row either (`keep_default_bounds()`
misses it); no current default bound depends on it (`nu` under logm1
has no box, `priortab-review-probe5b.txt`).

Fix: key `spec_target()` by `brms_stan_name()` too, or normalize `resp`
once when a specification is read.

### MINOR 5. `link_image()` misses softplus and squareplus

brms gives `sigma` `lb = 0` under `link_sigma = "softplus"` and
`"squareplus"`; the lane gives NA (`priortab-review-probe6.txt`), though
both of frmtmb's links hold sigma above 0. Cause
(`priortab-review-probe7.txt`): `linkinv(-Inf)` is NaN for both (the
RTMB `logspace_add` form, and `(-Inf + Inf) / 2`), and the far-point
fallback asks two points to be identical: softplus gives 9.86e-305 at
-700 and 0 at -1400, squareplus 0.00143 and 0.000714. The NEWS rule
"where frmtmb's link holds the parameter" is broken for these two. Fix:
take the end from the link's declared range, or accept a limit of 0
when the two far points shrink toward it.

### MINOR 6. The support box does not reach class `Intercept` or a natural dpar, but the docs say "a coefficient"

`uniform(0, 0.5)` on the centered `Intercept`, `uniform(0, 0.1)` on
`sigma`'s `Intercept` (`sigma ~ x`) and `uniform(0.6, 1)` on class
`sigma` still end in "NA/NaN gradient evaluation" on the lane build
(probe2 B7, B9, B10). The `?set_prior` paragraph and NEWS say a
coefficient with a bounded density is boxed; a reader takes the
intercept for one. Say "a slope (class `b`), not a centered intercept
or a distributional parameter's own class", or extend it.

### MINOR 7. The slopes line says "(flat) where your prior sets none" when the prior sets every slope

`set_prior("normal(0, 1)", class = "b")` covers every slope, and the
line still says some are flat (`test-prior-table-sample.R`, "the slopes
line" case, asserts exactly this). The line should list the slopes left
flat, or be dropped when there are none.

### MINOR 8. A backlog item is marked CLOSED for one third of it

`dev/test-backlog.md` line 1109, "Three spellings frmtmb accepts and
brms refuses": the CLOSED line covers `cor` with `dpar` only. A bound
with `coef` (brms: "Prior argument 'coef' may not be specified when
using boundaries", `brms.txt` 9d, 9g) and class `b` with
`coef = "Intercept"` on `y ~ 1` are still accepted. Word the line as a
partial close ("first spelling only; the other two stay open").
