## Findings

### 1. MEDIUM: `lncor_<resp>` uses the raw response name, not brms's Stan name

`lncor_blocks()` (`R/families-simplex.R`) builds the prefix as
`paste0("lncor_", r)` with `r` the frmtmb response name, and
frmtmb.sample's `draws_lncor_cols()` does the same. Every other
per-response name in the same fit goes through `brms_stan_name()`.
Evidence (`dev/catmulti-rev-mvln2.R`, log `mvln2.txt`; seed 46, n = 300):

- Response `Y_a`: `variables()` gives `sigmab_Ya sigmac_Ya ...
  lncor_Y_a__b__c`; the summary row is `lncor_Y_a(b,c)`. brms 2.23.0's
  own code for this model declares `Llncor_Ya` and `nlncor_Ya`.
- Response `cbind(a, b, c)`: `variables()` gives `sigmab_cbindabc` and
  `lncor_cbind(a, b, c)__b__c`, and the summary row
  `lncor_cbind(a, b, c)(b,c)`. `hypothesis(f3, "lncor_cbind(a, b,
  c)__b__c = 0", class = NULL)` fails: "Some parameters cannot be
  found in the model: 'a', 'b', 'c', 'b__c'". The correlation cannot be
  addressed by name at all. brms names this response `cbindabc`.

Fix: in `lncor_blocks()` set `prefix = if (multi) paste0("lncor_",
brms_stan_name(r)) else "lncor"`; in frmtmb.sample `draws_lncor_cols()`
use the same spelling (`gsub("[._]", "", make.names(r))` if core's
helper is not reachable there). Keep `set_prior(class = "lncor", resp =
)` matching the raw name, which is frmtmb's `resp` convention for every
class (see finding 8). In `tests/testthat/helper-brms.R`
`stan_pars_from_fit()`, map `Llncor_<stanname>` back to the response by
`match(rs, brms_stan_name(names(fit$spec$responses)))`, not by
`fit$spec$responses[[rs]]`, which is `NULL` for `Y_a`. Add tests:
`Y_a` gives `lncor_Ya__b__c` in `variables()`, `summary()` and the draws,
and `hypothesis()` on `lncor_cbindabc__b__c` returns a finite estimate.

### 2. MEDIUM: under `refcat = NA` the degrees of freedom count the flat directions

The lane allows a maximum-likelihood `refcat = NA` fit. Its
log-likelihood equals the reference fit's, but every df-based method
counts the unidentified shift as parameters. Evidence
(`dev/catmulti-rev-na.R`, log `na.txt`, `rev_cat_data(23, 3, n = 300)`;
`dev/catmulti-rev-consumers3.R`, log `consumers3.txt`, seed 21 data):

```
logLik df: NA 6  ref a 4
AIC: NA 626.6884  ref a 622.6884
anova(fa, fn): Df 4 vs 6, Chisq 0, Chi Df 2   (the same model)
drop1 refcat NA: x Df 3 LRT 64.120 p 7.737e-14; z Df 3 LRT 1.448 p 0.6942
drop1 refcat a : x Df 2 LRT 64.120 p 1.193e-14; z Df 2 LRT 1.448 p 0.4847
```

The LRT is right and the df is wrong, so the p-values and AIC are
wrong. With `(1 | p | g)` the overcount also includes the random-effect
covariance (the SE check flags 12 of 12 parameters, `consumers.txt`).
The lane's `drop1()` change reaches this case and its test covers only
the reference parameterization.

Fix: when a categorical or multinomial fit has `refcat = NA` and no
prior on its location dpars, (a) `logLik()` reports the df of the same
model with a reference category (build the frame with `refcat` = the
first category and take its `n_outer_est()`; this needs no refit), and
(b) `drop1()` and `anova()` use that df, or refuse with "under refcat =
NA the predictors are determined only up to a common shift; refit with
a reference category, which has the same log-likelihood". When a
category has its own formula, refuse rather than guess. Add a test:
`attr(logLik(fn), "df") == attr(logLik(fa), "df")` and equal `drop1()`
Df on the two parameterizations.

### 3. LOW: `posterior_linpred(transform = TRUE)` on a two-category categorical is not refused

frmtmb.sample refuses `transform = TRUE` without `dpar` only when
`length(stack) > 1L`. A two-category categorical has one location dpar
(`mub`) and no `mu`, so the call returns the identity-link predictor as
if it were transformed (`consumers2.txt`: dim 200 x 300, range -0.043 to
1.838, which is not a probability). brms 2.23.0 refuses it: "Invalid
argument 'dpar'. Valid distributional parameters are: 'mub'"
(`dev/catmulti-rev-brms2.R`, log `brms2.txt`).

Fix: in `posterior_linpred.frmtmb_draws()` refuse when
`is.null(dpar) && isTRUE(transform) && length(stack) >= 1L` (every family
`draws_mu_stack()` returns has no `mu`), and phrase the second sentence
for one location parameter. Add the two-category case to
`test-linpred-stack.R`.

### 4. LOW: the SE check does not name the flat direction of `refcat = NA`

The findings say "frmtmb's SE check names the flat direction". It does
not. It lists all parameters with the generic reasons: "Standard errors
are not available for 6 of 6 parameters. mua_(Intercept), mua_x, ...:
the likelihood is flat along them ... (a standard deviation at 0 does
this, and so do a mo() simplex split by a category no row is in and
parameters that enter only through a combination)" (`na.txt`). Nothing
says that adding one number to every category's predictor leaves the
likelihood unchanged. Category probabilities keep finite SEs (900 of
900 finite, equal to the reference fit's to 5 significant digits), which
is right.

Fix: add a `refcat = NA` reason to the SE explanation (the family can
record it as `se_explained`, as other known flat directions are
recorded): "under refcat = NA a common shift of every category's
predictor leaves the likelihood unchanged; set a reference category or
a prior on each predictor". Correct the findings sentence.

### 5. LOW (pre-existing, adjacent): `conditional_effects(categorical = TRUE)` on `categorical()` is still refused

The lane routes `multinomial()` through `ce_matrix_mean()`, which reads
`fitted()`'s delta-method `n x 4 x K`. `categorical()`'s `fitted()` has
the same array with the same kind of SEs, yet `conditional_effects(fb,
"x", categorical = TRUE)` refuses: "no analytic standard error for the
category probabilities of family 'categorical': the delta method it
uses is written for ordinal thresholds. Use band = "boot""
(`consumers.txt`; identical on rellib-r9, `base.txt`). brms draws it
(`brms.txt`: columns `x y g cond__ cats__ ...`, levels a b c). Not a
regression. Fix: include `identical(fam[["family"]], "categorical")` in
`ce_matrix_mean()` and drop the refusal for it, with a test against
`fitted(newdata = )`; or file it in `dev/test-backlog.md`.

### 6. INFO: the multinomial clamp makes lower bounds degenerate near p = 0, the SE is right

- The SE is correct. Independent delta method from `vcov()` through
  the softmax, times trials: estimate relative difference 1.4e-16, SE
  max relative difference 9.9e-11 over 750 cells
  (`dev/catmulti-rev-consumers.R`, seed 31, trials 1 to 30). Against
  brms 2.23.0 on the same data (2 chains x 750 draws, max R-hat 1.0013):
  dimnames identical, |z| median 0.023, max 0.102; SE ratio median
  1.009, range 0.956 to 1.044 over 750 cells; 1.013 on the 14 rows with
  one trial (`consumers3.txt`).
- The clamp. With a rare category (seed 41, trials 1 to 6, column
  totals 445 604 34), 57 of 900 Wald lower bounds are below 0 and are
  reported as exactly 0; no upper bound exceeds the trials
  (`consumers2.txt`). Example: row 3, category 3, N = 5, estimate
  0.01423, SE 0.00738, Wald [-0.00023, 0.02870], reported [0, 0.02870].
  The clamp hides no SE error, but it gives an interval that touches 0
  for a count the model says is positive. brms's bounds are quantiles
  of draws, in range by construction and asymmetric. This is the same
  rule categorical's probabilities have used since before this lane, so
  it is consistent. A follow-up could form the interval on the log or
  logit scale of the probability.

### 9. MEDIUM, NEW: `loglik_df()` fails on any transformed term, so AIC, anova and drop1 are lost

`loglik_df_na()` assembles the reference twin from
`object$frame[["data_frame"]]`. That is the MODEL frame, whose columns
are `y` and `log(x2)`, not the raw variables (`fit$data` is the same
model frame: `names(fit$data)` is `y log(x2)`, `r1b.txt`). Any term
that has to re-evaluate a raw variable then fails, and the df becomes
`NA` with an internal error as its reason (`r1.txt`, `r1b.txt`, seed 5,
n = 400):

```
y ~ poly(x, 2) + log(x2)   NA df NA (why: The model uses `x`, which is not a column of `data` ...) | ref df 8 | AIC NA vs 811.6332
y ~ scale(x) + I(x2^2)     NA df NA (why: The model uses `x`, ...)  | ref df 6 | AIC NA vs 813.4345
y ~ log(x2)                df NA (why: The model uses `x2`, ...)
update(f1, . ~ . + log(x2)) NA df NA                                 | ref df 6 | AIC NA vs 809.2229
```

Round 1 gave these models a wrong df. This round gives them none:
`AIC()` and `BIC()` return `NA`, and `anova()` and `drop1()` refuse.
Every case without a transformation passes, and the numbers match the
reference fit exactly: plain `x`, `offset(x2)`, `s(x, k = 5)` (df 6 and
6), `subset(keep)`, `weights(w)`, rows with missing values, `(1 | p |
g)` (df 7 and 7), `(1 || g)` (6 and 6), multinomial (4 and 4), data
removed from the workspace after the fit, a predictor found in the
workspace, priors (df 4). Assembly is cheap: on n = 50000 the first
`logLik()` takes 0.05 s and the cached call 0.000 s.

Exact fix: count the reference twin at FIT time, in `frm()`, where the
original data are in hand. When a family carries `refcat_first`,
assemble the twin's frame from the same data, `data2`, `na.action` and
subset, and store `frame_n_outer(twin)` on the frame (for example
`frame[["refcat_first_n_outer"]]`). `loglik_df()` then reads that
number and never re-evaluates the formula. Keep the `NA` with a reason
only for a category's own formula and for a multivariate fit, and word
that reason for the user, not as a data-lookup error. Add tests on
`y ~ poly(x, 2) + log(x2)` and `y ~ scale(x)` that `attr(logLik(fn),
"df")` equals the reference fit's and that `AIC()` is finite.
