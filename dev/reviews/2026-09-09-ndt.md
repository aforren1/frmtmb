### R2-1. The hash does collide, I built one, and it is still a nit

`dev/rev-ndt-collide.R` and `dev/rev-ndt-collide2.R`, exhaustive over
stated sets, no seed. `dev/rev-ndt-absent.R` uses the result.

The floor table is now keyed on a code derived from the group's LABEL:
two polynomial rolling hashes, base 131 modulo 33554393 and base 137
modulo 16777213 started at 1, packed as `h1 * 2^24 + h2`. Every number
below came from a vectorized copy of that function that was checked
against the package's own `ddm_label_code()` before it was trusted.

**A collision exists and here it is.** Meet in the middle over a
four-position difference box of side 6401, which the lattice count says
should hold 2.98 solutions and which held five candidates, one valid:

```
label A code points  11860  8855  8973 14299
label B code points  12000 12000 12000 12000
ddm_label_code(A) = 93108023994132
ddm_label_code(B) = 93108023994132
```

**Where the guard can see them it fires.** With both labels in one
column the fit is refused by name and both labels are printed:
"ndt_group(): the group labels ... collide under the code this term is
keyed on, so they cannot be told apart. Rename one of them."

**Where it cannot, the round-one defect returns one layer down.** Label
A fitted, label B on newdata only:

| newdata row | `ndt_time()` | `predict(type = "response")` |
|---|---|---|
| the fitted label A | 0.276338 | ran |
| the colliding label B | **0.276338** | **0.722571** |
| an ordinary unseen label | refused | refused |

Label B is silently scored against label A's bound. `R/ddm-shared.R`
predicts exactly this in its own comment and puts the rate at 2^-49.

**Two measurements say why that is a nit rather than a blocker.**

First, short labels cannot collide at all, and it is arithmetic rather
than luck. For a label of n printable ASCII characters neither hash
wraps until n = 4: at n = 3 the largest h1 is 2,178,918 against a
modulus of 33,554,393 and the largest h2 is 4,953,635 against
16,777,213. Below its modulus the code is a base-131 numeral whose
digits are smaller than its base, which is injective. All 866,495 labels
of one, two or three printable ASCII characters were hashed:
**0 duplicates.**

Second, structured identifiers do far better than the birthday count.
All 10^8 labels `S00000000` through `S99999999` were hashed, where the
birthday count over a space of P1 * P2 = 5.63e14 predicts 8.88 colliding
pairs. **0 found**, in 368 s. Not luck either. A collision is a nonzero
integer vector of per-position code-point differences lying in the
lattice

    { d : sum d_k 131^(n-k) = 0 mod P1, sum d_k 137^(n-k) = 0 mod P2 }

whose determinant is P1 * P2. A family whose labels vary in L positions
over an alphabet spanning s code points offers a difference box of
volume (2s+1)^L, and the expected number of nonzero lattice points in it
is that volume divided by 5.63e14:

| family | difference box | expected collisions |
|---|---|---|
| eight digits | 19^8 = 1.7e10 | 3e-05 |
| ten digits | 19^10 = 6.1e12 | 0.011 |
| four printable ASCII | 189^4 = 1.3e09 | 2.3e-06 |
| four positions, span 6401 | 6401^4 = 1.7e15 | 2.98 |

The construction had to reach the last row to succeed. The practical
residual is 1.8e-15 per pairing of an unseen label with a fitted group,
thirteen orders of magnitude below the smallest other error rate this
package quotes, and it is stated in the source rather than hidden.

The fix the coordinator names, keying on the label itself, is still the
better answer and it is not free: the addition-term registry's coercion
has to return numbers for the tape and is stateless, so it cannot hold a
fitted label set. Recording the fitted labels on the family and checking
them wherever the labels are still in hand is the shape of it. Worth an
item; not worth holding the merge.

## BLOCKERS

### B1. `droplevels()` silently gives every row another group's bound

`dev/rev-ndt-levels.R`, seed 808, 900 trials, three groups. This is the
defect the change exists to remove, in the code the change added, on the
path its own comment declares safe.

`ddm_coerce_ndt_group()` refuses a character or logical column with a
correct argument: such a column "would be coded on the levels PRESENT in
whatever data frame it is evaluated in", so newdata holding a subset
"would then pair a row with another group's bound, silently". It then
codes a FACTOR with `as.integer()`, that is by the level INDEX, on the
argument that "a factor is read on its LEVELS, which a data frame
carries through a subset".

A data frame carries the level SET through `[`. It does not carry the
level ORDER through `droplevels()`, `relevel()`, or a factor the user
builds for a prediction grid. Each of those permutes the indices and the
same defect follows.

Fitted floors: `s1` 0.317840, `s2` 0.325382, `s3` 0.324485. The floor
table the fit captured is keyed `1`, `2`, `3`.

| newdata, the SAME two rows `s2` and `s3` | `ndt_time()` | fitted mean |
|---|---|---|
| `d[d$g != "s1", ]` | 0.286143, 0.285354 | 0.695233, 0.694445 |
| ... then `droplevels()` | **0.279511, 0.286143** | **0.688601, 0.695233** |

After `droplevels()` every row is paired with the previous group's
bound: `s2` gets `s1`'s and `s3` gets `s2`'s. `relevel(ref = "s3")` on
three rows permutes the three answers the same way. Nothing warns.

It is not confined to `ndt_time()`. `predict(type = "response")`, that
is the fitted mean response time, moves too, because the frame's
`ndt_floor` is rebuilt from the coerced codes on the newdata path.

`droplevels()` after subsetting subjects is ordinary R. A user who fits
on all subjects and predicts on a subset is the exact case the per-group
bound was built for.

What would fix it: the code has to be a pure function of the group's
LABEL, not of its position in whatever frame it was evaluated in. Either
key the floor table on a label-derived code, or record the fitted level
set in `ndt_bound` and refuse newdata whose levels differ, or refuse
factors outright and require integer codes the user controls, which is
what the refusal message already tells a character-column user to do.
Whichever it is, the character and logical refusal should say the same
thing about factors, because today it points a user at the one spelling
that is broken.

### B2. A prior on `ndt` silently means something else, and still fits

`dev/rev-ndt-prior.R`, seed 4242, 400 trials, `min(rt) = 0.334522`.
SPEC.md section 5 promises that "brms code ports mechanically, priors
included", and that a distributional parameter's own class is "a density
on that PARAMETER, carried through its inverse link". The inverse link of
`ndt` used to yield a time and now yields a fraction, so the same row is
now a density on a different quantity. Nothing refuses and nothing warns.

| prior, written the way a brms user writes it | 0.6.0 | this branch |
|---|---|---|
| none | `ndt` = 0.295562 s | 0.295562 s |
| `normal(0.30, 0.01), class = "ndt"` | **0.296152 s** | **0.106955 s** |
| `normal(0.10, 0.01), class = "ndt"` | 0.160604 s | 0.039808 s |
| `normal(0.85, 0.01), class = "ndt"` | 0.327087 s | 0.286320 s |
| `normal(0, 0.1), class = "Intercept", dpar = "ndt"` | 0.206032 | 0.206032 |

The last row is the control and it is bit-identical, correctly: that
spelling is a density on the LINEAR PREDICTOR, and the linear predictor
did not move, because `log(ndt / (ub - ndt))` and `log(f / (1 - f))` are
the same number.

The first row is the defect. A user who wrote "the non-decision time is
about 300 ms" gets 107 ms, a fit that converges, and no message. To
express the same belief now they must write `normal(0.85, 0.01)`.

`NEWS.md` lists "a prior on one" under **What stops working**. Nothing
stops. The four help pages do not mention priors at all
(`grep -n prior R/wiener-family.R R/ddm-shared.R R/lba.R R/rdm.R
R/wiener-gng.R` finds one comment about the prior-predictive path).

What would fix it: refuse `class = "<dpar>"` on `ndt` by name for these
four families, with a message that says the parameter is a fraction and
points at `ndt_time()`; or divide the prior's location by the bound.
A refusal is enough and is cheap.

## The acceptance criterion: is `sd(ndt)` recovered by the model?

`dev/rev-ndt-floors.R`, seed 20260908, the tier's own design and its own
truths, 30 subjects at 100, 200 and 400 trials. Three arms on the SAME
data:

- `re`, `ndt ~ 1 + (1 | s)` with `ndt_group(s)`, which is what ships;
- `nore`, `ndt ~ 1` with `ndt_group(s)`, which has NO random effect on
  `ndt` at all, so every scrap of between-subject spread it reports is
  the floors;
- `global`, `ndt ~ 1 + (1 | s)` with no grouping, which is 0.6.0.

`nore` is the estimator the criterion has to beat. It was not built by
the lane; the lane's own falsification is a different design at 15
subjects and 250 trials.

| trials | arm | logLik | `sd(ndt)` | per-subject RMSE | corr with truth |
|---|---|---|---|---|---|
| 100 | `re` | -1887.866 | 0.03198 | 20.91 ms | 0.7770 |
| 100 | `nore` | -1887.866 | 0.03198 | 20.91 ms | 0.7770 |
| 200 | `re` | -3704.555 | 0.02882 | 14.08 ms | 0.8970 |
| 200 | `nore` | -3704.934 | 0.02957 | 15.68 ms | 0.8716 |
| 400 | `re` | **-7003.008** | **0.02543** | **7.67 ms** | 0.9607 |
| 400 | `nore` | -7011.446 | 0.02748 | 11.90 ms | 0.9092 |

Truth: `sd(ndt)` 0.02629.

**At 100 trials the two arms are identical in every digit printed.** The
variance component collapses to zero and the shipped model IS the
floors-only model. Whatever "recovers `sd(ndt)`" means there, the model
did not do it.

**At the tier's own 400 trials the random effect is not free.** It buys
8.44 log-likelihood units at one more parameter, cuts the per-subject
RMSE from 11.90 ms to 7.67 ms, a 36 percent reduction, and lifts the
correlation with the truth from 0.909 to 0.961. That is a real
contribution and it is larger than the 0.2 ms of 8.0 ms the lane's own
15 x 250 study found. The lane undersold its model on this axis.

**But the criterion as written is still not diagnostic.** The number the
plan asks for is `sd(ndt)`, and the floors-only estimator returns 0.02748
against a truth of 0.02629, a 4.5 percent overshoot, where the shipped
model returns 0.02543, a 3.3 percent undershoot. Both "recover" it. The
floors-only figure is arithmetic: `sd(floor)` is 0.03231 and the common
fitted fraction is 0.8497, and 0.03231 x 0.8497 = 0.02746. A criterion
that a model with the variance component switched off passes is a
criterion met in appearance.

**Verdict on the criterion.** Met, and the deliverable behind it is real,
but `sd(ndt)` is the wrong statistic to have asked for and the plan's
row should say so. The statistics that DO separate the model from its
floors are the per-subject RMSE and the log-likelihood, and both should
be what Phase 2 asserts. This has to be said in `NEWS.md` and in
`?wiener`, not only in `dev/ndt-findings.md`. Today `NEWS.md` prints
"`sd(ndt)` on the natural scale, truth 0.0263 | 0.0058 | 0.0254" with no

## Is the floor a bound whose bias moves with the trial count?

Same run. The floor's overshoot as a ceiling does shrink with trials,
and the lane's table said so. What the lane did not check at the MAIN
design is whether that propagates into the estimate:

| trials | floor overshoot | `re` bias | `re` RMSE | above the GLOBAL floor |
|---|---|---|---|---|
| 100 | 63.68 ms | +6.59 ms | 20.91 ms | 18 of 30 |
| 200 | 59.02 ms | +6.40 ms | 14.08 ms | 13 of 30 |
| 400 | 47.08 ms | +2.69 ms | 7.67 ms | 20 of 30 |

The population bias is +2.7 to +6.6 ms on a truth of 250 ms, that is 1
to 2.6 percent, and it SHRINKS with trials, as does the RMSE. The floor's
47 to 64 ms overshoot does not reach the estimate, because the fitted
fraction absorbs it. So the answer to "a bound that tightens as n grows
is a bound whose estimates move with sample size for a reason that is
not information" is: they move, in the direction and by the amount more
information buys, and not by the amount the bound tightens.

And the lane's exoneration argument holds at the main design in the
lane's favour rather than merely neutrally. On design B the lane showed
the global arm carries the same -23.9 ms bias, so the bias is the
design. At the MAIN design the two arms are not the same at all. The
third arm of the same run, on the same data, is 0.6.0:

| trials | arm | logLik | bias | `sd(ndt)` | RMSE | corr |
|---|---|---|---|---|---|---|
| 100 | `global` | -1926.759 | -15.09 ms | 0.00659 | 27.23 ms | 0.587 |
| 200 | `global` | -3755.676 | -7.62 ms | 0.01241 | 20.51 ms | 0.721 |
| 400 | `global` | -7149.635 | -19.46 ms | 0.00578 | 30.37 ms | 0.533 |

The per-group bound wins on every metric at every trial count, and the
difference that matters most is the last column of the previous table
against this one: **the per-group arm's per-subject RMSE halves as the
data grows, 20.91 to 14.08 to 7.67 ms, and the global arm's does not,
27.23 to 20.51 to 30.37 ms.** The global bound does not converge on the
truth with more data, because more data lowers the global minimum and
tightens the ceiling on every subject at once. That single comparison is
the strongest evidence for this change that I found, and the lane did
not produce it.

The rescale in that arm is worth recording as a trap: the first version
of `dev/rev-ndt-floors.R` read the global arm's
`predict(dpar = "ndt", type = "response")` as a time, because on this
build it is a fraction even with no `ndt_group()`, and reported a
+740 ms bias. That is B2 and B3's failure mode reproduced by a reviewer
who knew about it, in a script written to look for it.

## Item 1.0b, `rlddm()` in frmtmb.learn

Can proceed, with one addition to the lane's list. The lane names four
`@noRd` functions the sibling needs (`ddm_ndt_spec()`,
`ddm_ndt_scaler()`, `ddm_ndt_install()`, `ddm_ndt_preinstall()`) and
says the export seam has to come first. That is right, and the shape of
the seam is now measurable rather than a guess, because
`test-extension-api.R` had to change in exactly the way a downstream
consumer will: reaching into `wiener()$lpdf` directly now requires
`wiener(max_ndt = 1)`, because a family with no settled bound refuses to
score. Any extension that reads another family's density slot outside
`frm()` is in that position. The seam therefore needs a fifth entry: a
supported way to obtain a scoreable family with a stated bound, which
`ddm_ndt_preinstall()` already is, and it should be exported under a
name that says so.

Nothing else here blocks 1.0b. `ndt_group` is registered by
frmtmb.eam's `.onLoad()`, so a package that depends on frmtmb.eam has
the term, and `rlddm()` inherits the registered coercion rather than
copying it.

That last point is the reason to fix B1 in THIS lane. `rlddm()` will
share `ddm_coerce_ndt_group()` and the floor table keyed on level
indices, so it inherits the `droplevels()` defect the moment it takes
the bound, and a second family carrying it is a second family to
migrate when the keying changes. B2 and B3 land in `rlddm()` the same
way, since a reinforcement-learning drift model is exactly the kind of
model people put a prior on.

### R2-11. The version bump and item 1.0b, revised

Round one said major, or minor with two refusals in place. Round two
makes it **clearly minor**. Nothing a 0.6.0 model can express changed:
a model without `ndt_group()` is bitwise the same fit, a prior on
`class = "ndt"` still means seconds, a pinned constant still means
seconds, and `predict(dpar = "ndt", type = "response")` still reports
seconds. What is added is one addition term, one export, one refusal and
one behavior that only appears when the new term is written. That is an
addition, not a break, and the NEWS heading and the `?wiener` sections
say which of the two parameterizations a reader is in.

Item 1.0b can proceed. Round one asked for a fifth entry in the export
seam, a supported way to obtain a scoreable family with a stated bound;
that is still wanted, and `ddm_ndt_preinstall()` is still the thing to
export, because `test-extension-api.R` reverting to `wiener()` without
`max_ndt` shows the pre-change contract is back and a consumer reaching
into `$lpdf` outside `frm()` still meets the refusing link. `rlddm()`
will inherit `ddm_coerce_ndt_group()` and the label codes, so it
inherits R2-10 as well; that is a reason to write the item down now
rather than a reason to hold either lane.
