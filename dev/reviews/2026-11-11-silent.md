## Findings

### MAJOR 1 (3874): a lower truncation bound moves the default knots and refuses valid knots

`cox_read_bounds()` adds every `trunc(lb = )` above 0 to the bounds
that the knots must cover. The default lower knot then drops to the
smallest entry time, and a `Boundary.knots` with a lower knot above an
entry time is refused. The lower side does not need this. Below the
lower knot, `cox_cb_entry()` gives H = 0, and the model has zero
hazard there for every row anyway (for an untruncated row, on
`[0, lower knot)`). So `S(y) / S(lb)` with `H(lb) = 0` is exact under
the model. Only the upper side is defective: an interval upper bound
or a `trunc(ub = )` past the last knot gives a survivor function that
stays constant above the knot. Base shows this: S0 is 0.0001218 at
both 13.13 and 17.51.

Reproducer: `dev/reviews/silent-review-coxtrunc.R` (log `coxtrunc.log`).
Delayed entry is `entry = time / 2` and the times are shifted by 2.
The code is the test's own setup with seed 11, n = 200:

```
lane default knots 1.000221 10.92904  internal 2.77058  frmtmb logLik -215.6089451  hand -215.6089455
brms default knots 1.825371 10.92904  hand -189.1194011
```

The likelihood is correct on the knots that the lane chose: frmtmb
agrees with a hand-written likelihood (splines2 I/M-splines, BFGS from
8 starts) to 4e-7. But that default is 26.49 log-likelihood units
worse than brms's default knots, with the same df. In
`silent-review-cox.R`, on the same data, base gives logLik -192.7085
and the lane gives -218.5710. Passing brms's own default knots
explicitly is refused on the lane (`cox-lane.log`):

```
TRUNC brms knots given: ERROR: cox(): the boundary knots of the baseline basis, 1.825371, 10.92904, must cover every time the likelihood reads, and the interval-censoring and truncation bounds run from 1.000221 to 5.376986. ...
```

Delayed entry is the usual reason to use `trunc(lb = )` in survival
data. On such data, the change moves the default model away from brms
and away from the better fit, and it refuses knots that are correct.

Fix: in `cox_read_bounds()`, read only the upper bounds. These are
`cens_y2` of the code-2 rows and finite `trunc_ub`. A lower bound
cannot lie above the upper knot, because `lb < y`. Then update
`test-cox-bounds.R` ("a truncation bound is read like an interval
bound" asserts the lower widening and the refusal), the cox Rd
paragraph and the survival NEWS bullet ("a truncation bound").

### MAJOR 2 (4235, add1): adding a new random-effect term silently fits a different model

`add1.frmtmb_fit()` passes the label `1 | g` from `add.scope()` to
`add1.default()`, which runs `update(object, ~ . + 1 | g)`. That parses
as `(. + 1) | g`, so the refit is `y ~ (x + 1 | g)`: the fixed slope is
dropped and a random slope with a correlation is added. The table
shows no sign of this.

Reproducer: `dev/reviews/silent-review-add1re.R` (logs `add1re-lane.log`,
`add1re-base.log`; seed 11, n = 200):

```
       Df    AIC    LRT  Pr(>Chi)
<none>    781.27
1 | g   2 656.65 128.62 < 2.2e-16 ***
hand y ~ x + (1|g): LRT 133.5373 Df 1
hand y ~ (x + 1 | g): LRT 128.6162 Df 2
update(f1, ~ . + 1 | g) formula: y ~ (x + 1 | g)
```

Base gives the same output, so the lane did not cause this. But the
lane's findings and NEWS say that `add1()` no longer offers `(1 | g)`
"as fixed". That is true only when the fit already has the term. The
character spelling (`add1(f1, "1 | g")`, which step() uses) does the
same thing.

Fix: in `add1.frmtmb_fit()`, wrap each scope label that contains `|`
in parentheses before it calls `add1.default()`, for both the formula
and the character scope. As an alternative, refuse bar terms with a
message. Add the hand-refit row to `test-drop1-specials.R`.

### MINOR 1 (1562): NEWS leaves out the univariate `mi()` change

NEWS says "In a multivariate model". `df.residual()` and `anova()`
change on a univariate `y | mi()` fit too
(`dev/reviews/silent-review-mianova.R`, seed 9, n = 120, 4 missing y):

```
base df.residual mi fit 117 ...  anova(mi fit, complete-case fit): anova() needs fits with the same number of observations (got 120, 116) ...
lane df.residual mi fit 113 ...  anova(mi fit, complete-case fit): ran, Chisq 0.0809
```

The new behavior is correct, because both likelihoods are on the same
116 rows. But it is undocumented and untested. Add it to the NEWS
bullet, and add one assertion.

### MINOR 2 (1562): `anova()`'s "same data" guard is still a count

On both arms, `anova()` accepts a fit on rows 1..72 against a fit on
rows 9..80, because both counts are 72
(`dev/reviews/silent-review-nobs.R`, case E: "ran" on both arms). The
lane's change does not make this worse. Comparing the set of rows (the
union `loglik_nobs()` already builds) instead of its length would close
it. File it.

### MINOR 3 (650): `method = "traditional"` and `rotation` through `...` silently break the censored residual

`dharma_residuals()` passes `...` to `createDHARMa()`. On a correct
right-censored gaussian fit (`dev/reviews/silent-review-trad.R`, seed 5,
94 of 300 rows censored):

```
PIT: ... KS p 0.86
traditional: ... KS p 2.32e-25
rotation: KS p 2.27e-14
```

The Rd says that "traditional" "is not the residual described here",
but the call still returns it. `rotation` is not mentioned at all, and
it mixes rows before the tie rule applies. Refuse both on a fit with a
censored row.

### MINOR 4 (1562): readers of n now disagree on one fit

On case A, `nobs()` and `insight::n_obs()` give 80, and
`attr(logLik(), "nobs")` (read by `BIC()`) gives 72. So the AICc of
`performance::` (it reads `insight::n_obs()`) uses 80, and `BIC()` uses
72. brms's `nobs()` is 80, so keeping 80 there is right. Say in
`?logLik.frmtmb_fit` / `?nobs.frmtmb_fit` which count each one gives.
