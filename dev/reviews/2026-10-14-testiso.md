## Findings

### 1. The narrowed compat tests leave two contributed promises unchecked in every suite (Medium)

The registration-time validation the lane cites exists and is tested.
`compat_check_rules()` (`R/compat.R:498`) refuses an unknown bare
name, a `kind:` outside `frmtmb_compat_kinds`, an unknown `group:`, a
self pair and an unknown status. test-compat-register.R pins it ("a
rule naming a feature outside the vocabulary is refused", line 34; "a
rule pattern names a real kind and a real group", line 94). So
dropping contributed rows from "rule patterns name real kinds, groups,
and features" is sound. A contributed pattern that names nothing
cannot be registered.

Two things are now checked nowhere:

- A contributed rule whose side is in `expects =` but misspelled. It is
  exempt at registration by design. "every rule wins" now excuses it
  under any load set, because the side stays in
  `compat_unresolved_sides()` forever. `frm_compat()` reports it in its
  `unresolved` attribute, but no test asserts that attribute is empty
  when every owner is loaded.
- A contributed `method` feature that names no function. Registration
  checks only the kind, and no extension suite checks its own method
  rows. The surface tests of coupling, learn and spline check `key`
  membership and statuses, not that the function exists. The defect
  exists today: frmtmb.spline's `frm_curve_contrast` is found in no
  namespace (probe: `method frm_curve_contrast found in: NOWHERE`). The

### 2. The release gate's LEAK rule tags global and search-path leaks as namespace loads (Medium)

`leaks()` in `dev/release/run-session.R` tags every key except options
and environment variables with the `frmtmb*` namespaces the file loaded.
That includes `globals` and `search path`. A namespace load creates no
global and attaches nothing. round-handoff.md passes a release when
"every LEAK line ends in `[with load of ...]`". So a file that loads
any extension can leak a global or attach a package and still pass.
Attaching was the very dependence of the old "declared post-fit
methods are callable" test.

Evidence: `dev/testiso-rev-tag/` (deleted) held two files.
`test-leaky.R` loads frmtmb.latent, assigns a global and calls
`library(frmtmb.spline)`. `test-plain.R` assigns a global and loads
nothing. Log `dev/testiso-rev-tag.txt`:

```
LEAK test-leaky.R search path: +package:frmtmb.spline - [with load of frmtmb.latent frmtmb.spline]
LEAK test-leaky.R globals: +zz_leaked_global - [with load of frmtmb.latent frmtmb.spline]
LEAK test-plain.R globals: +zz_leaked_global2 -
```

Fix: in `leaks()`, never tag `globals` or `search path`
(`by <- character(0)` for those keys). For the registry keys, which the
lane names as a limitation (the sample preflight case), add a third
order, `preload`. It loads all seven extensions before the first file,
so no file loads an `frmtmb.*` namespace and every registry LEAK in that
order is the test's own. That is `dev/testiso-filecheck.R`'s method,
applied to the suite. Make the `preload` order part of the
round-handoff gate. With it, the sample preflight leak would have been
seen.

### 4. `local_frmtmb_registries()` deletes the registrations of an extension that loads inside its scope (Low)

Evidence: `dev/testiso-rev-probe.txt`, part 2, in a child process. A
scope that loads frmtmb.eam leaves this state:

```
inside: dec registered = TRUE
after: eam loaded = TRUE | dec registered = FALSE
after: y | dec(d) with frmtmb.eam loaded: ERROR: Addition term `dec()` is not supported ...
```

No current caller loads inside a scope (test-cens-trunc.R,
test-compat-register.R, test-compat.R and test-parse.R contain no
`loadNamespace`, `requireNamespace` or `skip_if_not_installed()` of an
extension inside a scope). But lane-rules.md now prescribes the helper
for every test that registers. A later test that calls
`skip_if_not_installed("frmtmb.eam")` inside such a scope reproduces
0.71.0's failure in the other direction. Also, helper-rl.R's
`teardown_env()` scope spans the whole run. At the run's end it removes
the entries of every extension the run loaded. That does no harm under
covr or R CMD check, where the session ends. It does harm a
`devtools::test()` session, which continues with the extensions
loaded and their registrations gone. The lane's notes do not mention
this case.

Fix: record `loadedNamespaces()` when the scope opens. When it closes,
restore, and then for each `frmtmb.*` namespace that appeared, run its
registration again (`asNamespace(p)$.onLoad(dirname(find.package(p)),
p)`). The restore removed the entries, so the rerun adds one copy.
The other option is to `stop()` and name the namespace, so the author
moves the load in front of the helper. Say in the helper's header
which option it uses.

### 5. A renamed registry makes the helper and the runner do nothing, silently (Low)

`ns$frmtmb_compat_contrib` returns NULL for a name the namespace does
not hold. `contrib$features <- saved$features` on NULL then modifies a
local list and gives no error (`dev/testiso-rev-probe.txt`, part 3:
"save and restore through an absent name: no error"). `snap()` would
compare NULL with NULL for ever.

Coverage today is complete for core. A grep of `R/` for top-level
`new.env()` finds nine environments:

- Five registries the helper saves: `frmtmb_compat_contrib`,
  `frmtmb_aterm_registry`, `frmtmb_frame_checks`,
  `frmtmb_prior_defaults`, `frmtmb_notice_state`.
- `frmtmb_compat_cache`, which the helper also saves.
- `compat_accepts_cache`, which is validated against the contributed

in `.onLoad` (`marginaleffects_model_classes`) and in `R/conditions.R:267`

Add a test that lists the top-level environments of the frmtmb

registry then fails a test until the helper covers it. One list in
`R/` (internal, reached as `frmtmb:::`) would also let
frmtmb.ode's and frmtmb.sample's tests stop carrying their own copies
of the save-and-restore code.

### Remaining fixes

**R1. The spline rename breaks the vocabulary's own conventions (Low-Medium).**
It is a user-visible change. `frm_compat("frm_curve_contrast")` now
errors (`Unknown feature: 'frm_curve_contrast'`, with no near-miss
suggestion). `frm_compat("frm_curve(contrast =)")` returns 133 rows,
and its `s()` row reads `works`. The spelling without the space,
`"frm_curve(contrast=)"`, is refused (`dev/testiso-rev2-spline.txt`).
So the BREAKING bullet is accurate, and it names the new query.

But the new name has two problems:

- It breaks the documented key rule. `frm_compat_features()` gives
  the row the key `frm_curve(contrast =)`, while `R/compat.R`

### The hook-based load order: correct

`dev/testiso-rev3-hooks.R` runs one fresh process per case. The hook
counts are listed for the seven extensions in alphabetical order.

| case | result |
|---|---|
| error inside the scope | hooks `0,0,0,0,0,0,0` before and after; `dec` registered after the error (the rerun ran in the deferred block) |
| another package's hook on frmtmb.eam | hooks `0,1,0,...` before, during and after; that hook fired once |
