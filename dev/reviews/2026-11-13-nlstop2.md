## Attack 1: pole escape (5079)

Script `nlstop2-review-pole.R`, logs `pole-after.txt`, `pole-before.txt`,
`ob0326-pole-after.txt` (OpenBLAS 0.3.26 + LAPACK);
`nlstop2-review-pole2.R`, `pole2-after.txt`, `pole2-before.txt`.

Confirmed:
- binomial mm 11 and 44: before -623.288529 (K -0.1825) and -626.898840
  (K -0.1103), silent; after -618.966489 (K -6.0152) and -625.980024
  (K -6.4531), message `frmtmb_nl_pole_start`, no warning. Same values
  under OpenBLAS 0.3.26.
- `Vm * xp * (K + xp)^-1` (negative literal power): same two escapes.
- Fits clear of poles are bit-identical to 0.82.0 in logLik (17 digits),
  estimates and SEs (10 digits), messages and warnings: mm gaussian 11,
  22, 55; `a / (1 + b * x)` with b at 0.95 / max|x|, seeds 1 to 5; `a / (x
  + b)` with b near the wall -0.1 (true b -0.095), seeds 1 to 3; the
  `K^2 + xp` and `exp(-1 / (K + xp))` bodies; `K ~ 1 + (1 | g)`.
- `a / (1 + b * x)` is not exempt by a pattern: the decision is the
  rule (denominator of mixed sign, or the fit nearer a wall than the
  median gap). The rows above near the walls are not moved.
- Two coefficients in one denominator, `a * xp / (b + c * xp)`, from
  given starts between the poles (the default start fails with NA/NaN on
  both arms): after warns `frmtmb_nl_pole` on 3 of 3 short starts
  (-627.16, -639.50, -641.26 against -618.97 and -625.98); before silent
  apart from the identification warning both arms give.
- A restart is kept only if it gains more than `nl_probe_gain()` and both
  the run and the refit end clear of the band; the refit's logLik must be
  finite. No case returned a worse fit or a non-finite one.
- `restarts = 0` and `options(frmtmb.nl_sign_probe = FALSE)` do not stop
  the pole restart (mm 11 still escapes). Consistent with the sign probe;
  the switch is the 5718 consolidation item.
- `optimizer = "optim"` is excluded by design; mm 11 stays at -623.288529,
  code 0, silent, on both arms.
- The thresholds (`1e-8` second difference, `1e-12` slope, `dist < gap`)
  decide whether restarts run, not the answer: a restart must gain 0.01.
  No rounding-decided verdict found under OpenBLAS.

Not covered (pre-existing, both arms identical, not filed):
- `a / (x + b)` with the true pole inside the data (y = 1 / (x - 2) +
  noise, x in [0, 4] minus |x - 2| < 0.3, seeds 1 to 3): the default fit
  stops at b 0.386, 0.481, 0.371, logLik -543.82, -525.22, -589.07, code
  0, no warning, no message. From start (1, -1.9) the fit reaches 47.73,
  66.61, 57.33 at b -2.004, -2.011, -2.002: 591, 592 and 646 short, in
  silence. The fit is clear of the band (all denominators positive), so
  the escape, which starts only from outside the band, never looks
  inside it. See F4.
- binomial mm with `K ~ 1 + (1 | g)` seed 11: -624.730349, warned
  (generic `frmtmb_warning`) with `frmtmb_nl_multistart`, 5.76 below the
  fixed-K model's -618.966489, which it nests. The walls are read with
  the random effects at 0. Warned, so LOW; seed 44 fails from the
  default start on both arms.

## Attack 2: the limit check (5093)

- explin: on 12 ulp draws of y (`pole-after.txt`), 4 end at code 0 with
  `frmtmb_nl_limit` (k 0, 5, 8) or `frmtmb_conv_gradient` (k 3), 8 at
  code 1 with the optimizer's warnings; `nl_limit_message()` called
  directly is non-NULL on all 12. On 0.82.0 it is NULL on all 12. Under
  OpenBLAS 0.3.26 (`ob0326-pole-after.txt`): 11 at code 1, 1 (k 7) at
  code 0 with `frmtmb_nl_limit`, direct check non-NULL on all 12. So the
  verdict is not BLAS-dependent; only the ending is. But the test is
  (F1).
- Hill: the lane's own profile (`dev/nlstop2-out/hilldbg3.txt`) reads
  "profile h x 2: gain 0.00175847 code 0": the fit is 1.76e-3 below a
  point with h doubled, above `grad_tol` (1e-3), at code 0 with no
  warning. No limit warning is right (h x 4: -0.147, h x 8: -Inf), but
  "the fit is a maximum" is not (F3).
- False positives: the lane's limit battery (1680 fits) moved 4 Cstart
  rows to `frmtmb_nl_limit`, each a fn_explin/fn_mmlin limit row; the
  new fresh-row warning (binomial sat_z 44) is at the reference value.
  The new code only lowers the moved objective (min of the move and the
  move plus one Newton step), so it can only add warnings, and only
  where a point 1000-fold along the flattest direction is within
  `grad_tol` of the fit, which is the claim the warning makes. The gate
  (quadratic model of the move at most 1e3 grad_tol) is unchanged up to
  rounding. No false positive found.
- Cost: 0.3 ms per call (lane, `cost-limit2.txt`), with a control arm.
  Accepted.

## Attack 3: huber() route (5065), now a revert

Measured before the user decision (logs `huber-*.txt`, `huber2-*.txt`);
kept here as the evidence for the docs item:
- `bf(y ~ x, sigma ~ (1 | g))`, seeds 1 to 10: after, 6 of 10 ERROR
  "quadrature = TRUE could not marginalize this model" at scale 1 and 6
  of 10 at scale 1e3; on 0.82.0 all 20 fit (scale 1 seeds 3, 6 and scale
  1e3 seeds 3, 5, 6, 7 at code 0 with no warning).
- `huber(link = "log")` with `(1 | g)`, seeds 1 to 5: after, 4 of 5
  ERROR; on 0.82.0 all fit (seeds 2, 5 at code 0, no warning).
- On a routed `(1 | g)` fit, `predict()`, `fitted()`, `residuals()`,
  `frm_linpred(se.fit = TRUE)` and `marginaleffects::avg_slopes()` now
  warn (group effects held at their modes); `vcov_cluster()` refuses.
  None did on 0.82.0.

(a) Accuracy of the lane's doc text. The numbers in `?huber`, the NEWS
bullet and `huber_quad_route()`'s comment match the logs: 11 of 20 short
at each scale, 6 and 5 silent, up to 0.188 and 0.272
(`huberkink-before.txt`); 0 of 40 by quadrature; 7 to 9 and 39 to 49
times the fit (`cost-huber.txt`, `cost-huber2.txt`). The scope list
("scalar group-level terms, no residual correlation term, no mi(), me()
or trunc(), no REML") omits that quadrature then FAILS on most
group-level terms in `sigma` and under the log link (above). The
docs item that replaces the route must say that, or recommend
quadrature only for group-level terms in the mean with the identity
link, and must say that a quadrature fit's `predict()` / `fitted()`
intervals hold the group effects at their modes and `vcov_cluster()`
refuses it.

**F1. Test depends on a rounding-decided branch.**
`tests/testthat/test-fit-restart.R`, test "a ridge that bends is read
after a step across it", lines `if (identical(as.integer(got$value$opt$
convergence), 0L)) expect_true(has_class(got$conds, "frmtmb_nl_limit"))`.
A fit can end at code 0 with `frmtmb_conv_gradient` and no limit
warning, because `limit()` in `nl_fit_probed()` is skipped when another
warning was given. Reproducer (`nlstop2-review-pole.R`, `pole-after.txt`
"explin k 3"): the test's data with `y * (1 + 2e-15 * 3)` ends "code 0
... warn frmtmb_conv_gradient"; the test's branch then fails. The test
body run on draws k 0 to 5 (`nlstop2-review-explintest.R`,
`explintest-after.txt`): "ROW k 3 code 0 warn frmtmb_conv_gradient
test-body FAIL", the other 5 PASS. Expected:
a test that holds on every ending. Fix: assert
`expect_false(is.null(nl_limit_message(fit)))` unconditionally (non-NULL
on all 12 draws on reference BLAS and all 12 under OpenBLAS 0.3.26, NULL
on all 12 on 0.82.0), as the existing mm 55 test does, and keep "any
warning"; drop the code-0 branch or condition it on "no other warning".
This also gives the new Newton-step code an assertion that runs under
OpenBLAS, where the code-0 branch is never taken (69 vs 71).
