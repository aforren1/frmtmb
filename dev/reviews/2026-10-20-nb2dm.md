The two families are right where it matters. negbinomial2 is
negbinomial() under a reparameterization that reaches every slot, and
every post-fit path I ran gives negbinomial()'s answer with sigma in
place of 1 / shape, to the last digit where the arithmetic is the same.
dirichlet_multinomial() shares multinomial()'s code path and its
compatibility rows exactly. The lgamma_shift_diff() deviation from
brms's formula is justified and reproduces on fresh seeds and a second
design. The full core and frmtmb.sample suites, the other six extension
suites and the gated files pass on the final build. The Stan-1 upstream
entry reproduces.

predictive draws fail with "NA in probability vector" on a fit with a
small phi (finding 1). The rest are LOW and NIT.

## Findings

### 1. MEDIUM: dirichlet_multinomial predictive draws fail at a small phi

`predict()` of a fit to data drawn at phi = 0.02 (seed 41, n = 200,
K = 3; the fit's phi is 0.0219) stops with an error
(`dev/nb2dm-rev-smallphi.R`, `smallphi.txt`):

```
### phi estimate
 0.02189695
### predict()
ERROR: NA in probability vector
```

The simulator draws the probabilities with `simplex_rdirichlet()`,
`rgamma(alpha) / rowSums(...)`, and at a small concentration every
gamma variate of a row underflows to 0, so the row is 0 / 0. Counted
over 20000 rows (`dev/nb2dm-rev-smallphi2.R`, `smallphi2.txt`):

```
phi 0.01   NaN rows, rgamma draw:    18 of 20000; log-scale draw: 0
phi 0.001  NaN rows, rgamma draw:  9570 of 20000; log-scale draw: 0
```

`predict()` fails at a fit of 0.022 because its parameter draws reach
smaller phi. The same simulator serves `simulate()`, frmtmb.sample's
`posterior_predict()` and `pp_check()`. brms 2.23.0 is no better
(`brms::rdirichlet()` at alpha = 1e-6 p: 1997 of 2000 rows NaN,
`misc.txt`), but brms crashing is clearly wrong, and a small phi is an
ordinary estimate for strongly overdispersed counts. Fix: draw the
Dirichlet on the log scale, `log G = log(rgamma(alpha + 1)) +
log(runif()) / alpha`, then a softmax; the second column above is that
draw, whose category means match softmax(mu) to 0.002 at every phi. The
same helper serves `dirichlet()` and `dirichlet2()`, so fixing it there
covers them too. Add a test that simulates at phi = 1e-3.

### 2. LOW: the `.eta_shape` translation rescues nothing that is reachable, and its test passes without it

`to_shape()` sets `.eta_shape = -log(sigma)` "so the log-scale density
input survives a sigma whose inverse link has under- or overflowed".
With the translation removed, test-negbinomial2.R passes 65 of 65
(`mut.txt`, `noeta`), so no test pins it. On the tape
(`dev/nb2dm-rev-mutcheck.R`, `mutcheck.txt`, y = 0, 2, 9, mu = 3):

```
log sigma -40 : lane -3.000000000 -1.495922603 -5.914316882 | noeta (same)
log sigma -700 : lane (same)                                | noeta (same)
log sigma -720 : lane -Inf  NaN  NaN | noeta NaN NaN NaN
log sigma 720 : lane -1.465438811e-310 -Inf -7.221972246e+02 | noeta NaN NaN NaN
```

At log sigma -40 the value is exact either way, because `1 /
exp(-40)` does not round; past -709, where sigma underflows, the lane
build is NaN too, because `dnbinom_robust()` overflows on a size of
exp(720). The translation acts only for sigma above 1e308. The test
"the log-scale density input survives a sigma near the Poisson" says it
pins the translation; it pins `dnbinom_robust()`. The fits in this
review stop at log sigma -16.8 and -17.5 at the Poisson limit
(`runoff.txt`), so no result is wrong. Either remove the translation and say in the comment that
negbinomial2 is as robust as negbinomial(), or keep it and correct the
comment and the test's name; the test as written proves nothing about
it.

### 3. LOW: the cost of lgamma_shift_diff() is 2x only with a Laplace inner problem

The findings say the accurate density "doubles the cost of an objective
and gradient evaluation". The lane's construction reproduces it on a
quiet machine: 1.919 with the control at 0.966 (a `(1 | g)` fit). A
fixed-effects fit (n = 2000, K = 4, `phi ~ z`, 512 evaluations per
block, minimum of 9 rounds) pays 1.239, control 1.018 (`cost2.txt`).
State both; the trade is right either way.

### 4. LOW: a non-count response under negbinomial2 is refused in negbinomial's name

`frm(I(y + 0.5) ~ x, family = brmsfamily("negbinomial2"))` stops with
"negbinomial: response must be non-negative integers" (`nb2.txt`,
`nb2b.txt`), because `valid_y` is inner's `count_y("negbinomial")`,
which `fam_reparam()` keeps. brms names the family it was given. Build
`valid_y` from `count_y(family)` in `fam_reparam()`, or give
`fam_negbinomial2()` its own.

### 5. LOW: the findings' before-arm count is stale

The findings say test-dirichlet-multinomial.R failed "err=10 of 10" on
rellib-r10; the file now has 12 blocks, and all 12 fail there
(`rev-before.txt`). The two blocks added later are the large-phi tests,
which the lane's naive arm covers. Update the line.
