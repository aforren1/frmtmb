### R2-4. `cor_max_abs` 0.916. Not a defect, and the row's truth is wrong

This is the one I was asked to attack, and it settles without needing
the fit, though the fit confirms it.
`dev/rev-rlddm-cormax.R`, seed 20260908, the tier's own design.

**The fitted matrix names the pair.** Refitted here, and the maximum is
`rt.ndt:(Intercept)` against `rt.bs:(Intercept)` at **-0.916032**. Every
other off-diagonal is small: alpha/drift -0.2545, drift/bs 0.1034,
drift/ndt 0.1163, alpha/bs -0.0224, alpha/ndt 0.0458.

**The truths already carry it, before any fit.** The design draws four
independent subject deviations. But the model no longer estimates the
deviation the design drew: under a per-group bound it estimates
`qlogis(ndt_i / floor_i)`, and `floor_i` is the learner's own fastest
response, which is a draw from that learner's WHOLE parameter vector.
Expressing the drawn truths in the parameterization the row now fits:

| pair | as drawn | in the parameterization now fitted | fitted |
|---|---|---|---|
| bs, ndt | +0.0604 | **-0.7768** | **-0.9160** |
| drift, ndt | +0.1591 | +0.0880 | +0.1163 |
| alpha, ndt | +0.0028 | +0.0085 | +0.0458 |
| alpha, drift | -0.1158 | -0.1158 | -0.2545 |
| drift, bs | +0.0695 | +0.0695 | +0.1034 |
| alpha, bs | +0.0139 | +0.0139 | -0.0224 |
| max abs | 0.1591 | **0.7768** | **0.9160** |

**The mechanism, measured.** `cor(log floor, bs deviation) = +0.4954`: a
learner with a higher boundary separation is slower, so its own fastest
response is later. `cor(log floor, ndt deviation) = +0.8433`, which is
the floor mostly being the non-decision time. So a learner with a high
`bs` needs a LOWER fraction to express the same non-decision time, and
the two deviations are negatively dependent by construction.

**So the answer is: a real induced dependence, not an artifact and not a
defect.** The lane's untested hypothesis, that it is the price of the
reparameterization with `ndt` trading off against `bs` through its own
floor, is exactly right, including which parameter.

**What follows is a correction to the row.** `test-scale.R` records
`cor_true = 0` for this row. That is the truth the design drew and it is
NOT the truth of the block the grouped model estimates, which is about
-0.78 at this seed and is computable per replicate from the drawn truths
and the floors with no fit at all. A row recording 0.916 beside a stated
truth of 0 says the fit invented a dependence. It did not; it recovered
one, and overstated it by 0.14.

**This matters most for Phase 2's item 2.2**, which is 60 replicates of
exactly this design with the correlated block on every parameter. If 2.2
asserts a diagonal truth it will fail on nearly every replicate for a
reason that has nothing to do with the estimator.

## BLOCKER B1. The `bf(ndt = )` defect is not a defect. 0.3.0 fitted 0.2

The lane reports that `bf(ndt = 0.2)` on `rlddm()` at 0.3.0 was
"silently accepted and fitted 0.0435872023 s, a 78.2 percent error",
and NEWS says so to users. Reproduced with the value read off the
OBJECTIVE rather than reconstructed, and it is false.

`dev/rev-rlddm-pin.R`, seed 4242, the same six-learner design
`dev/rlddm-scripts/rlddm-pin.R` uses, `min(rt) = 0.261523214`.

| | reference build, 0.3.0 | this branch |
|---|---|---|
| `bf(ndt = 0.2)`, no `max_ndt` | ACCEPTED | REFUSED |
| `ndt` link on the FITTED family | `scaled_logit(0, 0.2615)` | (not reached) |
| the value the frame put in the template | eta = **1.1789028** | |
| `linkinv(eta)`, the time the density used | **0.2** | |
| relative error | **0.00 percent** | |
| negative log-likelihood | 88.624345656 | |
| with `max_ndt = 0.26` | ndt 0.2, nll 88.62435 | ndt 0.2, nll 88.62435 |

**Why the lane's number is an artifact of its own reconstruction.**
frmtmb transforms a constant dpar TWICE. `R/parse.R:1266`
(`plain_dpar()`) calls `linkfun(constant)` and uses the result only to
decide whether the constant is IN RANGE; the value it computes is
thrown away and the raw constant is stored. `R/frame.R:2581` then does
the transform that counts, `lp[["link"]]$linkfun(lp[["constant"]])`,
into the parameter template, and by then `family_finalize()` has run
and `lp[["link"]]` is the settled scaled logit.
`dev/rlddm-scripts/rlddm-pin.R` never reads the template; it pushes
0.2 through the DECLARED `log` link by hand, gets -1.60943791, and
reads that back through the fitted link. That eta is never used by
anything.

Three independent proofs that the density used 0.2:

1. the template holds 1.1789028, which is
   `log(0.2 / (0.261523214 - 0.2))` exactly, the settled link's own
   transform of 0.2;
2. the same nll, 88.624345656, comes back on the reference build with
   NO `max_ndt` (bound 0.2615) and on the branch WITH `max_ndt = 0.26`
   (bound 0.26). Two different bounds, one nll. If either arm had
   decoded the parse-time eta the two would differ, since
   `linkinv(-1.6094)` is 0.04359 under one bound and 0.04334 under the
   other;
3. the lane's own smoke control records the reference arm's `pin_02`
   as 88.62435, the same number, which is the nll of a model pinned
   correctly at 0.2.

**What this costs.**

* `extensions/frmtmb.learn/NEWS.md` tells users that a pinned
  non-decision time "was read on the wrong link" and that
  `bf(ndt = 0.2)` "fitted a non-decision time of 0.0436 s, an error of
  78 percent". It did not. Anyone who pinned `ndt` on an `rlddm()` fit
  would refit a correct model for no reason.
* The change is a BEHAVIOR REMOVAL sold as a fix. `bf(ndt = 0.2)`
  worked and now refuses; the supported spelling becomes
  `rlddm(max_ndt = )`, which the user must now choose.
* `test-rlddm-ndt.R:270-289` pins the removal with a comment that
  repeats the false number, and the lane's "seen it fail" tally counts
  this as one of its six behavioral failures.
* `dev/rlddm-findings.md` carries the table, and the plan row the
  lane proposes carries it too.

**What IS true, and is worth keeping.** The pending bound catches a
different and real defect, which the lane did not claim. On the
reference build `bf(ndt = 0.3)` with `rlddm(max_ndt = 0.26)` is
ACCEPTED: the parse-time range check passes because the DECLARED link
is `log` and `log(0.3)` is finite, then `R/frame.R:2581` produces `NaN`
with no finiteness check, and the objective returns `NaN`. On the
branch the same call is refused at parse, by name: `Constant ndt = 0.3
is not in the range of the scaled_logit link`. That is the honest
justification for `ndt_bound_pending()`, and it is a better one.

**What to do.** Rewrite the NEWS bullet, the findings section, the test
comment and the proposed plan row around the out-of-range case, say
plainly that `bf(ndt = )` without `max_ndt` no longer works and what to
write instead, and delete every appearance of 0.0435872023 and
78 percent. Note also that `R/frame.R:2581` transforming a constant
with no finiteness check is a CORE defect worth its own item: the check
at `R/parse.R:1267` is against a link that a `family_finalize()` may
replace.

## BLOCKER B2. `ndt_bound_attach()` accepts `gddm()` and breaks it

The seam refuses `wiener()`, `lba()`, `rdm()` and `wiener_gng()` by
name. The guard is `if (!is.null(fam[["ndt_raw"]]))`, an internal
marker only those four carry. `gddm()` is in the same package, has an
`ndt`, and does not carry it.

`dev/rev-rlddm-seam-abuse.R` and `dev/rev-rlddm-gddm-attach.R`, on the
reviewer build:

| family | `ndt_raw` | `ndt` link | `ndt_bound_attach(f, <grouped bound>)` |
|---|---|---|---|
| `wiener()` | TRUE | yes | REFUSED by name |
| `lba(2)` | TRUE | yes | REFUSED by name |
| `rdm(2)` | TRUE | yes | REFUSED by name |
| `wiener_gng()` | TRUE | yes | REFUSED by name |
| `gddm()` | **FALSE** | yes | **ACCEPTED** |

What the accepted call does to `gddm()`:

| | before | after |
|---|---|---|
| `ndt` link | `scaled_logit(0, from data)` | **`logit`** |
| `aterm_data` | absent | adds `ndt_floor` |
| `ndt` starting value | 0.155 | **0.5** |

`grep -c ndt_floor extensions/frmtmb.eam/R/gddm.R` is **0**, so nothing
in that family's density reads the floor the seam just planted. The
export replaces a bounded link with a plain logit on a family whose
density reads `dpars$ndt` as a time, and moves its starting value from
0.155 s to 0.5 s. That is the silent-wrong-answer shape this whole item
exists to remove, reachable through the item's own new export, in the
item's own package, on the fifth family.

`?ndt_bound_attach` names no exception and its refusal message
enumerates four constructors, so a reader has nothing to warn them.

**What to do.** Guard on what the family can actually honor rather
than on `ndt_raw`: refuse any family this package owns, or better,
refuse any family that does not declare it reads `ndt_floor`. Either
