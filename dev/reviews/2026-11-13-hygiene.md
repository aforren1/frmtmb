## FIX items

### F1 (MEDIUM, silent). `register_once()` drops a second check made by one factory

`R/registries.R:44-58`. `registration_key()` keys a closure that is not
bound by name in its namespace by `<topenv name>|<deparse(fn)>`. Two
closures from one factory have the same code and differ only in what
they captured, so the second registration replaces the first.
`frmtmb_register_frame_check()` is the exported seam for extensions;
the refusal the first check makes is lost with no message. The same
holds for `frmtmb_register_prior_defaults()`.

Reproducer: `dev/reviews/hygiene-review-regonce.R <base|mine>`
(logs `hygiene-review-regonce-{base,mine}.log`). A factory
`make_check(tag)`; `make_check("refuse_negative_x")` stops the fit,
`make_check("log_only")` records that it ran.

    base  FACTORY checks added: 2 (2 registered)
          FACTORY fit with negative x: refused: refused by check refuse_negative_x
    mine  FACTORY checks added: 1 (2 registered)
          FACTORY fit with negative x: fitted
          FACTORY checks that ran: log_only
    base  FACTORY providers added: 2 (2 registered)
    mine  FACTORY providers added: 1 (2 registered)

Expected: two checks, the fit refused (base). Actual: one check, the
fit runs. No extension does this today (eam and ode register named
functions, sample one anonymous provider), so nothing in the suites
fails; the doc and NEWS say "the same function", which a factory's
second closure is not. `test-register-once.R:11-22` pins the collapse
of two `mk()` closures as intended ("the same code in two closures is
what a reload hands over"), so the test would need its absent case too.

Fix: key an unnamed closure by its code AND the values it captured
(for example `serialize(as.list(environment(fn), all.names = TRUE),
NULL)` when `environment(fn)` is not a namespace), and add the factory
pair as the absent case in `test-register-once.R`. A reload hands over
the same captured values (sample's provider captures `libname`,
`pkgname`), so 3154 stays fixed.

Cost, same scripts: the name search `get()`s every binding of the
closure's namespace, which forces its lazy-load database.

    library(frmtmb.eam, frmtmb.ode, frmtmb.sample)   base +4.6 MB  mine +11.6 MB
    one registration from testthat::test_env("frmtmb")
      (topenv() is frmtmb's namespace)              mine 0.17 s, +50.4 MB

Not a defect alone, but a key built without the namespace scan (as
above) removes it. It also makes a registration depend on every binding
of another extension's lazy-load file being readable.

What does work (same logs): `unloadNamespace("frmtmb.ode")` then
`library(frmtmb.ode)` gives checks 3 (base 4); the same for
frmtmb.sample gives providers 1 (base 2). The lane's
`pkgload::load_all()` twice result is consistent with this.

### F2 (MEDIUM). The coverage plan does not see the old path of a rename

`.github/scripts/coverage-plan.py:67` runs `git diff --name-only base
head`. Porcelain `git diff` detects renames by default and then prints
only the NEW path. A move of a core file into an extension, or of any
file into `dev/`, lists only the destination, so the job that lost the
file is skipped and Codecov carries its old report forward. Core to
extension moves are what the core-boundary rule produces (0.74.0,
c84587f0, moved files both ways).

Reproducer (scratch repository, `git mv R/y.R
extensions/frmtmb.eam/R/y.R`, the lane's script run verbatim; log
`dev/reviews/hygiene-review-plan.log`):

    git diff --name-only HEAD~1 HEAD      extensions/frmtmb.eam/R/y.R
    --no-renames                          R/y.R, extensions/frmtmb.eam/R/y.R
    plan: core=false, matrix eam learn sample

Constructed cases through `plan()` (`hygiene-review-plan.py`):

    core R file moved to an extension  rename: core False, eam learn sample
                                       --no-renames: core True, all eight
    core test moved to dev/attic       rename: core False, none
                                       --no-renames: core True, all eight
    eam test moved to frmtmb.ode       rename: core False, ode sample
                                       --no-renames: eam learn ode sample

Expected: the job that read the old path runs. Fix: add `--no-renames`
to the `git diff` call. Over the last 60 first-parent commits of main
the flag changes no plan (0 of 60), so it costs nothing today.

Smaller, same file: `neutral()` (line 47) treats every `*.md` as
unread, which includes testthat snapshots
(`tests/testthat/_snaps/*.md`). None exist today; a future
`expect_snapshot()` change alone would skip coverage. Exclude paths
under `tests/` and `extensions/*/tests/` from the `.md` rule. LOW.

### F3 (LOW, doc). The constant-weight sentence overclaims

`vignettes/inputs.Rmd:133-137` and `NEWS.md:31-34`: "in a model with no
random effect, a constant weight `c` on every row ... leaves every
estimate unchanged, `sigma` included". True for maximum likelihood with
no prior; false under `REML = TRUE` and with a prior
(`dev/reviews/hygiene-review-wreml.R`, seed 31, the data of
`test-weights-constant.R`; log `hygiene-review-wreml.log`):

    ML, w = 2 vs none            max |par diff| 1.1e-14
    REML, w = 2 vs none          sigma ratio 0.9904; sqrt(2(n-p)/(2n-p)) = 0.9904
    prior on b_x, w = 2 vs none  max |par diff| 0.105

Under REML the integrated fixed effects contribute `-1/2 log|c X'WX|`,
which `c` does not multiply, so sigma^2 goes from RSS/(n-p) to
c RSS/(cn-p). Fix: scope both texts to a maximum-likelihood fit with no
prior (and, if wanted, say what REML does). The test is ML-only and is
right as it is.
