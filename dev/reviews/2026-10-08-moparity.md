## Blocking

### B1. `update(prior = )` with a `brmsprior` drops the stored prior

`update_merge_prior()` (R/confint.R) returns the new prior unchanged
when it is not a `frmtmb_priorlist`:

```r
if (!stored || !inherits(new, "frmtmb_priorlist")) return(new)
```

A `brmsprior` from `brms::prior()` (or a `frmtmb_prior_rows` table from
`get_prior()`/`validate_prior()`) therefore REPLACES the stored prior,
silently, while `set_prior()` and frmtmb's `prior()` merge. `?frm` says
a brmsprior "is translated row by row, so priors copied out of a brms
script work whichever package's `prior()` was in scope", and with brms
attached after frmtmb, `prior()` is brms's.

`dev/moparity-rev-update.R` (`update.txt`), stored prior
`normal(0, 0.05)` on `b x` and `normal(0, 10)` on `Intercept`:

```text
new prior to update()                b_x       rows after
(none, the fit itself)               0.080061  b x, Intercept
set_prior("exponential(2)", sigma)   0.081058  sigma, b x, Intercept
frmtmb prior(exponential(2), sigma)  0.081058  sigma, b x, Intercept
brms::prior(exponential(2), sigma)   0.45576   sigma only
same, fit made with a brmsprior      0.45576   sigma only
```

brms 2.23.0 merges here (`dev/brms-suite/brms/R/update.R` lines
144-158: `rbind(dots$prior, old_user_prior)`, duplicates dropped).
Fix: `new <- as_priorlist(new)` before the merge, and a test that
passes a `brms::prior()` object, seen to fail on the lane's current
build.

## The key question: MAP and the chart (item 2)

**frmtmb's convention is the density of its own unconstrained
parameters, Jacobian included**, for every constrained class:

- class `"sd"`: `prior_logdens()` with `scale = "sd"` adds
  `jac <- x` for `x = log sd` (R/priors.R, "natural sd scale with the
  log-Jacobian applied");
- `cor`/`cortime`/`rescor` (LKJ): "THE DENSITY, ON FRMTMB'S OWN
  PARAMETERS ... carried onto `t` with the Jacobian of that map";
- ordinal thresholds (`ordthres`): the ordered map's log Jacobian;
- a dpar's own class on its natural scale: the inverse link's log
  Jacobian; `ar`, `ma`, `cosy`: the map's Jacobian (`trans`).

Stan's MAP convention is the other one: rstan 2.32's `optimizing()`
has no `jacobian` argument and maximizes the constrained density;
CmdStan's `optimize` defaults to `jacobian = false`. brms has no MAP
tool. So frmtmb already differs from Stan for an sd, and the lane's
Dirichlet with the stereographic chart's Jacobian is CONSISTENT with
frmtmb's own convention. It is not a blocking inconsistency.

The chart dependence is real, and the lane states it (`?frm`
"Monotonic effects", `?set_prior` class `"simo"`, NEWS). Its size,
`dev/moparity-rev-dirichlet-conv.R` (`dirichlet-conv.txt`), `y ~
mo(inc) + z`, the ML tape as the likelihood for the hand optima:

Weights at each optimum. Lane: stereographic chart with its Jacobian
(`frm(prior = )`); natural: no Jacobian; softmax: softmax chart with
its Jacobian. Data seed 3, n 120 (ML weight 3 at a face); seed 4,
n 400 (interior); seed 5, n 60 (weak).

max |w lane - w natural|: dirichlet(1) 0.0714, 0.0029, 0.3555;
dirichlet(2) 0.0358, 0.0027, 0.0097. The log likelihood the lane's
dirichlet(1) optimum gives up against ML: 0.4495, 0.0014, 0.0572.

Reading: in the stereographic chart `log p(z) = C + sum (2 a_k - 1)
log |u_k| - (D - 1) log(1 + |z|^2)`, and `u_k^2 = w_k`, so a lane MAP
under `dirichlet(a)` is the natural-scale mode under `dirichlet(a +
1/2)` times a conformal pull toward the barycenter. That is why
`dirichlet(1)` here sits near the natural mode of `dirichlet(2)` above.
The docs say "dirichlet(1) pulls toward the uniform simplex"; m5 asks
for this sentence in plain terms so a user can choose `a`.

The density itself checks independently
(`dev/moparity-rev-dir-norm.R`, `dir-norm.txt`): D = 3, a = (2, 1.5,
3), polar quadrature 600 x 600: integral 1.000005, E[w1] 0.307692
against 0.307692; D = 4, a = (0.7, 2, 1, 3), 2e5 Cauchy importance
draws: integral 0.9921 (se 0.0062), E[w] within 0.0016 of a / sum(a).

The refusal below 1/2: in the natural convention a concentration below
1 is also unbounded at a face (dirichlet(0.5), weak case: natural mode
at a vertex, 0.0000 0.9999 0.0001), so neither convention has an
interior MAP there; the lane's 1/2 cut is the chart's. The guard's
absent case holds: dirichlet(0.5) fits (lane w 0.2082 0.5077 0.2840,
weak case), and `frm_sample()` takes dirichlet(0.4) on the formula
route (`dev/moparity-rev-dir-sample.R`, `dir-sample.txt`).

  `Intercept` the table's default, b_x 0.6133. frmtmb: `b x` kept,
  `Intercept` the table's default, b_x 0.0520.
- One table row, `b x`, prior `""`. brms: `b x` flat, b_x 0.625.
  frmtmb: `b x` kept, b_x 0.0511.
- Two new rows on `b x`. brms: the first wins, silently. frmtmb:
  refused ("Duplicated prior specifications are not allowed").
- The formula drops `x` and a new row names `b x`. brms: the row is
  dropped, silently. frmtmb: refused ("Prior target not found").
- `brms::empty_prior()` (no rows), frmtmb: the stored prior is kept.

brms binds the new rows ahead of the stored user rows and drops
duplicates by slot (update.R lines 150-155), so a row with an empty
prior wins its slot and the slot returns to its default (flat for `b`).
frmtmb's `priorlist_from_rows()` skips an empty row, so the stored row
stays. The lane's comment in `update_merge_prior()` ("brms reads ... a
table with no prior in it, as 'keep the stored one'"), its NEWS and the
test "update(prior = ) merges a prior table and keeps a flat one"
assert the reverse. brms is not clearly wrong here: an explicit `""`
row means "no prior" in `brm(prior = )` and in `frm(prior = )` too,
and the table workflow is common (`p <- get_prior(...)`, edit one row,
`update(fit, prior = p)`). The estimates differ silently (b_x 0.052
against 0.613).

Fix: for a table input (a `brmsprior` or a `frmtmb_prior_rows`), drop
the stored specification of the slot of EVERY row, empty ones
included; keep a zero-row prior (`NULL`, `empty_prior()`) as "keep the
stored prior". Flip the test and see it fail first.

The two refusals above are frmtmb's `frm()` rules applied to rows the
user has just written; documented in round 1 and accepted.

### m3: the reparam gate, and what the test exists for

History (`git log -S` on main): the gate arrived with dbe6812f
(2026-09-02, "correlated blocks join non-centered sampling"), and its

predates the lane, and the lane only corrected the mo() case. Not
blocking; r2 files it.
