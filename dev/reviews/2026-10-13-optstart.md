## 1. The restart rule

Rule: if the first run has code 0, the restart has a nonzero code,
and the restart gains at most `rel.tol * max(1, |objective|)`, the fit
keeps the restart's point under the first run's code.

Measured on real fits (`optstart-rev-restart.R`, `restart-lane.txt`,
`restart-r8.txt`):

- re1000 (group sd 1000 times sigma), seeds 1 to 20. 14 restarts, 1
  relabel (seed 8): gain 0, move 0, 1 iteration. The final max|grad|
  is 4.1e-3, the headroom is 6.8e-12, and there is no warning. On
  rellib-r8, seeds 6 and 14 warn "false convergence (8)" at the same
  log likelihood (-285.0646492 and -295.2619201 on both builds).
- 20 fits with a caller's `rel.tol = 1e-4` (poisson and gaussian
  `(1 + x | g)`, n 3000), where the rule's tolerance is 0.25 to 0.5
  objective units. All 20 restarts end at code 0, so there are 0
  relabels. The gradient verdict warns on 20 of 20, with headroom
  1.5e-3 to 0.22.
- 10 collinear fits and 10 negative binomial fits on Poisson data: 1
  restart and 0 relabels.

Constructed case (`restart_result()` called directly): the first run
has code 0, "X-convergence (3)", objective 1e4. The restart gains 0.9
log-likelihood units, moves 5 units, runs 150 iterations, and ends at
"false convergence (8)" or "iteration limit (10)". With `optCtrl =
list(rel.tol = 1e-4)`, the result has code 0, message "X-convergence
(3)" and 150 iterations. The tolerance scales with the caller's
`rel.tol` and with |objective|, so it loosens as n grows. Under
`optimizer = "optim"` the rule reads `rel.tol`, not optim's `reltol`,
and falls back to 1e-10, so "the optimizer's own tolerance" in NEWS
is wrong for optim.

Can the rule hide a real failure? Only where the gradient verdict
also passes. `check_convergence()` still evaluates the reported point
and warns when the projected gradient is above `grad_tol` and the
Newton headroom is above `grad_tol` or cannot be computed. A hidden
failure therefore needs a point with less than 1e-3 log likelihood of
local headroom, which is the converged state the code claims. The real
costs are smaller:

- `fit$opt` is internally inconsistent (fix 4).
- A relabeled fit becomes eligible for `newton_polish()`. It also
  skips `se_boundary_stop()`, so a restart that ended at "singular
  convergence (7)" on a boundary gets the SE check as a converged fit.
  That is defensible, but NEWS does not say it.
