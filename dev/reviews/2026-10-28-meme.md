### 1. major: the `corme group = g` row's printed `lkj(1)` overrides an edited class row

Kept divergence 1 says the sampling-route `corme group = g` row prints
the inherited `lkj(1)` "by frmtmb's existing convention". That printed
value is read back as an explicit prior. brms's idiom, and frmtmb's own
refusal text ("For brms's defaults with your rows edited in, start from
default_prior(..., route = "sample")"), is to edit the class row and
pass the table back. brms prints `""` on the group row, so the edit
reaches the group. frmtmb does not.

`dev/review-meme-grpinh.R`, log `dev/review-meme-out/grpinh.txt`
(model `y ~ me(xg, sg, gr = g) + me(wg, sg, gr = g)`, seed 8, 2 chains
of 500 prior draws):

    set_prior("lkj(4)", class = "corme"):  KS vs Beta(4,4) p = 0.377
    sample table, class row edited to lkj(4), group row lkj(1) as printed:
      KS vs Beta(4,4) p = 1.33e-32; vs Beta(1,1) p = 0.892
      sampled corme eta: 1

The sampled density is also `lkj(1)` (resolved entry `eta = 1`), not
only the prior draws. The same trap is pre-existing for the `cor` and
`sd` group rows, identical on rellib-r15 and on the lane
(`dev/review-meme-grpinh2.R`, `grpinh2.txt`: class rows edited to
`lkj(4)` and `exponential(3)`, sampled `theta[3]:lkj1`,
`theta[1]:t`, `theta[2]:t`). So the "convention" the lane cites is a
defect, and brms is not wrong here. By the project rule the lane should
match brms.

Required fix: on the sampling route, the `corme group = <gr>` row
carries brms's `""` (printed as frmtmb prints `""`), and a table whose
class row is edited samples the edit on every group that has no edit of
its own. Add a test that round-trips an edited class row (prior draws
and resolved `eta`), seen to fail on the lane as it stands. Remove the
divergence from the findings. Fix the `cor` and `sd` group rows the

### S1. minor: the `class = "Intercept", nlpar =` exemption keeps finding 2's wrong prior draws

`refuse_coef_bounds()` skips a specification that has `$written` set.
That is frmtmb's spelling `set_prior(class = "Intercept", nlpar = "a",
lb = 0)` of a nonlinear parameter's intercept, which frmtmb stores as
`coef = "Intercept"`. brms's spelling of the same row, `class = "b",
coef = "Intercept", nlpar = "b", lb = 0.4`, is refused (`sc/frm.txt`).
The frmtmb spelling is sampled, and its prior draws ignore the bound.
`dev/review-meme-sc-exempt.R`, `sc/exempt.txt`: the model is
`y ~ a * exp(-b * x)`, with `a ~ 1` and `b ~ 1`, seed 3, 2 chains of
300 draws.

    class Intercept, nlpar a lb 0, nlpar b lb 0.4 (exempt):
      prior draw min  b_a_Intercept -1.666   b_b_Intercept -1.923
      posterior min   b_a_Intercept  1.857   b_b_Intercept  0.639
    class b, nlpar a lb 0, nlpar b lb 0.4 (brms's class row):
      prior draw min  b_a 0.018   b_b 0.402

A positivity bound on a nonlinear parameter is a common prior, and
`?set_prior` documents this spelling. Required fix: when the nonlinear
parameter's formula is `~ 1`, read the spelling as brms's class row
`class = "b", nlpar = ` and draw the prior under its bound. Otherwise,
refuse it as the brms spelling is refused. Add a test that checks the
prior draws against the bound. The other two exemptions hold:
- `theta`: a `toep()` block with `theta_5` and `lb = -0.5, ub = 0.5`
  samples.
- A restated `lb = 0` on `sd`/`sdme`: it is a no-op bound. `lb = 0,
  ub = 2` and `lb = 0.5` on `sd coef = "x"` are refused, so no real
  bound slips through. brms refuses even the restated `lb = 0`

### S3. minor: with both spellings, the order of the rows decides the prior

The case is a model with `a ~ 1` and two specifications in one call:
`pA = set_prior("normal(5, 0.1)", class = "Intercept", nlpar = "a")`
and `pB = set_prior("normal(0, 0.1)", class = "b", nlpar = "a")`.
`refuse_coef_bounds()` rewrites `pA` as a class row and keeps the later
of the two. On rellib-r15, and on `frm()` in both arms, the
coefficient-spelled row wins by specificity, as brms's `coef =
"Intercept"` row beats its class row:

    resolved entry       pA + pB             pB + pA
    lane frm_sample()    normal(0, 0.1)      normal(5, 0.1)
    base frm_sample()    normal(5, 0.1)      normal(5, 0.1)
    frm(), both arms     a = 4.839           a = 4.839
    posterior mean of b_a_Intercept, pA + pB: lane 0.470, base 4.833

A fit's own `pA` (from `frm()`) followed by the call's `pB` is affected
in the same way: lane 0.468, base 4.832. `check_prior_slots()` cannot
see the two as one slot, because they are different targets before the
rewrite. Required fix:
- Resolve the pair by specificity, as `frm()` does: the density of the
  `Intercept` spelling wins, and a bound on either row applies as the
  class bound.
- Or refuse the pair as a duplicated slot.
- Test both orders on both routes, and add a bullet to NEWS.
