## MAJOR 1. The prior restart runs where it cannot win, and doubles the fit

`prior_conflict_escape()` restarts on every conflict. Its own docstring
says that under a log-concave likelihood without a scale the posterior
has one mode "and the restart only costs one more optimization". It does
not skip that case, and the cost is not small when the fit is a Laplace
GLMM. It also runs on every refit path, because they all call
`fit_assembled()` with `start = NULL` and a warm `template`: `refit()`
(R/sugar.R:304, the bootstrap engine), `influence()` deletion refits
(R/influence.R:135), `allFit()` (R/allfit.R:126), `anova()`'s ML refit
(R/confint.R:2002), and the autoscale pre-fit.

`dev/reviews/nlstop-review-prior.R` (min of 3 interleaved rounds, log
`prior-a4.txt`, `prior-a.txt`):

```
a4  bernoulli, 20000 rows, (1 | g) 200 groups, 5 slopes at 2, normal(0, 0.25):
    on 20.28 22.53 22.97 s   off 9.71 11.08 11.28 s   restart 10.23-11.67 s
    llp -5586.801892 on every run, restart never won (ratio of minima 2.09)
a4g gaussian LMM, 20000 rows, slope 5 under normal(0, 1):
    on 1.91 2.18 2.36 s      off 1.50 1.54 1.57 s     (ratio 1.27), same llp
a1  gaussian, n 5000, slope 10 under normal(0, 1): restart ran, same point
a2u / a2b student_t(3, 0, 2.5), predictor in units 100x smaller
    (slope 294, 206): restart ran, same point, gaussian and bernoulli
a3all / a3mix 20 slopes at 3 under normal(0, 0.5), all or half in conflict:
    restart ran, same point
```

On `refit()` (`dev/reviews/nlstop-review-refit.R`, bernoulli GLMM 5000
rows, 3 simulated responses per round, log `refit.txt`):

```
ROW 1 on 20.22   ROW 1 off 8.20   ROW 2 off 8.30   ROW 2 on 18.92   ROW 3 on 18.71   ROW 3 off 7.59
logLik_penalized identical in every arm: -1740.584283, -1722.037017, -1674.757175
```

So a parametric bootstrap or `influence()` of a logistic GLMM with a
prior in conflict costs 2.3 to 2.5 times as much (minima 18.71 against 7.59 s, 2.47), for nothing, and says
nothing. No false message was seen on any of these (the gain threshold
works), and the kept point was never worse.

The lane's cost measurement (`dev/nlstop-cost.R`) timed only gaussian
`y ~ x` fits, whose restart is cheap (0.00 to 0.04 s here).

Fix options, in order of preference: run the restart only where the
second mode can exist, that is, when the likelihood has a free scale in
the outer vector (a dispersion such as sigma, phi or shape); and take it
only on a cold start (`is.null(template)`, the predicate ordstart's
`mixture_starts()` uses), so refits warm-started at the kept mode do not
repeat it. Measure the cost again on a4 and on `refit()`.

## MAJOR 2. The excluded centered-intercept conflict is silently wrong and not filed

NEWS says "a prior on a centered intercept is not read". The findings
give no reason, and no backlog item records it.
`dev/reviews/nlstop-review-intercept.R` (the 4850 data, seed 6201,
`yl ~ x`, `normal(0, psd)` on class Intercept; log `intercept.txt`):

```
psd 1e4 default -6668.727576 code 0, no warning, no message, b_Int 999890, sigma 943.9
psd 1e4 start0  -3055.084765 code 0, b_Int 19816.5, sigma 980119
  stan from default: lp -6668.727576 rc 0
  stan from start0:  lp -3055.084765 rc 0
```

brms 2.23.0's program (flat sigma, as frmtmb sets none) gives the same
log density at both points to the printed digits, and `optimizing()`
stays at each (both are local modes). The default fit is 3613.6 below
the posterior mode at code 0 in silence. It is the 4850 defect on the
intercept. At psd 1e3 and 3e3 the default happens to reach the prior's
mode, and at psd 2e4, 3e4 and 1e5 the data's mode is the higher one, so
the window is narrow, but it is not empty.

Fix: either read the centered intercept's entry (its location is on the
centered scale, so the restart sets the centered intercept, not
`b_Intercept`) or file it as a silent defect with this reproducer and
say in the findings why it was left.

## MINOR 1. `frmtmb_nl_limit` misses two limits it describes

No false positive: `dev/reviews/nlstop-review-limit.R` over
Michaelis-Menten, exponential decay, Emax with `normal(10, 5)` on Emax,
and `nlf(sigma ~ s0 + s1 * z)` (default start), plus logistic growth,
poisson MM, bernoulli logistic and a Hill body (located priors, and
starts at the truth), at n 50, 200, 1000, 2000 and 30 seeds (10 for
starts): 1200 fits, 0 `frmtmb_nl_limit`, 0 warnings of any class
(`limit-A.txt`, `limit-B.txt`, `limit-C-prior.txt`,
`limit-C-start.txt`).

False negatives (`dev/reviews/nlstop-review-fndebug.R`, `fndebug.txt`):

- `a * (exp(b * x) - 1)` on linear data (n 1000, seed 2): code 0, no
  warning, a = 1.40e4, b = 1.44e-4. Scaling (a, b) by (1000, 1/1000)
  raises the log-likelihood by 0.003285, above `grad_tol`. The check
  returns NULL: its flattest eigenvector in log magnitudes, from a
  finite-difference Hessian with eigenvalues 1.02e5 and 2.05e-3, is not
  exactly (1, -1), and the 1000-fold move along it leaves the ridge
  (gain -0.0200). A fit 3.3e-3 short of the limit, silent.
- Hill `Emax * x^h / (EC50^h + x^h)` on step data with a gap: h times
  1000 overflows (objective NaN), and the quadratic gate reads 9.14
  against 1. The check cannot test this limit.

Neither is a regression (0.81.0 is silent on both), and the NEWS bullet
claims only the mm row. File both; a fix would re-solve the stiff
direction after the move (one Newton step orthogonal to it) and move in
smaller factors when the body overflows.

The check's own cost is small (`dev/reviews/nlstop-review-nlcost.R`,
`nlcost.txt`): 0.000 to 0.010 s against fits of 0.14 to 0.67 s (at most
2.4 percent), 3 bodies, two with random effects.

### New MINORs

**S1. The cold-start rule differs from ordstart's.**

ordstart now passes `starts_cold = is.null(start) && is.null(template)`
into `fit_assembled()`, and hands `cold_start` to both of
`autoscale_choose()`'s fits. nlstop uses
`is.null(start) && announce_start && (is.null(template) || prefit_seeded)`.

| path | ordstart starts | nlstop restart |
|---|---|---|
| autoscale pre-fit | run (default `starts_cold`) | not run |
| autoscale "choose", seeded arm | run | not run |
| `frm_allfit(start_from_mle = FALSE)` | run | not run (`announce_start` FALSE) |

The lane's statement that the choice's two fits never run the escape is
wrong for the plain arm: it gets `template = NULL` and the user's
`announce_start`, so it does restart. `autoscale_choose()` also replays
the plain arm's messages whichever arm wins. In theory, then, a
`frmtmb_prior_multistart` message can describe a fit that is not the one
returned. Settle on one predicate at merge; ordstart's `starts_cold`
argument could carry nlstop's gate.

**S2. zero_inflated_poisson (and other `betad` entries that are not a
scale, such as zi and hu) pass the scale gate.**

This costs one restart on a conflict and gives no wrong answer. NEWS
names only "sigma, phi, shape, nu".

**S3. The fix adds restarts (the centered intercept), but the lane did
not rerun the extension suites ("the fix only removes restarts").**

I ran the 10 extension files that set a class-Intercept prior
(`nlstop-short-ext.sh`, `ext.txt`) on the lane core: all pass, 576 pass,
0 fail. The full extension suites are left for the consolidation.
