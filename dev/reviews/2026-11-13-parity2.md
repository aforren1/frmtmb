## FIX items

### F1. `band = "boot"` under the new default is too narrow (1497)

`R/ce-levels.R:486-499` (`ce_plan_draw()`): under `"uncertainty"` a
bootstrap replicate lends the refit's conditional MODE of a picked
level. brms lends a POSTERIOR DRAW of that level's effect, which
carries the level's conditional variance. Modes shrink: their spread is
about `sd_g^2 * shrinkage`, not `sd_g^2`. On the lane's own data (8 rows
per group, sd_g 0.8, sigma 0.5, shrinkage about 0.95) the gap does not
show, which is why the lane's table looks close.

Reproducer: `dev/reviews/parity2-review-snl2.R` and
`parity2-review-snl2-brms.R`. 30 groups of 2 rows, sd_g 1, sigma 2,
`y ~ x + (1 | g)`, data seed 100 (first seed of 100.. with an ML sd_g
of at least 0.7: 0.941, sigma 1.639; sd of the 30 modes 0.603). Band
width at x = -1, 0, 1, `re_formula = NULL`:

| arm | width |
|---|---|
| brms 2.23.0 "uncertainty" (default), 2 x 2000, seed 1 | 4.096 3.963 3.922 |
| brms "gaussian" | 4.448 4.367 4.387 |
| brms "old_levels" | 3.151 2.965 3.057 |
| frmtmb.sample NUTS draws, "uncertainty" (lane default) | 3.897 3.703 3.742 |
| frmtmb.sample NUTS draws, "gaussian" | 4.306 4.117 4.166 |
| frmtmb fit, boot 400, seed 2, "uncertainty" (lane default) | 2.903 2.815 2.787 |
| frmtmb fit, boot 400, seed 2, "gaussian" (0.82.0 default) | 4.036 4.344 4.560 |
| frmtmb fit, Wald | 3.967 3.840 3.940 |

The draws method is right (it lends sampled `r_g`, and matches brms to
5%). The fit's boot band under the new default is 29% narrower than
brms's default; the 0.82.0 default was within 2 to 16%. So on a fit
the BREAKING change moves the band away from brms where shrinkage is
material, and the band undercovers in silence. A first run on seed 31
(`parity2-review-snl.R`, part B) had a singular ML fit and showed the
same direction (boot "uncertainty" 2.075 1.789 2.288 against brms
3.054 3.073 3.377).

It is also inconsistent inside core: `predict()` and `fitted()` on the
same fit default to `"gaussian"` and REFUSE `"uncertainty"` by name
(`check_sample_new_levels()`, `R/predict-brms.R:395`: "chooses per
posterior draw, and is refused by name rather than ignored"), and
`fitted(sample_new_levels = "old_levels")` reads the chosen level's
fitted effect AND its conditional variance. The CE boot path reads the
mode alone.

Expected: on a fit, either (a) keep `"gaussian"` as the `band = "boot"`
default, as `predict()`/`fitted()` have it, and make `"uncertainty"`
the default on draws only (NEWS: BREAKING on draws only); or (b) draw
the lent level's effect from its conditional law at the replicate
(mode plus a draw from its conditional covariance), as `fitted(...,
"old_levels")` already accounts for it, and remeasure against brms on
the strong-shrinkage data above. (a) is the small change; (b) needs the
replicate's conditional covariance per replicate. Recommendation: (a)
now, (b) filed. A test should pin the width ratio against the Wald
band (or the gaussian boot) on strong-shrinkage data, not the identity
of the lent value alone, which is all `test-ce-new-levels-snl.R`
checks.

### F2. An explicit `sample_new_levels` on the Wald band changes nothing, in silence

`R/conditional-effects.R:2658` validates `sample_new_levels` on every
band (`ce_snl()`), but only the boot branch reads it (line 2835). The
default band of a fit is Wald, which is the gaussian law.

Reproducer (`parity2-review-snl2.R`): `conditional_effects(fb, "x",
re_formula = NULL, sample_new_levels = "old_levels")` is `identical()`
to the call without it: TRUE. Expected: a non-default value on a band
that does not draw is refused by name (or at least a message), as
`ce_dots()` refuses any other argument that would change nothing. The
same holds for `re_formula = NA` with the argument given, where brms
also ignores it; refusing there is optional.

### F3. A factor-by-numeric default display is named and drawn factor first (3922)

brms's `prepare_cond_data(reorder = TRUE)` (conditional_effects.R:838,
applied to default effects only) puts the numeric variable of a pair
first, so `y ~ f * x` gives the displays `f x x:f`: x on the axis, f as
the color. frmtmb gives `f x f:x` on both arms
(`parity2-review-ce.R`, `parity2-review-ce-brms.R`, shape `fx`). Not a
regression, but the lane's NEWS says the names "now equal brms
2.23.0's", and this is the commonest interaction shape. Expected: in
`ce_default_effects()` (or where `ce_grids_build()` takes it), order
each default pair numeric first, a grouping variable counting as a
factor, as brms does; `effects =` given by the caller keeps its order
(brms passes `reorder = FALSE` there). Add `y ~ f * x` to
`test-ce-default-effects.R`.
