## BLOCKER 1. `insight::get_residuals()` returns the matrix

`dev/shapes-rev-interop2.R`, `/tmp/io5.R`, both libraries, the fit
`frm(bf(y ~ x + f) + gaussian(), data = rev_data())`.

| accessor | base | lane |
|---|---|---|
| `insight::get_residuals(fit)` | `numeric`, length 150 | `matrix`, 150 x 4 |

25 insight accessors were swept (`clean_parameters`, `find_*`,
`get_data`, `get_dispersion`, `get_modelmatrix`, `get_priors`,
`get_simulated`, `get_variance`, `get_weights`, `model_info`,
`n_parameters`, `get_sigma`, `get_loglikelihood`, `get_intercept`,
`get_deviance`, `get_df`, `get_parameters`, `get_varcov`,
`get_predicted`, `get_residuals`, ...). **Exactly one changed**, and it
changed from the documented answer to four times as many numbers.

insight has a method for this and frmtmb does not:

```r
insight:::get_residuals.brmsfit
function (x, ...) {
    r_attr <- stats::residuals(x, ...)
    r <- as.vector(r_attr[, "Estimate"])
    attr(r, "full") <- r_attr
    class(r) <- c("insight_residuals", class(r))
    r
}
```

That method exists BECAUSE brms's `residuals()` is a matrix. Item 2.6f
gave frmtmb the same matrix and did not give it the same method, so
insight falls through to its default, which hands back the raw matrix.
The lane wrote `get_predicted.frmtmb_fit` for the exactly analogous
reason and stopped one method short.

**Why the lane did not see it.** `dev/shapes-interop.R` line 83:

```r
show("insight::get_residuals head",
     round(utils::head(as.numeric(insight::get_residuals(f)), 3), 4))
```

`as.numeric()` flattens the 150 x 4 matrix column first, so
`head(., 3)` is the first three entries of the `Estimate` column, which
is bit for bit what the base vector's first three entries are. The
harness prints neither length nor class. Its diff therefore reports
nothing, and section 5's claim, "Every number agrees with the base
build ... Nothing in the diff is a changed value", is false for this
entry point and false because of the formatting in the instrument. This
is the standing rule about checking the instrument, and about a guard
that must fail when the thing it guards is absent.

**Collateral, the same root cause.** `residuals()` returning a matrix
silently changes every scalar summary a user writes:

| expression | base | lane |
|---|---|---|
| `mean(residuals(f))` | -2.894331e-06 | 0.03897951 |
| `sd(residuals(f))` | 0.9701508 | 0.8689341 |
| `sum(residuals(f)^2)` | 140.2377 | 453.1844 |
| `length(qqnorm(residuals(f))$x)` | 150 | 600 |

brms behaves the same way, so this half is brms fidelity rather than a
defect, and it belongs in the migration vignette as a named consequence.
`insight::get_residuals()` is the part that is simply wrong.

**Fix.** One `@exportS3Method insight::get_residuals` method, insight's
brmsfit body. Then re-run the interop script with LENGTH and CLASS in
its output.

## BLOCKER 2. `predict(allow_new_levels = TRUE)` gives an unseen
group the interval of a seen one

`dev/shapes-rev-newlevel.R`, seed base 883000, 110 replicates of 10
fresh points, n = 60, 12 groups, tau = 0.7, sigma = 0.8, ndraws = 600.
Both arms use the SAME fits, so the difference is the arm and not the
harness.

```
new      948 of  1100 = 0.8618  (0.8400, 0.8817) binomial;
         replicate mean 0.8618 se 0.0102  z=-8.67  mean width 3.3029
known   1025 of  1100 = 0.9318  (0.9153, 0.9460) binomial;
         replicate mean 0.9318 se 0.0082  z=-2.23  mean width 3.2962

width ratio new/known: 1.0020
what a fresh-effect draw needs: sqrt(sigma^2 + tau^2)/sigma = 1.3288
```

Coverage 0.8618 against a nominal 0.95, at z = -8.67. The interval for a
group the fit has never seen is 1.0020 times as wide as the interval for
a group it knows, where it needs to be about 1.33 times as wide.

One fit, in full precision (`/tmp/nl2.R`, seed 883100):

```
frm_linpred se.fit, KNOWN level: 0.28998 0.32933
frm_linpred se.fit, NEW   level: 0.45378 0.46968
fitted() Est.Error, NEW level  : 0.45378 0.46968
predict Est.Error, KNOWN       : 0.84358 0.84842
predict Est.Error, NEW         : 0.84358 0.84842
correct at a new level          : 1.02794 1.03506
```

`frm_linpred(se.fit = TRUE)` and `fitted()` both widen at a new level.
`predict()`, which is supposed to be that spread plus observation noise,
does not widen at all: the two Est.Error columns are identical to five
decimals. So the package already holds the term and `predict()` does not
read it. The cause is `predict_dpar_values()`, which calls
`frm_linpred(type = "response")` with no `se.fit` and no draw of the
unseen group's effect, while `predict_par_drawer()` perturbs only the
outer vector.

This is worse than the documented omission. `?predict.frmtmb_fit` says
`Var(b | y)` is not in the interval, which is the SHRINKAGE term at a
known level. At an unseen level the missing term is the whole `tau^2`,
and the refusal message for `sample_new_levels` sends the user here:

> an unseen level is predicted at the POPULATION level here, with
> allow_new_levels = TRUE

The lane's own coverage study has no new-level arm, so nothing measured
it.

**Fix, smallest form.** In `predict_simulate()`, when
`allow_new_levels = TRUE`, add `rnorm(0, tau_draw)` per new level per
replicate, using the theta the replicate already drew. That is brms's
`sample_new_levels = "gaussian"` and it would also let the
`sample_new_levels` refusal become an answer.

## MAJOR 3. `lmtest::coeftest(fit)` silently loses the intercept row

`/tmp/io4.R`, both libraries, `y ~ x + f`:

```
base:  (Intercept) 1.20485  x 0.52384  fb -0.14307  fc -0.41505   [4 rows]
lane:                      x 0.52384  fb -0.14307  fc -0.41505   [3 rows]
```

The values that survive are unchanged. The intercept is gone, with no
warning, from a printed significance table.

The cause is a naming split the lane introduced:

```
names(coef(f))    : (Intercept) | x | fb | fc
rownames(vcov(f)) : Intercept   | x | fb | fc
intersect         :               x | fb | fc
```

`coef()` still uses the design-column name and `vcov()` now uses brms's.
`lmtest::coeftest()` is the canonical pairing of the two and it is not
the only one. brms is consistent here: its `coef()` and its `fixef()`
both say `Intercept`. frmtmb's own Rd for `coef()` already shows the
workaround in its example, which is the tell:

```r
all.equal(coef(fit)$g[["(Intercept)"]],
          fixef(fit)["Intercept", "Estimate"] + ranef(fit)$g[, 1], ...)
```

Either `coef()` takes brms's name too, or `vcov()` keeps a
`(Intercept)` alias. Leaving them split is the state that produces a
table with a missing row.

## The two questions the lane put to the user

**1. `variables()`'s order: leave it, but fix MAJOR 1 first.**

Measured, brms against lane:

| model | brms `variables()` | lane |
|---|---|---|
| gaussian | `b_Intercept, b_x, b_fb, b_fc, sigma, Intercept, lprior, lp__` | `b_Intercept, b_x, b_fb, b_fc, sigma` |
| distreg | `b_Intercept, b_sigma_Intercept, b_x, b_fb, b_fc, b_sigma_z, Intercept, Intercept_sigma, lprior, lp__` | `b_Intercept, b_x, b_fb, b_fc, b_sigma_Intercept, b_sigma_z` |
| multivariate | `b_y_Intercept, b_y2_Intercept, b_y_x, b_y2_x, ...` | `b_y_Intercept, b_y_x, b_y2_Intercept, b_y2_x, ...` |

brms's `variables()` also carries `Intercept`, `lprior`, `lp__` and the
`r_g[...]` rows, which frmtmb cannot and should not have, so
`variables()` will differ from brms's in CONTENT whatever its order.
Buying the order buys a partial match at the cost of moving the draws
matrix's column order, which is frmtmb.sample's surface. The one ledger
row that turns on it, `:635`, is a column-ORDER assertion that a ported
script fixes with one reindex. Keep frmtmb's order and say in
`?variables` that `fixef()`, `vcov()` and `summary()$fixed` take brms's.

The caveat matters more than the answer: on an ordinal fit brms puts
`b_Intercept[1]`, `b_Intercept[2]` FIRST and frmtmb puts `b_x` first.
Fix MAJOR 1 and revisit, because once the thresholds are rows of
`fixef()` their position becomes part of the shape a ported script
indexes.

**2. `brmshypothesis`: drop it. The stated reason is false.**

The findings say removing the class "changes which `print()` and
`plot()` methods dispatch". Constructed (`/tmp/hyp.R`, brms attached
before frmtmb):

```
class: frmtmb_hypothesis, brmshypothesis
brms S3 methods for brmshypothesis: plot.brmshypothesis, print.brmshypothesis
print identical with and without brmshypothesis: TRUE
plot(h): ok    plot(stripped): ok
getS3method print.frmtmb_hypothesis exists: TRUE
getS3method plot.frmtmb_hypothesis exists: TRUE
```

brms has exactly two methods for that class. frmtmb owns both generics
for `frmtmb_hypothesis`, which is FIRST in the class vector, and both
are exported in NAMESPACE. Stripping `brmshypothesis` leaves the printed
output identical and `plot()` working. Nothing dispatches differently.

What is actually lost is `is(x, "brmshypothesis")` in a ported script,
which is the same thing `dev/brmsport-ledger.tsv` already records
eighteen times as a rule-2 divergence, including `priors:27`
(`expect_is(bprior, "brmsprior")`). Keeping this one class name while
citing the rule eighteen times is an inconsistency inside the ledger.
Drop the class, add a row to the ledger citing rule 2, and the ledger
becomes self-consistent.
