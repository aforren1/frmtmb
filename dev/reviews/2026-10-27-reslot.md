## What I verified, by running

### Flat on the Cholesky factor (claim 3), analytic and against Stan

Stan's `cholesky_corr_constrain` adds `log1m(z^2)` per tanh and
`0.5 log1m(sum_sqs)` per scaled entry, which is the log determinant of
the map to L's free entries: `""` on `cor` is Lebesgue measure on each
row of L in its unit ball. frmtmb's row i is `(t, 1) / sqrt(1 + |t|^2)`
(`us_chol_L()`, filled column-major, the order `lkj_rows()` groups), so
the induced density on t is `prod_i (1 + |t_i|^2)^(-(i + 1) / 2)`; LKJ(eta)
on the same chart is `(1 + |t_i|^2)^(-(d + 2 eta - 1) / 2)` on every row,
so lkj(1) and flat on L agree at d = 2 only. That is the lane's formula.

`dev/review-reslot-p2a.R` (seeds 1 data, 21 draws, 31 Stan;
`p2a-after.txt`) checks the code, not the formula: per row it draws t
exactly from the induced density (a multivariate t with 2 df and scale
I / 2) and takes the log ratio of frmtmb's RESOLVED `prior = "flat"`
entry to it over 200 draws. A correct density gives a constant ratio.

| block | idx | range of log ratio, flat | same, lkj(1) |
|---|---|---|---|
| us d = 2 `(1 + x \| g)` | 3 | 4.4e-16 | 4.4e-16 |
| us d = 3 `(1 + x + z \| g)` | 4,5,6 | 1.8e-15 | 2.55 |
| us d = 4 `(1 + x + z + w \| g)` | 5..10 | 7.1e-15 | 5.36 |
| rescor d = 3 | 1,2,3 | 1.8e-15 | 1.44 |
| rescor d = 4 | 1..6 | 4.0e-15 | 7.39 |
| unstr d = 4 (cortime) | 1..6 | 4.0e-15 | 4.97 |

## Findings

### 1. MAJOR. The named-list prior is still a second slot, and drops the LKJ on positions it does not name

`dev/review-reslot-p4.R` section (i), seed 1, `(1 + x + z | g)`,
`frmtmb.sample:::sample_resolve_priors(fit, list(theta_4 =
prior_normal(0, 1)))`, both arms (`p4-before.txt`, `p4-after.txt`,
identical):

    entry theta 1 t sd / theta 2 t sd / theta 3 t sd
    entry theta 4 normal internal
    (no entry on theta 5 and theta 6)

The default lkj(1) on positions 4 to 6 is gone, and positions 5 and 6
carry no density: the exact defect this lane fixes for class `theta`
(its NEWS: "One such prior used to retire the default lkj(1) on every
correlation of its block"), reached through the other spelling. The
code comment in `sample_resolve_priors()` says the legacy spelling
"takes over exactly the internal parameters it names and leaves the
rest of the stack in place"; it does not, and the lane's findings
repeat that description. `list(theta_2 = )` likewise replaces the class
`sd` default on theta_2 with a density on the log sd. Pre-existing, but
it leaves claim 1 ("one prior slot per random-effect parameter") false
on frm_sample's route.

Required fix: remove the named-list spelling (recommendation (b)), or
at the least refuse a name that `cov_class_coefs()` or
`autocor_class_coefs()` reaches with `cov_class_refusal()`, as class
`theta` now is. An LKJ cannot be kept on part of a block, so a refusal
is the only coherent partial fix.

### 2. MAJOR. A flat run's printed prior does not round-trip

`dev/review-reslot-p4.R` section (ii), `p4b.R`. `prior_summary()` of a
`prior = "flat"` run on `y ~ x + (1 + x + z | g)` lists `(flat)` rows
for `sigma`, `sd` and `cor` only. Passed back as `prior =`, the slots it
does not list take the defaults again: the Intercept gets
`student_t(3, 1.2, 2.5)` (`p4b`: `entry beta 1 t internal`), and the
prior-augmented objective differs from the flat run's by 0.0157 in
value and 0.0128 in gradient, relative, over 50 points (seed 7). brms's
`prior_summary()` of a model fitted with `""` lists the Intercept and
`b` rows too, and passing it back gives the same program. The
data-frame form fails outright ("prior[['prior']] must be a prior
object (prior_normal(), prior_t())", pre-existing, also for a default
run: a plain data frame falls into the named-list branch), and its
`""` rows without bounds would be skipped by `priorlist_from_rows()`
anyway. Related gap: `set_prior("", class = "cor")`, brms's `(flat)` on
one slot, is refused ("set_prior() needs a distribution, bounds, or
both"), so brms's per-slot `""` has no frmtmb spelling (`p1-after.txt`).

Required fix: put the slots "flat" leaves without an entry (location
intercepts, a dpar intercept with a formula) into the flat stack as
kind `"flat"` rows, so `prior_summary()` lists them and the round trip
replaces the defaults; on frm_sample's route read a `""` row without
bounds that replaces a default as `(flat)` (it is brms's meaning). A
test: the flat run's `prior_summary()` passed back gives the same
objective value and gradient.

## User question (a): `frm(prior = default_prior(route = "sample"))` on ar(cov = TRUE)

Recommendation: keep the lane's reading (a `(flat)` row with lb/ub is a
box with no density on frm()'s route) and add finding 3's NEWS and doc
text. Reasons: it is what brms's program means (no `lprior` term; an
optimizer on it without the Jacobian, as `rstan::optimizing()` runs,
finds the constrained mode in brms's coordinates, which is what frm()
now finds for ar); it is how frm() reads every other bounds-only
specification (`set_prior("", class = "sd", lb = 0.1)` is constrained
ML there, and users bound to get constrained ML); and the alternative
(frm() adding the map's Jacobian for a row that writes no density)
would make a bound move an estimate. The cost is the lost identity
"frm() under the printed sampling table is the sampler's mode"; the
`prior_summary()` object keeps it, and the docs should say so.

### S1. MAJOR. frm_sample() under default_prior()'s default table now samples (flat) everywhere

`default_prior()` defaults to `route = "fit"`. That table prints
`(flat)` on `Intercept`, `sigma`, `sd` and `cor`, because they are
frm()'s defaults. Empty rows are now read as `(flat)`, so a brms user
who follows the porting workflow silently changes the sampled model.
The workflow is to take `p <- default_prior(f, data)`, edit one row
(`b`, `x` set to `normal(0, 1)`), and call `frm_sample(prior = p)`.

Measured with `q2` and `q3`, seed 1, on `y ~ x + (1 + x | g)`:
- **rellib-r14:** the resolved prior is `student_t` on the Intercept,
  sigma and sd, `lkj(1)` on cor, and `normal(0, 1)` on x.
- **Lane:** it is `normal(0, 1)` on x and flat on everything else,
  with the LKJ flat on L.
- **Notice:** the call prints no warning and no note. The
  "few groups, posterior need not be proper" warning that
  `prior = "flat"` gives does not fire either.
- **brms:** `brm(prior = <brms's default_prior(), one row edited>)`
  keeps its defaults on the rows not edited (`q2-brms.txt`).

The literal reading is consistent: the rows do say `(flat)`. But the
table's `route` attribute survives the edit (`q3`: "fit" before and
after), so frm_sample can tell this case apart. NEWS says empty rows
"are read the same way" but does not name this consequence.

Required fix (recommended): frm_sample refuses a table whose `route`
attribute is "fit". The message says that its `(flat)` rows are
frm()'s defaults, and points to `default_prior(..., route = "sample")`,
or to `prior = "flat"` for brms's `(flat)` everywhere. A brms-built
table and a `route = "sample"` table are unaffected.

Fallback, if (flat) from a fit-route table is to stay: give the same
propriety warning `prior = "flat"` gives whenever the effective prior
leaves a standard deviation flat, and add a NEWS bullet naming the
workflow.

Add a test either way: the edited fit-route table on frm_sample.

### S1: the fit-route table is refused, and nothing else is

Run with `q5-after.txt`, seed 1, on `y ~ x + (1 + x | g)`.

**frm_sample refuses the fit-route table however it is edited.** The
refusal names `route = "sample"`, `prior = "flat"`, and passing only
the specifications you set. These forms are refused:
- the unedited table;
- an edit through `$<-` or `[<-`;
- a subset to the one edited row, or to the rows that have a density;
- `rbind()`;
- `order()` subsetting;
- a column added;
- `transform()`;
- `as.brmsprior()`;
- `set_prior() + as.brmsprior(pe)`;
- `c(as.brmsprior(pe), set_prior())`;
- `validate_prior()`'s fit-route table.

The refusal fires before sampling in both `frm_sample(fit, prior =)`
and `frm_sample(formula, data =, prior =)`. `update()` of draws has no
method, which is pre-existing, so that path does not exist.

**The mark does not leak.**
- `frm(prior = pe)` is bitwise equal to the single `b`/`x` spec.
  `frm(prior = <unedited table>)` is bitwise `frm()`.
  `update(<ML fit>, prior = pe)` is bitwise the single spec.
- A MAP fit's own prior carries no route attribute. frm_sample then
  stacks the defaults under it (Intercept, sigma, sd, lkj, plus the
  normal on x).
- A run's `prior_summary()` carries no route attribute. Passed back,
  it resolves to exactly the defaults.

**Tables without the mark are read as written.**
- The sample-route table, edited, resolves to the defaults plus the
  edited row.
- brms's own `default_prior()`, edited (saved by the `brms` arm),
  resolves to the same thing. brms does the same with that table.
- A hand-built table with `""` on class `sd` is flat on sd, which is
  brms's class-level meaning.

**The decision not to refuse a sample-route table in frm() is sound.**
That table's density rows are brms's defaults, and frm() applies them
as the MAP penalty the user asked for. Its `(flat)` rows are boxes or
nothing there, which is decision (a), documented, and also brms's
`(flat)`. So nothing is read against the user's intent. The
frm_sample refusal exists because there the unedited rows silently
became something other than what a brms user expects. The reverse case
has no such reinterpretation.

### R1. MINOR (release fix): the plain-data-frame refusal leads back into the trap

`as.data.frame()` drops the route mark. `frm_sample(prior =
as.data.frame(pe))` is refused with "turn it into a prior with
as.brmsprior()". Following that advice, `as.brmsprior(as.data.frame(pe))`
carries no mark. It then resolves silently to `normal` on x and
`(flat)` on every other slot, with flat on L (`q5-after.txt`): the
outcome S1 was fixed to prevent.

It takes two deliberate steps, and the lane documents it as "read as
written", so this is minor.

Release fix: either keep the mark through `as.data.frame()` (or have
`as.brmsprior()` restore it from the table's first-line header text),
or add to the data-frame refusal that a `default_prior()` table should
be passed as it is, or taken with `route = "sample"`.
