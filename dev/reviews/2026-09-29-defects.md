## Blockers

### B1. `residuals()` of a multivariate fit reports residuals for missing `mi()` responses

`residual_values()` takes `y` from `frame$y`. For the rows that an
`mi()` response is missing, `frame$y` holds the placeholder 0, so the
residual there is `0 - mu`. That is a number, and it is wrong. brms
keeps `Y` as NA with `internal = TRUE`, so its predictive error there
is NA. The structured-family path of the same function already masks
these rows (`r[blk$miss] <- NA`). The rowwise path does not mask the
rows in `frame$mi_map[[resp]]$rows`.

- Construction: `dev/defects-rev-probe2.R` section A, seed 21, n = 100,
  `bf(y ~ mi(xmi)) + bf(xmi | mi() ~ z) + set_rescor(FALSE)`. At all
  18 missing rows the residual is not NA, and it equals
  `-fitted(resp = "xmi")` (`dev/defects-rev-log/probe2-lane.txt`).
- On base, a multivariate fit refused `residuals()`, so the lane turned
  a refusal into a silent wrong answer. `mi()` needs a multivariate
  formula in frmtmb, so this is the common `mi()` shape.
- The univariate `ymi | mi() ~ x` has the same defect on BOTH arms
  (100 rows, 0 NA; `probe2-base.txt`). The univariate case is
  pre-existing, but the same one-line mask fixes both cases.
- Fix: set `r[mi_map[[resp]]$rows] <- NA` in the rowwise branch before
  `napred()`. Also add a test.

### B2. `fitted(scale = "linear")` of a multivariate fit with an ordinal `cs()` response dies with an internal R error

With `resp = NULL`, `fitted_mv()` stacks the per-response layers.
Because `ord_linear_per_threshold()` now makes the ordinal response
`n x 4 x (K - 1)`, the stack fails with R's "length of 'dimnames' [3]
not equal to array extent".

- On base, the same call returned `150 x 4 x 2`. On the lane, it
  errors. Response order makes no difference. `resp = "yo"` gives the
  correct `150 x 4 x 2` layers, which equal the univariate fit's
  layers. Script: `dev/defects-rev-probe5.R` (seed 5, n = 150). Logs:
  `dev/defects-rev-log/probe5.txt` and `probe5-base.txt`.
- The base answer was the pre-fix one (the ordinal layer was the shared
  predictor), so the correctness loss is small. But this is a new
  internal-error defect, of the class the ledger exists to remove.
- Fix: in `fitted_mv()`, refuse by name when a response has a
  per-threshold layer and suggest `resp =`, as `residuals()` already
  does for a matrix-valued response. Add a test.
