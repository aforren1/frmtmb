## Verdict: FIX

Items 2, 3 and 4 of the lane are sound in substance; item 3's new
assertion is one step too wide. Item 1 replaces a rounding-decided rule
with a magnitude-decided one: it calls estimated rows "not estimated"
and, in one constructed case, turns 0.82.0's NA bounds and warning at
the edge of the space into a silent zero-width interval. TMB-7 is a
duplicate of RTMB-4.

## FIX 1 (MAJOR). The "fixed row" rule is a magnitude threshold, not structure

`R/confint.R:822-824` calls a row fixed when, for every theta, the
central difference moves it by at most `16 * eps * max(|g0|, 1)`.
`:886` then sets its se to 0, AFTER the lost-direction rules at
`:838-848` set NA, so `fixed` also overrides those NAs. The absolute
floor `max(|g0|, 1)` makes the tolerance 3.6e-15 for every small row,
whatever its own scale, and the step is `1e-5` of theta. So any
estimated row whose derivative is below about 1.8e-10 passes as fixed.

Evidence (`dev/reviews/ci082-review-vc.R`, `ci082-review-out/`):

1. A natural fit, no caller start: `ou(tim + 0 | g)`, times
   0, 0.5, 1, 2, 8, 20, 40, data with no correlation across times
   (case `ouind`, seeds 1 to 3, code 0, log rate 3.45 to 3.64). Every
   correlation row is `exp(-exp(theta_2) * D)`, a function of an
   estimated parameter.
   - lane (`lib-ouind.txt`): 19 of 21 cor rows se 0, zero width, no
     warning, for example `cor(tim(0),tim(1))` = 2.593068e-17 with
     interval [2.593068e-17, 2.593068e-17].
   - 0.82.0 (`base-ouind.txt`): 8 of these rows have a positive
     delta-method se (2.2e-13 for that row, relative to its size 1e4)
     and 11 (those that underflow to 0) NA bounds with the "No
     interval" warning.
   The lane's NEWS and doc say such a row is "a component that no
   parameter moves ... not estimated". It is estimated. The numbers
   are tiny either way, but the classification is false and the
   11 rows changed from NA + warning to a silent zero width with no
   NEWS entry.
2. A regression vs 0.82.0 at the edge of the space: `homcs(0 + t | g)`
   with d = 3, data whose group effects sum to zero, started at
   `theta_2 = -28` (case `csstart`, seed 1). The fit stops there
   (code 8, "the curvature at the stop is unusable"; at -30 also
   "Standard errors are not available for ... theta_2: the
   likelihood is flat along it"). The correlation is -0.5 =
   -1/(d-1), a singular correlation matrix, the edge of its space.
   - 0.82.0 (`base-csstart.txt`), starts -20, -26, -28, -30: NA bounds
     and the "No interval for 3 components" warning.
   - lane (`lib-csstart.txt`): -20, -26 the same; -28, -30, -34:
     se 0, interval [-0.5, -0.5], no warning.
   The row moves by 7 ulps over the difference step at -28 (derivative
   1.4e-12): real movement, below the 16-eps floor. The lost-direction
   NA of the nocurv rule (`:838-843`) that 0.82.0 kept is overwritten
   by `se_g[fixed] <- 0`. A caller start reaches it here; a warm start
   or a flatter saturating map (a registered structure) reaches it
   without one. Natural fits of the same data stop at -7 to -18, where
   neither build is flat (`lib-cslow.txt`).
3. The rule still decides a truly fixed row on rounding where atanh is
   steep. A registered structure fixing the correlation at 0.999
   (case `fix999`, 20 ulp perturbations, reference BLAS):
   - lane (`lib-fix999.txt`): 6 of 20 zero width, 14 of 20 width
     3.0e-12 to 9.1e-12 (se 3.9e-10 to 1.2e-9, not fixed).
   - 0.82.0 (`base-fix999.txt`): the same 6 NA + warning, the same 14
     positive width.
   The lane removed the NA/warning flip, but "fixed: zero width" is
   still rounding's choice: atanh' = 500 at 0.999 turns a few ulps of
   the correlation into 1e-13, above the tolerance of 6e-14. A test
   like the lane's new one with `identical(lwr, estimate)` would fail
   14 of 20 times on this structure.

What the right rule needs, and where it is: `varcorr_trans_rows()`
has the block (`bk`: covstruct, `theta_idx`, `dim`) and the registry
entry (`cs_entry(bk$covstruct)`: `vcov`, `start`, `npar`, `sd_idx`).
Neither the registry nor the parameter vector says which rows a
structure fixes: an `xcs()` correlation is not a parameter at all, so
no map or `Vfull` row can tell it from an estimated one. Two
structural options:

- (a) Probe at macroscopic points, not at `1e-5`: a row is fixed when
  it takes the same value at the estimate, at the structure's
  `start(bk)`, and at the estimate moved by -1 and +1 in each theta,
  to `1e-10` relative to the larger of the two values (no absolute
  floor). A row a structure fixes is constant everywhere; an estimated
  row that is flat at the estimate is not. Prototype
  `dev/reviews/ci082-review-proto.R` (log `proto2.txt`): xcs at 0.5
  fixed on 20 of 20 perturbations, xcs at 0.999 fixed on 20 of 20
  (the lane: 6 of 20), the `ou` rows estimated (lane: 19 fixed),
  `homcs` at -30 estimated (lane: 3 fixed), an interior `us` block
  estimated. The gap between the classes is about 10 orders of
  magnitude, not 1 ulp. (The first prototype, `proto.txt`, kept a
  floor of 1 and called 5 underflowed `ou` rows fixed: the floor is
  the defect, not the step.)
- (b) Let the registration say it: an optional slot of
  `frmtmb_register_covstruct()` naming the rows the structure fixes.
  Exact, but an API addition, larger than a patch.

Either way: set `se_g[fixed] <- 0` before the NA rules, or exclude
fixed rows from them, so a lost-direction NA is never overwritten; and
add the `ou` independence fit and a fixed 0.999 correlation to the new
test (`test-covstruct-seam.R`), each over 20 perturbations: the
estimated rows must not have se exactly 0 with a zero width; the fixed
ones must have zero width on every perturbation.

## FIX 2 (MINOR). The "ignore" assertion of `test-se-limit.R` accepts a stop short of the maximum

`tests/testthat/test-se-limit.R:104-113`: when `opt$convergence != 0`
it accepts exactly one warning that starts "Optimizer did not report
convergence: ". `conv_headroom_clause()` (`R/fit.R:6270-6287`) ends
that warning three ways: "the estimates are at the maximum", "would
still gain ... short of the maximum", or "the curvature at the stop is
unusable". Only the first is the valid code-8 ending the lane measured
(`ref-nbk.txt` k = 3, 4: false convergence (8), the Newton gain within
`grad_tol`). The other two are the defect the old `expect_silent()`
caught: a fit that stopped short. Expected: in the else branch also
`expect_match(ri$warnings, "false convergence (8)", fixed = TRUE)` and
`expect_match(ri$warnings, "so the estimates are at the maximum",
fixed = TRUE)`, and the estimates equal to the "warning" fit's
(`ri$value$opt$par[1:2]` against `r$value$opt$par[1:2]`, ratio within
1e-6 of 1; the warn and ignore fits run the same path, `ref-nbk.txt`).
With that, the new test accepts only valid endings.

The code-8 branch was never run inside the test file on any setting
(k = 0 stops at code 4 everywhere tried). `dev/reviews/ci082-review-nb8.R`
(log `nb8.txt`, reference BLAS) runs the lane's assertion verbatim on
k = 3 and 4: code 1 "false convergence (8)", one warning ending "A
Newton step from the stop gains 9.9e-07 [3.51e-06] ... so the estimates
are at the maximum", parameters identical to the "warning" fit's, and
the assertion passes. So the branch works, and the two extra matches
above hold on the valid ending.

Is the code-8 ending valid under "ignore"? Yes, by the documented
contract: `test-se-conv.R:145-149` pins that a code-8 stop keeps its
`frmtmb_conv_code` warning when `check_se = "ignore"`, because the
at-the-maximum verdict needs the SE analysis "ignore" turns off. The
warning on the runner is that contract, not the limit verdict flipping:
on the runner the "warning" fit of the same data (line 86, same path)
passed with 0 warnings and 1 message.

### Lane item 4: `RNGkind()` restore

`R/mixture-starts.R:275` `do.call(RNGkind, as.list(kinds))`. R-devel's
`RNGkind(kind, normal.kind, sample.kind, binom.kind)` (read from
`src/library/base/R/RNG.R` with `gh api`) takes the fourth by
position; R 4.3 to 4.6 have three, and `as.list()` of a length-3
vector passes three. Each name `RNGkind()` returns is one `pmatch()`
accepts. A "Rounding" sample kind, a "Buggy Kinderman-Ramage" normal
kind and a "Buggy BTPE" binom kind warn on restore; `suppressWarnings()`
hides them, as 0.82.0 hid the first. "user-supplied" restores only
while its library is loaded, which it is if the caller set it.
`.Random.seed` is put back after the kinds, as on 0.82.0 (unchanged
lines `:276-280`); a seed that did not exist is removed. The draws use
only `rnorm()`, so the caller's binom kind cannot change them. No other
`RNGkind()` restore exists in `R/` or `extensions/`. Not run on
R-devel (none here).
