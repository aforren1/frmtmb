## Findings

### 1. major: fractional new data outside the range are not refused

`mo_codes()` rounds before it checks the range
(`as.integer(round(v - lo))`), so every value in `[min - 0.5,
max + 0.5)` is accepted and moved to a category without a message.
`dev/review-mocode-frm.R` on the lane, 1..4 fit:

```
k = 0.6 (below the minimum)        2.230883      (the k = 1 value)
k = 4.4 (above the maximum)        6.638541      (the k = 4 value)
k = 2.5                            5.962138      (the k = 3 value)
k = 2.4                            4.698644      (the k = 2 value)
```

brms 2.23.0 refuses all of these (`dev/review-mocode-brmsfit.R`,
`posterior_epred()`): "Invalid values in variable 'k': '0.6'", the same
for '2.5' and '4.4'. NEWS says "a value below the fitted minimum or
above the fitted maximum is refused, as brms's `validate_newdata()`
refuses it", and `man/frm.Rd` says "a value outside the fitted range
is refused". Both are false for 0.6 and 4.4. The rounding is
pre-existing (0.75.0 gives the same values), but the sentences are
new. The lane's item 2 left the rounding as "a separate decision"; the
tiebreaker decides it: brms refuses, and brms is not wrong to refuse a
covariate the model does not define. Silent rounding also answers a
question the user did not ask (finding 2 shows the cost).

Also, `marginaleffects::avg_slopes(fz, variables = "k")` returns 0
(`interop-lane.txt`, base the same): the finite difference never leaves
a category. Refusal makes that loud.

Fix (prototyped in `dev/review-mocode-patch.R`, applied to a copy):

```r
  lo <- mo_min(mi)
  if (!is.numeric(v) || anyNA(v) || any(v != round(v)) ||
      any(v < lo | v > lo + mi$D)) {
    frm_stop(...)   # say "whole numbers in the fitted range lo..hi"
  }
  as.integer(v - lo)
```

plus finding 2's change to `conditional_effects()`, which otherwise
feeds the mean in. Then add a test: `fitted(newdata = k = 0.6, 2.5,
4.4)` refused, as brms. The NEWS bullet then holds as written; add
"or a value that is not a whole number" to it and to `man/frm.Rd`.

### 2. major: `conditional_effects()` and emmeans hold `mo()` at the mean

`round(median())`, and gives its moderator values as
`round(median + (-1:1) * mad)` (`R/conditional_effects.R` 795 and
889 to 891 of the brms tree in `dev/brms-suite/`). frmtmb holds it at
`mean()` and `mean +/- sd`, which `mo_codes()` then rounds. Run on the
same data (seed 5) and model `y ~ mo(k) + z`:

### 3. minor: `conditional_effects()` refuses `mo()` in a `subset()` response

`dev/review-mocode-ce.R` (lane, `ce-lane.txt`):
`bf(y | subset(k > 1) ~ mo(k)) + bf(y2 | subset(s2) ~ mo(k))`,
`conditional_effects(fs, effects = "k", resp = "y")` stops with
"mo(k): new data outside the fitted range 2..4", and so does the call
without `resp`. The grid is built from every row of the data (1..4),
while `y`'s term was fitted on 2..4. This is new: 0.75.0 coded from 0
and predicted `k = 1` (an empty category). It is loud, not silent.

brms is wrong here, so do not follow it: `dev/review-mocode-brms-subset.R`
(`brms-subset.txt`) shows that with `subset()` in a multivariate model
brms codes new data from the NEW data's own minimum. `y2` (fitted on
1..4, `Jmo_y2` 3) codes new data `2 3 4` as `0 1 2` (the fit codes them
`1 2 3`), and `y` codes `1 2 3 4` as `0 1 2 3` with `Jmo_y` 2, a code
past the simplex. Without `subset()` the same data are coded `1 2 3`
for both responses. File it as brms-41.

Fix: build the stepwise grid of a `mo()` variable from the fitted
term's range, `seq(mi$min, mi$min + mi$D)` of the response's entry,
not from the data column; one test on this model.
