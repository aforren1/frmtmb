# Review of lane arspat2 (round of 2026-11-13, base ec8178d3)

Adversarial review. Lane tree `frmtmb-wt-arspat2`, library
`wt-arspat2-lib`, base `rellib-r21`. Scripts
`dev/reviews/arspat2-review-*.R|sh`, logs `dev/reviews/arspat2-review-out/`.
Comparison against ec8178d3 by `git show` copies and `diff
--strip-trailing-cr`; no `git diff`, no git writes.

## Verdict: FIX

The 5289 margin is correct on every case tried (relative 1e-11 or
better). Two items block: the 5264 interval loses coverage badly where it
matters, and the margin route's cost is not "about 2x": it grows faster
than m^2, and two fcor fits that 0.82.0 completed now fail out of memory
(surfacing as a NaN-gradient optimizer error).

## FIX items

### F1. 5264: the logit-scale interval undercovers rho near its end (HIGH)

`R/autocor.R:1904-1912` (`autocor_trans_rows()`), used by
`confint_varcorr()` (`R/confint.R:1003-1005`), `summary()` (`R/methods-fit.R:359-363`,
`:659-665`) and `frm_multiple()` (`R/multiple.R:164-169`).

Reproducer: `dev/reviews/arspat2-review-cover.R` (200 seeds per cell,
`y ~ x + sar(W)`, lag, row-standardized rook W, data
`solve(I - rho W, 1 + 0.5 x + e)`). Both intervals from the same lane
fit; the old one rebuilt as `est +/- z Est.Error`, checked against base's
`confint_varcorr()` (base run: coverage 0.935, past hi 133, identical to
the rebuild). Logs `cover-lane.txt`, `cover-base-0.9.txt`,
`cover-lane-0.5.txt`.

| lattice | true rho | coverage new (logit) | coverage 0.82.0 (raw) | upper end past hi, raw | upr < rho, new / raw |
|---|---|---|---|---|---|
| 5 x 5 | 0.9 | 0.665 | 0.935 | 133 / 200 | 67 / 13 |
| 10 x 10 | 0.9 | 0.860 | 0.930 | 4 / 200 | 28 / 11 |
| 5 x 5 | 0.5 | 0.920 | 0.925 | 14 / 200 | 16 / 13 |
| 10 x 10 | 0.5 | 0.915 | 0.925 | 0 / 200 | 13 / 10 |

Expected: a nominal 95% interval that stays inside (lo, hi) and covers
about as well as before. Actual: on the lane's own design (5 x 5, rho =
0.9) coverage drops from 93.5% to 66.5%. The ML estimate of rho is biased
low on small lattices; the logit map compresses the upper side, so the
interval's upper end lands below the truth in 67 of 200 fits. The
out-of-range end was cosmetic (rho past 1 is impossible, so it never
cost coverage); the new failure is a real one. The lane's test
("rho's interval is the Wald interval on the logit of its range",
`extensions/frmtmb.spatial/tests/testthat/test-sar.R:653`) pins the
regressed behavior.

Fix options (user decision, see below): (a) the raw-scale delta interval
clamped to `[lo, hi]` keeps 0.935 / 0.930 and stays inside by
construction; (b) a profile interval on theta (correct but costs refits);
(c) keep the logit interval and document the undercoverage. Recommend (a)
with type kept `"raw"` plus a clamp flag, or a `"bounded"` type whose
untransform is `pmin(pmax(v, lo), hi)`.

### F2. Margin route cost: superlinear in m, and one fit now fails (HIGH)

`R/autocor-seam.R:319-347` (`autocor_seam_t_margin()`): `m` dense
`whiten()` columns, then `t(Km) %*% Km` (n x m by m dense, O(m^2 n)) and
an m x m solve and determinant, all on the tape.

Reproducers `dev/reviews/arspat2-review-cost.R` (n = 1000, 25 x 40

`cost-sar-lane.txt`, `cost-sar-base.txt`, `nan-lane.txt`, `nan-base.txt`.

sar at n = 400: 4.6, 27.6, 75.8 s at m = 100, 200, 300 (base 0.8, 1.7,
9.3). fcor's peak working set was 11.1 GB at n = 1000, m = 50 (base 8.6
GB). Two fcor fits that 0.82.0 completed now stop with "The optimizer
failed on this model (student, ML, prior, nlminb): NA/NaN gradient
evaluation" (optim: "L-BFGS-B needs finite values of 'fn'"): n = 1000,
m = 200 (base: code 0, 196.6 s) and n = 400, m = 300 (base: code 0,
59.5 s).

Root cause, `dev/reviews/arspat2-review-nandiag.R` and `-nandiag2.R`
(logs `nandiag-lane.txt`, `nandiag2-lane.txt`), n = 400, m = 300, the ML
margin route through `mi_sampling(dry_run, "laplace")`: the objective is
NaN at the start point itself; the joint nll there is finite (526.9).
Building TMB's inner Hessian tape fails: `env$spHess(random = TRUE)`
raises "Caught exception 'std::bad_alloc' in function
'MakeADHessObject2'" after the process peak went from 3.5 GB to 32.7 GB;
inside `obj$fn` the same failure is swallowed and comes back as NaN
(peak 37.3 GB). The margin couples every missing value with every other
through `d = G^-1 K_m'u` and `G`, so the inner Hessian is dense m x m and
its tape scales with m^2 times the per-column cost. `log|G|` is not the
cause: RTMB 2.0's taped `determinant()` is exact to m = 300 and |log| >
1000 (`arspat2-review-logdet.R`).

Expected: the documented "one call of the term's map per missing value"
(NEWS, `?frmtmb_register_autocor`) and every fit 0.82.0 completed still
completes. Actual: superlinear cost, and an out-of-memory failure that
surfaces as an optimizer NaN error with no hint at memory (on a shared
63 GB machine one such attempt took 37 GB).

Fix: for sar the Jacobian is `A / sigma` and the `jacobian` slot already
returns it sparse (`sar_jacobian()`); `K_m' K_m` is then a sparse m x m
product, and `d` and `|(I - P) u|^2` follow from one sparse solve. For
fcor, `K = L^-1 / sigma` with constant `L`, so `K_m' K_m = [M^-1]_mm /
sigma^2` is data times a scalar. Either way no dense n x m block on the
tape. At minimum: say the real cost in NEWS and the docs, file the n =
1000, m = 200 failure with the reproducer, and gate (message) above some
m.

### F3. Docs and compat notes contradict the fix (LOW)

- `R/compat.R:2131` and `R/autocor-seam.R:388` (registered term's `mi()`
  row): "on student() its error is a function of nu and the numbers of
  rows and of missing values alone, which the objective takes off, so the
  fit is exact there too ..., also with random effects or REML beside
  them". With random effects the error is NOT a function of nu, n, m
  alone; that is the defect fixed here. Reword: the objective writes the
  observed rows' margin there.
- `R/fit.R:1356-1358` comment "beta joins the integrated values" and the
  findings' "REML/profile also integrates beta": `profile = TRUE` passes
  `profile = "beta"` to `MakeADFun` (`R/fit.R:1617`), which maximizes beta
  in the inner problem with no Laplace term for it. Base with profile and
  no random effect is exact on the constant route (`margin-base.txt`,
  "profile, no RE": diff 4e-14, 3e-14, -1e-14). The flag only costs time
  there (margin route is exact too), but the stated reason is wrong.
  Measured: the lane's "(1 | h), profile" base error comes from the
  random effect, not from profile.
- Cost wording ("one call of whiten() per missing value") in NEWS.md,
  `R/autocor-seam.R:250` and `R/autocor-seam.R:313-316`: see F2.

### 2. Flag readers

`mi_inner_beta` is read only by `autocor_seam_t_missing()`; that function
returns nothing without `mi_map`, so REML without `mi()` is unchanged
(ident: gaussian fcor REML bit-identical). `mi_laplace_exact()` reads
the route; `mi_retape()` keeps the frame, so the flag survives retapes.
Registered terms take gaussian and student only, so skew_normal or
lognormal cannot reach this path.

### 4. 5264 mechanics

Only `sar()` registers a bounded seam parameter (no other
`frmtmb_register_autocor()` call in the extensions; car's rho is a
covstruct `prop` row and unchanged). The logit is sar's own theta, so
the delta step is the identity up to the central difference. `lo`/`hi`
are internal columns of `varcorr_trans_rows()`; the exported
`confint_varcorr()` columns are unchanged. Rubin pooling in
`frm_multiple()` is on the logit scale, consistent with log / Fisher-z
for the other types. No tidy/broom method reads the type. Edge: an
estimate with theta past about 37 rounds `p` to 1, `est_t` to Inf and the
row to NA with the "standard deviation at zero, correlation at +/-1"
warning text; not reachable in practice since `log|A|` diverges there.
The zero-SE NA rule (and ci082's `fixed` exception) applies to
`re_blocks` rows only; autocor rows never had it, before or after.

## Needs the user

2. F2: the margin route turns fits 0.82.0 completed (wrongly, by 27
