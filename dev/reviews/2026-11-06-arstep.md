## Verdict: FIX

The AR marginal is exact, the gate refuses what it should, the state

## Findings

### B1. BLOCKER: panel designs fit 100 to 500 times slower, same answer

`dev/review-arstep-cost.R`, log `cost-1.txt`. One process, lane against a
namespace mutant that sends `ar()` down the 0.79.1 route (`noar`:
`gp_marginal_ar()` refuses every AR term), interleaved, two reps:

| design | rows | positions | lane wall, s | `noar` wall, s | ll both |
|---|---|---|---|---|---|
| `y ~ gp(x) + ar(time = t, gr = s)`, 12 subjects by 50 times | 600 | 50 | 47.2, 45.4 | 0.51, 0.41 | 32.589404 |
| same, 25 subjects by 40 times | 1000 | 40 | 180.4, 175.7 | 0.34, 0.39 | 173.765935 |
| `y ~ gp(x) + ar(time = t)`, distinct x | 300 | 300 | 22.7, 24.8 | 17.8, 18.6 | 227.607924 |

For contrast, on 500 distinct positions (`a500`, `cost-2.txt`, one rep) the
lane took 117.8 s against 155.5 s and reached ll 269.968071 against
262.192289: faster and 7.78 nats higher. The AR marginal pays off where rows
are positions, and costs two orders of magnitude where they are not.

Cause. `gp_marginal_data()` sets `J <- seq_len(n)` whenever an AR term is
present ("An AR term mixes rows, so every row is its own"), so the marginal
is over every row, not over the distinct positions. The base compresses 1000
rows on 40 positions to a 40 by 40 problem. The lane factors 1000 by 1000 in
each of the scan's 220 cells (11 length scales by 4 AR coefficients by 5
noise ratios), then runs up to 13 tape descents through `RTMB::dmvnorm()`
on a dense 1000 by 1000 covariance, with `n x n` masks per lag
(`gp_ar_data()`). The gate's only size limit is `gp_marginal_max_rows`
(1000), so 1000 rows pays the full cost and 1001 rows falls back to the
working route at 0.3 s.

This design is not exotic: repeated measures on a shared time axis is the
standard use of `ar(gr = )` beside a smooth trend. The lane's cost runs
(`dev/arstep-cost.R`, findings section 8) used distinct positions only, where
rows equal positions.

Fix: use the AR marginal only where it is cheap, for example where the row
count is at most a small multiple of the distinct positions, or under a row
cap of a few hundred measured against the working route; otherwise keep the
0.79.1 route. Measure it on the panel designs above. Then NEWS states the
cost on both kinds of design.

### M1. MAJOR: a constant `sigma` beside `ar()` lets 19 warnings escape

`dev/review-arstep-sigconst.R`, logs `sigconst-lane.txt`, `sigconst-base.txt`,
seed 12, n 50:

| formula | base warnings | lane warnings | ll both | marginal start used |
|---|---|---|---|---|
| `bf(y ~ gp(x), sigma = 0.3)` | 0 | 0 | -21.493400 | yes, both |
| `bf(y ~ gp(x) + ar(time = t), sigma = 0.3)` | 0 | 19, "NA/NaN function evaluation" | -20.653908 | no, both |
| `bf(y ~ gp(x) + ar(time = t), sigma = 0.2)` | 0 | 19, same | -20.360064 | no, both |

`gp_marginal_gate()` admits a constant `sigma` (`betad_fixed_idx`) and sets
`has_sigma = FALSE`, so the marginal has no noise term at all. With `ar()`
the scan's tape descents then read `NaN`, and `stats::nlminb()` warns. The
call in `gp_marginal_opt()` is wrapped in `tryCatch(error = )`, which does not
catch warnings. The agreement guard then refuses the start (the marginal
reads `NaN`, `dev/review-arstep-out/exact-lane.txt`, "edge sigma constant
0.3"), so the result is the base's, after a wasted scan and 19 warnings that
name nothing the user wrote.

Fix: refuse a constant `sigma` in the AR gate (or carry it as a known noise,
`s0`, which `gp_marginal_cell()` already supports), and muffle the
`nlminb()` warnings of the marginal's own descents. Add the case to test 3
with `allow_warnings()` absent, so an escaped warning fails it.

Pre-existing, not this lane's: without `ar()` the base's gate admits the same
constant `sigma`, builds a marginal with no noise, and uses its maximum as the
start and as `.frmtmb_gp_marginal`, the number `check_convergence()` compares
the stop with. That number is not the model's. See the open questions.

`ar(time = )` with gaps: brms and frmtmb order by time and ignore the
spacing, and the marginal does the same. `det(A) = 1` holds for every
admitted structure: `A` is unit lower triangular in time order within each
group, block diagonal over groups, so a permutation of a unit triangular
matrix. The masked rows (a group's first `k` rows at lag `k`) are what
`nomask` breaks, and the tests catch it.

Gate edges (same log): `weights()`, `ar(cov = TRUE)`, `ma()`, `arma()`,
`sigma ~ z`, `gaussian(link = "log")`, `student()`, `skew_normal()` are
refused; `se()` with `cov = FALSE` is refused by `ar()` itself (an error, as
brms). A prior on `ar` makes the objective differ from the marginal, and the
agreement guard refuses the start (`marginal used FALSE`). `sigma ~ 1` is
admitted and exact. The one edge that is admitted and not exact is the
constant `sigma` of M1, which the guard catches.

### The no-warning decision

No cheap rule separates the short fits. From the lane's logs
(`dev/arstep-out/trace-ng-rows.txt`, `r2ng3-lane.txt`), the 46 disagreeing
fits include the 2 short ones at |difference| 0.65 and 0.026. A rule
"disagree by 1e-3 to 1 nat" fires on 11 of them and catches both, which
looks like a rule but is tuned on those rows. On my fresh rows (`FRSD`
lines of `fresh-N-lane.txt` and `fresh-P-lane.txt`, 37 second descents) the
two descents disagree by more than 1e-3 on 21 fits (16 in part N, 5 in part
P); 0 of the 21 are short after the better is kept. The same rule fires on 9
of the part N fits and on all 5 part P fits (0.001 to 0.23), all false. The
11 short fresh fits are ones where the two descents agree (4) or where there
is no second start (7), so no rule on the disagreement can catch them. I
agree with the lane: no warning.

## Merge hazards

- **nestquad, `R/fit.R`**: certain textual conflict. Both lanes insert
  lines right after the `}))` that closes the first `optimize_obj()` call in
  `fit_assembled()` (base line 1644): arstep its `gp_second_descent()` line,
  nestquad a new `} else if (!is.null(qnest)) {` branch. Resolve by keeping
  arstep's line inside the first branch, before nestquad's `else if`.
- **fitedge, `R/gp-start.R`**: `gp_marginal_setup()` and `gp_marginal_data()`
  gain `max_rows` in fitedge; arstep left both signatures alone and reads the
  AR term from `frame`. The hunks are separated by unchanged lines and should
  merge, but check by hand. Semantic hazard: fitedge's new non-`mu` branch in
  `gp_start_working()` appends to `theta` and `next`s without extending
  `alts`. With a `mu` block first (a multivariate model with a linear `mu`
  gp in one response and a nonlinear `a ~ gp()` in another), `alts` is then
  shorter than `theta`, and `tpl[["theta"]][w$idx] <- w$alts[[1L]]` in
  `gp_start_scan()` recycles it. The lane's findings (section 14) say "add
  this lane's `alts` lines after a successful `m` on the `mu` branch only";
  the non-`mu` branch must also do
  `alts <- lapply(alts, function(th) c(th, m$theta))`.
  fitedge's `gp_body_start()` calls `gp_marginal_data()` with a frame that
  has no `autocor`, so the AR term stays off there. fitedge's
  `gp_marginal_outer_gr()` refuses `thetaac`, so it never meets the AR
  marginal; on a constant `sigma` its own value check refuses.
- **fitedge, `R/se-check.R`**: does not touch `obj_state_save()` or
  `obj_state_restore()`, which the second descent uses.
- **bigx, `R/fit.R`**: rewrites `optimize_obj()`'s inside (coordinates) but
  keeps its signature and `start_par` in natural coordinates, so
  `gp_second_descent()`'s call is compatible.
- **loglik, nlstart, superassign, `R/fit.R`**: hunks elsewhere (loglik and
  nlstart before line 1600; superassign in `nlminb_trial_fn()`,
  `newton_polish()` and `mo_search()`). No overlap with arstep's two hunks.

## Open questions for the user

1. B1: which rule for when the AR marginal is worth its cost? A row cap, a
   ratio of rows to positions, or a group-wise computation (`A` is block
   diagonal by group, but `K` is not, so the gain needs work).
2. Should frmtmb say anything when a `cov = FALSE` `ar()` fit lands past a
   unit root? It is brms's likelihood, brms's own chains split over the two
   basins on the lane's row, and on step-shaped data it is now the usual
   answer (m6).
3. Pre-existing: the base's gaussian marginal ignores a constant `sigma`
   (`has_sigma = FALSE` with no noise), uses that number as the start and as
   the convergence proof. Not this lane's change; it needs its own fix.

### M1 and the base bug

Same log, constant `sigma` and `se()` against the objective:

```
EX2 sigma = 0.3                        admitted u 38 n 50 ... warnings 0 worst rel 2.7e-15
EX2 se() alone                         admitted u 50 n 50 ... warnings 0 worst rel 8.8e-15
EX2 se(sigma = TRUE)                   admitted u 50 n 50 ... warnings 0 worst rel 1.1e-14

EX2 se() alone, sigma = 0.3            admitted u 50 n 50 ... warnings 0 worst rel 8.8e-15
EX2 ar, sigma = 0.3                    gate REFUSED, start used FALSE, warnings 0
EX2 ar, sigma = 0.2                    gate REFUSED, start used FALSE, warnings 0
```

The marginal reads the objective with and without `se()`, including
`se()` alone beside a constant `sigma`, which `resid_sd()` ignores. The
AR gate refuses a constant `sigma` (`if (!is.null(ar) && !has_sigma)`)
before any scan, and no warning escapes. Note that `sigma = 0.3` with
repeated `x` (u 38 of 50) also exercises the within-position sums.

`suppressWarnings()` wraps only the two `stats::nlminb()` calls of the
marginal's own descents (`gp_marginal_opt()`, `gp_ar_descend()`). What they
can emit is about the start's private descent (`NA/NaN function evaluation`,
iteration limits). A failed descent returns `NULL` and the start falls back.
The AR descent's objective maps non-finite values to `1e300`. Any warning a
covariance structure's `vcov()` raises there is raised again by the fit's
own objective, which is not wrapped. Nothing the user can act on is hidden.
