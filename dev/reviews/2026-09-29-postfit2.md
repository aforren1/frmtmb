# Review of lane postfit2, 2026-09-29

Worktree `frmtmb-wt-postfit2`, branch `wt-postfit2`, uncommitted
against `1f40800d` (frmtmb 0.65.0). Lane library
`wt-postfit2-lib`; base build `rellib-r3`. Every script and log named
here is under `dev/`, prefixed `postfit2-rev-`. No package file was
edited.

## Verdict: NOT MERGEABLE

The ported functions (`conditional_smooths()`, the `surface`,
`too_far`, `select_points` and `spaghetti` options, the nonlinear Wald
band, `make_conditions()`, `posterior_average()`, `update_adterms()`)
are good: I reproduced every brms comparison of the lane, and I found
no regression on models that do not use the new options. The late fix
(`ce_set_vars()`, the conditional bootstrap) is the problem. It fixes
the case it was built for, one grouping factor set to an observed
level. It also creates new silent wrong answers on adjacent shapes that
base answered correctly or answered differently wrong, and on one shape
the NEWS entry says it is fixed when it is not.

## Blockers

B1. **A level that `conditions` sets and the fit never saw now gets
the population band (a regression).** `ce_set_vars()` counts any
non-NA value as "set", so `g = "99"` is taken out of `na_vars` and gets
no new-level draw. With `allow_new_levels = TRUE` each replicate or
draw predicts the unseen level at zero effect.
`postfit2-rev-adv-fit.R` (data seed 21, boot 40, seed 5), band widths
at the 3 grid points:

    fit boot, lane   0.840 0.313 1.005   (the population band)
    fit boot, base   4.561 4.222 4.018   (= the new-group band, A0)
    fit Wald, both   4.912 4.811 4.891

`postfit2-rev-adv-draws.R` (seed 9, 200 hand-built draws) gives the
same result on draws: lane 0.5406 0.1827 0.6122, which is identical to
the population row; base 1.1185 0.9774 1.2025. Without
`allow_new_levels`, the draws method used to answer and now stops
with "New levels in grouping factor `g`: NA". brms always sets
`allow_new_levels = TRUE` in `conditional_effects.brmsterms()` (source
in `postfit2-rev-brmssrc/`) and draws a new level: in
`postfit2-rev-brms.R` section 3 (40 draws), the brms width is
0.7054 0.5372 0.6592 against a population width of
0.4504 0.1761 0.5638. A value is "set" only if it is an observed
level. An unseen value is a new level, as base treated it.

B2. **Rows that mix a level with `NA` give a silent population band
for the NA row under `allow_new_levels = TRUE`.** This is the "known
unfixed" case. It is silent, so it must be refused or handled per row.
Measurements:

- `postfit2-rev-mixed-fit.R`, the boot width of the NA row:
  0.8404 0.3132 1.0051. The Wald width of the same row is
  4.9123 4.8110 4.8912.
- On draws, the NA row equals the population row, 0.4504 0.1761 0.5638.
- brms gives this row a new level: 0.5284 0.4382 0.5879 in one run and
  0.4704 0.4236 0.7037 in another (random new-level choice,
  `postfit2-rev-log/brms-lane.txt`).

Without `allow_new_levels`, both methods stop with "New levels ... NA",
which does not name the cause.

B3. **Nested `(1 | g / h)` with `g` set and `h` unset drops the new
`g:h` level's variance.** `ce_new_level_spec()` skips a block unless
ALL its grouping variables are in `na_vars`, and `ce_set_vars()`
removed `g`. `postfit2-rev-nested.R` (the crossed-within design, 8 x 4,
data seed 25) gives these widths:

    lane boot width / Wald width    0.2547 0.2157 0.2932
    base boot width / Wald width    1.1167 1.2003 1.2440

Base is wrong in a different way: its band misses its own estimate
(hi 1.3615 < est 1.4097). The draws method is too narrow in the same
way. Its width equals the observed-level width (`adv-draws`, "nested
g=5 set").

B4. **Crossed `(1 | g) + (1 | h)`, `g` set, `h` unset: the fit's boot
band is still centered on the population curve, and NEWS says this is
fixed.** A remaining new-level spec makes `sim_re` equal to `NA`
(fresh effects). `postfit2-rev-adv-fit.R` B (data seed 22, boot 60,
seed 5) measured:

- The mean of the refits is 1.035 modes from the estimate. Base
  measured 1.059.
- The band misses its own estimate at 2 of 3 points: est 0.8967 >
  hi 0.7836, and est 2.5728 > hi 2.4479.

The NEWS bullet and the help paragraph ("A curve at an OBSERVED group
... is refitted to responses simulated conditional on the fitted group
effects") are false for this shape. The draws method is correct here:
brms at the same draws, with `h` pinned to 0, matches to 1.6e-08
(`postfit2-rev-brms.R` 1b).

B5. **An unannounced change of the boot band on models with smooths
and no unset group.** `sim_re` is `NULL` whenever
`re_formula != NA` and `nspec` is empty. That includes a model with no
grouping factor at all. `y ~ s(x)` (`postfit2-rev-adv-fit.R` D, data
seed 24, boot 60, seed 5) measured:

- The `re_formula = NULL` boot band changed from base (identical to the
  `NA` band, 9.8 to 14.0 times the Wald width) to 0.057 to 0.085 of
  it.
- On the lane, `NA` and `NULL` now differ by 12 to 17 times on a model
  where `re_formula` has nothing to act on.

This is not in NEWS or the findings. The trigger must be "a grouping
variable is set to an observed level", not "no new-level spec".

B6. **A false refusal.** On a nonlinear `mu` with no group term and
`sigma ~ (1 | g)`, `re_formula = NULL` refuses the Wald band "at a new
group". The linear control with the same shape answers
(`postfit2-rev-guards.R`). The guard tests `anl` over the whole model,
not over the predictor on display. The refusal is narrower than base,
which refused every nonlinear Wald band, but it fires on a correct
model.

B7. **No test pins the new reuse-key field.** I dropped `conditional`
from `ce_boot_key()` in the process (mutant `keydrop`,
`postfit2-rev-runtest.R`). `test-ce-options.R` 32/32,
`test-ce-bands.R` 169/169 and `test-brms-methods.R` 983/983 still
pass. With the field dropped, a population boot on a byte-identical
grid (`g` at level 1, `postfit2-rev-adv-fit.R` E) is accepted for an
observed-level call. The other mutants are caught:

| Mutant | Failures |
|---|---|

| `simNA` | 2 |
| `fitrevert` | 3 |
| `drawsrevert` | 4 |

### Blockers

P1-B1. **`(1 | gr(g, by = f))`: every `re_formula = NULL` display on
`band = "boot"` and on draws is refused, including an OBSERVED level.**
`ce_level_plan()` treats the block of every by-level as read by every
row. So in a row with `f = "a"`, the `f = "b"` block is "new", and its
placeholder would have to move `g` to a `b` level.
`postfit2-rev-p1-grby.R` (data seed 44; 12 levels of `g`, with `f`
constant within `g`) shows:

- **`g` unset, `f = a` or `f = b`:** boot and draws refuse. The Wald
  band answers (widths 0.89 and 6.17).
- **`g = 3`, `f = a` (observed):** boot and draws refuse with "cannot
  draw a new level of the group-level term (1 | g [f = b])". The Wald
  width is 0.55 0.41 0.58.
- **`g = 9`, `f = b`:** refused the same way.

The draws method has no other band, so `conditional_effects(ds,
re_formula = NULL)` cannot be called at all on such a model. Base
answered, but wrongly (4.7 to 5.4 wide regardless of `f`). brms
answers, and its `get_new_rdraws()` picks within the row's by-level
(source read). Classify a by-split block as read only by the rows
whose by-level it is.

P1-B2. **No test pins `ce_locked_vars()`.** The mutant `p1_nolock`
(lock nothing, injected in the process) passes all 9 relevant files:

- `test-ce-levels`, `test-ce-options`, `test-ce-bands`,
  `test-simulate-newdata`, `test-boot`;
- `test-postfit-draws`, `test-conditional-effects-draws`,
  `test-re-formula-draws`, `test-predfix-new-levels`.

The rule changes answers. Take `y ~ x + trt + (1 | trt:subj)` with
`trt = "b"` set (`postfit2-rev-p1-nolock.R`, data seed 41). Under the
mutant, the placeholder moves `trt` to `"a"`, so the fixed effect reads
`"a"`:

    lane:          boot mean of refits 1.0917 2.1500 3.2083 | draws est 0.9883 2.0616 3.1308
    mutant nolock: boot mean of refits 0.2882 1.3465 2.4047 | draws est 0.1506 1.2225 2.2886

This is the same class as B7 of the first review.

### Major

P1-M1 (pre-existing; section 7c misdescribes it).
`(1 | mm(g1, g2))` under `re_formula = NULL` never reads a new level.
Base and lane are identical here (`postfit2-rev-p1-mm.R`, data seed
43):

- **Nothing set:** the grid holds `g1 = g2 = "1"`. The estimate is
  `identical()` to the call that sets `g1 = g2 = "1"`, so the first
  observed level silently stands in for the group.
- **`g1 = g2 = "2"` set (observed):** the mean of the boot refits sits
  near the population curve. The boot band is 5.1 to 6.0 times the
  Wald band.

Section 7c says such a term "gets no drawn level ... the Wald band
carries its variance". That is false: no band carries it, because
nothing is new. Refuse or fix `mm()` under `re_formula = NULL` on boot
and draws, and correct the record.

P1-M2. **Crossed `(1 | g) + (1 | h) + (1 | g:h)`, with `g` and `h`
set to a combination the fit never saw.** Boot and draws refuse by
name. The Wald band answers (width 3.24, `postfit2-rev-p1-attack.R`
P5). The refusal is honest: the placeholder cannot move columns that
observed blocks read. But draws have no other band, brms answers, and
`?conditional_effects` does not mention the limitation.

P1-M3 (pre-existing; base behaves the same). **The reuse key does not
carry `re_formula`.** Take `y ~ x + (1 + x | g)` with `g = "3"` (P8):

- A bootstrap from a `re_formula = NULL` call is ACCEPTED by a
  `re_formula = ~ (1 | g)` call.
- That call drops the slope and predicts a different curve: 3.3975
  against 3.7586 at the third point.
- The reused band there is [2.9230, 3.9647]; the call's own bootstrap
  gives [3.4920, 3.8616].

The by-value comparison itself is sound. An integer `3L` grid against
a double `3` is refused (P8b), and `identical()` compares factor level
order.

- **Silent `NA` for a new factor-smooth level.** With `s(x, g, bs =

### Major

P2-M1. **`mm(g1, g2)` beside `(1 | g1)`, with nothing set (the
default display) or with `g1 = "99"`:** boot and draws refuse ("cannot
draw a new level of the group-level term (1 | mm(g1, g2))"). The Wald
band answers (4.81), and brms answers (`postfit2-rev-p2-mm.R`, C).

No observed term reads `g1` in these rows, so the help's own rule does
not cover this refusal: the rule refuses only a column that a term
reads at an OBSERVED level. `ce_plan_part()` refuses because the plain
term has already placed `g1`. One placeholder could serve both new
terms, since their coefficient slots are separate. Either make the
placement share it, or document this case. Where this shape answers,
it equals brms at the same draws (see point 2).

   - **The Wald band at a mixed row.** I set the fit's SD to 1 and
     then to 2. The difference in `se^2` is exactly the expected
     variance of the new members: 0.7621 at the mixed row against
     `3 * w2^2` = 0.76209; 3.0000 with nothing set; 1.5001 at `"99"`
     and `"98"` against `3 * (w1^2 + w2^2)` = 1.50010.
   - **The shared draw of brms is an artifact, not a design choice.**
     `brms:::data_gr_local()` numbers the unseen values of each `mm()`
     member separately:
     `J[is.na(J)] <- match(new_gdata, new_levels) + length(levels)`,
     with `new_levels` taken within that member. So `g1 = "99"` and
     `g2 = "98"` both become level `nlevels + 1`. For one grouping
     factor, two different unseen values get different indices, and
     brms's `get_new_rdraws()` then draws each one. frmtmb's
     independent draws are the consistent reading, and
     `?conditional_effects` states the difference. The measured gap is
     a frmtmb draws width of 1.72 against brms's 2.47 (weights), and
     1.27 against 1.85 (three members).
