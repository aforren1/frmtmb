### Which side carries the fold. brms does

This is the question the brief asked to settle, and brms's generated
code answers it in one line. For S7:

```
lprior += student_t_lpdf(sigma | 3, 0, 59.3)
  - 1 * student_t_lccdf(0 | 3, 0, 59.3);
```

`student_t_lccdf(0 | 3, 0, 59.3)` is `log P(T > 0)` for a t centered at
0, which is `log(1/2)` for **every** df and every scale. Subtracting it
ADDS `log 2`: brms's statement is the **normalized half-t**, i.e. brms
carries the fold. frmtmb evaluates the **unfolded** student_t and adds
the `sd`-scale log-Jacobian. Both sides checked analytically against
the measured numbers:

| side | closed form | measured | diff |
| --- | --- | --- | --- |
| stan prior | `st(Ic) + st(sigma) - lccdf(0)` | -9.8792878013 | -2.7e-14 |
| frm prior | `st(Ic) + st(sigma) + log(sigma)` | -6.7119596444 | -2.3e-14 |
| `frm - stan` | `log(sigma) - log 2` | +3.16732816 | exact |

So the constant is `log 2` **per lower-bounded parameter that carries a
prior**, and it is a constant only because `lccdf(0)` for a
zero-centered symmetric density does not depend on the hyperparameters.
The claim is correct as stated, with one clarification the findings
leave implicit: it is one `log 2` per lower-bounded **priored**
parameter, not per lower-bounded parameter. Stan's `jac` runs over
every constrained parameter whether priored or not; the renormalizer
does not. The earlier review made the same distinction and it still
holds.

### The other directions

| direction | input | internal bound | fit |
| --- | --- | --- | --- |
| **ub, log link** | `ub = 0.12` on `class = "sigma"` | `log(0.12) = -2.1202635362` | sigma pins at **0.1200000000** (unbounded fit is 0.1354697363) |
| lb, log link | `lb = 0` | `-Inf` | no constraint |

So `internal_bound()` is correct in both directions and on a non-log
link. brms's `lb = 0` / `ub = 1` on a logit-linked `zi` or `hu`
degenerate to no constraint, which is what brms means by them.

### Two defects in `internal_bound()` (`R/priors.R:1674-1692`)

Both are reachable only from a `natural` (brms-routed) row, because the
frmtmb spelling short-circuits at `scale == "internal"`. Both are
one-liners.

**B1. A `ub` whose link image is `NaN` raises a bare R error instead of
the intended message.** `internal_bound(-1, <log link>, "ub")` gives
`missing value where TRUE/FALSE needed`. `log(-1)` is `NaN`, so
`b == Inf` is `NA`, so `identical(which, "ub") && b == Inf` is `NA`,
and `if (NA)` stops. The function has a written message for exactly
this case ("describes an empty box") and never reaches it. Fix: test
`is.nan(b)` in the `ub` branch as the `lb` branch already does.

**B2. An `lb` whose link image is `+Inf` is reported as a `ub`.**
`internal_bound(1, <logit link>, "lb")` gives
`ub = 1 is outside the support of the parameter this prior is about`.
The user wrote `lb = 1`. The `stop()` string hardcodes `"ub = "`.
Fix: interpolate `which`.

Neither is reachable from a brms default table (brms never writes
`ub = -1`, and its `zi`/`hu` rows carry `lb = 0, ub = 1`), so neither
blocks the merge; both are a hand-written `brms::prior(..., lb =, ub =)`
away, and B2 is a message naming the wrong argument, which this repo
otherwise polices.

## 4. D3 on other shapes. CONFIRMED on all four

Each shape checked twice: brms's placement read off its **generated
Stan code**, frmtmb's read off the **resolved entry** and the objective.

### (a) Distributional, `bf(y ~ x + z, sigma ~ x)`

brms generates two independent centerings:

```
vector[Kc] means_X;              vector[Kc_sigma] means_X_sigma;
real b_Intercept       = Intercept       - dot_product(means_X, b);
real b_sigma_Intercept = Intercept_sigma - dot_product(means_X_sigma, b_sigma);
```

frmtmb resolves two entries, each with its own offset:

| entry | offset over | weights | truth |
| --- | --- | --- | --- |
| `beta[1]` | `beta[2,3]` | `2.985418, -1.982923` | `mean(x), mean(z)` |
| `betad[1]` | `betad[2]` | `2.985418` | `mean(x)` |

One centering per sub-formula, exactly `means_X` and `means_X_sigma`.
This is the shape whose measured residual is **exactly 0** in the tier.

### (b) Smooth plus parametric, `ys ~ x + s(w)`

brms's standata: `K = 2`, **`Kc = 1`**, `Ks = 1`. So `means_X` has
length `Kc = 1`: the parametric column only. The smooth's unpenalized
`Xs` is a separate matrix outside `Xc` and outside `means_X`; the
generated code has no `means_Xs`.

frmtmb: `n_param_cols = 2`, `X` columns
`(Intercept) | x | s(w).fx1`, and `lp_center_offset()` returns
`idx = 2, w = 2.985418` only.

**Discriminating check.** `colMeans(Xs)` is 0 here, so a mean-based
exclusion and a structural one would look alike. I shifted the
`s(w).fx1` column to a mean of **+5** and re-called
`lp_center_offset()`: the result was **unchanged** (`idx = 2`,
`w = 2.985418`). The smooth column is excluded by `n_param_cols`, not
incidentally by having a zero mean. The claim is structural, as the
findings say.

### (c) REML

`y ~ x + z + (1|g)`, same prior table, `REML = TRUE` vs `FALSE`:

| | intercept | slope `x` | entries |
| --- | --- | --- | --- |
| `REML = TRUE` | 0.805754572 | 0.865834789 | `beta[1]` centered over `beta[2,3]`, `theta[1]/sd`, `betad[1]/sd` |
| `REML = FALSE` | 0.818129765 | 0.861637765 | identical structure |

The centering offset is present and identical under REML; only the
estimates move, as REML should. No interaction between D3 and REML.

### (d) A nonlinear parameter's intercept

brms's generated code for `bf(y ~ a*exp(-b*x), a + b ~ 1, nl = TRUE)`
declares `X_a` and `X_b` and contains **no `means_X`, no `Xc`, no

`class = "Intercept", nlpar = "a"` carry
`offset = NULL (not centered)`, which is `target_coefs()`'s
`!want_np` guard. Matches brms exactly.

### Note A: row 3 is a tighter correspondence than the lane claims

brms's two dpar spellings are **mutually exclusive by model shape**, and
frmtmb matches brms on both. Measured with `make_stancode`:

| model | `class = "sigma"` | `class = "Intercept", dpar = "sigma"` |
| --- | --- | --- |
| `y ~ x` (no sigma predictor) | `student_t_lpdf(sigma \| ...)` | **brms ERRORS**: "do not correspond to any model parameter: Intercept_sigma" |
| `bf(y ~ x, sigma ~ 1)` | **brms ERRORS**: "do not correspond to any model parameter: sigma" | `student_t_lpdf(Intercept_sigma \| ...)`, i.e. **log sigma** |

frmtmb routes `class = "sigma"` to the natural scale and keeps
`class = "Intercept", dpar = "sigma"` on the link scale. **That is
exactly brms's meaning for each spelling.** The lane's routing follows
brms in both directions, which is a stronger result than "same as
`means_X_sigma`" and deserves saying.

### Note B: row 7's divergence is real but much narrower than presented

The findings call this "the one to decide" and present two live

- there is **no brms script** whose prior is ambiguous after porting;
- the only way to meet the divergence is to write frmtmb's

**C1 (the important one). `coef =` on `class = "sd"` is silently

brms's own generated code, `y ~ x + (x|g)`:

```

     lprior += exponential_lpdf(sd_1[2] | 1);        # ONLY sd_1[2]
```

| row | resolved entries | penalized objective |
| --- | --- | --- |

## Recommendations

### On the STOP: keep it, and shrink its reach

The three options and what each costs, measured:

| option | cost |
| --- | --- |
| **stop** (this lane) | 6 of 20 common shapes error; the remedy is 1-2 named edit rounds |
| skip with a message naming the rows | the porting call fits, but silently fits a **different model** than the brms script, and the message is the only warning |
| skip silently | what main does today; the earlier review established this is a correctness bug |

**Keep the STOP.** The lane's own principle is right: a live row is a
density the user's model has and frmtmb's would not, so fitting anyway
produces a different model rather than no model. And frmtmb cannot tell
a default row from an edited one, which is precisely what D1
established about the `source` column, so "skip only brms's own
defaults" is not implementable.

Note the distinction that makes this consistent: the D1 bug was
dropping rows frmtmb **can** represent. Skipping rows it **cannot** is
a different act, and the lane already skips *flat* rows of unnameable
classes. The argument is only about *live* ones.

**But shrink the reach, which is cheaper than changing the policy.**
Three of the six stops are **distribution** refusals on parameters
frmtmb already has:

| shape | stops on | the parameter exists in frmtmb? |
| --- | --- | --- |
| negbinomial | `inv_gamma(0.4, 0.3)` on `shape` | **yes** |
| zero-inflated (all) | `beta(1, 1)` on `zi` | **yes** |
| hurdle (all) | `beta(1, 1)` on `hu` | **yes** |
| `s(x)` | class `sds` | no |
| `gp(x)` | class `lscale`, `sdgp` | no |
| `mo()` | class `simo` | no |

Adding `inv_gamma` and `beta` to `parse_prior_dist()` is one `switch`
arm, one AD-safe density and one sampler each, exactly the shape of
work this lane already did twice for `logistic` and `gamma`, and it
removes **three whole family groups** from the stop set without
weakening the principle at all, because those rows land on parameters
frmtmb holds. That is the highest-value follow-up in this area. The
remaining three are genuine representational gaps and STOP is right for
them.

**One ergonomics fix worth taking now:** collect refusals across all
rows and name them in ONE message. `y ~ gp(x)` currently costs two edit
rounds because the call stops at `lscale` and only reveals `sdgp` after
that row is blanked. One pass over the table before stopping makes
every refusal visible at once.

### On exposing `natural = TRUE` in `set_prior()`: yes, but low priority

The divergence it addresses is **narrower than the findings present**
(Note B: brms rejects each spelling on the model shape where frmtmb
would diverge, so no brms script is ambiguous). So the case is not
"close a divergence".

The real case is an asymmetry: `print.frmtmb_priorlist()` renders
`scale=natural`, `frm_sample()`'s own defaults use the flag, and
`resolve_priorlist()` reads it, so a user can **see** a placement they
have no way to **write** except by routing a `brmsprior` row through
the translator. Exposing it closes that, makes
`frmtmb.sample:::natural_dpar_prior()` redundant, is purely additive,
and the earlier review already built and tested the shape (its only
casualty was one assertion greping obsolete refusal text). Cost: one
argument, its documentation, one test, and the implementation note the
lane already honors (write the field only when TRUE, or
`test-sample-direct.R:220` fails).

Take option 2, after the higher-value items. Do **not** take option 3
(flipping the existing meaning): the review measured one hard failure
and a silent ddm sign flip, and Note B removes what little urgency
remained.
