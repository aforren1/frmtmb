Worktree `frmtmb-wt-ndaterm`, branch `wt-ndaterm`, uncommitted over
47cf659d. Lane library `wt-ndaterm-lib`, base `rellib-r9` (0.71.0).

## Verdict: MERGEABLE AFTER FIXES

The core change is right and well tested: `predict_simulate()`,
frmtmb.sample's `posterior_predict()` and `arma_cond_fill_dpars()` now
take every term from `aterms_for_newdata()`, and each new test fails on
r9 for the behavioral reason. The audit claim is not right, though. The
rowwise `mixture()` simulator hands every component the whole term
list, not the rows of that component. So `predict(newdata =)` on a
binomial mixture, which the lane now routes to that simulator, gives
counts above `trials()`. The same defect is in the grouped mixture and
the hmm simulators in sample. The new wiener refusal also fires on the
default `conditional_effects()` call of every numeric-`dec()` fit.

Scripts are `dev/ndaterm-rev-*.R` and `dev/ndaterm-rev-run.sh`. The logs
are in `dev/ndaterm-rev-out/` (gitignored). The scripts use seed 7
unless stated.

## Findings

### 1. HIGH: mixture and hmm simulators misalign per-row terms

`mixture_build()`'s `sim` (R/families.R about line 5900) draws each
component on its rows `idx` and calls `sk(dk, aterms, length(idx))`
with the full length-n `aterms`. A binomial component then reads
`trials[1:length(idx)]`, which are the trial counts of other rows. The
same pattern is in `mx[["comp_sim"]](dk, av, length(idx), k)` (the
grouped mixture, R/families.R about line 6905). It is also in
frmtmb.latent's `state_sim`, `comp$sim(dk, aterms, length(rows))`
(R/hmm.R line 546).

Evidence (`dev/ndaterm-rev-probe2.R`, `probe3.R`; logs
`probe2-<arm>.txt`, `probe3-<arm>.txt`). The data are
`mixture(binomial(), binomial())` with `N` in {2, 50}, n = 200.

| quantity | r9 | lane |
|---|---|---|
| `simulate()` in sample, share of draws > N | 0.25033 | 0.25033 |
| `simulate()` in sample, mean draw on N = 2 rows (`fitted()` 0.98305) | 11.767 | 11.767 |
| `predict(newdata, summary = FALSE)` means, N = 1000, 2 | 0.435, 0.420 | 432.03, 243.03 |
| same, max | 1, 1 | 777, 768 |
| `simulate(newdata)` means / max | 489.58, 240.73 / 760, 769 | same |
| `fitted(newdata)` | 483.92, 0.968 | same |
| grouped mixture `simulate()`, share > N | 0.21263 | 0.21263 |
| `hmm(K = 2, binomial())` `simulate()`, share > N | 0.25973 | 0.25973 |

`simulate()` has been wrong since before 0.71.0. The lane changes
`predict(newdata =)` from one wrong answer (0/1 draws) to another (243
where N = 2), and nothing is raised. The NEWS bullet says that
`predict()` "reads the terms as `simulate()` and `fitted()` read them".
For a mixture that is true, but `simulate()` is wrong.

Fix: subset the terms to the class rows in all three places.
`subset_obs(aterms, idx, n)` is the helper that core already has for
this:

- R/families.R, mixture `sim`:
  `out[idx] <- sk(dk, subset_obs(aterms, idx, n), length(idx))`
- R/families.R, grouped mixture:
  `mx[["comp_sim"]](dk, subset_obs(av, idx, n), length(idx), k)`
- frmtmb.latent R/hmm.R `state_sim`: the same subset, written as a
  local helper (`subset_obs` is not exported).

Add a test that a mixture of binomials with per-row trials gives no
draw above N in sample and on newdata, and gives column means within
k Monte Carlo SEs of `fitted()`. The test must fail on r9 (share 0.25).
Add the same test for the grouped mixture and for the hmm. Add a NEWS
bullet in core and in frmtmb.latent.

### 2. MEDIUM: default `conditional_effects()` on a numeric-`dec()` wiener fit now fails

`ddm_indicator_binary()` refuses the grid value, and the grid holds
`upper` at its mean. Both `conditional_effects(fw)` and
`conditional_effects(fw, "x")` fail on a correct model
(`probe2-mine.txt`): "wiener: the boundary indicator must be 0 (lower)
or 1 (upper) on every row, and 100 row(s) hold 0.5733." This happens
for the default `posterior_epred` method as well as for `predict`. It
was a silent wrong answer before, so a refusal is better than that. But
the most common call on the most common spelling of the model now
fails, which conflicts with the evidence standard: a refusal must not
fire on a correct model.

brms (2.23.0 `prepare_conditions()`, `get_int_vars()`) holds the
variables of `trials` (at 1), `thres` and `vint` at
`round(median())`. brms does not condition wiener on `dec`, so brms
holds `dec` at its mean and nothing breaks there. frmtmb conditions on
`dec`, so for frmtmb `dec` is an integer variable in brms's sense.

Fix: in the conditions code of R/conditional-effects.R (beside the
`subset()` holding, about line 1797), hold an unpinned variable that is
read only by `thres()`, `vint()` or a registered term at
`round(stats::median())`, with a message like the trials message. This
also closes the lane's own "not done" item: `vint()` held at its mean,
9.985, draws NA. Keep `ddm_indicator_binary()` for explicit newdata.
Change the first `expect_error()` of "a dec() value that is not a
boundary is refused" to expect a held value that is finite and equals
the CE at `conditions = data.frame(upper = 1)` (median of the test
data's `upper` is 1).

### 3. MEDIUM: `dec()` on newdata is still coded by newdata's own levels

`aterm_coerce()` is documented as "coded as the frame coded it". For a
factor, character or logical value on newdata, that is false.
`ddm_coerce_dec()` sees only the newdata vector. The lane notes this
as not fixed, but the NEWS and the roxygen say otherwise. Fit
`dec(side)` with levels `up, down`; then `fitted()` at x = 0 is 0.79946
for `down` and 0.55046 for `up` (`probe2-mine.txt`):

- `relevel(side, "down")` newdata: 0.55046, 0.79946 for down, up. The
  levels are swapped and nothing is raised.
- character `c("down", "up")`: swapped, silent.
- `factor(c("left", "right"))`, levels the fit never saw: accepted and
  silent.
- `factor("down")` after `droplevels()`, character `"down"` alone, a
  logical fit given `lg = TRUE` alone: refused, with the wrong reason.
  The message is "dec(side) could not be evaluated on newdata; supply
  the variable". The column is present. The coercion's own message
  (two levels needed) is replaced by the generic one in
  `aterms_for_newdata()`'s `tryCatch(error = function(e) NULL)`.
  A one-row newdata with a logical `dec()` can never be predicted.

The CE grid is right (it uses the training levels), so the lane's CE
fix holds.

Fix: at frame assembly, record the levels of a registered term whose
input is a factor, character or logical vector (an attribute on
`aterm_values`, or on `rspec$aterms`). In `aterm_coerce()`, apply
`factor(as.character(v), levels = <training levels>)` before the
registered coercion, and refuse a value outside those levels by name.
In `aterms_for_newdata()`, when every variable of the term is in
newdata, rethrow the evaluation error instead of the generic "could not
be evaluated". Add tests for relevel, character and single level. They
fail today, because the shares are swapped.

The r9 failures are behavioral: the `max(p[, 1]) > 2` failure, the mean
and sd ratios outside tolerance, the binomial-type refusals that do not
fire, and "invalid arguments" from `rbinom()`/`rnorm()` for vint and
vreal. These match the lane's counts.

Monte Carlo tolerances. Each check is a two-sided 6-SE bound. Under the
normal approximation the false-failure rate is 2e-9 per check. There
are about 24 checks (core 12, sample 6, eam 6), so the rate is about
5e-8 per run. Each block also sets a seed, so a run is deterministic on
one platform. The SEs are correct for what is compared:

- predict against simulate: independent draws. The Jensen gap of
  parameter uncertainty is about 0.04 on 576, against a 6-SE band of
  about 7.6.
- posterior_predict minus epred: the SD of the per-draw difference.
- sd ratio: 1/sqrt(2(n - 1)).
- median share: 0.25/n, for each of the two samples.

The r9 margins are wide. The narrowest is the sample `se()` check at
s = 0.05, where the observed ratio is 0.55 and the tolerance is 0.30.
