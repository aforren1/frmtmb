## 1. FALSIFIED: the structural guard is not total, and its count is wrong

`dev/argspell-findings.md` 8.1 prints, and `dev/argspell-report.R`
regenerates:

    METHODS STILL SWALLOWING THEIR DOTS: 0

and `tests/testthat/test-arg-refusal.R`'s last block asserts that no
registered S3 method has a `...` its body never touches. Both are
false, and by the same cause.

The detector, in the test and in the report script, is

    any(grepl("...", deparse(body(fn)), fixed = TRUE))

which asks whether the literal three characters appear ANYWHERE in the
deparsed body, INCLUDING inside a string literal.
`print.frmtmb_par_template()` prints a truncation line:

    cat("... ", length(v) - n, " more\n", sep = "")

so it is scored as a dots user while its body never mentions `...` as a
symbol. Construction, `dev/asrev-swallow.R`:

    class: frmtmb_par_template/list
    formals: x, n, ...
    SWALLOWED: print(pt, nosucharg = 1, re.form = NA) returned with no
    error; output identical to print(pt): TRUE

    lines of the body matching the literal three dots:
      cat("... ", length(v) - n, " more\n", sep = "")

    any `...` SYMBOL in the parse tree:  FALSE

A parse-tree detector settles it without ambiguity. In
`dev/asrev-static2.R` I ran both detectors over every registered method
of both packages:

    frmtmb: disagreements 1
      print.frmtmb_par_template (grep=FALSE parse=TRUE)
    frmtmb.sample: disagreements 0

So exactly one method is missed, and swapping the detector introduces
no false positive: the two methods whose only textual `...` looked
string-like to a crude regex (`[[.ranef_frmtmb`'s `unclass(x)[[i, ...]]`
and `update.frmtmb_fit`'s `match.call(expand.dots = FALSE)$...`) are
real dots users and the parse detector agrees.

**BLOCKER.** Fix, in `tests/testthat/test-arg-refusal.R` and in
`dev/argspell-report.R`:

    if (any(all.names(body(fn)) %in%
            c("...", "..1", "..2", "..3",
              "...length", "...names", "...elt"))) return(FALSE)

and add `frm_check_dots(...)` to `print.frmtmb_par_template()`. The
lane's own standing rule applies to the new detector: exercise it on
the absent case, i.e. assert that
`function(object, ...) { message("a ... b"); object }` IS reported as a
swallower. The existing synthetic cases in the block above do not cover
a string, which is why this survived.

The count "with `...` never read: 12" becomes 13, and "METHODS STILL
SWALLOWING THEIR DOTS: 0" stays 0 only after the method is guarded.

A factor of 9.8, no message. The findings' section 4 reasoning for

should say in the same breath that `predict()` still defaults to the

**Named fix** (one sentence), with the default itself left to the

## 9. Nit: `frm_check_dots()` and the calling frame

`dev/asrev-static.R` section B attacks the frame read. Results:

    B1 direct        m1() has no argument `bogus`. It takes: object
    B2 do.call(chr)  m1() has no argument `bogus`. It takes: object
    B3 do.call(fn)   this function has no argument `bogus`. It takes: object
    B4 UseMethod     gen.asrev() has no argument `bogus`. It takes: object
    B5 NextMethod    gen.asrev_base() has no argument `bogus`
    B6 nested helper helper() has no argument `bogus`. It takes:
    B7 anonymous     (function(object, ...) fcd(...))() has no argument ...

B1, B2, B4 and B5 are correct. B3 degrades to "this function", which is
acceptable. **B6 is wrong**: called from a helper the method delegates
to, it reports the HELPER's name and an EMPTY formal list, so the
message names a function the caller never typed and tells them it takes
nothing.

This is latent, not live. `dev/asrev-callsites.R` parses every R source
in core and `frmtmb.sample`: 103 `frm_check_dots` call sites, and
**0** that are not a top-level statement of a function that itself
takes `...`. So today every call site is correct. The hazard is that
the helper has no defence against being moved one frame down, and the
failure is a bad message rather than a bad answer.

**Nit.** Either add an explicit `.what`/`.formals` override for a
future forwarding site, or assert the invariant: a test that parses the
sources and fails if `frm_check_dots(...)` ever appears anywhere but as
a statement of a dots-taking function. The second is four lines and
turns a silent degradation into a failing test.

## 10. Nit: the shape exemption smuggled the name list back in

`ar_refuses_always()` recognises a shape, but the shape is "the body is
a single call whose head is one of `ar_refusers`", and

    ar_refusers <- c("stop", "fit_no_draws", "multiple_no_draws")

is a name list of HELPERS. I confirmed both helpers are unconditional
(`dev/asrev-static.R` section E prints each body: a single `stop()`
with `call. = FALSE`), so the exemption is sound TODAY. But nothing
asserts it. If either helper ever grows a branch, thirty-eight methods
become exempt swallowers with no test failing.

The count is right: `dev/asrev-static2.R` finds exactly **20** in
frmtmb and **18** in frmtmb.sample exempted by shape, which is the 38
`dev/argspell-unstop.R` reports removing. I could not find a NEEDED
guard among them: the removal predicate requires the body to be exactly
`{ frm_check_dots(...); <refuser>(...) }` with length 3, so after
removal the body is a single unconditional refusal and every call to it
errors before any argument could be swallowed. The near-miss assertion
in the test (a refusal on a BRANCH is still a swallower) is present and
passes.

On the brief's question of whether the shape test can be fooled by a
method that refuses unconditionally for an unrelated reason: yes, in
the sense that ANY single-statement `stop()` body is exempt
(`dev/asrev-static.R` D3 confirms), but that is sound, because such a
method cannot reach the swallow. The exposure is the helper list, not
the shape.

**Nit.** Add two expectations:
`expect_true(ar_refuses_always(frmtmb:::fit_no_draws))` will not do it;
what is needed is that the HELPER is unconditional, e.g. that
`body(fit_no_draws)` is a `{` of length 2 whose one statement is a
`stop()`.

Also verified: `conditional_effects()` on a `frm_multiple()` result now
gives the right message, both positionally and by name
(`dev/asrev-static2.R`):

    conditional_effects(fm, "x"): conditional_effects() has no pooled
    version for a frm_multiple() result ...

### What to do about it, and why another `.allow` is the wrong fix

Three rounds of this have each uncovered the next, and the scan says
more names of the same kind remain. The collision is structural: the
project's rule is "refuse what the method does not have", and R's S3
contract is "a method must tolerate the arguments its GENERIC
documents", which is why every `stats` default method carries
`use.fallback`, `env`, `data`, `na.rm` or `trace` and ignores them.

The fix that converges is one place, not eight: a single table from
generic to the argument names base R itself passes, consulted by
`frm_check_dots()` or spliced into each `.allow`, plus a TEST that
walks the base packages for the pattern instead of waiting for the next
report. `dev/asrev-hopscan.R` is a working first draft of that test.
Today's table would be at least:

    nobs         use.fallback
    drop1, add1  scale, trace, k
    formula      env
    terms        data
    model.frame  data, subset, na.action, xlev, drop.unused.levels
    confint      trace
    residuals    na.rm
    weights      type
    coef         complete

Everything not in the table stays refused, so the guard keeps its
value: `drop1(fit, re.form = NA)` and `nobs(fit, nosucharg = 1)` still
error, as the run above shows.
