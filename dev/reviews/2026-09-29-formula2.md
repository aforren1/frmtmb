## Blockers

### B1. `update(fit, newdata = )` on a `y ~ .` fit expands the dot again

Construction: `dev/formula2-rev-dot.R` (data seed 6) and its log.
`fit <- frm(y ~ ., data = d)` stores `y ~ x1 + x2 + g`.
`update(fit, newdata = d2)` then fits
`Intercept x1 x2 g2 ... g6 extra`, where `d2` is `d` plus a column
`extra`. `update()` evaluates the stored call again, so `.` expands
against the new data. brms keeps the expanded formula.
`brm(y ~ ., d, empty = TRUE)$formula` is `y ~ x1 + x2`
(`dev/formula2-rev-brms-dotupdate.log`), and `update.brmsfit()` sets
`dots$formula <- object$formula` when no formula is given
(`dev/formula2-brms-src/update.brmsfit.R`). frmtmb silently changes the
model, and a `newdata` with a missing column silently drops a
predictor. Fix: when the stored formula has a `.`, give `update()` the
stored `object$bform` instead of the call's formula.

### B2. `cmc = FALSE` is silently ignored on a multi-membership term

Construction: `dev/formula2-rev-cmc.R` (seed 21) and its log.
`bf(y ~ x + (0 + f | mm(h, h2)), cmc = FALSE)` gives the component
columns `fa fb fc`, which is cell-mean coding. brms's `standata()` has
two coefficients per member (`Z_1_1_1 Z_1_1_2 Z_1_2_1 Z_1_2_2`), which
are the treatment contrasts. In `assemble_frame()`, the cmc rewrite
covers only `plain_k`, and the code excludes `mm()` bars from
`plain_k`. Fix: apply the rewrite to the mm design too, or refuse
`cmc = FALSE` on an `mm()` term.

### B3 (new). The cmc = FALSE refusal also refuses correct models

The guard fires when a bar of `ar1`, `hetar1`, `cs`, `homcs`, `toep`,
`homtoep`, `ou`, `exp`, `gau` or `mat` has no intercept. It does not
check whether `cmc = FALSE` removes a column. A structure over numeric
slopes has the same columns under both settings, and the guard refuses
it all the same (`dev/formula2-rev-p1-cov.R`, seed 41):
`cs(0 + x1 + x2 | g)` has cnms `x1,x2` with cmc = TRUE, and with
cmc = FALSE it is "REFUSED: cmc = FALSE does not apply to cs(...)".
The same happens for `ar1`, `hetar1`, `homcs`, `toep` and `homtoep`
over `0 + x1 + x2`. An interaction without a main effect also keeps
every level, and the guard refuses it too: `cs(0 + f:x1 | g)`
(`dev/formula2-rev-p1-m12.R`). The message says that cmc = FALSE
"would leave one level out", which is false for these models. The
lane's rules say a refusal that fires on a correct model is worse than
none. brms cannot parse any of these structures (`standata()` stops at
the parser), so brms offers no reading to follow. Fix: refuse only
when the columns built with cmc = FALSE differ from the columns built
with cmc = TRUE, for example when `bar_with_intercept()` and the
intercept drop change `cnms`. Then add the absent-condition case to
`test-formula-cmc.R`.

Where the guard is correct: every one of the ten structures over a
factor (`0 + t`, `0 + tim`, `0 + pos`) is accepted with cmc
left at its default and with cmc = TRUE, and is refused with cmc =
FALSE. The `ar1` fit with the default has the same `logLik()` as the
fit with cmc = TRUE (-186.0736). The guard does not fire when cmc =
FALSE is on another formula than the structure's: `lf(sigma ~ 0 + f,
cmc = FALSE)` beside `ar1()` in mu is accepted, and so is mu with
cmc = FALSE beside sigma's `ar1()`. With cmc = FALSE, a term with an
intercept (`cs(1 + x1 | g)`), `us(0 + f | g)`, `diag(0 + f | g)` and
`(0 + f | g)` are accepted, and each has cnms `fb,fc`. The
autocorrelation term `ar(t, g)` beside `0 + f` with cmc = FALSE fits,
and brms's `standata()` for it has `X` = `fb,fc`.
