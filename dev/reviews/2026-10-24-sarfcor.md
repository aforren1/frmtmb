## Findings

### 1. major: the seam passes `sigma` per row when `sigma_varies = FALSE`, against its own documentation; the help page's example fails

`?frmtmb_register_autocor` says `sigma` "has one value, or one per row
when the term takes a predicted sigma (`sigma_varies = TRUE`)". Core
passes one per row in both cases:

    $ Rscript dev/review-sarfcor-sigprobe.R   (sigma_varies = FALSE)
          2 whiten: length(sigma) = 20 length(mu) = 20
          9 unwhiten: length(sigma) = 20

The help example writes `logjac = -aux$logdet - length(y) * log(sigma)`,
which is then a vector of length n. Run verbatim
(`dev/review-sarfcor-helpex.R`, `helpex.txt`):

    help-page example, sigma_varies = FALSE: ERROR: 'func' must return a *scalar* (forgot to sum?)

It sits in `\dontrun{}`, so R CMD check never runs it.
`test-autocor-seam.R` says its toy "is ?frmtmb_register_autocor's
example", but its `whiten` has an extra
`if (length(sigma) == 1L) ... else sum(log(sigma))` branch, and
frmtmb.spatial's `sar_whiten()` carries the same branch with the comment
"sigma is constant here (sigma_varies = FALSE), but it may come as one
value per row". The lane knew the contract was not what the page says.
My AR(1) term written from the page alone failed the same way
(`toyar1.txt`, first run) until I added the branch.

The seam also checks nothing that `whiten` returns (`toyar1.txt`):

    whiten with u one short:     FIT logLik -95.671961     (correct -96.466747)
    unwhiten not the inverse:    FIT, autocor_matrix[1,2] 0.0000 (true 0.8712)
    whiten with a per-row logjac: ERROR: 'func' must return a *scalar* (forgot to sum?)

Required fix: pass `sigma[1]` (a scalar) to `whiten` and `unwhiten`
when `sigma_varies = FALSE`, as the page says, or change the page to
"always one per row". Make the example run (drop `\dontrun`, or make
a test run the page's code verbatim). At frame time, check on numbers
that `whiten()` at the start returns `length(u) == n` and
`length(logjac) == 1` and that `whiten(unwhiten(u))` returns `u` to a
relative tolerance, and refuse with the term's name. That is the
`cs_check_entry()` analogue the seam lacks.

### 2. major: frmtmb.sample samples rho flat on the logit, announces "brms 2.23 defaults", and refuses brms's class

`dev/review-sarfcor-sample.R` (`sample.txt`), a sar fit:

    frm_sample(): default priors (brms 2.23 defaults; prior = "flat" opts out)
      Intercept          student_t(3, 1.9, 2.5)
      sigma              student_t(3, 0, 2.5)  [natural scale]
      b                  (flat), as brms leaves slopes
    mentions lagsar/rho/thetaac in messages: FALSE
    prior class lagsar: REFUSED: class = "lagsar" names no distributional parameter of this model. ...

brms's `default_prior()` gives `(flat)` on `lagsar` / `errorsar`
bounded by `min_eigenMsar`, `max_eigenMsar` (`brms-nocompile.txt`).
frmtmb.sample's density on rho is `1 / ((rho - lo)(hi - rho))`, on a
wider interval. The posterior differs from brms's, and the
announcement says it does not. The refusal names no route
(`class = "theta", coef = "thetaac_1"` is in the record, not in the
message). NEWS of frmtmb.spatial and frmtmb.sample say nothing of it.

The cost is small. Core already carries a logistic map with its log
Jacobian for `cosy` (`ac_trans_value()`, `ac_trans_logjac()` in
R/priors.R); sar's map `lo + (hi - lo) plogis(theta)` is the same form
with `lo`, `hi` from `aux`.

Required before release: the default for a sar block is flat on rho,
the log Jacobian `log(hi - lo) + log(p) + log(1 - p)` with
`p = plogis(theta)` added on the tape, and `class = "lagsar"` /
`"errorsar"` accepted. If that does not fit the round, the minimum is
a line in the default-prior announcement that names lagsar and its
logit-flat prior, the refusal naming the `theta` route, and a NEWS
bullet. Note: the same flat-on-internal default holds for `ar` and
`cosy` at 0.74.0 (no Jacobian in `default_priors_for()`), so this is
not new in kind, but sar is new and its departure is undisclosed.

### 3. major: brms accepts `newdata` of the same rows; frmtmb refuses and says brms does not

`brms-fit2.txt` and `brms-nocompile.txt`:

    sar newdata of the same 16 rows, no newdata2 : 16 x 16
    fcor newdata of the same 16 rows, no newdata2 : 16 x 16
    brms posterior_epred(newdata = same 64 rows, x + 1): works, draw 17 vs A^-1 mu_new 4.44e-16
    frmtmb fitted(newdata = same rows): A prediction cannot use newdata with sar(W): ... brms refuses
      the same call unless a matrix over the new rows is given in newdata2, which frmtmb does not take.

brms checks only that `M` matches the row count of `newdata`. A
counterfactual on the fitted locations (`x + 1` everywhere, the spatial
spillover of a lag model) is the main post-fit use of a lag SAR, and
brms gives it. frmtmb's message, core NEWS ("brms refuses it too
unless `newdata2` holds a matrix over the new rows"), `?sar` and
`?frmtmb_register_autocor` all state the false version. My toy term's
message also says "the term's matrix", which a generic term need not
have.

Required fix: accept `newdata` whose row count equals the fitted
data's `n_all` (no NA drop on newdata, or the same `rows`), reusing
`aux`, in `fitted()`, `predict()` and `simulate()`; refuse other row
counts as now. If not built, correct the message, NEWS and both help
pages to say what brms does.

### 7. minor: two of the four brms defects are overstated

- Defect 1 (fcor indefinite `M`). brms's R-side check is wrong, but
  its Stan program computes `cholesky_decompose(Mfcor)` in transformed
  data, and the fit fails there (`fcorindef.txt`:
  "cholesky_decompose: Matrix m is not positive definite ...
  failed to create the sampler"). brms never fits an indefinite `M`;
  it fails late. frmtmb's refusal is right and matches brms's outcome.
  NEWS says brms's check "passes a matrix with a negative eigenvalue";
  add that brms's fit then fails.
- Defect 3 (unstandardized W). Confirmed (0/1 4 x 4 lattice: brms
  interval (-3.236, 3.236), valid (-0.309, 0.309)). But outside the
  valid interval brms's `log1m()` is NaN and Stan rejects, so brms's
  effective support for a W with `lambda_min <= -1 <= 1 <= lambda_max`
  (every 0/1 adjacency) is frmtmb's interval: the cost is rejected
  proposals and initial values, not a different model. Say so.
- Defect 2 confirmed (rook 8 x 8: max |Im| 7.97e-17, `standata`
  `eigenMsar` class complex, Stan "variable does not exist ...
  eigenMsar"). Defect 4 confirmed: `rstan::stanc()` rejects brms's
  code for `weights`, `se`, `cens` and `trunc`, and accepts the plain
  model.

### 8. minor: the rho interval changes the model for a correct row-standardized W; justified, but say what it does

On a correct W (row-standardized 8 x 8 queen lattice, real
eigenvalues, range -0.5006 to 1), data drawn at rho = -0.8
(`brms-fit2.txt`, seed 7, brms seed 71):

    frmtmb ML lagsar -1.1034 (delta CI -1.4918, -0.7149); logLik -63.9885
    best inside brms's (-0.5006, 1): rho -0.5006, -67.7297; LR = 7.483
    brms lagsar median -0.4432 (2.5% -0.4983, 97.5% -0.2141); share of draws within 0.02 of the bound 0.203
    brms b_x median 0.3967; frmtmb b_x 0.3478 (SE 0.0808)

So frmtmb and brms fit different models there. I judge the departure
justified under "brms is clearly wrong": brms's bounds are the
eigenvalues where the nonsingular interval is their reciprocals, the
same code gives an invalid interval for an unstandardized W, and
(1 / lambda_min, 1 / lambda_max) is spatialreg's default. Keep it.
Required: the spatial NEWS bullet and `?sar` say the consequence in
one sentence (a different estimate from brms when the data favor rho
below the smallest eigenvalue; brms's posterior piles at its bound).

Side effect, nit: the wider interval reaches the singular end
`1 / lambda_min`. A complete-graph W (`lambda_min = -1/8`, multiplicity
8, n = 9; `g1.txt`) ran to rho = -8 with "false convergence" and a
gradient of 4.6e5: the lag likelihood is unbounded there when the
design spans the range of `A`. brms's narrower interval hides it. The
warnings fire, so it is not silent; a targeted message would help.

### 9. minor: pearson residuals and `autocor_matrix()` refactor the sparse system n times

`dev/review-sarfcor-scale.R` (`scale.txt`), 50 x 50 rook lattice,
n = 2500:

    frm() lag, n = 2500      2.80 s
    fitted()                 0.19 s
    residuals(pearson)      20.81 s
    autocor_matrix()        22.53 s

`autocor_seam_B()` calls `unwhiten()` once per column, and
`sar_unwhiten()` does a sparse LU each call. Fix: let `unwhiten` take
a matrix of innovations (one factorization for all columns), or an
optional slot that returns `B` or the covariance directly.

### 10. major: `full_rank = FALSE` for `us_t` and `diag_t` contradicts the property's definition, and the check fails open on a model with no maximum

The new property is "positive definite at some parameter value, so an
effect a row owns can reach any value with a finite density". A
Student-t latent satisfies it. The lane set FALSE "because no fit
measured them". Measured (`dev/review-sarfcor-b2.R`, `b2.txt`, the
lane's wu_data() design, seed 20261020, Gamma(log), 72 rows):

    weights 1.5, (1 | obs)                          -> REFUSED: The weighted likelihood of this model has no maximum. ...
    weights 1.5, (1 | gr(obs, dist = 'student'))    -> FIT logLik 47184158.72 shape 8.401e+19 warnings: 2
       first warning: Optimizer did not report convergence: false convergence (8). ...
    weights 1.0, (1 | gr(obs, dist = 'student'))    -> FIT logLik -139.3659383 shape 6.1 warnings: 0

The same runaway on rellib-r12 (`b2base.txt`: logLik 47184158.72,
shape 8.401e+19), so it is not a regression, but the lane now states
the property, and the stated value is false. Fix: `full_rank = TRUE`
for `us_t` and `diag_t`, with this case in test-weights-unbounded.R
(and its `weights 1.0` absent case).

### 11. minor: the inferred `full_rank` refuses a correct model

`full_rank = NULL` reads TRUE off a positive definite `vcov` at the
start. That assumes the latent's support is all of R^d. A registered
structure with a bounded latent (scaled beta(2, 2) on (-0.3, 0.3),
`b2.txt`):

    boxre info full_rank: NA
    weights 1.5, boxre(1 | obs) [bounded latent]                      -> REFUSED: The weighted likelihood of this model has no maximum. ...
    weights 1.5, boxre2(1 | obs) [bounded latent, full_rank = FALSE] -> FIT logLik -190.4849794 shape 2.066 warnings: 0

The model has a maximum and is refused. The lane-env rule is that a
refusal that fires on a correct model is worse than none. The case is
exotic and the registrant can state `full_rank = FALSE`, so minor.
Fix: document the assumption in `?frmtmb_register_covstruct`
(`full_rank`), or default NULL to FALSE (the check open, as for every
registered structure through 0.74.0) and let registrants opt in.

### 12. minor: `log_lik()` refusal (cost of building it)

brms gives the leave-one-out conditional density per row for sar,
fcor and ar(cov = TRUE) (`log_lik_gaussian_lagsar()` and
`log_lik_gaussian_time()` in brms's log_lik.R, citing the loo
vignette on non-factorized models); `brms-fit2.txt`: `brms log_lik dim:
4000 64`. frmtmb refuses it for all residual covariance terms, so
this is the existing policy, not new. Acceptable for this release.
Cost of building it once for every seam term and the ar family: per
draw, `Q = K'K / sigma^2` with `K` the Jacobian of `whiten` (affine,
so `n` evaluations or one solve with `B`), `g = Q e`,
`yloo = y - g / diag(Q)`, `sdloo = 1 / sqrt(diag(Q))`, and brms's
`student_t_cov_factor()` for student; about 80 to 120 lines in core
plus the frmtmb.sample plumbing and tests against brms's function
through the same draws. One lane. Seven bin-2 brms rows read it.

## Merge with smallfix (`R/extension-home.R`)

sarfcor appends a loop over seam blocks (`ac_block_entry()`) at the end
of the old `require_structure_packages()` body. smallfix replaces that
function with a collector: `structure_missing_parts()` returns
`list(kind, pkg, what)` parts, `require_structure_packages()` and
`require_model_packages()` each stop through `stop_extension_parts()`
with family parts plus structure parts, and `require_extension()`
delegates to the same function. A per-file merge conflicts in that
hunk. Resolution:

1. Add `autocor_missing_parts(x)` beside `structure_missing_parts()`:
   for each seam block (`autocor_is_seam(ac)`) whose term is not in the
   registry, a part with `what = "The <name>() term of this model"`
   and kind "session" (no package), "missing" (`!extension_usable()`)
   or "stale" (package loads but does not register it).
2. Include it in both combinations, so a fit with a family from one
   absent extension and `sar()` names both packages in one refusal,
   which is smallfix's goal.
3. `ac_block_entry()` keeps its `require_extension()` call (it now
   delegates to `stop_extension_parts()`), and its own trailing
   "is not registered in this session" refusal becomes
   `stop_extension_parts(autocor_missing_parts(...))`, so the
   session/stale wording is one template (test-message-uniqueness.R
   will otherwise see two).
4. smallfix's "session" sentence says "Register it again with
   frmtmb_register_covstruct()"; for a seam term it must say
   `frmtmb_register_autocor()`.
