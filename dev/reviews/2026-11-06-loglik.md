### MAJOR

**M1. `logLik_penalized` is missing from the pkgdown reference index, so
the pkgdown job fails.** `dev/review-loglik-pkgdown.R`,
`dev/review-loglik-out/pkgdown.log`, pkgdown 2.2.1:

`_pkgdown.yml` lists every topic by name; `.github/workflows/pkgdown.yaml`
builds the site and deploys Pages, and pkgdown aborts on a missing topic
on CI. Neither R CMD check nor the suites see it. Fix: add
`logLik_penalized` under "Inference and diagnostics" next to
`anova.frmtmb_fit`, and run `check_pkgdown()` once.

**M2. The AIC/BIC refusal is bypassed by every call that does not dispatch
on an `frm()` fit, and NEWS says otherwise.** `refusals.log`, seed 201,
`fp` with `normal(0, 0.1)` on `b`:

    AIC(fp)                            ERROR <frmtmb_prior_ic> ...
    AIC(f0, fp)                        ERROR <frmtmb_prior_ic> ... model 2 has a prior ...
    AIC(lm, fp) (stats default first)  300.4906272 301.5597279
    BIC(lm, fp)                        308.3061378 311.9804087
    AIC(logLik(fp))                    301.5597279
    -2 logLik(fp) + 2 df               301.5597279

`AIC(lm_fit, map_fit)` returns a table that compares an ML fit with a MAP
fit on the data likelihood at the MAP and full degrees of freedom, which is
the comparison the lane refuses for `AIC(f0, fp)`. Every package that
builds a criterion from `logLik()` (performance, MuMIn, bbmle) gets the
same number. The lane lists this under "Not done", but NEWS states "`AIC(m0,
m1)` stops when any of the fits has such a prior", which is false when `m0`
is not an `frm()` fit. It is not a regression (0.79.1 returned the
penalized AIC here), but the claim is new.

Recommendation: under a prior with a density, `logLik()` returns
`df = NA` with `df_why` saying why ("a parameter that the prior shrinks is
not a full degree of freedom"). `df_why` already exists for this purpose
and `anova.frmtmb_fit()` already reads it (`R/confint.R:2108`). Then
`AIC.default`, `AIC.logLik` and every third-party reader return `NA`, never
a number; the value of `logLik()` stays the data log-likelihood.
`pooled_order()` (`R/multiple.R:391`) must then read `loglik_df()`
directly, as the Wald rule D1 still runs under a prior and compares the
two dfs. A `logLik` subclass with its own `AIC` method would catch
`AIC(logLik(fp))` but not `AIC(lm, fp)`, which dispatches on `lm`. At the
least, reword the NEWS bullet and the Rd to "when the first fit is an
`frm()` fit".

`refusals.log`: `uniform(-5, 5)` on `x` gives `b_x` 0.38708779 and logLik

`set_prior("", lb = -5, ub = 5)` answers 297.7524169. Inside its support a
uniform density is a bound, and the estimates do maximize the likelihood

**m4. `log_prior` is not "the log density of the prior", and the Rd names
only the simplex chart.** `discrete-after.log`, seed 304, `normal(0, 1)` on

frmtmb omits brms's `- normal_lccdf(0 | 0, 1)` (log 2). So `log_prior` is
the log prior on the optimizer's unconstrained scale, with every

no truncation normalizer. `logLik()` is unaffected (the same closure is
subtracted), but the Rd and NEWS read as if it were brms's `lprior`. Say
both facts in `?logLik_penalized`.

## Answers to the brief's questions

- AIC under a prior only on variance components: keep the refusal. A prior
  on `sd` shrinks a parameter as a prior on `b` does, the remedy (refit
  without it) is cheap, and an exception would make `AIC()` and `anova()`
  disagree. The `@param prior` text calls stabilizing singular variance
  components the main use of `prior =`, so the refusal message for an
  sd-only prior could say that the model without the prior may be
  singular, and that `loo()` on a sampled fit is the comparison under the
  prior. Exempt uniform densities (m3).
- `AIC(fit1, fit2)` with one prior fit and one plain fit: refused when the
  first is an `frm()` fit, in either position (`model 2 has a prior`);
  answered when the first is not (M2).
- `anova()` between prior fits: refused before any log-likelihood is read,
  with `prior_lrt_refusal()`'s message.
- `frm_allfit()` refits through `fit_assembled(prior = fit$prior)`, the
  nonlinear restarts through the same `run()` closure, and `hmm_starts()`
  through refits that carry the prior (I read the first two; the lane's
  latent test checks the third); each compares maximized objectives.
  nlstart's probe does not (M3).
- Name: `logLik_penalized()` is defensible. brms's `log_posterior()` is
  taken (frmtmb.sample exports it with brms's meaning), glmmTMB has no
  accessor, lme4's nearest is `REMLcrit()`. It sits next to `logLik()` in
  the index, which M1 must add. The Rd follows ASD-STE100 in the main:
  short declarative sentences, one idea each; fix the content (m4) and the
  REML sentence, which names class `b` and `Intercept` but not `nlpar`.
- NEWS: both behavior changes are marked BREAKING; no lane names, no
  `dev/` paths, no version numbers; only the new top section is touched.
  The `AIC(m0, m1)` sentence is wrong (M2). The last bullet describes no
  change in what `frm_allfit()` and the restarts compare (they read the
  penalized value on 0.79.1 too); only the header line of
  `print.frmtmb_allfit()` is new.

### Remaining

- **MINOR, NEWS overclaims for insight.** NEWS says "other packages that
  compute a criterion from `logLik()` get `NA`". `insight`
  fills the NA with its own count:
  `insight::get_loglikelihood(fp)` is `'log Lik.' -177.53 (df=2)`, while
  `f0` keeps df 4 (`short2.log`). So `performance::performance_aic()`
  would return a number with the wrong df (performance is not installed
  here). Reword to "`AIC.default()`, `AIC.logLik()` and readers that use
  the `df` attribute get `NA`; packages that count parameters themselves,
  as insight does, do not".
- **Question, pooled D1 under a prior.** It runs (`statistic 1.125`
  against `2.084` without the prior, seed 702) and is consistent with
  the Wald intervals `summary()` prints under a prior. It is a Wald test
  at the MAP with the penalized curvature, though, not a test with its
  nominal size: it is conservative when the prior shrinks toward the
  null and can be anti-conservative when the prior shrinks away from it.
  `anova()` of two single fits refuses outright. Keep D1 and say this in
  `?anova.frmtmb_multiple`, or refuse it for consistency: the user should
  decide.
