# The 0.67.0 round, 2026-09-30

Three lanes of brms parity, then their consolidation into frmtmb 0.67.0.
This is the record of what was done, how it was verified and what is
left. Each lane's `dev/<lane>-findings.md` has its validation, numbers
and scripts, and `dev/reviews/2026-09-30-<lane>.md` has its adversarial
review.

## Lanes

Every lane worked in a git worktree off `57c25589` (frmtmb 0.66.0).

| lane | what | review, punch rounds, final state |

## How the release tree was built

The three lanes were combined in `../frmtmb-wt-release` (branch
`wt-release` at `57c25589`), in the order ordinal, ceplot, formrobust.
Nothing was committed there.

- Each lane was merged file by file with `git merge-file` against the
  lane's base blob, which touches no index (`dev/rel067-merge-lane.sh`,
  the 0.66.0 round's `r066-merge-lane.sh` with the three inputs of
  each conflicted file kept). `man/*.Rd`, `NAMESPACE`
  and frmtmb.sample's generated `helper-brms-suite.R` were left out.
- The permission check refused this session's run of the script for
  formrobust. The user ran the same script, and it merged with 4
  conflicts, below.
- Untracked lane evidence was copied without overwriting: 1364 files
  from ordinal, 2246 from ceplot and 3028 from formrobust, 0 clashes.
  The 5 skipped files are the lanes' new generated Rd files, which
  roxygen writes. R CMD check trees, tarballs and Stan caches are
  gitignored and were not copied.
- `dev/stan-cache` was seeded from main, the three lane caches and the
  three reviewers' caches (content-addressed, so a union is safe): 193
  programs.
- `dev/brms-suite/` (gitignored) was missing from main's checkout. It
  was restored from `brms_2.23.0.tar.gz`, whose sha256 matches the one
  `dev/brmsport-blocks.R` asserts, and extracted again.
- `roxygen2::roxygenise()` on core, install into
  `C:/Users/adf44/source/r/rellib-r5` (new; `rellib-r4` keeps the
  0.66.0 reference build), with drmTMB 0.7.0 from CRAN, then each
  extension roxygenised against it and installed in dependency order
  (`dev/rel067-install.sh`, log `dev/release/install-r5.log`).
  `?bf` needed a second roxygen pass, since its link to formrobust's new
  `autocor-terms` page resolves only once that page exists. A third
  pass of all eight packages changed none of the 209 generated files.
- The release harness reads `rellib-r5`: `dev/release/run-tests.R`,
  `run-check.ps1`, `run-docs.ps1`, `dev/warnleak-scan.R`, and the
  defaults of `dev/brmsport-run.R` and `dev/brmsport-guards.R`.
- `pkgdown::check_pkgdown()` passes for all eight packages.

### Conflicts, and how each was resolved

1. `NEWS.md`, at ceplot and again at formrobust: both sides kept, then
   regrouped by section under one `# frmtmb 0.67.0` heading
   (`dev/rel067-news-merge.R`): breaking changes first, then new
   features, formula grammar, new arguments and answers, bug fixes and
   the extension API. Every lane's bullets are there once. One
   breaking bullet was added, so that formrobust's addition-term change
   (a bare name outside the data is now refused) stands with the other
   breaking items; the full text stays under Formula grammar.
2. frmtmb.sample's `NEWS.md`, at ceplot and formrobust: regrouped the
   same way under `# frmtmb.sample 0.15.0`; the three lanes' "needs the
   development version" lines are one "Needs frmtmb 0.67.0" paragraph.
3. `R/sampling-api.R` (formrobust against ordinal), the `@aliases` of
   `?frmtmb-sampling-api`: one list with ordinal's `ord_delta_info` and
   formrobust's `arma_cond_fill_dpars`, `arma_cond_fill_epred` and
   `response_codes_newdata`.
4. `tests/testthat/test-generic-collision.R` (formrobust against
   ceplot), the list of generics shared with brms: both `autocor` and
   `parnames`.

Every other file merged clean, the expected hotspots included:
`R/conditional-effects.R`, `R/predict.R`, `R/confint.R`, `R/frame.R`,
`R/families.R`, `R/interop.R`, `R/generic-owners.R`, frmtmb.sample's

Core's `tests/testthat/helper-brms-suite.R` is lane ordinal's copy: no
other lane changed it. frmtmb.sample's copy was never merged:
`dev/brmsport-gen.R` regenerated it, and `test-brms-suite-helper-copy.R`

**Removed and renamed functions.** After each lane, the function
definitions the lane removed or re-signed were listed from its diff and
every call site was read. Lane ordinal removed `hurdle_cum_fit_check()`,
which nothing calls. Lanes ceplot and formrobust removed none. The
functions whose formals changed (`ord_sim()`, `ord_cat_probs()`,

extensions and the tests, or through a default.

### A defect the merge created, found and fixed

**`conditional_effects(effects = )` accepted a variable that only an
`offset()` reads.** Lane formrobust puts an offset's variables in the
model frame, so the grids can hold them at their means. Lane ceplot's
effect check (`ce_model_vars()`, brms's `get_all_effects()` set) read
every variable of the terms object, offsets included. On the merged
tree `conditional_effects(fit, "time")` on `yc ~ x + f +
offset(log(time))` drew a curve, where brms's set is `x` and `f` and
brms refuses. On either lane build alone the call stopped or answered
for a different reason (`dev/rel067-effoffset.R`,
`dev/rel067-log/effoffset.txt`, four libraries). `ce_model_vars()` now
reads `ce_lp_vars(lp, rsv = FALSE)` and keeps brms's reserved
`intercept`, which `get_all_effects()` keeps. The new block of
`test-offset-grid.R` failed 3 assertions on the merged tree before the
fix (`dev/rel067-log/effoffset-test-before.txt`) and passes after, with
its guard-absent case: a variable that the offset and a term both read
stays valid.

The rest of the ceplot and formrobust interplay was checked by
construction (`dev/rel067-ceoffset.R`, `dev/rel067-log/ceoffset.txt`):
a `poly()` variable beside an offset, `plot(plot = FALSE)` objects, a
crossed unseen `g:h` on an offset model under the Wald band and the
bootstrap, and `fitted(sample_new_levels = "old_levels")` there.

### Found at consolidation and not fixed

- **`emmeans()` on a fit with a transformed predictor** (`poly(z, 2)`,
  `log(abs(z) + 1)`, `scale(z)`) stops with "undefined columns
  selected", with or without an offset. Pre-existing: 0.66.0 and both
  lane builds do the same (`dev/rel067-emmoffset.R`,
  `dev/rel067-log/emmoffset.txt`). Filed in `dev/test-backlog.md`.
- **Ledger row `brmsfit-methods:955`.** Lane formrobust recorded it as
  a class-name divergence, like `:953`: `update()` refits. On the
  release build and on the lane's own library, the update is accepted
  with brms's message and the refit then stops from the default
  starting values, "NA/NaN gradient evaluation"
  (`dev/rel067-update955.R`, `dev/rel067-log/update955.txt`). It stays
  a defect, with that reason. Filed in `dev/test-backlog.md`.

### Small fixes folded in

- `vignettes/brms-migration.Rmd` said that `ar()`, `ma()`, `arma()`,
  `cosy()` and `unstr()` fit "in their covariance form only", which
  lane formrobust reported and did not edit (its section 10). It now
  says that `ar()`, `ma()` and `arma()` fit both forms and that
  `cosy()` and `unstr()` have the covariance form only, as in brms.
- `dev/lane-rules.md` said 53 active generic bindings, 25 in frmtmb and
  28 in frmtmb.sample. That was stale already at 0.66.0 (55, counted
  with `bindingIsActive()` over each namespace's exports on
  `rellib-r4`); at 0.67.0 it is 56, 29 and 27, since `parnames()` moved
  to core and `autocor()` is new.
- `dev/brms-api-diff.md`: the rows of the four ordinal constructors,
  `conditional_effects()`, `nsamples()`, `parnames()`,
  `posterior_samples()` and `bf()` are rewritten from the release
  build's formals, with a note on the new shared names.
