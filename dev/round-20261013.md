## How the release tree was built

The three lanes were combined in `../frmtmb-wt-release` (branch
`wt-release` at `2884ccbd`, frmtmb 0.69.1), in the order moparity,
optrap, seflags. Every lane is on `48c1e6c9` (0.69.0); 0.69.1 differs
from it only by lane ci691's commit (`R/fit.R` `nlminb_best_par()`,
four test files, `DESCRIPTION`, `codemeta.json`, `NEWS.md`). Nothing
was committed and no git write was made: blobs are read with `git
show`, and `git merge-file` works on files, not on the index.

- `dev/rel070-merge.sh` merges every lane in one rerunnable pass: it
  restores each of the 38 tracked files a lane changed to its HEAD
  (`2884ccbd`) blob, removes the untracked lane files an earlier run
  copied (`dev/rel070-log/copied-<lane>.lst`), merges the lanes in
  order with `git merge-file` against the `48c1e6c9` blob (line
  endings normalized to LF), copies the lanes' untracked files again,
  then runs the consolidation's edits (`dev/rel070-resolve.R`) and the
  NEWS merge (`dev/rel070-news-merge.R`), and stops if a conflict
  marker is left. A replacement file in a lane's tree is merged by
  rerunning. `man/*.Rd`, `NAMESPACE` and frmtmb.sample's generated

## Conflicts, and how each was resolved

Textual conflicts (`dev/rel070-log/merge-1.txt`):

1. **`R/fit.R`, the tail of `mo_search()`**, at optrap. Lane moparity
   added step 3 (a `cox()` baseline weight at a face the likelihood
   rises from, `cox_face_leave()`) and a restore of the objective's
   state after its probes; lane optrap made the tail settle the
   objective whether or not anything was refitted (`obj_settle()`)
   and return early after it. Resolved as the reviews asked
   (`dev/rel070-resolve.R`): moparity's step 3 first, then optrap's

   moparity's restore is dropped, because `obj_settle()` restores the
   saved state when `best` is `opt` and the state is not at it, which

   textually (optrap's step 2 wording, moparity's step 3); the
   resolve rewrites the lead, which said "two things remain", to two
   for a `mo()` term and a third for a `cox()` baseline, and says that
   the objective is left at the kept optimum. 0.69.1's
   `nlminb_best_par()` hunk and optrap's `newton_polish()`,
