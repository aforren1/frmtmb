## 1. Default priors

### The measured table

`dev/sampleprior-table.R` runs `brms::default_prior()` and
`frmtmb::default_prior(route = "sample")`, which lists what
`frm_sample()` applies, on the same data (seed 20261014, n = 60, 6
groups) for every brms family frmtmb fits (48 names including the
mixture; brms's `dirichlet_multinomial` and `negbinomial2` have no
frmtmb family), and for each family three kinds of model: `y ~ x + (1 |
g)` with every other dpar left without a formula, then each dpar with
`dpar ~ x` and with `dpar ~ 1`. Extra models cover the terms with
classes of their own: `s()`, `gr(dist = "student")`, `(x | g)`, `ar()`,
`unstr()`, `mo()`, equidistant thresholds, a three-part mixture, a
Student-t `mvbf()` with `set_rescor(TRUE)`, a log `mu` link on a wide
response, a wide positive response under `sigma ~ x`, and mixtures of
poissons, negative binomials and cumulatives. Rows are matched on
class, coef, group, resp and dpar. Logs:
`dev/sampleprior-log/table-r9.tsv` and `table-lane.tsv`; the markdown
below is `dev/sampleprior-table-md.R`'s.

How a row is read:

- `=`: the same density (as numbers: brms keeps `normal(5.0, 0.8)` as
  typed and writes `uniform(0, min_Y)` with a symbol, which is the
  smallest response of the data, here 0.348979089734591 for the shifted
  lognormal and 0.354641719488436 for wiener).
- **bold**: differs, or frmtmb has no row.
- A brms group or coefficient row that is empty under a class default
  is left out (brms's "vectorized" rows; frmtmb's table repeats the
  class density there, which is the same prior), as are brms's
  per-coefficient sd rows (lane prilabel's).
- "applied, not tabled (theta)": a mixture's weights without a formula.
  brms's class `theta` row is `dirichlet(1)`; no frmtmb class names the
  weights (`theta` is frmtmb's covariance vector, and `set_prior()`
  refuses the word for that reason), so the density is added by the
  sampler (`mix_theta_nlp()`) and named in the disclosure message, but
  `default_prior()` cannot list it.
- "brms row applies nothing (reference weight)": with `theta2 ~ x` on
  two components brms lists `theta1` with `logistic(0, 1)`; theta1 is
  the reference, a parameter on neither side (core's
  `brms_prior_class_refusal()` says so).
- "frmtmb spells it sd (smooth)": brms's `sds` is frmtmb's class `sd`
  with the smooth's label as group; the density is the same.
- "no parameter (frmtmb fixes the df)": `gr(dist = "student")` fixes
  the degrees of freedom (`dist_nu = 5`); brms estimates them under
  `gamma(2, 0.1)`.

### What changed in frmtmb.sample

`default_priors_for()` now follows brms 2.23.0's `def_dpar_prior()`
line for line (`brms_def_dpar_prior()`, `brms_family_prior()`,
`brms_dpar_class()` in `extensions/frmtmb.sample/R/sample.R`):

- A dpar without a formula gets its class's default on the parameter
  itself, through `set_prior(class = <dpar>)`, which applies the link's
  Jacobian. A dpar with a formula, `dp ~ 1` included, gets the
  link-scale default on its intercept. brms's switch is keyed on the
  dpar's class (`sigma2` is class `sigma`), and on the link: identity
  for a dpar without a formula, the dpar's link with one.
- brms's family hooks (brms#1614): `xbeta`'s `kappa`, the negative
  binomials' `inv_gamma(0.4, 0.3)` on `shape`, and `von_mises`'s
  `student_t(1, 0, 1)` on the `tan_half` intercept. A mixture never
  reaches them (brms asks the mixture family, which has none); measured
  on the mixture of negative binomials, whose `shape1` is
  `gamma(0.01, 0.01)` in brms.
- `sigma`'s scale reads the response on sigma's own link: the identity
  without a formula, whatever the `mu` link (brms
  `student_t(3, 0, 47.5)` on a log-link gaussian whose 0.19.0 default
  was `student_t(3, 0, 2.5)`, read on log y), and sigma's link with one
  (`student_t(3, 0, 5.9)` on a wide positive response under
  `sigma ~ x`, where 0.19.0 wrote 2.5).
- The ordinal thresholds get `student_t(3, 0, 2.5)` on class
  `Intercept`, one row per threshold vector as `get_prior()` lists it
  (core's `ord_lp_blocks()`, now exported). Sum-to-zero thresholds stay
  flat and the message says why.
- `ndt` gets `uniform(0, min_Y)`, written to 17 significant digits so
  that the density's edge is the response's own minimum.
- A mixture's weights without a formula get `dirichlet(1)` on the
  simplex: `lgamma(K) + sum(log w)` on the log ratios the sampler works
  on, whichever component is the reference. `prior = "flat"` drops it
  with the other defaults.
- `unstr()` gets `lkj(1)` on class `cortime`.
- com_poisson's dispersion is frmtmb's `nu` and brms's `shape`; it
  takes brms's `shape` default.
- A family brms does not have (frmtmb's `tweedie`, `huber`, `nbinom1`,
  `nbinom2`) takes the default of the dpar's name, which is what brms
  gives a custom family with a dpar of that name.

Defects in 0.19.0 found on the way, fixed by the same change:

- `sigma ~ 1` (and `sigma<k> ~ 1` of `logistic_normal()`) took the
  natural-scale default of a sigma without a formula, keyed by the
  number of design columns rather than by the formula, so the
  sampling-route table listed `Intercept sigma (flat)` where brms has
  `student_t(3, 0, 2.5)` (asym_laplace, exgaussian, gaussian,
  gen_extreme_value, hurdle_lognormal, lognormal, shifted_lognormal,
  skew_normal, student, zero_inflated_asym_laplace in the table).
- A mixture component's location was read on the family's `mu` link,
  which a mixture does not have; it is now read on the component's own
  link (`dev/sampleprior-mixprobe.R`: brms and frmtmb both give
  `student_t(3, 3, 2.5)` on a mixture of poissons with median log y
  3.04).
- The disclosure note "no defaults for shape, phi, nu, kappa (brms uses
  gamma / inverse-gamma)" said `set_prior()` could not express them; it
  could, since `gamma()` and `inv_gamma()` were already supported.

### What changed in core (minimal, named for the consolidation)

- `R/priors.R`: `parse_prior_dist()` takes `uniform(lb, ub)` and
  `lognormal(mu, sd)`; `prior_base_logdens()` evaluates them, the
  uniform as `-log(ub - lb)` plus `nan_unless_pos()` guards at both
  ends, so the value outside the interval is `NaN` on the tape too
  (rtmb-pitfalls item 22; the test builds the tape and reads it there).
  `prior_dist_params` and the refusal's list of supported densities
  name both. `set_prior()`'s documentation lists every density.
- `R/simulate-new.R`: `rprior_one()` draws both (prior-predictive
  simulation).
- `R/sampling-api.R`, `NAMESPACE`, `man/frmtmb-sampling-api.Rd`:
  `ord_lp_blocks()` exported in the sampling API.
- `tests/testthat/test-prior-compat.R`: the "unsupported density"
  example was `uniform(0, 10)`; it is `chi_square(3)` now.

## 2. `frm_sample(seed = )` fixes every chain

The jitter of chains 2 and up (`mode_inits()`) was drawn from the
session's stream. It is now drawn inside `with_sample_seed(seed, ...)`,
which seeds R's stream with `seed`, draws, and restores the caller's
stream (or removes it if there was none). Without a seed, or with
brms's `NA`, the session's stream decides, as before. That is brms's
semantics: `brm(seed = )` reaches Stan, which draws brms's inits, so a
seed fixes every chain there.

rstan's `sampling()` itself still moves the session's stream whatever
the seed: it draws each chain's permutation of its kept draws with
`sample.int()` (`dev/sampleprior-rngprobe.R`), and `brm()` goes through
the same function, so neither leaves the stream alone. The test asserts
that frm_sample()'s own draw does.

`test-sample-seed.R`: two calls with `seed = 3`, 2 chains and the
session's stream moved between them give identical draws, and
`seed = 4` gives different ones. On rellib-r9 it fails at row 101 of

## 3. brms's draw names

The draws matrix now carries brms's covariance summaries as columns
after the sampled ones and before `lp__`: `sd_<group>__<coef>`,
`cor_<group>__<coef1>__<coef2>`, and where the model has them a
smooth's `sds_`, `rescor__`, `ar[1]`, `ma[1]`, `cosy`, `cortime__`,
`sdme_` and `corme__`. Their names are the ones core's `hyp_env_vals()`
gives at the fit's estimate, which is also what core's `variables()` of
a fit lists, so the two cannot disagree; lane prilabel's nested labels
(`g1:g2`) reach the draws through the same function without a change
here. ASSUMPTION for the consolidation: prilabel changes the labels
inside `brms_group_name()` and `hyp_env_vals()`, which `variables()`
reads, and not in a separate path. If it changes `hyp_env_vals()` alone,
the fast path below fails its check and every draw is named through
`hyp_env_vals()`, so the names stay core's either way.

The `theta_` columns stay: the model reads them, and every reader that
hands a draw back to the model (`draws_internal_matrix()`) drops the
derived columns first, as it drops a mixture's last weight. `summary()`
reports both.

position is taken from core's naming functions and kept only if it
