## How the release tree was built

The lanes were combined in `../frmtmb-wt-rel075` (branch `wt-rel075`
at `4fd134db`), in the brief's order: smallfix, bhaz, brmsnames,
sarfcor. No git write was made: blobs are read with `git show`, and
`git merge-file` works on files.

- `dev/rel075-merge.sh` (from `dev/rel074-merge.sh`) merges in one
  rerunnable pass. It checks that `18b536fc..4fd134db` changed exactly
  `pkgdown.yaml` and `build-docs.R`, restores each file a lane changed
  to its 4fd134db blob, and merges each lane three-way: the release
  file (ours), the 18b536fc blob (base) and the lane's file (theirs),
  LF-normalized. It copies the lanes' untracked files, then regenerates
  `R/links-brms.R` (equal to the HEAD blob: no lane changed it or its
  generator) and runs `dev/rel075-resolve.R` and
  `dev/rel075-news-merge.R`; it stops on a conflict marker left.
  `man/`, `NAMESPACE` and the generated helpers are left out of the
  textual merge; roxygen writes them.
- Files changed (`dev/rel075-log/merge-work/<lane>.status`, final run
  `merge-8.txt`, the same in `merge-7.txt`): smallfix 49, bhaz 15,
  brmsnames 11, sarfcor 54; 108 in all, 92 without generated ones. No
  lane deleted a file.
- Untracked lane files copied: smallfix 31, bhaz 16, brmsnames 27,
  sarfcor 88, no clash. Not copied: the reviewers' `dev/review-*`

  `dev/release/sarfcor-fr1.jobs` (scratch), generated Rd files, Stan

- Every regenerated `man/*.Rd` and `NAMESPACE` equals the one lane

- Files two or more lanes changed: `NEWS.md` (all four), `R/priors.R`
